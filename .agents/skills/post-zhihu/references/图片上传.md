# 知乎图片上传策略

## 核心原理

知乎专栏编辑器基于 Draft.js，图片以 "atomic block" 形式存储。图片必须上传到知乎 CDN（`pic*.zhihu.com`）才能在文章中显示，外部图床 URL 会被过滤。

## 上传方案对比

| 方案 | 实现方式 | 可靠性 | Draft.js Race Risk |
|------|---------|--------|-------------------|
| **串行 set_input_files** | Chrome CDP 逐一喂文件到 file picker | ⭐⭐⭐⭐ | 低（串行） |
| 并行 set_input_files | 并发喂多个文件 | ⭐⭐ | 高（图片丢失） |
| ClipboardEvent 粘贴 | 模拟系统粘贴板 | ⭐⭐⭐ | 中（需等待） |
| 直接 API 上传 | POST /upload | ⭐ | 鉴权复杂 |

**推荐方案：串行 set_input_files + DOM 验证**

## 串行上传流程

```
打开知乎专栏编辑器
  ↓
定位到需插入图片的位置
  ↓
循环每张图片:
  ① 点击编辑器工具栏「图片」按钮 (或 Ctrl+G)
  ② 等待 file input 出现
  ③ set_input_files(local_path)
  ④ 等待上传完成 (DOM 出现 atomic block / img 标签)
  ⑤ 验证图片 URL 以 https://pic 开头
  ⑥ 确认后继续下一张
  ↓
全部插入完成，继续编辑
```

## Draft.js Race Condition

知乎编辑器的已知坑：多图并发上传会导致：

- 只插入 1 张，其余被覆盖
- Draft.js 内部状态不一致，后续编辑错位
- Preview 页占位符残留

**规避**：
- 每次只上传 1 张图片
- 等待 `document.querySelector('figure')` 或 `.image-container` 出现
- 验证 `img.src` 以 `https://pic` 开头
- 设置超时 15s，超时重试一次

## 文件大小限制

| 类型 | 最大 | 格式 |
|------|------|------|
| 普通图片 | 5 MB | PNG/JPG/GIF |
| 动图 GIF | 5 MB | 会被转静图 |
| 封面图 | 10 MB | PNG/JPG |
| SVG | ❌ 不支持 | 需转 PNG |

## 推荐：zhihu_image_uploader 思路

从编辑器自动捕捉换为预上传：

1. 启动 Chrome (CDP) → 登录知乎
2. 打开专栏编辑页
3. 对每个图片路径：
   - 找到 file input（工具栏「图片」触发的 `<input type="file">`）
   - `set_input_files(path)` 
   - 等待并验证
   - 记录替换后 CDN URL
4. 用 CDN URL 替换 promote 中的本地路径
5. 最后通过 CDP 粘贴完整 HTML 内容

## 实例代码（Chrome CDP via Playwright）

```python
page = context.pages[0]
file_input = page.locator('input[type="file"]').first
page.locator('.toolbar button:has-text("图片")').click()
file_input.set_input_files('/path/to/img.png')
page.wait_for_selector('img[src*="pic.zhihu.com"]', timeout=15000)
```

## 关于我们项目

当前图片路径（weixin.md 中的本地图片）：
- 封面图: `00-cover.png`（21:9 / 16:9）
- 内文图: `img_*.png` 或 `figure_*.png`

知乎发布需要：
1. 先粘贴 HTML 内容（文本+公式）
2. 再逐张插入内文图
3. 最后设置封面图

封面图通过编辑器「设置封面」功能单独上传（推荐 PNG/JPG, 16:9 或 21:9）。
