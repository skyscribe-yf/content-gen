如何理解 Adam 算法 (Adaptive Moment Estimation)？

你看不懂，大概率不是因为数学难——而是因为你没从 SGD 的痛点出发去理解。

Adam 的论文只有 4 个公式，每个公式都对应 SGD 的一个具体缺陷。搞清楚了 SGD 哪里不行，Adam 的每一行就都自明了。

一、SGD 只有一个问题，但这个问题是致命的

最朴素的梯度下降长这样：

θₜ₊₁ = θₜ − η · gₜ

η 是学习率，gₜ 是当前梯度。梯度告诉你往哪走，η 告诉你走多大步。

问题在哪？η 只有一个值，你模型里有百万个参数。

举个例子：一个简单的二维损失函数：

f(x, y) = (x²/100) + y²

x 方向极平缓（梯度小），y 方向极陡峭（梯度大）。等高线是一个被压扁的椭圆——长轴是短轴的 100 倍。

用同一个 η：（图见文末原文）

  • y 方向本来就陡 → η 显得太大 → 冲过头 → 冲回来 → 反复震荡
  • x 方向本来就平 → η 显得太小 → 几乎没动

之字形震荡着往下蹭，走 100 步还不如人家 10 步。

这不是 SGD 的算法 bug——是数据本身的问题。你的数据对某些参数的约束很强（梯度的方差大），对另一些很弱（梯度方差小）。数据越"偏心"，一刀切的 SGD 就越难受。

所以问题不是"优化器能不能练得更快"——而是需要一种方法，给每个参数自动分配不同的步长。

Momentum（动量法）迈出了第一步。它给梯度加"惯性"——上一步往右走，这一步也往右偏：

vₜ = β·vₜ₋₁ + η·gₜ

θₜ₊₁ = θₜ − vₜ

震荡方向的梯度符号来回变，累加后会趋近于 0；一直下坡的方向符号一致，越累越大。Momentum 解决了震荡，但没解决尺度差异。 y 方向仍然比 x 方向受 η 的影响大 100 倍。

Adam 要解决的，就是这个。

二、Adam 的核心洞察：方向 ÷ 尺度

Adam 的更新公式只有一行：

θₜ₊₁ = θₜ − η · m̂ₜ / (√v̂ₜ + ε)

拆开来看，其实就是四个字：方向 ÷ 尺度。

分子 m̂ₜ 告诉你往哪走（方向估计），分母 √v̂ₜ 告诉你这一步迈多大（尺度估计）。两个估计值都是自动算的，不需要你给每个参数单独调学习率。

下面逐个拆这背后的四个方程。

方程 1：mₜ —— 给梯度加记忆（动量）

mₜ = β₁·mₜ₋₁ + (1−β₁)·gₜ

mₜ 是梯度的指数滑动平均。β₁ 通常取 0.9——意味着：当前这一步，90% 看历史方向，10% 看新梯度。

打个比方：你在浓雾里下山，脚下感觉到的坡度是当前梯度。但你不能只看脚下，得记着上一脚踩了哪。 上一步往左，这一步坡度也往左 → 放心迈大步；上一步往左，这一步坡度往右 → 犹豫一下，少走点。

mₜ 天然地放大了一致方向、抑制了震荡方向。但它只解决了方向问题，没解决尺度问题。

方程 2：vₜ —— 记住每个参数的"脾气"

vₜ = β₂·vₜ₋₁ + (1−β₂)·gₜ²

vₜ 是梯度平方的指数滑动平均。β₂ 通常取 0.999，意味着记忆窗口约 1000 步。

为什么 vₜ 出现在分母？ 这是 Adam 最聪明的地方。

打个比方：你家水龙头有两个旋钮——冷水管很粗（大梯度），拧 1 度就喷一脸；热水管极细（小梯度），拧 10 度才出一点点水。SGD 给你一把扳手，两个旋钮拧同样的角度。

vₜ 做的事：记住每个旋钮的历史——冷水那边一直哗哗流，v 就大，分母变大，自动减速；热水那边水流细，v 就小，分母变小，自动加速。 拧几次之后，两个水龙头出水量自动平衡了。

大梯度 → v 大 → η/√v 小 → 自动减速。小梯度 → v 小 → η/√v 大 → 自动加速。

这就是"自适应"（Adaptive）的含义。不需要你手动调任何东西。

方程 3：偏差修正 —— 一个工程补丁

mₜ 和 vₜ 初始化为 0。所以训练第一步时，m₁ 和 v₁ 都比真实值小了 10 倍（对 m）甚至 1000 倍（对 v）。

m̂ₜ = mₜ / (1−β₁ᵗ)

v̂ₜ = vₜ / (1−β₂ᵗ)

除以 (1−β₁ᵗ) 就是在前面几步把值放大回去。当 t 很大时，β₁ᵗ → 0，修正自动淡出。这个补丁只在训练开头有用，跑几分钟后就可以忽略。

合在一起：一个信号噪声比估计器

把四个方程压成一句话：

θₜ₊₁ = θₜ − η · (方向估计) / (尺度估计)

这个结构的本质是逐参数的 SNR（信噪比）估计器。

把梯度想象成"信号 + 噪声"：

  • m̂ₜ 估计信号（梯度的真实方向）
  • √v̂ₜ 估计噪声（梯度的波动幅度）

信噪比高的参数 → 大步走（方向明确）。信噪比低的参数 → 小步走（方向模糊）。

震荡参数 = 高噪声 → 分母大 → 步长小。平缓参数 = 低噪声但信号也小 → 分母小 → 步长大。一切自动。

符号做了什么解决了什么
m̂ₜ（分子）梯度的方向估计SGD 的震荡——动量让方向更稳定
√v̂ₜ（分母）梯度的尺度估计SGD 的一刀切——大梯度自动减速、小梯度自动加速
ε（10⁻⁸）防止除以 0纯数值稳定项
β₁ᵗ, β₂ᵗ 修正前几步放大m 和 v 初始为 0 的偏差

没有多余的符号。 四个方程，覆盖了 SGD 的所有已知缺陷。

三、实际怎么用？看 DeepSeek 和 Qwen 的配置

Adam 不是教科书玩具。直接查 HuggingFace 上的 config.json：

模型优化器β₁β₂weight_decay
DeepSeek-V3AdamW0.90.950.1
Qwen3AdamW0.90.950.1

两个关键信息：

1. 都用 AdamW，不是原版 Adam。 AdamW 把权重衰减从 L2 正则里拆出来、直接加到参数更新上。原版 Adam 的 L2 正则和自适应学习率会互相干扰，AdamW 一刀切干净。现在所有大模型默认 AdamW。

2. β₂ = 0.95，不是经典的 0.999。 为什么降？大模型训练时 batch size 巨大（几千上万），每步梯度本身就比较稳定。β₂ = 0.999 的记忆窗口 ≈ 1000 步——对稳定的大 batch 梯度来说，1000 步前的东西没有参考价值了。降到 0.95，记忆窗口缩短到 ~20 步，让优化器更快响应最新梯度变化。

四、Adam 之后：Muon 正在改写规则

Adam 不是终点。

2024 年，Keller Jordan 提出了 Muon 优化器——不再像 Adam 那样逐元素缩放，而是对整个参数矩阵做 Newton-Schulz 迭代，把梯度更新矩阵正交化。

Kimi K2（2025，1 万亿参数）率先全量采用 Muon 改进版 MuonClip，15.5 万亿 token 全程不用 AdamW。DeepSeek-V4（2026 年 4 月发布，1.6 万亿参数）紧随其后，把大部分参数从 AdamW 换成 Muon，只留 embedding 和输出层给 AdamW。

优化器的牌桌已经在换了。

五、一句话总结

SGD 用同一个学习率 η 更新所有参数 → 大梯度震荡、小梯度不动。Adam 用 m̂ₜ（方向）除以 √v̂ₜ（尺度），给每个参数自动调速：大梯度自动减速，小梯度自动加速。本质是一个逐参数的 SNR 估计器。新一代大模型已经从前几年的 AdamW 转向 Muon。
