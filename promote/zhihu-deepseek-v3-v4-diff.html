DeepSeek V3 与 V4 有什么区别？V4 是 V3 的升级版吗？

先给结论：V4 不是 V3 的简单升级版，而是架构层面的代际跃迁。两者在注意力机制、残差连接方式、优化器、上下文长度、训练数据量上都发生了根本性变化。如果 V3 是一辆油改电的混动轿车，V4 是从底盘开始重新设计的纯电平台——虽然外观都是"DeepSeek 牌"，但内部的力学结构已经不同。

下面按"到底变了什么"逐项拆开。

一、参数规模：总参数翻了 2.4 倍，但激活参数只增了 32%

维度DeepSeek-V3 (2024.12)DeepSeek-V4-Pro (2026.04)
总参数671B1.6T
激活参数37B49B
上下文长度128K1,000K（1M）
训练 token 数14.8T32T+

数据来源：DeepSeek-V3 技术报告（arXiv:2412.19437）§2；DeepSeek-V4 技术报告（arXiv:2606.19348）Introduction。

关键细节：总参数从 671B 暴涨到 1.6T，但激活参数只从 37B 增到 49B。这说明 V4 继续走 MoE（混合专家）路线——模型的知识存储容量大幅扩展，但每次推理时真正参与计算的参数增长有限。

打个比方：V3 是一个拥有 256 个科室、每次请 8 个科室会诊的医院；V4 是扩建到 384 个科室、每次只请 6 个科室的新院区。总床位多了很多，但每次会诊的医生反而省了一个——因为每个诊室的专业化程度更高了。

二、注意力机制：MLA 被 CSA+HCA 取代

这是 V3 到 V4 最核心的架构变化。

V3 用的是 MLA（Multi-head Latent Attention，多头潜在注意力）。它的核心思路是低秩压缩：把每个 token 的完整 Key、Value 压成一个更小的潜在向量 cᴷⱽ。在 DeepSeek-V3 的公开配置中，这个 KV latent 维度是 512。推理时只需缓存压缩后的摘要而非完整 KV，大幅减少显存占用。

V4 彻底抛弃了 MLA，改用混合注意力架构 CSA + HCA：

  • CSA（Compressed Sparse Attention，压缩稀疏注意力）：先把 KV 序列沿长度方向 4 倍压缩（每 4 个 token 压成 1 个），再用"闪电索引器"（Lightning Indexer）从压缩后的池子里挑出最相关的 top-k 个块，做稀疏注意力。相当于先把一本书缩成目录，再从目录里挑出最相关的几章精读。
  • HCA（Heavily Compressed Attention，重度压缩注意力）：更激进，直接 128 倍压缩，不做稀疏选择，每个 query 都对全部压缩块做 dense attention。但因为序列已经被压得很短，dense 计算量反而很小。相当于只读全书的"一句话摘要"。

两种机制在层间交替排列。V4-Pro 的 61 层中，第 0-1 层用 HCA，第 2-60 层 CSA 和 HCA 交替。

官方数据：在 1M token 场景下，V4-Pro 的单 token 推理 FLOPs 仅为 V3.2 的 27%，KV Cache 仅为 10%。（来源：DeepSeek-V4 技术报告 Introduction）

三、残差连接：从简单相加到流形约束超连接

Transformer 的标准残差连接是 y = x + F(x)——输入直接加上子层输出。V3 也用这个。

V4 换成了 mHC（Manifold-Constrained Hyper-Connections，流形约束超连接）。核心变化是：不再是"一条线"把输入送过子层，而是用 hc_mult 条并行残差流（默认 4 条），每条流保持独立形状 [B, S, hc_mult, D]，经过注意力/FFN 子层时通过一个(pre, post, comb)三元组来混合这些流。关键是 comb 矩阵是一个双随机投影，通过 Sinkhorn-Knopp 迭代实现，使信号传播成为非膨胀映射——直觉上，它让信息在多深度网络中流动时更稳定、更不容易爆炸或消失。

四、优化器：从 AdamW 到 Muon

V3V4
优化器AdamW（β₁=0.9, β₂=0.95）Muon（大部分参数）+ AdamW（仅 embedding 和输出层）

（来源：V3 技术报告 §4.2；V4 技术报告 Introduction）

Adam 给每个参数单独算学习率，用一阶矩 m̂ₜ 除二阶矩 √v̂ₜ 做自适应缩放。Muon 走得更远：对整个参数矩阵做 Newton-Schulz 迭代，把梯度更新矩阵正交化，一步释放所有更新方向。2024 年 Keller Jordan 提出 Muon，2025 年 Kimi K2 率先全量采用 MuonClip，2026 年 V4 紧随其后。

这意味着 V4 的训练动力学和 V3 完全不同——不只是"换了个更好的工具"，而是优化器改变了参数空间的探索方式。

五、MoE 细节的变化

虽然都是 MoE，但具体设置有明显调整：

V3V4-Pro
路由专家数256384
共享专家数11
每 token 激活专家数86
路由激活函数SigmoidSqrt(Softplus(·))
路由方式纯动态路由前几层 Hash-MoE（静态查表），后续层动态路由

（来源：V3 技术报告 §2.1.2；V4 技术报告 §2.1）

值得注意：V4 每 token 激活的专家数从 8 降到了 6，但总专家数从 256 增到 384。这意味着激活比（每次计算占总专家的比例）从 3.1% 降到了 1.6%——单次推理更稀疏，但专家池更大、分工更细。

V4 还在前几层引入了 Hash-MoE：用冻结的 token-id → expert-id 哈希表做静态路由，跳过学习路由的收敛成本，相当于医院的"预检分诊台"——常见症状直接分流到对应科室，只有复杂病例才走专家会诊。

六、精度与推理效率

  • 训练精度：V3 首次在超大模型上验证 FP8 混合精度训练；V4 进一步用 FP4 + FP8 混合（MoE 专家用 FP4，其他参数用 FP8）
  • 上下文：V3 支持 128K；V4 支持 1M（8 倍扩展）
  • 推理成本：1M token 场景下，V4-Pro 的单 token FLOPs 仅 V3.2 的 27%，KV Cache 仅 10%

所以，V4 是 V3 的升级版吗？

准确地说：V4 是 V3 的"继任者"，不是"升级版"。

"升级版"意味着同样的架构做参数扩容（像 iPhone 15 → 15 Pro）。但 V4 在注意力、残差、优化器三个最根本的组件上都做了重新设计。它更像是从"用 MLA 压缩 KV cache"的技术路线，转向了"用 CSA/HCA 同时压缩 KV cache 和注意力计算量"的新路线。

V3 解决的核心问题是"怎么用 MoE + MLA 把模型做大同时控制推理成本"；V4 解决的核心问题是"怎么在 1M token 的极端长上下文场景下，让注意力和存储成本仍然可承受"。
