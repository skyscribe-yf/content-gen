DeepSeek V4 为什么能卖这么便宜：大模型的成本到底花在哪？

大模型 API 的价格差距，不是"谁补贴多"——而是"谁少算了多少"。

我拿自己写代码时的真实 token 账单拆开算了一遍：DeepSeek-V4 Pro 每 1M 总 token 约 ¥0.20，GPT-5.6 Sol 约 ¥5.92，Claude Fable 5 约 ¥11.51。差距最大到 56 倍。

这 56 倍不是靠亏本换来的。拆开看，便宜来自三层：缓存复用、稀疏计算、系统工程。下面逐层拆。

一、先算一笔真实账

很多人比价格只看"输入 ¥3/百万 token，输出 ¥6/百万 token"——这是标价，不是你实际付的钱。

我写代码时的真实 token 结构：每 1M 总 token 中，99.5% 是输入，0.5% 是输出；输入里 95% 命中缓存，5% 是新写的需求。

为什么 95% 能命中缓存？因为代码助手场景下，系统提示词、仓库目录、团队规则、相关文件——这些每轮都带，但内容几乎不变。第一轮写入缓存，后面每轮直接命中。

成本公式：

成本 = 0.995 ×（0.95 × 缓存命中价 + 0.05 × 普通输入价）+ 0.005 × 输出价

标价差 10 倍，实际账单差 50 倍。 差距被放大的核心原因：缓存命中价差。DeepSeek 缓存命中 ¥0.025，Claude 是 ¥6.80——差 272 倍。而 95% 的输入都走缓存。

所以第一个答案：DeepSeek 便宜的第一大原因不是模型架构，是缓存定价策略。 但缓存谁都能做，为什么 DeepSeek 敢定 ¥0.025？这就得看第二层。

二、稀疏计算：256 个专家只请 8 个干活

传统稠密模型像全科会诊——一个 token 进来，所有参数都参与计算。参数越多，每个 token 的计算量越大。

MoE（混合专家）像分诊台：先看当前 token 需要什么，再决定请哪些专家处理。DeepSeek-V3 有 256 个路由专家，每个 token 只选 8 个，另有 1 个共享专家所有 token 都经过。

打个比方：一家医院有 256 个科室。传统模式是每个病人都要 256 个科室全看一遍；MoE 模式是分诊台根据症状只挂 8 个号。 病人还是能得到对症的治疗，但 248 个科室这轮不用开灯。

专家前馈分支的计算量大致是全量执行的 8/256 = 1/32。这是 MoE 最核心的省算力来源。

但注意：这不是整个模型端到端快 32 倍。注意力层、路由器、专家间通信、内存访问都还在。实际吞吐提升取决于硬件和服务系统能否把额外开销压下去。

路由器怎么选人？三步：打分 → 选人 → 合并答案。

sᵢ(x) = router(x)ᵢ （为每个专家打分）
y = Σᵢ∈Top-k wᵢ(x) · Expertᵢ(x) （按权重合并选中专家的输出）

还有一个关键问题：会不会所有 token 都挤到同一个专家？DeepSeek-V3 用的是无辅助损失的负载均衡——不靠惩罚项硬推，而是动态调整偏置：忙的专家降低入选概率，闲的专家提高入选概率。像分诊台根据排队长度调整导流，而不是对病人收拥堵税。

三、系统工程：理论省算力 ≠ 实际低账单

MoE 负责"谁干活"，但稀疏计算变成低账单，还差三道工程关：

1. 低精度计算。 FP8 训练和推理把每个数值从 16 bit 压到 8 bit，显存和带宽直接减半。DeepSeek-V4 是最早全量采用 FP8 的大模型之一。

2. 高效通信。 256 个专家分布在不同 GPU 上，token 要发过去、结果要收回来。通信延迟如果压不住，省下的计算全被等网络吃掉。DeepSeek 的方案是让每个 GPU 负责多个专家，减少跨设备通信次数。

3. 批处理与服务调度。 同一时刻不同用户的不同 token 可能需要不同专家。调度器要把"去同一个专家的 token"攒成一批一起算，避免专家空转。这叫专家并行（expert parallelism），是 MoE 服务最复杂的工程问题。

所以完整的公式是：

低成本 API = 缓存复用 + 稀疏计算 + 低精度计算 + 高效通信与服务

四把钥匙，缺一把都锁打不开。

四、大模型的成本到底花在哪？

回到问题本身。训练一个大模型的成本主要花在：

成本项占比（大致）说明
GPU 算力60-70%数千张 H100 跑几个月
数据10-15%清洗、标注、去重
人力10-15%研究员、工程师、基础设施
电力与冷却5-10%数据中心运营

但训练成本是沉没成本，API 定价看的是推理成本——每生成一个 token 要花多少算力、带宽和电费。

推理成本的核心公式：

推理成本/token ∝ 激活参数量 × 精度位数 × 通信开销

MoE 降低了第一项（只激活 8/256 专家），FP8 降低了第二项（8 bit 替代 16 bit），工程优化降低了第三项。三层叠加，才是 DeepSeek 敢定 ¥0.025 缓存命中价的底气。

五、一句话总结

DeepSeek 便宜不是单点突破，是四层叠加：缓存复用压低重复输入成本（95% 命中时账单差 50 倍），MoE 稀疏路由只激活 1/32 专家，FP8 减半精度开销，工程调度把理论优势变成实际吞吐。缺任何一层，价格都做不到现在的水平。
