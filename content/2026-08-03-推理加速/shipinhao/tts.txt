你给大模型 API 发出一个请求，以为它会直接抵达 GPU。可十几秒过去，屏幕上连第一个字都没有。到底慢在哪？
首字延迟，工程上叫 TTFT，Time To First Token。从你按下发送，到收到第一个流式 token，中间这段等待，就是首字延迟。
请求并不是直通 GPU 的电线。它要过网关鉴权、模型路由，可能还要排队等批处理；真正进入模型后，先 prefill 读完整段输入，再逐 token decode，最后流式返回。
prefill 要建立输入位置之间的两两关系，工作量随输入长度近似平方增长。输入翻一倍，注意力配对的工作量，可能接近四倍。
decode 阶段，KV Cache 把历史的 Key 和 Value 存下来，避免每次重算。但缓存占用随上下文线性增长：历史越长，显存压力越大。
作者的真实请求日志：输入从 16K 涨到 128K，TTFT 中位数从 4.7 秒升到 14 秒，将近三倍；但首字之后的生成速度，稳定在每秒 25 到 30 个 token。长输入，主要撞上的是 prefill 和排队。
想提速，先看慢在哪一段：输入太长，就压缩提示词和历史；decode 慢，用 KV Cache 和推测解码；显存吃紧，可以量化。四种扳手，各管一段。
给每次请求记下输入、输出、TTFT 和 TPS，看 P50 和 P90，再决定优化方向。关注数解AI，继续拆大模型推理链路。
