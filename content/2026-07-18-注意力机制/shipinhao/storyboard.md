## 段落设计（8 段）

| # | 场景 | 动画要点 | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子 | 「注意力」大字 + 数据库图标被划掉；Q/K/V 三个牌；「先看它怎么算」箭头 | 大模型最常被讲错的一个机制，就是注意力。有人说：Q 是查询，K 是键，V 是值——像数据库一样。这个说法，帮倒忙。注意力到底是什么？先看它怎么算。 |
| S2 | 四步计算 | token 生成 Q/K/V 三向量（猫追老鼠 4 token 简化 1 个）；内积 ⟨Q,K⟩ → ÷√d → softmax → 加权求和 V 四步链路；「四步而已」强调 | 每个 token 生成三个向量：Q、K、V。Q 和 K 做内积，得到匹配分数；分数除以 √d，过 softmax 变成权重；再用权重对 V 加权求和。内积、缩放、归一化、求和——四步而已。可它和数据库查询，差在哪？ |
| S3 | 数据库 vs 圆桌 | 左：数据库（查询方→被查方单向箭头）；右：圆桌 4 人各带 K 名片/Q 提问/V 信息，双向箭头；「同时提问也同时被问」标签 | 差在：数据库里，一方查、一方被查；注意力里，每个 token 同时生成 Q、K、V，既是提问者，也是被提问者。token 1 的 Q 和 token 2 的 K 打分，token 2 的 Q 也和 token 1 的 K 打分。更贴切的是圆桌讨论：每人都带一张名片 K、一个提问 Q、一份信息 V。那它会只挑一条记录吗？ |
| S4 | 权重分配 | 4 token 热力图行（0.7/0.2/0.1 权重条）；「关注≠只看一个」；指数函数 e^x 曲线永远为正 → 无零权重；分配 vs 选择标签 | 不会。对每个允许的位置，softmax 都给一个权重：0.7、0.2、0.1——不是只取一个。指数函数永远为正，softmax 之后没有零权重。「关注」不是「只看一个」，是在一组位置之间做分配。那公式里的矩阵，又是怎么回事？ |
| S5 | 矩阵只是打包 | Attention(Q,K,V) 公式卡；QKᵀ 第 i 行展开 = qᵢ 和之前所有 K 打分；矩阵 → GPU 并行标签；「各算各的」 | softmax(QKᵀ/√d)V，别被矩阵吓住。QKᵀ 的第 i 行，就是第 i 个 token 拿自己的 Q，和之前每个 token 的 K 打分的结果。矩阵只是把 N 个 token 的运算打包，让 GPU 一次算完——逻辑上，每个 token 各算各的。那凭什么内积能当匹配分数？ |
| S6 | 内积几何 + √d | 二维向量图：q 与 k₁ 夹角小（分数高）、q 与 k₂ 正交；公式 ‖Q‖‖K‖cosθ；维度膨胀 ±10 → ±100 数字条；÷√d 压回 | ⟨Q,K⟩ 等于 ‖Q‖‖K‖cosθ——方向越对齐，分数越高；正交，就是零。但高维里分数会膨胀：64 维还好，4096 维内积可能跑到 ±100，softmax 就退化成 one-hot。除以 √d，把方差压回来。一个头，只学一种问法吗？ |
| S7 | 多头注意力 | 单头（一套 QKV）→ 多头（3 组投影）；Qwen3-8B 卡片：4096 维 / 32 头 / 每头 128 维；「多套问法」标签 | 不止。实际模型用多头注意力：Qwen3-8B，隐藏维度 4096，32 个头，每头 128 维。一个头重视附近的词，另一个头追踪指代对象——多套独立的 QKV 投影，不是一副更大的眼镜。那这场加权汇总，代价是什么？ |
| S8 | 总结 + 品牌尾卡 | O(N²) 曲线 / 4K→32K 64 倍数字对比；GQA、MLA 标签；回顾「加权汇总」定义；尾卡：avatar 圆角图 + 黄色「关注「数解AI」」+ 当期文章标题 + 「查看公众号文章」绿色引导 + 下一篇预告（FFN） | 代价是 O(N²)。上下文从 4K 扩到 32K，可比较的位置变成 64 倍——所以才有 GQA、MLA 这些省法。回到开头：注意力不是数据库查询，是每个 token 按自己的需要，从上下文里做加权汇总。关注数解AI，下一篇拆 FFN：注意力找人，知识到底存在哪？你觉得模型该更看重近的词，还是更相关但更远的词？评论区聊聊。 |

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（tts.txt = 8 段合并）+ `--subtitle` 句子级时间戳 → `scripts/tts_split.py` 按时间戳切分 8 段（克隆音色 `branding/my-voice-denoised.wav`，speed 1.15 pitch +2，speech-2.8-turbo）
2. 动画：每段一个 Manim Scene（S1..S8），`construct` 末尾 `pad_to_voice()`；动画节点按台词时间轴铺满（≥80% 配音时长）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：Cover 场景单帧渲染（复用圆桌讨论/权重分配视觉）→ `<标题>-封面.png`（1080×1920，关键内容在 3:4 安全区 y∈[240,1680]）
5. 归档：`content/2026-07-18-注意力机制/shipinhao/`
