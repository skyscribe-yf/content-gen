## 段落设计（8 段）

| # | 场景 | 动画要点 | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子 | 「注意力 ✓」+「FFN ?」；参数占比条（FFN 一条更宽）；问号放大 | 注意力已经把上下文汇进每个 token 了，为什么 Transformer 还要留一块前馈网络？它不让 token 之间交流，却常常占掉最多的参数。这不矛盾吗？前馈网络 FFN，到底在干什么？ |
| S2 | 圆桌 vs 思考室 | 左：圆桌 4 token 互相看（双向箭头）；右：4 间无门小房间各 1 token；「互相看 / 各自想」标签 | 把一层 Transformer 想成一次工作流程：token 先围坐圆桌，在注意力里听取彼此的线索——这是互相看。散会后，它们回到一间间没有门的思考室，各用各的设备处理笔记。这间思考室，就是 FFN。注意力负责互相看，FFN 负责各自想。 |
| S3 | 独立性 yᵢ=f(xᵢ) | 函数卡 yᵢ=f(xᵢ)；token1 箭头只进自己那格（xⱼ 灰掉）；「共享参数 ≠ 互相影响」红叉式强调；「带上下文的 xᵢ」标签 | 各自想，怎么个算法？FFN 对每一行只做一件事：y 等于 f 作用在 x 上。同一个函数 f，复用给每个 token，但算第 1 个 token 时，绝不去读第 2 个。共享参数，不等于互相影响。不过，它真的完全不知道上下文吗？ |
| S4 | SwiGLU 四步：扩张 | 公式四行卡（gate/up/hidden/y 逐步点亮）；d_model 7168 → d_ff 28672 数字条（4 倍）；「先铺开，才有得选」 | 现代大模型用的是 SwiGLU 版 FFN，四步。第一步，x 分别乘 W gate 和 W up，从 d model 维扩张到更宽的 d ff——通常是四倍。比如 DeepSeek V4 Pro，7168 维输入，中间展开到两万八千多维。先铺开足够多的方向，才有得选。 |
| S5 | 门控 + 投影 | SiLU 曲线（连续 0→1，非阶跃）；一排小闸门逐维控制 up 条；W_down 高→低箭头（dimension 压缩示意） | 第二步最妙：SiLU 生成一排阀门，连续调节，不是简单的开或关。第三步，gate 和 up 逐元素相乘——每个维度独立控制，开到最大就放行，关到接近零就截断。第四步，W down 把结果投影回原来的维度。扩张、筛选、归位，一次 FFN 完成。 |
| S6 | 实验：扰动不跨行 | 2×2 矩阵两行（token1/token2）；token1 +0.3/-0.4 红色扰动 → token2 输出「纹丝不动」绿勾；「批量=单独」标签 | 两行真的互不干扰吗？做个实验：一个两维的 SwiGLU，两个 token，固定权重。改动第 1 个 token，猜猜第 2 个的输出变不变？逐元素，纹丝不动。反过来也一样。批量算和单独算，结果完全相等——独立性不是定义，是算出来的。 |
| S7 | 真实模型 + MoE | DeepSeek V4 Pro 配置卡（7168 / silu 打勾）；Dense：1 间大思考室全走；MoE：路由器把 token 分到 3 间专科室（专家内部仍是 FFN） | 真实模型呢？2026 年的 DeepSeek V4 Pro，配置里写得分明：hidden size 7168，激活函数 silu——和上面讲的完全对得上。Dense FFN，每个 token 走同一间思考室；MoE 呢，路由器把 token 分到少数几间专科思考室。专家内部，还是 FFN。 |
| S8 | 残差 + 总结 + 尾卡 | 输出=输入+FFN(输入) 回路；一层节奏三行回顾；尾卡：avatar 圆角图 + 黄色「关注「数解AI」」+ 当期文章标题 + 「查看公众号文章」绿色引导 + 下一篇预告（归一化） | 思考室不是终点。FFN 的输出会通过残差连接，加回输入：输出等于输入加 FFN 的输入。即使 FFN 没学到有用变换，原信息也有直通路。一层 Transformer 的节奏：注意力把上下文写进 token，FFN 各自加工，残差把它们接回去。FFN 不让 token 交流，却占了大部分参数——这种各自思考，是浪费，还是不可或缺？评论区聊聊。下一篇，归一化怎么稳住数值，让几十层模型不崩。关注数解AI，不迷路。 |

> 配音稿两版：`tts.txt` = 纯净版（字幕基准 + 切分 probe）；`full.txt` = 带拟声标签版（TTS 输入，标签：`(breath)`/`(sighs)`/`(gasps)` + `<#0.5#>` 显式停顿）。

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（full.txt = tts.txt 8 段合并带标签）+ `--subtitle` 句子级时间戳 → `scripts/tts_split.py` 按时间戳切分 8 段（克隆音色 `branding/my-voice-denoised.wav`，speed 1.15 pitch +2，speech-2.8-turbo）
2. 动画：每段一个 Manim Scene（S1..S8），`construct` 末尾 `pad_to_voice()`；动画节点按台词时间轴铺满（≥80% 配音时长）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：Cover 场景单帧渲染（复用思考室/SwiGLU 四步视觉）→ `<标题>-封面.png`（1080×1920，关键内容在 3:4 安全区 y∈[240,1680]）
5. 归档：`content/2026-07-23-FFN/shipinhao/`

## 爆点节奏核对

- S1 开场钩子：问句设疑（前 3 秒「注意力已经把上下文汇进每个 token 了，为什么还要留一块前馈网络？」）
- 4 类爆点轮换：问句钩子（S1/S6 猜猜变不变）、数字对比（S4 7168→28672）、短句断句（S5 放行/截断、S3 共享参数≠互相影响）、转折爆点（S6 纹丝不动、S8 直通路）
- 段间悬念钩：S1 尾「到底在干什么」→ S2 揭晓思考室；S2 尾「各自想」→ S3 揭晓算法；S3 尾「完全不知道上下文吗」→ S4 揭晓（xᵢ 已带上下文）；S5 尾「一次 FFN 完成」→ S6 实验验证；S6 尾「算出来的」→ S7 真实模型；S7 尾「专家内部还是 FFN」→ S8 残差回路
- 结尾：下一篇预告（归一化）+ 开放式互动问题（浪费还是不可或缺）
- 公式口语化：yᵢ=f(xᵢ) → 「y 等于 f 作用在 x 上」；W_gate/W_up/W_down → 「W gate / W up / W down」；⊙ → 「逐元素相乘」；d_model/d_ff → 「d model / d ff」；无任何符号串进配音稿
