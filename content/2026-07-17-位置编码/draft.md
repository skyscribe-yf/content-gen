## 🎯 驱动问题：词全认识，顺序却丢了

**位置编码** 解决一件事：Transformer 默认「看得见词，分不清先后」。词嵌入只告诉模型「这是谁」，位置编码才补上「排第几」——词序一错，意思全变。

前两篇 [BPE 分词](https://mp.weixin.qq.com/s/5nR_KI47v_U8KwpQA4Uv5Q)和[词嵌入](https://mp.weixin.qq.com/s/rDryn1z_hLt7mwi3X8fsxQ)，解决了一件事：把每个 token 变成一个向量。模型拿到向量，就知道这个 token "是谁"。

但它还不知道 token 之间谁先谁后。

看这两句话：

> **猫追老鼠**

> **老鼠追猫**

三个词完全一样。只换了顺序，意思却反过来了。

如果你只把三个词的向量丢给模型，模型能认出"猫""追""老鼠"，却未必知道谁是主动者，谁是被追的对象。向量需要额外的位置信号，才能变成有顺序的输入。

这就是今天的问题：**注意力能看见所有词，但天生分不清词的顺序。**

位置编码，就是给每个 token 补上一张"座次表"。

## ① 注意力为什么没有顺序感？

Transformer 的注意力会把每个 token 变成 Query、Key、Value，再计算它们之间的相关性。

你可以先把它理解成：每个词都拿着一张小纸条，去问其他词“你和我有多相关？”

问题在于，最基础的注意力只看向量之间的关系。

如果输入向量是 x₁、x₂、x₃，它计算的是一张相关性表：谁和谁更像，谁应该多看谁。

但它没有一个天然的“第几个”字段。

把 x₁、x₂、x₃ 换成 x₃、x₁、x₂，词的集合没变，向量本身也没变。没有额外信息时，模型不知道这次只是换了座次。

不是模型漏看了顺序。

注意力擅长比较向量关系，却不会自动读取序列下标。

于是，位置编码要做的事很朴素：**让同一个 token 出现在不同位置时，输入给注意力的表示不一样。**

## ② 直接加一个位置向量

最直接的方案，是给每个位置准备一个向量 pᵢ。

第 i 个 token 的输入，不再只是词向量 xᵢ，而是：

> **hᵢ = xᵢ + pᵢ**

![](01-position-vector.png)

*同一个词在不同位置，加上不同的位置向量后，输入给模型的向量就不一样了*

这一行就是"词是谁"加上"词在哪里"。

比如"猫"在第 1 个位置，输入是 x_猫 + p₁；它在第 7 个位置，输入是 x_猫 + p₇。词向量相同，最终送进 Transformer 的向量不同。

这类方法叫**绝对位置编码**。它直接告诉模型：“你现在是第 1 个位置”“你现在是第 7 个位置”。

好处是简单。问题也在这里：p₁ 和 p₂ 只是两张不同的向量。模型得从训练数据里学出“第 2 个位置紧挨第 1 个位置”。位置编号之间的连续关系，没有写进公式。

能不能让位置向量自己带上规律？

## ③ 正弦位置编码：用不同频率记录位置

2017 年 Transformer 论文给出了一种漂亮的方案：不用为每个位置单独存一张随机向量，而是用不同频率的正弦、余弦函数生成它。

对于位置 pos 和维度 2i，可以写成：

> **PE(pos, 2i) = sin(pos / 10000²ⁱ⁄ᵈ)**

对于相邻的维度 2i + 1，则用余弦：

> **PE(pos, 2i + 1) = cos(pos / 10000²ⁱ⁄ᵈ)**

不用被下标吓到。它只是在说：**不同维度，用不同速度变化的波来标记位置。**

有的维度变化快，能分清相邻位置。有的维度变化慢，能表示更远的距离。

像一组钟表：秒针负责短距离，分针负责中距离，时针负责长距离。把它们放在一起，模型就能得到更细的位置信息。

![](04-sinusoidal-encoding.png)

*不同频率的正弦/余弦波叠加：高频分近邻，中频辨中距，低频看远方*

为什么要同时用 sin 和 cos？

因为它们像一对互相垂直的坐标轴。位置向前移动，向量就在平面上转动；不同位置会落在不同角度。

这套编码还有一个额外好处：位置不一定非要事先存进表里。只要把 pos 代入函数，就能生成更长位置的编码。

但它仍然是“加法”：先生成位置向量，再和词向量相加。位置与内容混在了一起。

## ④ 可学习位置编码：让模型自己学座次

另一条路线更直接：每个位置的向量不手工生成，也不使用 sin/cos，全部设成可训练参数。

训练开始时，p₁、p₂、p₃ 是随机数。模型每次预测错了，反向传播就顺手调整这些位置向量。

最终，p₁ 可能学会“句首的特点”，p₁₀₀ 可能学会“长文本中段的特点”。

它的优势是灵活。模型可以自己发现位置模式。

代价也很明确：如果训练时只见过 2048 个位置，推理时突然给它 8192 个 token，后面的 p₂₀₄₉ 到 p₈₁₉₂ 根本没有学过。

这叫长度外推问题。

位置编码不只是“编号”。它还要让模型理解：第 100 个词和第 101 个词相邻，第 100 个词和第 1000 个词相隔很远。

有没有办法直接把“相隔多远”放进注意力计算？

## ⑤ RoPE：不加位置，直接旋转 Q 和 K

RoPE 的全名是 Rotary Position Embedding，中文通常叫旋转位置编码。2021 年由中文社区研究者苏剑林提出。

它的思路很特别：**不把位置向量加到 token 上，而是根据位置，把 Query 和 Key 旋转一个角度。**

位置 0 不旋转。位置 1 旋转一点。位置 2 再多旋转一点。

二维情况下，旋转可以写成一个矩阵：

> **R(θ) = [[cos θ, −sin θ], [sin θ, cos θ]]**

一个二维向量 x = (x₁, x₂) 乘上 R(θ)，就得到旋转后的向量。

这不是把向量拉长或压扁，只是改变方向。

如果第 i 个位置对应角度 iθ，那么：

> **qᵢ′ = R(iθ)qᵢ**

> **kⱼ′ = R(jθ)kⱼ**

注意力真正关心的是 qᵢ′ 和 kⱼ′ 的点积。把它们放在一起：

> **qᵢ′ᵀkⱼ′ = qᵢᵀR((j−i)θ)kⱼ**

关键就在括号里：**j − i**。

两个词最后的相关性，不再只和“第 i 个”“第 j 个”有关，还和它们相隔多远有关。

第 3 个词看第 4 个词，间隔是 1；第 100 个词看第 101 个词，间隔也是 1。对 RoPE 来说，这两个关系的旋转差相同。

这就是它比“给每个位置加一个编号”更漂亮的地方：**绝对位置参与计算，最后留下的是相对距离。**

![](02-rope-2d-rotation.png)

*同一个向量放在不同位置，旋转角度不同；两个位置的角度差携带相对距离*

## ⑥ 二维小实验：旋转真的改变了什么？

先取一个简单向量：

> **q = (1, 0)**

位置 0 不旋转，它仍然指向 x 轴。

位置 1 旋转 60°，它变成：

> **q₁ = (cos 60°，sin 60°) = (0.5，0.866)**

位置 2 旋转 120°，它变成：

> **q₂ = (cos 120°，sin 120°) = (−0.5，0.866)**

现在看位置 1 和位置 2 的夹角：60°。

换成位置 7 和位置 8，只要每一步仍然旋转 60°，夹角还是 60°。

模型因此能学到一种稳定关系：**相邻位置的表示有固定的相对旋转。**

这也是"旋转"这个动作的价值。它没有粗暴地给词向量贴一个"第 7 个"的标签，而是把位置信息变成了向量之间的角度关系。

```python
import numpy as np

q = np.array([1.0, 0.0])
theta = np.pi / 3  # 60°

cos, sin = np.cos(theta), np.sin(theta)
R = np.array([[cos, -sin], [sin, cos]])

q1 = R @ q    # [0.5, 0.866]
q2 = R @ q1   # [-0.5, 0.866]

# 相邻位置夹角始终 = 60°
angle = np.arccos(q1 @ q2)  # 1.047... = 60°
```

二维实验验证了 RoPE 的核心性质。但真实模型的旋转速度由哪个参数决定？

## ⑦ 真实模型里，θ 这个数怎么选的？

RoPE 的关键参数只有一个：基频 θ（`rope_theta`）。它决定了旋转的速度——θ 越大，旋转越慢，能覆盖的位置范围越宽。

拆开看三个模型的 config.json：

| 模型 | rope_theta | max_position_embeddings | 含义 |
|------|-----------|------------------------|------|
| DeepSeek-V3 | 10000.0 | 131072 | 慢旋转，原生支持 128K |
| LLaMA-3-70B | 500000.0 | 8192 | 极慢旋转，但仅训练了 8K |
| Qwen3-235B | 1000000.0 | 131072 | 最慢旋转，搭配 YaRN 插值 |

三种选择，三种策略：

- DeepSeek-V3 用较小的 θ，让旋转快一点，配合 MLA 在 128K 上下文里稳定工作。
- LLaMA-3 把 θ 放大 50 倍——旋转几乎停下来了。好处是即使未经长文本训练，推理时简单外推就能覆盖更长上下文。代价是近距离分辨能力下降。
- Qwen3 取了一个极值 1M，再通过 YaRN 位置插值微调旋转频率，在长文本和短文本之间找平衡。

所以 `rope_theta` 不是越大越好。它是一个旋钮：**拧快了，相邻位置分得清但远距离看不清；拧慢了，能看很远但近处模糊。**

实际使用时，`max_position_embeddings` 只是设计上限，不代表模型在这么长的文本上一定能稳定推理。训练长度、注意力实现（比如是否用了 sliding window）和评测方式都会影响结果。

![](03-rope-theta-comparison.png)

*三个模型的 rope_theta 对比：旋转速度决定了模型能分辨多远的 token 关系*

## 🔄 回到开头：位置编码到底补上了什么？

词嵌入告诉模型：这是猫，那是老鼠。

位置编码告诉模型：猫排在第 1 个，老鼠排在第 3 个。

专业一点说：

1. 词嵌入提供 token 的内容表示；
2. 绝对位置编码把位置加进输入；
3. 正弦编码用多种频率表示位置；
4. 可学习编码让模型自己调整位置向量；
5. RoPE 通过旋转 Q/K，让注意力分数感知相对距离。

所以位置编码不是给 token 贴座位号这么简单。

它是在告诉注意力：**词是谁很重要，词和词隔了多远，同样重要。**

这篇一直提到 Q、K、V 和注意力分数，你可能已经隐约感觉到——位置编码把距离信息注入了注意力的计算过程。但注意力本身到底怎么算出"这个词应该多看哪个词"？下一篇，我们把 Q、K、V 拆开看。
