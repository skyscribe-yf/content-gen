## 🎯 驱动问题

上一篇我们知道了梯度下降怎么"蒙着眼下山"——沿着负梯度走，误差就会越来越小。但有个前提被一笔带过了：**误差怎么算？**

同一个二分类任务，同一个网络，同一个学习率，只换一个损失函数——交叉熵 97 步到 80% 准确率，MSE 要 193 步。模型结构、数据、学习率全都没变，凭什么差一倍？

答案藏在梯度里。损失函数不只是"打分"，它决定了梯度信号的强弱。选错了，模型最需要纠错的时候，推力反而最弱。

这篇我们对比两种损失函数，看打分标准怎么决定学习方向。

---

## 💡 直觉解释

想象你是个射击教练，要给学员打分。

**MSE 的打分方式**：看离靶心多远。偏了1环扣1分，偏了5环扣25分——惩罚和偏差的平方成正比。学员一看分数就知道"偏了多少"，然后往靶心调。这适合射击——目标是连续的，偏1环和偏5环之间有明确的远近关系。

**交叉熵的打分方式**：不看离靶心多远，看"正确答案被忽视了多少"。学员把90%的注意力放在了错误靶位上，正确靶位只给了10%——狠狠扣分。学员把50%的注意力放在正确靶位上——扣得轻一些。关键不在偏差本身，而在**正确答案得到的概率有多低**。

为什么分类要用交叉熵？因为分类不是"偏了多少"的问题，是"猜对了没有"的问题。猫就是猫，狗就是狗，没有"半猫半狗"。MSE 会觉得"猜成狗但给了49%的猫概率"和"猜成狗但给了1%的猫概率"差不多——都离正确答案很远。但交叉熵知道，后者比前者好得多，因为至少它没把概率浪费在错误类别上。

**选错损失函数，梯度方向没错，但信号被稀释了——不是走不到，是走了一条更长的弯路。**

## 📐 数学原理

### 均方误差（MSE）

> **L_MSE = (1/n) Σ(yᵢ − ŷᵢ)²**

翻译成人话：预测值和真实值差的平方，取平均。偏得越远，惩罚越重——惩罚和偏差的平方成正比。

MSE 的梯度：

> **∂L/∂ŷᵢ = −(2/n)(yᵢ − ŷᵢ)**

这一行在说：梯度大小和偏差成正比。偏得多就调得多，偏得少就调得少。直觉上很合理——但分类任务里，这恰恰是问题所在。

### 交叉熵（Cross-Entropy）

二分类的交叉熵（真实标签 y ∈ {0, 1}，模型输出概率 ŷ）：

> **L_CE = −[y·log(ŷ) + (1−y)·log(1−ŷ)]**

翻译成人话：正确答案的概率取对数，加个负号。概率越接近1，log 越接近0，损失越小；概率越接近0，log 趋向负无穷，损失爆炸。

> 多分类时，sigmoid 换成 softmax，ŷ 变成概率向量，公式变成 **L = −Σ yᵢ·log(ŷᵢ)**，原理完全一样。

交叉熵的梯度（对 ŷ 求导，真实标签 y=1 时）：

> **∂L/∂ŷ = −1/ŷ**

**这一行是关键**：梯度大小和预测概率成反比。正确答案的概率越低，梯度越大——模型越忽视正确答案，惩罚越狠。而 MSE 的梯度只看偏差大小，不管正确答案被给了多少概率。

### 为什么分类不该用 MSE？

把两个梯度放在一起看（真实标签 y=1）：

| | MSE 梯度 | 交叉熵梯度 |
|---|---------|-----------|
| 正确答案概率=0.01 | **2 × 0.99 = 1.98** | **1/0.01 = 100** |
| 正确答案概率=0.49 | **2 × 0.51 = 1.02** | **1/0.49 ≈ 2.04** |

当模型把正确答案的概率压到极低（0.01）时，MSE 的梯度只有交叉熵的五十分之一。**模型最需要大力纠错的时候，MSE 给的信号最弱。** 这就是分类用 MSE 收敛慢的数学根源。

![](02-gradient-comparison-art.png)

图里看得更清楚：蓝色直线是交叉熵的梯度，模型错得越离谱（p 越小），推力越大；红色抛物线是 MSE 的梯度，p 小的时候反而推力最小——模型最需要纠错时，MSE 说"差不多得了"。

如果直接拿这两个梯度去训练分类器，MSE 的梯度会比交叉熵弱多少？跑一下就知道了——数字比表格里的更夸张。

## 🔧 算法实现

```python
import numpy as np

# ── MSE：偏差的平方 ──
def mse_loss(y, p):
    # 公式：(y - p)² 取平均
    return np.mean((y - p) ** 2)

# ── 交叉熵：正确答案被忽视的程度 ──
def bce_loss(y, p):
    # 公式：-[y*log(p) + (1-y)*log(1-p)]，加 eps 防止 log(0)
    eps = 1e-7
    return -np.mean(y * np.log(p + eps) + (1 - y) * np.log(1 - p + eps))
```

**代码和公式的对应**：`mse_loss` 就是 **(y − p)²** 取平均，`bce_loss` 就是 **−[y·log(p) + (1−y)·log(1−p)]** 取平均。

### 同一个分类任务，两种损失函数

用二分类跑一遍：真实标签 y=1，模型初始预测 p=0.1。

```python
y = np.array([1.0])
p = np.array([0.1])

print("MSE 损失:", mse_loss(y, p))       # 0.81
print("交叉熵损失:", bce_loss(y, p))      # 2.30
```

MSE 说"偏差是0.9，损失0.81"；交叉熵说"正确答案只给了10%概率，损失2.30"。**同一个错误，交叉熵的惩罚是MSE的近3倍。** 而且随着正确概率越压越低，这个倍数会越来越大——sigmoid饱和区会让MSE的梯度进一步衰减。

同一个任务，损失函数不同，梯度差了几十倍——实测会放大这个差异。

## 🧪 实测

同一个二分类任务，同一个网络（4维输入→16个隐藏单元→sigmoid输出），同一个学习率0.01，只换损失函数。

交叉熵版本：97步到80%准确率，最终99%。

MSE版本：193步到80%准确率，最终96%。

![](training-curve.png)

左图看准确率：蓝色（交叉熵）一路领先，80%那条虚线上，交叉熵97步到达，MSE要193步——慢了整整一倍。右图看损失：交叉熵的loss从0.64快速下降，MSE的loss从0.23缓慢下降。

**为什么MSE慢？** 回到梯度对比图：当模型预测概率低时，MSE的梯度被 **p(1−p)** 因子压扁了。sigmoid的输出越极端（不管对错），**p(1−p)** 越小，梯度信号越弱。交叉熵没有这个问题——它的梯度就是 **p − y**，永远和误差成正比。

这不是模型写得差，是数学决定的：MSE 在分类任务里梯度信号被稀释，模型最需要纠错的时候推力不够。

## 🔄 回扣原理

回到开头的问题：**同一个任务，只换损失函数，凭什么差一倍？**

数学已经告诉我们了——MSE 的梯度和偏差成正比，交叉熵的梯度和正确答案的概率成反比。当模型把正确答案压到极低概率时，MSE 给的梯度微乎其微，交叉熵给的梯度爆炸式增长。实测完全印证了这一点：交叉熵97步到80%，MSE要193步。

损失函数的本质不是"衡量误差"，而是**定义梯度信号的强度**。选对损失函数，模型每一步都走在最陡的下坡路上；选错了，梯度信号被稀释，模型在平地上磨蹭。

上一篇说梯度下降是"蒙着眼下山"——但下山之前，你得先选对坡度计。**损失函数就是那个坡度计，它决定了你感受到的坡度是真实的还是被压缩过的。**

还有一个细节值得注意：交叉熵 + sigmoid 的梯度恰好等于 **p − y**，一行搞定，不需要单独算 sigmoid 的导数。这不是巧合，是链式法则的魔法——下一篇讲反向传播的时候，我们会看到为什么。

---

## 📌 一句话总结

损失函数的本质是打分标准，MSE按偏差平方打分管回归，交叉熵按正确答案被忽视的程度打分管分类，选错损失函数会让梯度信号被稀释——实测证实分类用MSE收敛慢一倍。
