# 大纲：写代码已经不再是瓶颈，交付依然困难重重，AI Native SDLC能解决吗

发布日期：2026-10-18 22:00 | 系列：软件工程 | 类型：诊断篇

## 一句话
Anthropic 的结论不是"用 AI 写代码更快"，而是代码不再是瓶颈、瓶颈搬到了代码周围的流程上——但它的 playbook 只答对了一半：MECE 六问里它真正扎实的只有"能"这一格。

## 结构（目标 ~2300 字）

### 0. 开场（~200 字）[原声槽 1]
- 作者原声：高强多实践 AI coding 两年多，工具链经历，营销口号被打回原形
- 诊断句："写代码已经不贵了，但交付还是慢——瓶颈从 coding 搬到了流程"
- 过渡：Anthropic 2026-08 发布的 AI-native SDLC playbook 是目前最系统的回答

### 1. Anthropic playbook 的诊断与骨架（~400 字）
- 传统 SDLC 为"写代码最贵"设计；PRD/估点/评审是为了几周~几季度的开发周期对齐
- 现在写代码成本断崖下跌，但仪式没跟着变 → 收益被流程吃掉（Amdahl 形态）
- 六阶段对照表（Plan/Design/Build/Test/Deploy/Maintain）简表
- 贯穿主线：committed artifact 链 intent.md → spec.md → plan.md → diff → PR → incident
- 知识载体三分法：CLAUDE.md（工作知识，≤1 页）/ skill（必须一致执行的机构知识）/ hook（不许例外的确定性执行）= 建议→强制梯度

### 2. Anthropic 自家数据与踩坑（~300 字）
- 数字：8× 产出（2021-2025）、~80% Claude 写的代码 merge、16%→54% review 评论率、1/3 事故 bug 本可被自动化抓到
- Slack 事故：incident agent 自己找另一个 Claude 推修复 → "把边界画在访问权限和动作上，不是画在模型的指令上"
- 外部对照：Intercom 自动批准 PR 19%、部署翻倍、破坏性变更停机 -35%

### 3. 外部证据：生产数据怎么说（~300 字）
- Google C++ 生产 12 个月：build 失败 1.3×、revert 0.9×、blocking threads 1.92×；review 努力度代理指标与低效代码存活**无相关**
- Borg et al. 449 人受控实验：可维护性无系统性差异
- GitClear 623M 变更：连通性 -35%、重构 -70%、块重复 +81%（厂商数据、相关分析，非因果）——两组数据矛盾，说明"可维护性"目前无法被现有指标捕捉
- 原声槽 2：作者对"可维护性无差异"研究的个人解读

### 4. MECE 六问：playbook 真正扎实的只有"能"一格（~500 字）
- 轴：能/值/该/愿/撑/知，回答方式互不可替代
- 覆盖度表：能 高 / 值 近零 / 该 仅内部治理 / 愿 近零 / 撑 零 / 知 给了度量但未质疑度量
- 权重：能 < 值 < 该 < 愿 < 撑 < 知（前两格一两年内收敛，后三格反馈延迟 3-10 年）
- 三格长期风险预告：junior 断层（IZA/SSRN/CACM）、技术债自我毁灭回路（agent 写低价值测试 → 套件膨胀 → 反馈延迟回升）、平台团队容量
- 原声槽 3：作者对 Anthropic playbook 推广价值的疑问

### 5. 【知】的深水区：冗余 ≠ 独立性（~300 字）
- Anthropic 建议"多条窄 scope review agent"，论据是"不共享偏见和盲点"——只做到角色分离，没做到误差去相关
- n_eff = k/(1+(k-1)φ̄)：9 判官 = 2.2 票（Apple 实测 φ̄=0.39）
- β 共失败天花板：任何聚合架构的上限 = 1-β
- 推论：只能用一个底座模型时 φ̄→1，n_eff→1，增加 agent 纯浪费
- 过渡：下一篇深挖成本、独立性、验收三道坎
