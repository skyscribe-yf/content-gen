上一篇[预训练](https://mp.weixin.qq.com/s/XoGHVycQHR5Tp-BWPac9Hg)讲过，预训练是在造一个语言和知识底座。这道工序成本有多高？据 36氪报道，被称为"AI 六小虎"的 6 家中国大模型独角兽中，至少有 2 家已经逐步放弃了预训练模型。它们缩减预训练算法团队，业务重心转向 AI 应用\[1\]。零一万物创始李开复公开表态："超大基模预训练对初创公司来说性价比、投资回报（ROI）极低"\[2\]。连硅谷的明星公司 Character.AI 也在 2024 年 8 月宣布放弃预训练，转向与第三方模型合作。理由是"能把更多资源投入后训练，为用户创造新的产品体验"。

这不是个别公司的预判。当预训练的成本高到连独角兽都撑不住时，整个行业都在重新思考一个问题：是不是一定要从零造轮子？

答案是：对绝大多数公司来说，不需要从头预训练，只需要**在已有的预训练模型上做 SFT（监督微调）**。

## 一、为什么要做 SFT

SFT，全称 Supervised Fine-Tuning，中文叫监督微调，也叫指令微调。做法很简单：拿一个已经训练好的预训练模型（比如 Qwen3-8B），喂给它几百到几万条"指令—回答对"，让它继续训练。模型不需要重新学语言、学知识——它已经会了。它要学的只有一件事：**怎么在特定指令下，给出符合期望的回答**。

这背后的账很好算。

以 [Qwen3-8B 的公开模型卡](https://huggingface.co/Qwen/Qwen3-8B-Base) 为例，模型约有 82 亿个参数。Qwen3 官方资料披露的预训练规模约为 36 万亿个 token。

按训练 FLOPs ≈ $6 \times$ 参数量 $\times$ token 数的粗略估算：

$$6 \times 8.2\times10^9 \times 36\times10^{12}\approx1.77\times10^{24}\ \mathrm{FLOPs}$$

如果我们手里已经有一个会读、会写、懂基本知识的 base 模型，只想让它学会按指令回答呢？

假设准备 1 万条指令-回答对，每条平均 2,500 个 token。总训练量就是 2,500 万个 token。

同样只跑一遍，并沿用上面的粗略公式：

$$6 \times 8.2\times10^9 \times 25\times10^6\approx1.23\times10^{18}\ \mathrm{FLOPs}$$

这两个计算量相差约 144 万倍。这里比较的是同样参数量下的粗算，不是两次真实训练的完整账单。

SFT 也不是免费。假设每条数据人工处理 2 分钟，人工成本按 50 元/小时计算：

```text
10,000 条 × 2 分钟 ÷ 60 × 50 元/小时 ≈ 16,667 元
```

[AutoDL 的计费规则](https://api.autodl.com/docs/price/)按实例开机时长计费。具体 GPU 单价以控制台现价为准。

若把当日 4090D 单价记为 $r$ 元/小时，90 分钟小实验的 GPU 账就是 $1.5r$ 元。若只作 2 元/小时的示例，就是 3 元。

所以，问题不是“预训练和 SFT 哪个更高级”。问题是：模型已经具备语言能力时，为什么还要为它重新学习一遍世界？

如果目标是补充广泛的新知识，继续预训练才有意义。如果目标只是让模型知道该说什么、怎么说，SFT 通常是更小、更快的那笔账。

同一个模型，同一个问题，两种命运。

给 Qwen3-8B-Base 输入"请解释什么是梯度下降"。

它续写出"**算法**，并提供一个简单的 Python 实现"。它可能知道相关知识，却没有稳定识别出这是一个解释请求。

给 Qwen3-8B 的 post-trained 版本同样输入。

它稳定地输出"**梯度下降**（Gradient Descent）是一种……**迭代算法**"。定义、直觉、举例，结构清晰。

两个 checkpoint 的参数规模相同，但这不等于只有少量参数发生了变化。下面的实验比较的是 base 与 post-trained checkpoint，不把所有差异都归因于单独的 SFT。

我们要观察的是：后训练如何改变输出分布，以及为什么这种改变能让模型更像一个助手。

下面先看一组对比实验，再用一个比喻把直觉讲清楚，最后看数学上到底发生了什么。

## 二、同一个模型，两种输出

我们在 AutoDL 的一张 4090 上加载两个 checkpoint。

它们是 Qwen3-8B-Base 与 Qwen3-8B（post-trained）。我们用五类指令做对比：解释概念、改写句子、比较异同、写代码、情感分类。

每个指令下，我们记录模型生成前 32 个 token 时每一步的 top-1 概率和信息熵，然后取平均。

### 首个 token 的概率分布

先看最直观的：第一个生成位置上，两个模型分别把多少概率押在最高分的 token 上。

以"请解释什么是梯度下降"为例：

**Base 模型**的首 token top-10：

| Token | 概率 |
|-------|------|
| 算法 | 0.570 |
| 法 | 0.209 |
| ， | 0.060 |
| ，并 | 0.060 |
| 。↵ | 0.013 |
| ？ | 0.010 |
| ？↵ | 0.010 |
| 方法 | 0.008 |
| 。↵↵ | 0.008 |
| 。 | 0.008 |

概率分散。"算法"和"法"加起来占 78%。

但 base 模型不知道你要的是"解释"。它续写的是"算法，并提供一个简单的 Python 实现"，方向偏了。

**Instruct（post-trained）模型**的首 token top-10：

| Token | 概率 |
|-------|------|
| 梯 | 0.813 |
| 当然 | 0.076 |
| ** | 0.076 |
| 好的 | 0.032 |
| " | 0.003 |
| 好 | <0.001 |
| ### | <0.001 |
| 很好 | <0.001 |
| 「 | <0.001 |

概率高度集中。"梯"一个 token 就占了 81.3%，post-trained 模型直接以"梯度下降是……"开头，干净利落。

![base 与 instruct 模型的 token 概率分布对比：base 分布宽而平，instruct 分布窄而尖](01-comparison-distribution-narrowing.png)

**分布的形状变了。** base 模型的概率像摊开的手掌，五指张开，每个方向都有可能。post-trained 模型的概率像握紧的拳头，力量更集中在一个方向。这组实验展示了后训练如何收窄特定任务中的输出分布。

### 五个指令的聚合对比

单个 prompt 可能是巧合。五个不同类型的指令呢？

| 指令类型 | Base 首 token top-1 | Instruct（post-trained）首 token top-1 |
|----------|---------------------|------------------------|
| 解释概念 | 0.902 | 0.863 |
| 改写句子 | 0.331 | 1.000 |
| 比较异同 | 0.126 | 0.432 |
| 写代码 | 0.082 | 0.846 |
| 情感分类 | 0.681 | 1.000 |

改写、代码、分类这三类指令，post-trained 模型的首 token 集中度远高于 base。尤其是"情感分类"——记录中的 top-1 概率为 1.000，而 base 模型还在犹豫。

再看前 32 步的**平均指标**：

| 指标 | Base | Instruct（post-trained） | 变化 |
|------|------|----------|------|
| 平均 top-1 概率 | 0.820 | 0.916 | +12% |
| 平均熵 (bits) | 0.896 | 0.333 | −63% |

**熵从 0.90 bits 降到 0.33 bits，不确定性减少了近三分之二。** 这是这组后训练对比中观察到的分布变化，不等于单独测出了 SFT 的贡献。

> 实验细节：Qwen3-8B-Base 与 Qwen3-8B（post-trained），BF16 精度，greedy decoding，5 个中文指令，前 32 步 token 级指标取均值。完整数据与复现脚本见[文章仓库](https://github.com/skyscribe/content-gen)。这里的对比对象是 base 与 post-trained，不是只经过 SFT 的严格对照组。

## 三、入职培训：不是重新学，是学会该说什么

预训练像大学四年。

四年里你学了微积分、线性代数、概率论、编程、经济学、心理学……你什么都知道一点。但毕业第一天走进公司，老板问你"这个季度的增长策略是什么"，你可能开始讲马尔可夫链。不是因为你不懂增长策略，而是因为你不知道**在这个场景下该说什么**。

SFT 就是入职培训。

入职培训不会教你微积分——你已经会了。它教你的是：

- 老板问策略，你就讲策略，别讲马尔可夫链
- 写邮件用"尊敬的"开头，别用"亲爱的"
- 会议纪要用 bullet point，别用散文

**主要变化是行为和输出格式。** 这不等于模型完全没有学到任务知识，也不等于原有知识保持不变。

![入职培训比喻：左侧"大学四年"知识广而散，右侧"入职培训"聚焦于该说什么、怎么说](02-metaphor-onboarding-training.png)

对应到模型：

| | 预训练 | SFT |
|---|---|---|
| 目标 | 猜对下一个 token | 在给定指令下，猜对下一个 token |
| 数据 | 互联网文本（无格式约束） | 指令-回答对（有格式约束） |
| 分布形状 | 宽（什么都可能说） | 窄（该说什么就说什么） |
| 类比 | 大学四年 | 入职第一周 |

关键洞察：**预训练模型可能已经具备相关知识，但不一定会把知识组织成用户需要的回答。SFT 主要改变的是输出分布和行为策略。**

实验数据能支持一个更窄的结论。先看"改写句子"这个指令。

base 模型的首 token top-1 只有 0.331，熵高达 4.49 bits。这个数接近 22 个等概率选项的不确定性。

它未必不会改写，只是首个 token 的选择更分散。post-trained 模型的记录值则是 top-1 概率 1.000，说明它更稳定地进入了改写任务。

## 四、数学上发生了什么：从宽分布到窄分布

### 3.1 SFT 的训练数据长什么样

SFT 的训练数据是**指令-回答对**（instruction-response pairs），格式如下：

```
<|im_start|>user
请解释什么是梯度下降<|im_end|>
<|im_start|>assistant
梯度下降是一种优化算法，用于最小化损失函数。它的核心思想是：沿着损失函数梯度相反的方向更新参数，每一步都让损失减小一点。<|im_end|>
```

注意两个关键点：

1. **`<|im_start|>user` 和 `<|im_start|>assistant`**：这是 chat template，告诉模型"这是用户在说话"和"现在轮到你回答了"。如果训练和推理使用的角色标记不一致，模型就更难稳定接话。
2. **回答的格式是固定的**：定义 → 直觉 → 举例。后训练数据里的回答反复采用这种结构，模型更容易学会"回答解释类问题就用这个格式"。

### 3.2 交叉熵：SFT 的 loss 函数拆解

SFT 用的还是交叉熵，和预训练一模一样：

$$H(p, q) = -\sum_x p(x) \log q(x)$$

这个公式看起来和预训练一样，但**数据不同，同样的公式做了不同的事**。让我们逐项拆解。

**$p(x)$ 是什么？** 它是训练标签分布。

在 teacher forcing 的 next-token 训练中，两个阶段都可能使用 one-hot 标签。

正确 token 为 1，其他 token 为 0。

SFT 的关键不在于标签突然从“混合分布”变成 one-hot，而在于输入里出现了指令、角色和回答示范。

实际训练中还常把 prompt token 的 loss mask 掉。这样只对 assistant 回答 token 计算损失。

具体做法取决于训练实现。

**$q(x)$ 是什么？** 它是模型当前的输出分布——模型给每个 token 分配的概率。比如 base 模型给"算法"分配 0.570，给"梯"分配 0.001。

**$\log q(x)$ 的作用是什么？** 它是惩罚项。当模型给正确 token 分配的概率 $q$ 接近 1 时，$\log q$ 接近 0，惩罚很小。当 $q$ 接近 0 时，$\log q$ 趋向 $-\infty$，惩罚极大。

用一个具体例子感受这个惩罚的力度：

| 模型给正确 token 的概率 $q$ | $-\log_2 q$ (bits) | 直觉 |
|---|---|---|
| 0.99 | 0.014 | 几乎确定，几乎不惩罚 |
| 0.90 | 0.152 | 很确定，轻微惩罚 |
| 0.50 | 1.000 | 一半一半，惩罚 1 bit |
| 0.10 | 3.322 | 很不确定，惩罚 3.3 bits |
| 0.01 | 6.644 | 几乎猜不到，惩罚 6.6 bits |

概率每降一个数量级，惩罚翻三倍多。**交叉熵逼模型把概率往正确 token 上集中——概率越低，惩罚越狠。**

**预训练 vs SFT 的区别**：对同一个纯文本上下文，预训练语料可能提供多种合理的延续。模型在大量上下文上学习后，会保留更宽的续写可能性。

SFT 则反复提供“用户指令 → 助手回答”的配对。它把“现在该回答”“应该用什么格式回答”这些信息放进训练上下文，因此会在特定任务上把概率质量推向更符合示范的续写。

**同样的公式，不同的数据和上下文，会带来不同的行为分布。**

### 3.3 熵：量化"不确定性"

前面实验里反复提到"熵从 0.90 bits 降到 0.33 bits"。熵到底是什么？

**熵是分布的不确定性指标**——分布越分散，熵越高；越集中，熵越低。公式：

$$H = -\sum_x p(x) \log_2 p(x)$$

注意：这里的 $p(x)$ 是模型自己的输出分布（不是训练数据的 one-hot），所以熵衡量的是**模型自己有多犹豫**。

用我们的实验数据算一遍。Base 模型在"改写句子"指令下的首 token 分布，top-1 概率 0.331，熵 4.49 bits。4.49 bits 意味着什么？

- 1 bit = 两个等概率选项（抛硬币）
- 2 bits = 四个等概率选项
- 4.49 bits ≈ 22 个等概率选项

base 模型在第一个 token 上，相当于在 22 个选项之间犹豫——它不知道该从哪个方向开头。

而 post-trained 模型在同一位置的记录值是 top-1 概率 1.000，熵约为 0 bits。这里的 1.000 和 0 是记录精度下的结果，不代表数学上的绝对确定。

**熵的降低 = 犹豫的减少 = 分布的收窄。** 这是这组后训练对比中观察到的数学现象。

![熵的计算与直觉：左侧高熵分布（宽而平，多个选项等概率），右侧低熵分布（窄而尖，一个选项占绝对优势）](03-infographic-entropy-intuition.png)

### 3.4 SFT 的梯度：往哪个方向收窄

为了看清梯度，先把模型最后一层的 logits 记为 $z$，softmax 后的概率记为 $q$。对于目标 token $x^*$，交叉熵对每个 logit 的梯度是：

$$\frac{\partial H}{\partial z_j}=q_j-\mathbf{1}[j=x^*]$$

翻译成人话：正确 token 的梯度是负的，更新会把它的 logit 往上推。

其他 token 的梯度通常是正的，更新会把它们的相对优势往下压。

所以，“收窄”不是因为 SFT 独占 one-hot 梯度。预训练在单个 next-token 位置上也有同样的梯度形式。

差别在于，SFT 的输入和目标反复围绕指令、角色和示范回答组织。经过多条样本更新后，模型在这些任务上下文里更偏向示范过的回答路径。

这也解释了它的代价：如果示范过于单一，模型可能过拟合某种格式；如果数据有偏或有误，模型也可能把错误行为一起学进去。

**一句话总结：SFT 通过指令-回答数据改变特定上下文中的概率分布，而不是凭 one-hot 标签单独创造一种新梯度。**

### 3.5 Chat Template 的作用

Chat template 是 SFT 最容易被忽略但最关键的部分。

base 模型的输入就是纯文本续写：给它"今天天气"，它续写"很好"或"怎么样"。没有角色区分，没有对话结构。

post-trained 模型的输入被 chat template 包裹：

```
<|im_start|>system
你是一个有帮助的AI助手。<|im_end|>
<|im_start|>user
请解释什么是梯度下降<|im_end|>
<|im_start|>assistant
```

这些特殊标记（`<|im_start|>`、`<|im_end|>`、`system`、`user`、`assistant`）会在后训练数据中反复出现，并与回答行为绑定。它们的作用是：

- **角色标记**：告诉模型"这是用户说的"和"现在轮到你回答"
- **轮次分隔**：多轮对话中区分每一轮
- **行为约束**：system prompt 定义了模型的行为边界

从概率的角度看，chat template 做了一件关键的事：**它把"什么时候该说话"这个信息编码进了输入**。

base 模型只看到"请解释什么是梯度下降"时，无法从输入本身确定这是一个对话轮次。post-trained 模型看到 `<|im_start|>user\n请解释什么是梯度下降<|im_end|>\n<|im_start|>assistant` 时，角色信息更明确。

输入里的角色标记，会改变模型对"接下来该输出什么"的概率判断。**Chat template 像入职培训的考勤卡：不是教知识，而是告诉模型现在轮到谁发言。**

## 五、听话不等于说得好

SFT 解决了"听话"的问题，但没解决"说得好"的问题。

一个经过 SFT 的模型会乖乖地按指令格式回答，但它可能：

- 编造事实（幻觉），因为 SFT 数据里可能有错误回答
- 过度迎合用户，因为 SFT 数据倾向于"让用户满意"的回答
- 学会了有毒的指令格式，如果训练数据里混入了有害内容

**听话是必要条件，不是充分条件。** 模型需要学会的不仅是"按指令回答"，还有"回答得对、回答得好、回答得安全"。

![训练管线全景：预训练（学语言）→ SFT（学听话）→ RLHF/DPO（学说好话），三道工序依次递进](04-framework-training-pipeline.png)

这就是下一道工序——RLHF/DPO——要解决的问题。它不是只教模型遵守格式，而是在多种可能的回答中，选择人类更偏好、更安全、更准确的那一个。
