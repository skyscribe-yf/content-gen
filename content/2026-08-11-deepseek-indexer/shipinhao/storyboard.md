# 《稀疏注意力怎么挑重点？DeepSeek-V4 只算 1/64》视频号分镜脚本

基于 content/2026-08-11-deepseek-indexer/weixin.md
规格：竖屏 1080×1920 · Manim 动画 · **MiniMax 克隆作者音色**（speech-2.8-turbo，speed 1.0 pitch +2，`--clone-audio branding/my-voice-denoised.wav`）+ 烧录字幕 · 目标 **4-5 分钟**
风格参考：content/2026-08-15-deepseek-dualpipe-deepep/shipinhao/（6 段 + 段间悬念钩 + 品牌尾卡）

## 段落设计（6 段）

| # | 场景 | 动画要点 | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子：死结 + 图书馆类比 | 概念图（翻档案/图书馆）；「选择依赖计算，计算依赖选择」死结环；短句爆点「全读，贵；赌，怕漏」 | 注意力想跳过不重要的内容，可它得先知道哪些不重要。想知道哪些不重要，就得先读一遍全部——读一遍的代价，跟全量计算一样贵。这就是先筛后算的死结：选择依赖计算，计算依赖选择。图书馆查资料，目录卡只有读了正文，才知道哪本有用。全读，贵；赌，怕漏。V4 的答案，是一个只有 4 比特精度的小网络。它凭什么敢替大模型做决定？ |
| S2 | 压缩块 + Indexer 登场 | 128K→32K 块数字滚动（主视觉）；64 头打分→ReLU→Top-512 流程链；FP4 徽章 | 先看它怎么挑。V4 把每 4 个 token 压成一个块，128K 的上下文，压完是 3 万 2 千个块。这个叫 Lightning Indexer 的小网络，要给每个 query 给全部块打分。64 个打分头，各看各的维度；ReLU 把负分就地淘汰；最后只留分数最高的 512 块，交给核心注意力。主模型负责精读，Indexer 负责速览。速览便宜到每个 token 都能跑，精读贵到只留给选中的块。一个用残缺数字训练的小网络，凭什么敢替大模型挑重点？ |
| S3 | 三个支柱 | 天平概念图（漏看 vs 全算，主视觉）；64 倍数字滚动；99.7% 强调 | 三个支柱。第一，ReLU 淘汰制，是 FP4 下的唯一活路。4 比特只有 16 个可表示的值，Softmax 的指数运算直接溢出；ReLU 只有比较，零精度损失。这不是设计偏好，是软硬件协同的必然。第二，多头加权：64 个 head 各学一套重要性标准，权重由 query 动态生成，可正可负。第三，也是底气所在：选错的代价有上限。漏掉一个关键块，只是信息少一点，输出会模糊，但不会胡说；全都算，才是刚性成本。k 等于 512，对 3 万 2 千块，稀疏 64 倍，召回率守住 99.7%。漏看只是少看一点，全算才是真的贵。 |
| S4 | 两阶段训练 | 两阶段流程（密集预训练 1T → warmup Indexer → 稀疏训练，主视觉）；「老师是谁？」悬念卡 | 敢挑，还得会挑。Indexer 是随机初始化的，直接上稀疏训练，等于随机丢块，训练直接崩。V4 用两阶段教会它。阶段一，前 1 万亿 token，模型用密集注意力正常预训练，先把语言能力学好。阶段二，引入稀疏注意力之前，先专门 warmup 这个 Indexer。老师是谁？论文没写，但推理链条只有一条：warmup 时模型仍按密集方式跑，把密集注意力的真实权重当老师，让学生预测「密集注意力会把权重放在哪些块上」。学的是真正重要的块长什么样。先学全量，再学偷懒，偷懒才不至于变成瞎。 |
| S5 | 他山之石：GLM / Kimi | 三方案对比表（拉幕，主视觉）；2.9 倍 / 81% 数字 | 这条路，只有 DeepSeek 在走吗？不是。GLM-5.2 直接采用了同一套方案，还更进一步：相邻层的 top-k 选择有七成到十成重叠，那就让每 4 层共享一个 Indexer，官方披露 1M 上下文下，计算量降 2.9 倍。Kimi K3 更狠，压根不筛：线性注意力把历史压成固定大小的状态，没有 top-k，也没有 Indexer，选择问题被结构消解。有意思的是，粗筛自己也会变成瓶颈——实测 200K 上下文时，Indexer 的点积消耗了 81% 的 prefill 时间。三家其实在解同一个新问题：筛选成本本身。 |
| S6 | 回扣 + 预告 + 互动 | 速览 vs 精读概念图（主视觉）；尾卡：品牌图 + 关注引导 + 当期标题 + 下一篇预告 | 回到开头：它怎么知道该翻哪几卷档案？不是大模型自己翻的。是一个 FP4 精度、参数占比不到 1% 的小网络替它速览——先花 200 万次廉价点积给几万块打分，挑出 512 卷，大模型才动手精读。这行的聪明人，不是把一件事做到极致，而是想清楚什么事该用多大的力气做。如果先筛后算这么好用，你觉得模型里还有哪些「全部算一遍」的地方，可以换成先筛后算？评论区聊聊。下一篇，算另一笔时间账：MTP 一次猜两个词，推理为什么快 1.8 倍？关注数解AI，我们下期见。 |

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（full.txt = 6 段合并）+ `--subtitle` 句子级时间戳 → `scripts/tts_sb_create.py` 建 sentence-boundaries.json → `scripts/tts_split.py` 按时间戳切分 6 段（**克隆音色** `branding/my-voice-denoised.wav`，speed 1.0 pitch +2，speech-2.8-turbo）
2. 动画：每段一个 Manim Scene（S1..S6），`construct` 末尾 `pad_to_voice()`；动画节点 `at_clip("S1-c01")` 挂 sentence-boundaries.json（先声音后动画门禁）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：yairouter 出 1080×1920（3:4 安全区）
5. 归档：`content/2026-08-11-deepseek-indexer/shipinhao/`
