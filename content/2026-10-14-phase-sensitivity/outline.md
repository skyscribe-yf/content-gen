## 交付句（全文唯一想证明的事）

> **它不是变笨了，也不是上下文太长——是分块压缩从第一个 token 起就在替你决定「该记什么」，而它的偏好每 4 个 token 就换一次。**
> 所以遇到「取错地方」，**先重试一遍，别急着重新规划**。

## 反直觉答案（三连）

1. **跟长度无关。** 论文自己的代码补全实验，prompt **只有 88 行源码 + 一段装饰 docstring**，照样翻；作者的现场也才**大约两万 token**。相位弱点不是「上下文塞满」的产物，压缩从第一个 token 就在发生。
2. **不是幻觉，是「取错地方」。** 模型拿出来的往往是**别处真实存在**的代码——命中错了条目，不是编造。两者机制不同（幻觉是「记错」，相位是「取错格子」），作者两个现场都踩过。
3. **平均分会把它藏起来。** 受控实验里压缩模型的**平均准确率与验证损失几乎追平全注意力基线**，最差相位却只剩 **9.9%**（基线 **58.4%**）；论文原话：summary metrics **conceal** much of this difference。

## 拿得走的结论

- **现场处置**：取错地方 → **重试一遍**（作者亲历：重试就过去了），不要立即重新规划、不要让它「自我怀疑式」反复纠错——那是幻觉型错误的处置，不是这一型的。
- **评测/选型**：只看平均分的长上下文评测**测不出这个**——必须**按相位分组**报（同一份 prompt，把目标信息挪几个 token 重放）。
- **选型判断**：这条弱点**不只属于 DeepSeek**。相位的来源不是位置编码（去 RoPE、换均匀平均、窗口重叠，现象都还在），而是「**查询出现之前就压完**」这件事本身 → 凡在「把相似内容合并起来」的地方都在同一个赌注上：KV 量化、agent 的记忆摘要、RAG 分块、长文摘要。

## 结构（7 节，叙事弧线，零导航开头）

### 开头钩子（零导航，亲历场景，~180 字）

一次写代码的会话，上下文才大约两万 token。模型要从我贴进去的文件里改一处代码，它改的地方**不是那一处**——是同一个文件里另一个位置的行，形状很像。没有报错、没有超限，它很自信。我换了说法让它重试一遍，它就对了。

> **它不是变笨了。同一份文件、同一件事，位置挪了几个 token，答案就换了。**

### 一、先把两个最顺手的解释排掉（~240 字）

- **不是幻觉**：幻觉是「哪儿都没有的一行」，这里是「别处真实存在的行」——取错了条目，不是造了个条目。
- **不是「上下文太长导致智商下降」**：这一步最反直觉。论文的代码补全实验 prompt **只有 88 行源码**加一段装饰 docstring，一样翻；作者现场也只有大约两万 token。
- 🔗 内链：《Context Rot 是真的吗？上下文还没满，模型为什么就先认输了》+《为什么 AI 上下文越长越慢？两道数学硬墙一次讲透》
- 落点：那问题就不是「它变笨了」，而是「**它该记的东西，被换成了别的东西**」

### 二、同一段代码，docstring 多一个字符就翻（~300 字）

- 论文 §2.1（一手）：让它补 `T.Cast(compute_dtype, T.Cast(FP`，源码继续是 `8`。
- 唯一改动：前置一段装饰 docstring，**只改第二行重复的 `\=` 个数**，代码一字不动——长度 $L$ 从 24 到 39。
- 结果：**$L \bmod 4 \in \{2,3\}$ 时答 `8`，其余八个长度答 `32`**；$\Delta = P(8)-P(32)$ 从 **−0.79 到 +0.95**。
- 附录 B.2 更狠：**`DeepSeek-V4-Flash-0731`（作者每天在用的那个 checkpoint）** 是 4 token 一个周期，16 个长度里只对 **4 个（25%）**；`V4.1-Flash` 换成奇偶交替，**8/16（50%）**。
- **术语 1 · 相位**：一个 token 落在压缩窗口里的第几格（位置对压缩步长取模）。多塞几个无关 token，内容和顺序都没变，**相位变了**。
- 🔗 内链：《KV 缓存压到 1bit：省 92% 显存，凭什么不掉点？》+《DeepSeek V4.1 四十层网络，为什么不给每层都记账？》
- 落点：改个注释长度就翻答案，说明**这不是知识不够，是位置在决定它取到哪一份**

### 三、128K 上的检索：最好的相位和最差的差 40.2 个百分点（~300 字）

- 实验设定（一手）：128K prompt、**16k 个键值对**、问靠近中间的一个源键；按源键位置 **mod 8** 分八组，**各组的 prompt 长度、查询位置、源键绝对位置的均值与方差全部对齐**——唯一的差别就是相位。
- 五个模型的「最好相位 − 最差相位」：`V4-Flash-Base` **40.23** / `V4-Pro-Base` 34.77 / `V4-Flash-0731` **19.14** / `V4-Pro-0813` 14.84 / `V4.1-Flash` **6.09**（平均准确率分别 52.6 / 72.1 / 91.4 / 84.4）。
- **本节最强证据（建议做成本文主图）**：周期 4 在数据里肉眼可见——`V4-Flash-0731` 的八列里 **$r$ 与 $r+4$ 几乎相等**：80.47↔81.25、88.67↔90.23、98.05↔99.61、96.48↔96.09。
- 后训练把差距压小（19.14 → 14.84 → 6.09）但**没消掉**；`V4.1-Flash` 把压缩步长从 4 收到 2，**四个偶数相位仍然整组高于四个奇数相位**（95.0/95.1/94.7/95.3 vs 89.2/89.7/90.3/89.7）。
- 🔗 内链：《同样 1M 上下文，KV 缓存差 15 倍：四家架构差在哪一层》
- 落点：你平时看到的那个「平均分」，正好盖住了这 40 个百分点

### 四、压缩在查询之前就写完了（~350 字，机制主干）

- **术语 2 · 分块压缩**：每 $S$ 个 token 开一个窗，把窗口里的内容揉成更少的条目存起来（V4 的 CSA 是 **8 token 窗口、步长 4**；V4.1 步长收到 **2**）。
- 关键在时序：**压缩发生时，查询还没出现**。摘要必须"以后也许会用到"全都留一点——它不能按具体问题取舍。
- 于是每个 head 只能押注：**如果以后真要用，多半是窗口里某一格的东西**。押哪个格子，就是它的相位偏好。
- **因果证据（knockout，mean replacement 换掉某个 KV head 在该 prompt 的输出）**：
  - 全注意力基线：**水平条纹**——每层在每个相位贡献差不多；
  - 压缩模型：**异质图案**，不同 head 的损失集中在不同相位；
  - `V4-Flash-Base`：图案**按 4 重复**，且奇数层用 HCA（压缩率 **128**）对检索贡献很小。
- 门偏好（自训模型上的直接观察）：层 9/10/14 的 key 门沿对角线走向**静态集中**（分别偏窗口后部 / 中部 / 前部），**value 门峰值偏后一个偏移**——像在记一个 bigram。

### 五、这不是 bug，但论文只敢在理想化模型里这么说（~240 字）

- 论文正文的两条定理**自带 (Informal) 标签**，正式版在附录：**定理 8** = 在 **oracle 类**上，每个全局最优都是「硬相邻选择」——每个 head 把全部 key 权重压在一个相位、全部 value 权重压在下一位（叫 route，**route 可以随上下文和块变化**）；**定理 12** = **线性压缩器 + 小随机初始化**做梯度流，高概率收敛到静态集中，**不同 head 可以选同一个 $r_h$**。

### 六、平均分怎么骗你，以及为什么你的「记忆」也在同一个赌注上（~330 字）

- **平均分掩盖**：受控预训练里，W8/S8 压缩模型的**平均准确率与验证损失几乎追平全注意力基线**，最差相位却只有 **9.9%**，基线是 **58.4%**；论文原话 summary metrics **conceal**。
- **第二层（本篇的扩大键）**：论文做了三组消融——**去掉 RoPE / 换成均匀平均 / 窗口重叠**，现象都在。均匀平均只把最好−最差从 **75.3pp 收到 19.2pp**，没消掉。
- 所以相位的来源**不是位置编码**，是「**查询出现之前就把内容合并掉**」这件事本身。凡是在做这个动作的东西，都在同一个赌注上：**KV 量化、agent 的记忆摘要、RAG 分块、长文摘要**。
- **进作者原声（槽 4 + 槽 5）**：两个现场——有时取到同一个文件的其他位置，有时取了一个**相似的文件**。→ 正文写成推断并标明：**论文没有测相似性这个维度，这是作者两个样本上的猜测**（相似的东西被合并进同一个摘要条目，检索就容易命中错的条目）。
- 🔗 内链：《信息熵：压缩 1000 倍，为什么信息反而少？》+《给 Agent 装了记忆，为什么它还是不懂我的项目？》
- 落点句：**压缩省下的每一分显存，都是用一个"猜"换来的——它赌你以后不会用到被丢掉的那部分**

### 七、所以怎么办（~200 字，回应开头）

- **现场**：取错地方 → **重试一遍**（作者亲历：重试就过去了），别马上重新规划，也别让它陷入自我怀疑式纠错。
- **自测思路**（只给思路，本文不跑）：同一份长内容，把目标信息**挪 1–4 个 token** 重放几次；如果答案跟着翻，你的链路就吃到了相位弱点；评测要**按相位分组**报，别看平均分。
- **结尾悬念（论文自己留的）**：为什么不同 head 不把每个相位都覆盖掉？论文允许它们选同一个相位；把门的参数整体循环移位能修窗口内的偏好，**修不了边界那一个**——窗口内和边界的不对称，论文至今没有统一解释。后训练把差距压小了，也没压没。
