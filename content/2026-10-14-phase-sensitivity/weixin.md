一次写代码的会话，上下文才**大约两万 token**。

我让它改一个文件里的一处代码。它动手的地方不是那一处，是**同一个文件里另一个位置**的行，形状还挺像。

没有报错，没有超限，它很自信。我一开始甚至没看出来。

我先想到的是幻觉。后来才发现不是——它取的是**别处真实存在**的行：没有编造，只是**取错了地方**。

我感觉那个任务迟迟没有结束，花的时间比预期的要长不少，待翻看了具体思维链才发现原来前面很大一段翻车了。

这两个词差别很大。幻觉是「记错」，我遇到的是「取错格子」。

而这篇文章要讲的是更别扭的一件：

**同一份内容，只把位置挪几个 token，答案就换了。**

## 一、先把两个最顺手的解释排掉

第一个解释是幻觉。它最顺手，但对不上现场：幻觉是「哪儿都没有的一行」。

第二个解释是「上下文太长，模型被压笨了」。

它同样站不住。而且反驳它的不是我一个人的感觉，是论文自己做的实验：它让模型补全**只有 88 行**的源码，照样翻。

所以真正的问题不是「它变笨了」。

**它该记的那一份，被换成了另一份。**

这两件事的分工我写在前面。本篇讲**取错地方**。至于「记错了什么」那一类，[Context Rot 是真的吗？上下文还没满，模型为什么就先认输了](https://mp.weixin.qq.com/s/6bdNSe1hiGFUvL1qV_ICUw) 讲的是另一半。

## 二、同一段代码，注释多一个字符就翻

论文开场给的例子很干净。

DeepSeek-V4 的官方推理代码里有一处 FP8 类型转换。让它接着往下写，源码给的是 `8`。

改动只有一处：在前面垫一段装饰用的 docstring，**只改第二行重复的等号个数**。代码一个字都没动。

长度从 24 个 token 到 39 个，一共十六种写法。结果是：

- $L \bmod 4$ 等于 2 或 3 时，它答 `8`
- 其余八个长度，它答 `32`

`32` 不算胡说，它只是重复了外层那次转换、跳过了舍入。但两个答案的把握之差，从 $-0.79$ 一路摆到 $+0.95$。

**一段注释的长度，决定了它选哪个答案。**

更值得看的是后训练版。我每天在用的 `DeepSeek-V4-Flash-0731`，同样是 4 个 token 一个周期。十六种长度里，它只对了 4 个（25%）。`V4.1-Flash` 换成奇偶交替，对了 8 个（50%）。

这里需要一个新的坐标词：**相位**。一个 token 落在压缩窗口里的第几格，就是它的相位——位置对压缩步长取的那个模。

多塞几个无关的 token，内容没变、顺序没变，**变的只有相位**。

## 三、128K 检索上，最好的相位和最差差 40.2 个百分点

88 行的例子太小。同一件事放到真正的长上下文里，更清楚。

### 八组之间，只差一个相位

实验是这样搭的：每个 prompt 装 128K 上下文，里面塞 **16k 个键值对**，然后问靠近中间的一个键的值。按源键位置 **mod 8** 分成八组。

各组的 prompt 长度、查询位置、源键绝对位置的均值和方差**全部对齐**——八组之间唯一的差别，就是相位。

五个模型的「最好相位减最差相位」：

| 模型 | 差距 |
|---|---|
| DeepSeek-V4-Flash-Base | **40.23** |
| DeepSeek-V4-Pro-Base | 34.77 |
| **DeepSeek-V4-Flash-0731** | 19.14 |
| DeepSeek-V4-Pro-0813 | 14.84 |
| DeepSeek-V4.1-Flash | 6.09 |

最漂亮的一条证据藏在细节里：**周期 4 在这张表上肉眼可见**。`V4-Flash-0731` 的八列里，第 $r$ 格和第 $r+4$ 格几乎一一对应：

- 80.47 对 81.25
- 88.67 对 90.23
- 98.05 对 99.61
- 96.48 对 96.09

后训练确实把差距压小了，但**没有压没**。`V4.1-Flash` 把压缩步长从 4 收到 2。四个偶数相位仍然整组高于四个奇数相位：

- 偶数：95.0 / 95.1 / 94.7 / 95.3
- 奇数：89.2 / 89.7 / 90.3 / 89.7

### 平均分恰好盖住了它

而这五个模型的**平均准确率**是 52.6、72.1、91.4、84.4。

**平均分恰好盖住了这 40 个百分点。**

## 四、压缩在查询之前就写完了

我把它叫**分块压缩**：每 8 个 token 一个窗口，每 4 个开一个新窗，把整个窗口揉成更少的几条记录存起来。V4 的步长是 4，V4.1 收到 2。

要紧的是：**压缩发生的时候，查询还没出现。**

### 关键在时序

所以摘要没法按具体问题取舍，它只能「以后也许会用到」全都留一点。

于是每个 head 只剩一条路——**押注**：如果以后真用得上，多半是这个窗口里某一格的东西。押哪一格，就是它的相位偏好。

### 不是猜的，有干预实验撑着

有干预实验撑着：把某个 head 在某一步的输出换成它在别的 prompt 上的平均值，再看哪里掉分。

- **全注意力基线**：图上是水平条纹，每层在每个相位贡献都差不多
- **压缩模型**：图案变得很不均匀，不同 head 掉在不同的相位上
- **`V4-Flash-Base`**：不均匀**按 4 重复**。奇数层压到 1/128，对检索贡献很小

更细的一层是门的分工。受控预训练里，第 9、10、14 层的 key 门沿对角线走向集中。它们分别偏窗口的后部、中部、前部。value 门峰值**偏后一位**，像在记一个 bigram。

很难说这是不是 DeepSeek 有意为之还是不可避免的缺陷，本来长上下文下做到极致压缩的注意力就相当困难，不应该因为这样的缺陷就认为是节省显存的设计本身有问题。

所以它不是在「记错」，它是在用一个训练时押好的注，去回答一个它当时看不到的问题。

## 五、这不是 bug，但论文只敢在理想化模型里这么说

这一节我要给论文本身踩一脚刹车。

论文正文有两条定理，标题里直接标着 **Informal**。正式版本在附录里。

附录的定理 8 说：在某个**理想化的检索类**上，每一个全局最优都是「相邻硬选择」。

翻译过来，每个 head 把全部 key 权重压在一个相位，全部 value 权重压在下一位。

附录的定理 12 说：只做线性压缩、从很小的随机初始化出发跑梯度流，高概率会收敛到这种固定的相邻选择。

而且**不同 head 可以选同一个相位**。

论文自己的措辞很克制。它说的是**一个简化的 bigram 检索模型**，机制只在所述假设之下成立。原文还加了一句：这不构成真实大模型里相位敏感性的普遍原因。

所以这篇只写一句：**「最优解本身就是集中的」这件事，论文是在理想化模型里证的。**

顺带把另一个口径也收掉：中文媒体写的是「字节找到了 DeepSeek 抽风的原因」，而论文说的是**检索**的相位差。

**我们跟它划同一条线，也给自己划同一条线。**

其实这篇文章的很多理想化的假设，还是让我有些隐隐的担心。不过理论方向有些时候也不得不如此了。

## 六、平均分是怎么骗你的，而且你的「记忆」也在同一个赌注上

### 平均分是怎么骗你的

先说平均分。

受控预训练里，八头压缩模型的**平均准确率和验证损失几乎追平全注意力基线**。可它最差的那个相位只剩 **9.9%**，基线是 **58.4%**。

论文对这件事的原话是：**汇总指标把这部分差别藏起来了**。

所以拿平均分给长上下文模型打分，等于用一个平均值去替一个周期性失败签字。

### 而你的「记忆」也在同一个赌注上

再说第二层，这一步才是我想让它出圈的。

论文做了三组消融：**去掉 RoPE、把门换成均匀平均、让窗口重叠**。现象都还在。均匀平均只是把最好与最差的差距从 **75.3 个百分点收到 19.2**，没有消掉。

也就是说，相位的来源**不是位置编码**，而是「**查询出现之前就把内容合并掉**」这件事本身。

凡是做这个动作的东西，都在同一个赌注上：KV 缓存量化、agent 的记忆摘要、RAG 的分块、长文摘要。

它们都在赌你以后用不到被合掉的那一部分。

当时我在修复一个稍微复杂一点的 bug，需要修改的上下文，恰好关联到两个非常相似的模块，文件名字只有后缀不同，里面的实现也是非常样板化的 python 代码。

论文没有测相似性这个维度，这是我两个样本上的推断。我倾向于认为：相似的东西被合进同一个摘要条目之后，检索就更容易命中错的条目。

省下的每一分显存，都是用一个「猜」换来的。

## 七、所以怎么办

最实用的一条，来自我自己的现场。

其实发现了 agent 走偏，短短几个字的回复给它一点点提示，它马上就从泥坑里爬出来了。即便遇到不起作用的时候，及时 fork 新会话即可。

所以处置是两级的：先给一句话的提示拉回来，不行就 fork。别让它原地反复纠错——那是幻觉型错误的处置方式。

第二条是给评测和选型的：**别只看平均分**。

要测自己在不在弱相位上，做法也不复杂——同一份内容，只把目标信息挪一到四个 token 再问一次，看答案会不会跟着翻。翻，就说明你的链路吃到了相位。

最后留一个论文自己没答的问题：为什么不同 head 不把每个相位都覆盖掉？

把门的参数整体循环移位，能修掉窗口内部的偏好，却**修不掉边界那一个**。

窗口内部和窗口边界的不对称，论文至今没有统一解释。
