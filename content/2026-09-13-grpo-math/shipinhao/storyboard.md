## S1 · 开场钩子：省了一个 critic，崩在哪（~55s）

**动画要点**：
- 页1：标题「省了一个 critic，长任务为什么反而崩了？」+ 概念图「被撤走的 critic 老师：空椅子」（`s1-empty-chair-round.png`，FadeIn 合规）
- 页2：**16 份答卷**（脚本画：4×4 点阵，对了绿勾错了红叉，混合 10 对 6 错）→ 组内**减均值除标准差**流程条 → counter 滚动出 A_i
- 页3：**公式卡**（MathTex：`A_i = (r_i − mean) / std`）→ 对比双卡：critic「一格一格估，这步还有多少希望」vs GRPO「看你在组里排第几」+ 卡「critic 是和策略一样大的网络」
- 结尾悬念：账面上纯赚。但有三堵墙，都砌在「排名」两个字上

**配音稿**（= `full.txt` 第 1 段，逐字一致）：
> GRPO 砍掉的那个 critic 老师，省下的不只是显存，还有长程任务里的判断力。这条视频讲清楚，它到底崩在哪。(breath) 同一道题，采样 16 份答卷，规则判分：对了是 1，错了是 0。然后组内减均值、除标准差，每份答卷拿到一个相对成绩——比组内平均好就是正，差就是负。critic 干的本来是另一件事：一格一格估，走到这一步还有多少希望。而它是一个和策略一样大的网络。GRPO 把这整套估值，换成了一句：看你在组里排第几。<#0.5#>账面上，这是纯赚。但有三堵墙，都砌在「排名」这两个字上。

**爆点类型**：问句钩子（开场即问崩在哪）+ 转折爆点（纯赚→三堵墙）

## S2 · 第一堵墙：全对的组，一步都没学到（~62s）

**动画要点**：
- 页1：**16 个绿勾全对**（点阵全亮绿）→ 等式链「均值 1、标准差 0」→ 红卡「0 除以 0，工程置 0」→ 红叉「整组梯度为零，这批样本白跑」；全错同理小字
- 页2：主视觉**概率阶梯**（脚本画：p 从 0.5 到 0.99 四级柱，0.003% → 18.5% → 44.0% → 85.1%，grow_bar 逐级生长 + 数字 counter）
- 页3：金句卡「模型越练越强，简单题成批退化成全对组」→ **emphasize「练得越好，信号越少」**（强调 1/5）→ 反转卡「差一点全同分：16 份对了 15 份，除以极小的标准差，微弱差异放大成大梯度」→ 修法卡「DAPO 动态采样：过采样，扔掉全对全错组，补满有效样本」
- 结尾悬念：训练时间基本不变，收敛步数反而更少。可第二堵墙，连修的法都还没人找到

**配音稿**（= `full.txt` 第 2 段，逐字一致）：
> 第一堵墙：16 份答卷全对，奖励全是 1。均值是 1，标准差是 0，优势变成 0 除以 0，工程上置 0。整组梯度为零，这批样本白跑。全错，同理。(breath) 这不是偶发故障。一组全同分的概率，是 p 的 16 次方，加 1 减 p 的 16 次方。正确率一半的题，全同分几乎不可能，百分之零点零零三；正确率九成，一成八；九成五，四成四；九成九——八成五。模型越练越强，简单题成批退化成全对组。看起来，训练得越好，信号反而越少了。<#0.5#>反转还在后面。差一点全同分的组，16 份对了 15 份，除以那个极小的标准差，微弱差异被放大成大梯度。简单题和难题的权重，被系统性扭曲。修法是 DAPO 的动态采样：过采样一批组，把全对全错的扔掉，补满有效样本再更新。论文报告，训练时间基本不变，收敛步数反而更少。可第二堵墙，连修的法都还没人找到。

**爆点类型**：数字对比（百分之零点零零三 → 八成五阶梯）+ 转折爆点（练得越好信号越少）

## S3 · 第二堵墙：一个总分，泼给几万个 token（~58s）

**动画要点**：
- 页1：**长序列条**（脚本画：一条长 token 带，第 3 个与第 3000 个节点高亮）→ 双卡「同一个优势值，乘在每一个 token 的梯度上」
- 页2：主视觉**连坐对比**（左：好答案长卷，浑招节点被一同推高，红；右：烂答案长卷，妙手节点被连坐拉低，绿）→ 金句「好答案里的浑招被抬高，烂答案里的妙手被拉低。连坐」
- 页3：对比卡「有的方案：100 步功劳按视野打折，逐格分摊」vs「GRPO：终点一个总分，平摊给全部几万个 token」→ 卡「序列越长，每个 token 分到的信号越稀」→ **emphasize「长程任务撑不住的数学本体」**（强调 2/5）
- 结尾悬念：这堵墙至今没有修法。但长度这件事，还藏着更荒唐的第三堵

**配音稿**（= `full.txt` 第 3 段，逐字一致）：
> 第二堵墙：基础 GRPO 是 output-level，整条序列共享同一个优势值。第 3 个 token 和第 3000 个 token，梯度里乘的是同一个数。好答案里面的浑招，也会被一同推高；一堆烂答案里面的妙手，却被连坐拉低。(breath) 作为对比，有的方案给每一步单独配一个估值，把 100 步的功劳按视野打折、逐格分摊。GRPO 反过来：终点一个总分，平摊给全部几万个 token。序列越长，每个 token 分到的信号越稀。长 CoT、长程 agent 任务，动辄几万 token——这就是长程任务撑不住的数学本体。这堵墙至今没有修法。DAPO 的 token-level loss，只是把 loss 的加权方式改了，分摊本身一动没动。critic 的位置，没人补上。但长度这件事，还藏着更荒唐的第三堵。

**爆点类型**：短句断句（第 3 个 token，第 3000 个 token，同一个数）

## S4 · 第三堵墙：错了，还更啰嗦（~58s）

**动画要点**：
- 页1：**长度归一示意**（脚本画：同一份惩罚，长答卷摊成薄薄一层 vs 短答卷厚厚一坨）→ 卡「负面答卷越长，每个 token 摊到的惩罚越薄」→ 卡「模型从这套规则学到：答案越长越好」
- 页2：主视觉**双条对比** grow_bar（错误回答 8206 字符 vs 正确回答 4965 字符，+65% 标注）→ 金句「错了，还长 65%」→ **emphasize「长了 65%」**（强调 3/5）→ MUTED 小字「DeepSeek-R1-Zero 实测」
- 页3：GSPO 一句话卡「Qwen 从另一个方向撞上长度的墙：逐 token 的修正系数噪声沿长序列累积，训练崩到撤销检查点都救不回来；GSPO 把修正挪到整条序列一级，Qwen3 的 RL 训练用的就是它」
- 结尾悬念：删掉除以长度就完了？三堵墙，其实是同一个根源

**配音稿**（= `full.txt` 第 4 段，逐字一致）：
> 第三堵墙：GRPO 的损失里，每份答卷还要按长度归一，除以回答长度。负面答卷越长，每个 token 摊到的惩罚越薄。模型会无意间从这里学习到：给的答案越长越好。这也是很多人诟病的老版本 DeepSeek，经常思考和输出过长的原因。(breath) Dr. GRPO 论文统计过 R1-Zero：错误回答平均 8206 字符，正确回答 4965。错了，还长 65%。同年，Qwen 团队从另一个方向撞上长度的墙：逐 token 的修正系数，噪声沿长序列累积，训练能崩到撤销检查点都救不回来。他们的 GSPO 把修正挪到整条序列一级——Qwen3 的 RL 训练，用的就是它。可删掉除以长度，就完了吗？三堵墙，其实是同一个根源。

**爆点类型**：数字对比（8206 对 4965，长 65%）
