## 交付句（本篇的双半句）

- **转 1（第二条轴）**：MoE 是**按需计算**——每个 token 只激活一部分专家去算；Engram 是**按需记忆**——每个 token 只查字典里被哈希命中的几行。大模型稀疏化的第二条轴：稀疏化不只省「算」，还能省「背」。
- **转 2（分家的收益）**：把「背题」从网络里挪出去挂成字典，**算力才全部花在推理上**——关掉字典，事实知识类基准只剩 29–44%，阅读理解保留 81–93%：字典管背事实，骨干管推理，分工之后两头都变好。
- **回扣**：「为什么反而更聪明」——因为聪明从来不是背出来的；背出来的东西搬走之后，网络剩下的容量全部花在刀刃上。

⚠️ **事实纪律（红线，成稿逐条遵守）**：

1. **「不参与计算」的准确口径**：不参与 Transformer 主干的矩阵乘法（每 token 只稀疏激活命中的表行），但**参与训练**——端到端梯度更新（momentum + Sinkhorn balancing）。**禁止写成「不训练 / 只做检索不学习」**。这是本篇最容易写错的一处。
2. **「挂在 CPU 上」的准确口径**：推理时嵌入表驻留**主机内存（cheap host RAM）**，GPU 经 RDMA 后台异步预取、与计算重叠；RL rollout 时表常驻 GPU；**训练时表在 GPU 间按行分片**（All-to-All 取活跃行）。禁止写成「模型跑在 CPU 上」「完全不放 GPU」。
3. **两个规模数字不得混用**：原始论文实验是 **27B Engram**（对等参等 FLOPs MoE 基线的提分数据全来自这个规模）；**V4.1-Flash 落地是 196B**（763B 总参中独立于 552B 骨干的部分）。提分数字挂 27B 实验，落地规模挂 196B，不互相挪用。
4. **「反超自家 Pro」防自撞**：昨天四家架构篇（09-24）槽 3 已用过 Codeforces 3471 vs 3348 锚点，本文最多一句带过「编程评测反超自家 Pro」，不重复具体分数；主证据用原始论文 Figure 6 消融数字。
5. DeepSeek-V4.1-Flash 与 Engram 原始论文时间均写 **2026**（`docs/data-freshness.md` 红线）；Engram 论文 2026-01（arXiv:2601.07372，官方开源 github.com/deepseek-ai/Engram），V4.1-Flash 技术报告 2026-09（arXiv:2609.19969）。
6. 「字典」是哈希表的比喻，首次出现时锚定一次「哈希表」；之后全文可用字典。U 型缩放是「稀疏度分配」实验结论（Figure 3 左），不当定理陈述。

## 结构（6 节；小标题连成故事链；正文 ≈2000 字）

### 1. 196B 参数，一次矩阵乘法都不参加

- 开头钩子（零导航）：深度学习的铁律是「每个参数都要参与计算」；DeepSeek 9 月的新旗舰挂了 196B 参数，**不进矩阵乘法，只做一件事——查表**。
- 【槽 1 · 作者亲历】第一反应。
- 驱动问题：查字典为什么反而更聪明？
- 立框架：MoE 稀疏的是「算」（互链 MoE 篇一句），Engram 稀疏的是「背」——**第二条稀疏轴**；官方定位原话「条件记忆，把记忆从计算里解耦」。
- 收口：字典怎么查，一句话说不清，值得拆开。

### 2. 字典怎么查：8 把哈希钥匙

- 机制（V4.1-Flash 实装口径）：n-gram {2,3,4} 阶 × 8 个哈希头 × 每头约 16M 条目（表长取不同质数防碰撞聚集）；查到的嵌入经**上下文感知门控**融回网络。
- 【原论文 Figure 1 · 架构图】读图：检索静态 n-gram 记忆 → 门控融合。
- 关键性质：查询只依赖输入 token 序列 → **确定性寻址** → 还没算到就能提前预取。
- 挂载位置：V4.1-Flash 把两个模块挂在第 1、14 层（为平衡训练各 stage 内存）； FP8 存储（内链 FP8 篇一句）。
- 【槽 2 · 作者吐槽/感叹】对「哈希 + 质数这种『土办法』直接进 2026 旗舰」的看法。
- 收口：查法不贵，贵的是表往哪放——答案更反直觉。

### 3. 表挂在最便宜的内存上

- 推理时：整张表驻留**主机内存**，GPU 用 RDMA 后台预取、与计算重叠（确定性寻址让预取可以跑在需求前面）。
- 【原论文 Figure 2 · 系统图】读图：(a) 训练 GPU 分片 + All-to-All；(b) 推理主机内存 + 异步预取。
- 为什么划算：KV 缓存随上下文线性涨（1M 上下文各家 0.93–13.7 GB，昨天刚算过账）——**Engram 一字节 KV 都不占**；主机内存是最便宜的大容量存储。
- 训练侧：表参与梯度更新，但用 momentum + Sinkhorn 替代 Adam 省优化器状态；按行分片并行。
- 【槽 3 · 作者判断】对「最贵的数据放最便宜的内存」的看法或亲历。
- 收口：省是真省，但读者真正想问的是——查表能查来聪明吗？

### 4. 关掉字典，事实题崩到三成

- 提分证据（27B 实验规模）：对等参等 FLOPs 的 MoE 基线，MMLU +3.4、BBH +5.0、多查询 NIAH 84.2→97.0。
- 【原论文 Figure 6 · 消融柱状图】杀手锏：推理时把字典输出关掉——**事实知识类只剩 29–44%，阅读理解保留 81–93%**。「字典管背事实、骨干管推理」的直接实验证据。
- 落地证据：V4.1-Flash 196B Engram（编程评测反超自家 Pro 一句带过，防自撞）；Qwen3.8-Next 跟进 +51B n-gram 表（放加速器之外、从主机内存预取——同一条路线）。
- 【原论文 Figure 7 · 门控热力图】（可选，篇幅紧则砍）门控在「Princess of Wales」这类多 token 实体处强激活——模型自己学会了什么时候翻字典。
- 【槽 4 · 作者情绪/判断】对「关掉字典掉分分化」或「国产跟进」的反应。
- 收口：看到这里容易得出「字典越大越好」——Qwen 的数据恰好泼了盆冷水。

### 5. 泼冷水：字典不是越大越好

- Qwen3.8-Next 实测：n-gram 词表加大，**loss 单调下降、下游精度却饱和**。
- 原因回到原论文的**稀疏度分配**实验：验证损失对「计算↔记忆」的分配比例呈 **U 形**——记忆给少了背不动，给多了挤占计算，中间有最优配比。
- 【原论文 Figure 3 · U 形曲线 + 对数缩放】读图。
- 【槽 5 · 作者立场】对「loss 好看但下游不涨」（刷指标 vs 真能力）的判断。
- 收口：所以「第二条轴」不是免费午餐，是一门配比的手艺。

### 6. 所以，为什么反而更聪明

- 回扣开头（必须回答驱动问题）：铁律「参数都要算」错在把「背」也算成计算——背出来的东西搬进字典，网络剩下的容量全花在推理上。
- 架构含义一句：MoE 之后，「多大算力配多大记忆」正在成为架构设计的第二个旋钮。
- 一句话总结卡（分享借口）：「DeepSeek 把背题变成了查字典：196B 参数不算数，事实题却更多对——省下的算力都花在了刀刃上。」
