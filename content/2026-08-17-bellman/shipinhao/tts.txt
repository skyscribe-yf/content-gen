上一篇，你让一个 coding agent 修 bug。它停在第三步：后面还有二十七步，每一笔奖励，都写在未来。那到底该看什么？看一个数。这个数，把从当前到终局的所有未来奖励，压成当下值多少钱。它叫价值函数。而把它算出来的那个记账法，就是贝尔曼方程。
你肯定想问：为什么不把每条可能的未来都展开，一条条算回报再取平均？算给你看。哪怕每步只有三种可能，走到第三十步，就是三的三十次方，大概二百零五点九万亿条路径。每条都算一遍，计算机也扛不住。这就是必须压缩的原因：用每个状态的一个数，换掉指数多条未来路径。那这个数怎么定义？先立一条铁律。
大写字母，像骰子还没掷下去，结果是随机变量。小写字母，是骰子已经落地，纸上一个确定的数。记住这条，后面所有公式都看得懂。现在写价值函数：站在状态 s，按策略 pi 走下去，把所有可能路径的回报按概率平均。就像买二手车，你不会等未来十年每一张维修单开出来再定价。你给一个数。这一口价，把所有的可能，全算进去了。
贝尔曼的功劳，就是把这张无限长的账单，改写成只看一步。第一步，把回报写完整：马上进账的，加上一笔比一笔折得更狠的未来。第二步，把今天单拎出来，明天那整本收据，先打个九折。第三步，认出右边这本，其实就是明天的总账。第四步，最漂亮：明天的总账，等于站在明天那个路口，问那一口价多少。于是一张无限长的账，折成了今天这一步的奖励，加上折现后的明天价值。这就是贝尔曼方程。
用简化版，三个状态排成一条地铁线。A 上车，B 换乘，C 到站。只有到站时给一块钱，折扣是零点九。先算笨办法：终点那一块钱，折两次回到 A，零点八一。再用方程倒推。终局没未来，是零。站在 C，下一步就能拿一块，所以 C 等于一。注意，奖励在 C 到终局这一步当场到账，不打折。于是 B 等于零点九，A 等于零点九乘零点九，零点八一。跟笨办法严丝合缝。未来的长度，被 C 一口吞掉了。
因为 V(s') 不是随便一个数，它里面压着 s' 之后全部的未来的价值。看下一步，等于透过 S' 看完全程。这就是不动点：账无论怎么绕，最后都平在同一个点上。那真实的大模型怎么用这笔账？Q-learning，是真正在解方程的。PPO，只用了价值函数解评估这一半：让 critic 学会打分。GRPO 更省，连价值函数都不养，用同题的几份回答取平均当基线，等于绕开了账本。下一篇，我们用实际奖励加下一步估值当老师，一步步逼近，拆 TD 和 Q-learning。如果给 coding agent 配一个价值函数，你最想让它估哪一笔账？评论区聊聊。
