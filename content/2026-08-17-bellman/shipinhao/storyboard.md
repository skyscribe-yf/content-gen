1. 配音稿确认（门禁 1）→ `tts/full.txt` 整段生成：`scripts/minimax_tts.py --speed 1.0 --pitch 2 --subtitle --out shipinhao/tts/full.wav`

## S1 · 开场钩子：决策在现在，奖励在未来（~38s）

**场景 1 动画**：修 bug agent 停在「第 3 步」→ 一条时间轴 3,4,5...29,30 步，后面 27 步全是"未来奖励" → 主视觉：G_t 折现链（R_{t+1}, γR_{t+2}, γ²R_{t+3} 一条比一条暗/小）

**配音稿**：
> 上一篇，你让一个 coding agent 修 bug。它停在第三步：后面还有二十七步，每一笔奖励，都写在未来。(breath) 那到底该看什么？(gasps) 看一个数。这个数，把从当前到终局的所有未来奖励，压成"当下值多少钱"。它叫价值函数。而把它算出来的那个记账法，就是贝尔曼方程。

**结尾悬念**：未来有指数多条路径，怎么用一个数，全压扁？

## S2 · 为什么必须压成一个数：路径爆炸（~38s）

**场景 2 动画**：主视觉 = 指数增长。画树状分叉（每步 3 种可能）→ 分支越来越多 → 数字 3^30 滚动 → 爆出 205.9 万亿

**配音稿**：
> 你肯定想问：为什么不把每条可能的未来都展开，一条条算回报再取平均？算给你看。哪怕每步只有三种可能，走到第三十步，就是三的三十次方。大概二百零五点九万亿条路径。每条都算一遍，计算机也扛不住。这就是必须压缩的原因：用每个状态的一个数，换掉指数多条未来路径。那这个数怎么定义？先立一条铁律。

**结尾悬念**：价值函数是"一口价"，怎么算？先得把符号说清楚。

## S3 · 字母大小写 + V 的一口价（~40s）

**场景 3 动画**：大写 S_t, A_t, R_t, G_t（随机变量）vs 小写 s,a,r（具体值）两栏对照 → 主视觉：V^\pi(s) 定义为 E[G_t | S_t=s]

**配音稿**：
> 大写字母，像骰子还没掷下去，结果是随机变量。小写字母，是骰子已经落地，纸上一个确定的数。记住这条，后面所有公式都看得懂。现在写价值函数：站在状态 s，按策略 π 走下去，把所有可能路径的回报按概率平均。就像买二手车，你不会等未来十年每一张维修单开出来再定价。你给一个数。这一口价，把所有的"可能"，全算进去了。

**结尾悬念**：一口价很好，但按定义硬算，又要遍历所有未来——又绕回那二百万亿条了。怎么办？

## S4 · 贝尔曼推导：把无限求和折成"今天+明天"（~48s）

**场景 4 动画**：主视觉 = 复式记账。一张长收据（R_{t+1}+γR_{t+2}+γ²R_{t+3}+…）→ 撕成两半：今天 + 明天一整本（折价）→ 认出明天的 G_{t+1} → 折成 V(s') → 标准形式 ΣπΣP

**配音稿**：
> 贝尔曼的功劳，就是把这张无限长的账单，改写成"只看一步"。第一步，把回报写完整：马上进账的，加上一笔比一笔折得更狠的未来。第二步，把今天单拎出来，明天那整本收据，先打个九折。第三步，认出右边这本，其实就是明天的总账。第四步，最漂亮：明天的总账，等于站在明天那个路口，问那一口价多少。于是一张无限长的账，折成了今天这一步的奖励，加上折现后的明天价值。这就是贝尔曼方程。

**结尾悬念**：方程是写出来了，可左边 V，右边又冒出 V。用未知数定义未知数，这不是循环论证吗？拿真实数字算一笔就懂。

## S5 · 三态链倒推，对账 0.81（~50s）

**场景 5 动画**：三个状态 A→B→C 一条地铁线，C 下车 +1，γ=0.9 → 笨办法 G_A=0.81 → 倒推 V(C)=1, V(B)=0.9, V(A)=0.81（红叉盖住第一次算错的 V(C)=0.9）→ 最终严丝合缝

**配音稿**：
> 用简化版，三个状态排成一条地铁线。A 上车，B 换乘，C 到站。只有到站时给一块钱，折扣是零点九。先算笨办法：终点那一块钱，折两次回到 A，零点八一。再用方程倒推。终局没未来，是零。站在 C，下一步就能拿一块，所以 C 等于一。注意，奖励在 C 到终局这一步当场到账，不打折。于是 B 等于零点九，A 等于零点九乘零点九，零点八一。跟笨办法严丝合缝。未来的长度，被 C 一口吞掉了。

**结尾悬念**：站在 A 不用知道终点长什么样，只看 B 递过来的信封。可这方程右边，为什么说它是全局视角？

## S6 · 为什么只下一步就是全局 + 三家用法 + 预告（~45s）

**场景 6 动画**：主视觉 = "自洽"账本（不动点）→ 三种走法分三路：Q-learning 解它 / PPO 用一半 / GRPO 绕开 → 结尾品牌尾卡 + 预告下一篇

**配音稿**：
> 因为 V(s') 不是随便一个数，它里面压着 s' 之后全部的未来的价值。看下一步，等于透过 S' 看完全程。这就是不动点：账无论怎么绕，最后都平在同一个点上。那真实的大模型怎么用这笔账？Q-learning，是真正在解方程的。PPO，只用了价值函数解"评估"这一半：让 critic 学会打分。GRPO 更省，连价值函数都不养，用同题的几份回答取平均当基线，等于绕开了账本。下一篇，我们用"实际奖励加下一步估值"当老师，一步步逼近，拆 TD 和 Q-learning。

**结尾互动**：如果给 coding agent 配一个价值函数，你最想让它估哪一笔账？评论区聊聊。
