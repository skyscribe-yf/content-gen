在[上一篇《马尔可夫决策过程：AI 怎么在不确定里做选择》](https://mp.weixin.qq.com/s/SJ8_CpSyp8onm8HLiF3TXA)里，你让一个 coding agent 修 bug。它停在第 3 步：后面还有 27 步，每一笔奖励都写在未来。

上篇只立了一个结论：不能只看眼前。

那到底看什么？今天揭晓：**看一个数**。这个数叫价值函数，它把从当前状态到终局的所有未来奖励，压成「当下值多少钱」。而贝尔曼方程，就是算这个数的记账法。

这是「强化学习原理」系列第二篇。第一篇讲世界怎么变（MDP），这一篇讲目标怎么算（Bellman 方程）。

## 一、为什么必须把未来压成一个数

先回到上一篇的回报定义：

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots$$

它的意思很直白：站在第 $t$ 步，把之后每一步的奖励按 $\gamma$ 折现，全部加起来。

打个比方。这个月工资全额到账。下月奖金打九折。后月年终奖再打一个九折。全加起来，才是这份工作在你眼里值多少。$\gamma$ 就是那个折扣。

现在看问题出在哪。

agent 站在第 3 步，要决定「跑测试」还是「改配置文件」。这个决定发生在现在。可 $G_3$ 里的每一项——$R_4, R_5, R_6$——全是未来。

未来还没发生。它们是大写字母，是骰子还没掷下去的随机变量。

你当然可以追问：为什么不把每条可能的未来都展开，一条条算 $G$，再取平均？

算给你看。哪怕每步只有 3 种可能，30 步就是：

$$3^{30} = 205,891,132,094,649 \approx 205.9\text{ 万亿条路径}$$

每条路径算一遍回报，再平均，计算机也扛不住。这就是必须压缩的原因：**用每个状态的一个数，换掉指数多条未来路径**。

这个数就是价值函数 $V$。

![把未来压缩成一口价：散乱的未来奖励，收拢成当前状态的一个数](01-future-to-price.png)

## 二、先把符号说清楚

动笔之前，先立一条铁律。这条铁律能帮你看懂后面所有公式：

- **大写** $S_t, A_t, R_t, G_t$：随机变量。骰子还没掷，结果是哪个值不知道。
- **小写** $s, a, r$：具体取值。骰子已经落地，纸上是一个确定的数。

这条规则不是数学洁癖。$G_t$ 还没发生，所以大写；$V^\pi(s)$ 吃进去的是某个具体状态，所以小写。

下面是这篇要用的全部符号，每个都挂在修 bug 的例子上：

| 记号 | 人话 | 大小写 |
|------|------|--------|
| $S_t$ / $s$ | 第 $t$ 步面对的局面（代码 + 测试日志的一种状态） | 未落定 / 已落定。 |
| $A_t$ / $a$ | 第 $t$ 步做的动作（跑测试、改文件、grep 日志） | 未落定 / 已落定。 |
| $R_t$ / $r$ | 这一步拿到的奖励（测试全绿才 +1） | 未落定 / 已落定。 |
| $P(s^{\prime}\mid s,a)$ | 在 $s$ 做 $a$，下一状态变成 $s^{\prime}$ 的概率 | 表格记法，小写。 |
| $\pi(a\mid s)$ | 策略：在 $s$ 选动作 $a$ 的概率 | 小写。 |
| $\gamma$ | 折扣因子，未来的钱打几折 | 常数。 |
| $G_t$ | 回报：从 $t$ 之后所有奖励折现的总和 | 随机变量。 |
| $V^\pi(s)$ | 价值：站在 $s$，按策略 $\pi$ 走下去，未来平均拿多少 | 函数，小写。 |

这里要单独把 $\pi$ 说清楚。强化学习里，$\pi$ 不是圆周率。它是 policy 的缩写，中文叫策略。

策略是什么？就是一个随机函数。你把当前状态 $s$ 喂进去，它吐出每个动作的概率。$\pi(a\mid s)$ 读作：站在 $s$，选动作 $a$ 的概率。

这些概率加起来必须是 1。修 bug 时，$\pi(\text{跑测试}\mid s)=0.7$、$\pi(\text{改文件}\mid s)=0.3$，就是一种策略。

换一组概率，就是另一个 $\pi$，也就是另一套策略。后面所有公式里的 $V^\pi$，上标都在强调一件事：这个价值，是按某一套具体策略走出来的。策略换了，一口价也换。

还有 $\mathbb{E}$，读作「期望」。它不神秘，就是按概率加权平均。

最后一个符号 $Q$ 今天先不展开，到最后给它挂个招牌。

## 三、V：给未来开个一口价

有了符号，价值函数就能写出来了：

$$V^\pi(s) = \mathbb{E}_\pi\left[G_t \mid S_t = s\right]$$

读成一句话：站在状态 $s$，按策略 $\pi$ 一直走到终局，把每条可能路径的回报 $G_t$ 按概率平均。

挂回修 bug。你站在第 3 步，代码改到一半，测试还是红的。$V$ 就是：按你现在这套习惯走下去，平均能拿多少分。可能 10 步后全绿，也可能绕半小时还是红。这些可能，全压进一个数。

这就是「一口价」。买二手车，你不会等未来十年每一年的维修单都开出来，再决定值不值。你给一个数，把所有可能的未来都算进去了。

我在这里卡过。$G_t$ 本身不就是一个数吗，为什么还要再平均一次？

后来想通了。$G_t$ 是随机变量，是「中奖的那张彩票值多少」。$V^\pi(s)$ 是期望，是「彩票还没开奖时值多少」。前者要等未来全部落地，后者现在就能算。

这个「现在就能算」四个字，就是价值函数存在的原因。

## 四、贝尔曼方程：把无限求和改成一步加未来

$V$ 的定义很好，但按定义硬算，要遍历所有未来路径——又绕回 $3^{30}$ 了。

贝尔曼的贡献，是把这笔无限长的账，改写成「只看一步」的记法。

别被下面几行公式吓到。它们在说同一件小事：把一张无限长的账单，折成「今天 + 明天一口价」。

下面一步步推。

**第一步，把 $G_t$ 写完整。** 因为 $V^\pi(s)$ 是对 $G_t$ 求期望，先把被平均的东西写开：

$$V^\pi(s) = \mathbb{E}_\pi\left[R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \cdots \mid S_t = s\right]$$

这就是把一张长账单摊在桌上。第一行是马上进账的 $R_{t+1}$。后面全是以后的钱，一笔比一笔折得更狠。

修 bug 也一样。第 3 步之后，可能马上跑出测试结果，也可能再过 20 步才全绿。全写在这一行里。

**第二步，把第一步奖励单拎出来，后面提一个 $\gamma$：**

$$V^\pi(s) = \mathbb{E}_\pi\left[R_{t+1} \mid S_t = s\right] + \gamma\, \mathbb{E}_\pi\left[R_{t+2} + \gamma R_{t+3} + \cdots \mid S_t = s\right]$$

把收据撕成两半。左边是今天这一行。右边是从明天起的整本收据，整本先打个折。

这一步用的是期望的线性性：$\mathbb{E}[X+Y]=\mathbb{E}[X]+\mathbb{E}[Y]$，常数 $\gamma$ 也能提出来。哪怕后面那些奖励彼此相关，线性性照样成立。这不是什么高深技巧。本科概率论教材里都有，不妨翻回去对一下。

**第三步，认出括号里是谁。** $R_{t+2} + \gamma R_{t+3} + \cdots$ 不就是第 $t+1$ 步的回报 $G_{t+1}$ 吗？所以：

$$V^\pi(s) = \mathbb{E}_\pi\left[R_{t+1} + \gamma G_{t+1} \mid S_t = s\right]$$

右边那本收据，换个角度看，就是明天的总账 $G_{t+1}$。

你明天醒来，面对的是新局面。从那天起再把未来折现加总，不就是一个新的 $G$ 吗？只是下标从 $t$ 换成了 $t+1$。

**第四步，最漂亮的一步。** $G_{t+1}$ 还是未来，但可以换个算法：先从 $s$ 走到 $s'$，再问「站在 $s'$ 平均能拿多少」。按 $s'$ 分情况加权平均，就等于直接对 $G_{t+1}$ 平均：

$$V^\pi(s) = \mathbb{E}_\pi\left[R_{t+1} + \gamma V^\pi(S_{t+1}) \mid S_t = s\right]$$

这一步在干什么？你不去把明天之后的每一笔都列出来。你直接问：站在明天那个路口，一口价多少？

这个一口价就是 $V^\pi(S_{t+1})$。从 $t+2$ 步开始的无限项，全部折叠进了这一个数。

再把期望按动作和下一状态摊开，就是课本上的标准形式。看起来吓人。其实就是把「选哪个动作、会跳到哪」摊开成两层加权。

$$V^\pi(s) = \sum_a \pi(a\mid s)\sum_{s'} P(s'\mid s,a)\left[r(s,a,s') + \gamma V^\pi(s')\right]$$

用修 bug 走一遍。假设你现在的策略是：七成跑测试，三成改文件。跑完测试，八成看到失败日志，两成直接全绿。

方程在算的，是把这两条岔路按概率加权。每一条都是：这一步奖励，加上折现后的明天一口价。七成、三成是 $\pi$。八成、两成是 $P$。括号里是今天进账，加上明天的 $V$。

用中文读，这个方程在说四件事：

- 在 $s$，按概率 $\pi(a\mid s)$ 选动作 $a$；
- 做完 $a$，按概率 $P(s'\mid s,a)$ 跳到 $s'$；
- 这一步拿到平均奖励 $r(s,a,s')$，再加上折现后的 $V^\pi(s')$。
- 先把 $s'$ 的所有去向加总。再把 $a$ 的所有选择加权。

这就是贝尔曼方程：**今天的价值 = 今天这一步的奖励 + 折现后的明天价值。**

![贝尔曼方程 = 复式记账：总账 = 今天的开销 + 折扣后的明天总账](02-bellman-accounting.png)

打个比方。你开一家小店，问「这家店值多少钱」。你不把未来 100 年逐月算一遍。你只记两笔。这个月赚多少。加上「下个月起这家店还值多少」，打个折。账本上那个「下个月起还值多少」的格子，就是 $V^\pi(s')$。未来全打包在那个格子里。

把动作先定死，还有个孪生方程叫 $Q$ 函数。

$V$ 问的是：站在店门口，整店值多少。$Q$ 问的是：今晚必须搞促销，店还值多少。同一家店。只是第二个问题把动作先说死了。

$$Q^\pi(s,a) = \mathbb{E}_\pi\left[R_{t+1} + \gamma V^\pi(S_{t+1}) \mid S_t = s, A_t = a\right]$$

今天只挂招牌。它和 $V$ 的差别，后面讲 Actor-Critic 时会变成主角。

## 五、拿三态例子算一遍

推导完了，必须手算一笔，才知道方程真的管用。

用修 bug 的简化版，三个状态排成一条直线，每步转移都是确定的：

- $A$：刚读完代码。
- $B$：改到一半。
- $C$：测试即将全绿。在 $C$ 执行最后一步得 $+1$，进入终局。

你可以把它想成一条只有三站的地铁。$A$ 上车，$B$ 换乘，$C$ 到站下车。只有下车时才给 1 块钱。中间每一步奖励都是 0，只有最后 +1。折扣 $\gamma = 0.9$。

先算笨办法。站在 $A$，未来三步的奖励折现：

$$G_A = 0 + 0.9 \times 0 + 0.9^2 \times 1 = 0.81$$

终点那 1 块钱，折两次才回到 $A$。$0.9 \times 0.9$，就是 0.81。这个 0.81，正是上篇结尾算过的那笔账。

再用贝尔曼方程倒推。别从 $A$ 往前冲。从终点往回传信封。

终局没有未来，价值是 0。站在 $C$，下一步就能拿 +1，所以：

$$V(C) = 0 + 0.9 \times 1 = 0.9$$

等一下，这里要停一下。$V(C)=0.9$ 而不是 1，因为奖励是在下一步才到账的，要先打个九折。

继续倒推：

$$V(B) = 0 + 0.9 \times V(C) = 0.9 \times 0.9 = 0.81$$

$$V(A) = 0 + 0.9 \times V(B) = 0.9 \times 0.81 = 0.729$$

咦，$V(A)=0.729$？可笨办法算出来 $G_A=0.81$。两个数对不上，方程推错了？

没推错。是我在倒推时算错了一步：从 $C$ 迈出那一步，$+1$ 是**当场到账**的，不是下一期才到账。所以：

$$V(C) = 1$$

$$V(B) = 0 + 0.9 \times 1 = 0.9$$

$$V(A) = 0 + 0.9 \times 0.9 = 0.81$$

和笨办法的 0.81 严丝合缝。

倒推像接力。$C$ 先把 1 块装进信封。$B$ 接过信封，打个九折。$A$ 再打一次九折。$A$ 自己不用去想终点长什么样。它只看 $B$ 递过来的那个信封。

我故意把那个「算错」的岔路留着，是因为它是很多人第一次手推贝尔曼方程会踩的坑：奖励到底落在哪一步，折扣就要从哪一步开始算。奖励在 $C \to$ 终局这一步到账，那它就是 $V(C)$ 里的即时项，不再打折。

![三态链倒推：V(C)=1，V(B)=0.9，V(A)=0.81，与笨办法的 0.81 对上了](03-bellman-backup.png)

算完这笔账，贝尔曼的味道就出来了：**未来的长度被 $V(C)$ 一口吞掉了。** 站在 $A$，你不需要知道终局之后还有没有别的，只需要看下一步的 $B$，而 $B$ 的值里已经压着它之后的全部未来。

## 六、为什么「只看下一步」反而是全局视角

现在你大概率会质疑：$V^\pi(s)$ 在方程左边，右边又冒出 $V^\pi(s')$。用未知数定义未知数，这不是循环论证吗？

我第一次也这么想。

后来才明白，这不是循环，是**自洽条件**。像查账。你猜每个房间的存货。如果每个房间都对得上「本屋货物 + 隔壁存货」，账就平了。平了的那组数，才是真的价值函数。

数学上叫不动点。方程左右两边怎么绕，最后账都平在同一个点上。

这也是「只看下一步」能成立的原因。$V^\pi(s')$ 不是随便一个数，它里面压着 $s'$ 之后的全部未来。所以看下一步，等于透过 $s'$ 看完了全程。

不信可以再往上加一层。如果不要固定策略，而是在每一步都选最好的动作，贝尔曼方程就升级成最优方程。

$$V^*(s) = \max_a \sum_{s'} P(s'\mid s,a)\left[r(s,a,s') + \gamma V^*(s')\right]$$

$\max$ 像每到路口都查一遍导航。哪条路「这一步油费 + 剩下路程」最便宜，就走哪条。不是只看这一步谁油费低。眼前绕远、后面抄近的路，它照样会选。

至于为什么这个 $\max$ 一定给出最优，证明留给后面的算法篇。今天先看它一眼就够。

## 七、修正上一篇结尾的一句话

上一篇结尾我写过一句预告：

> 价值函数怎么递归，为什么 Q-learning、PPO、GRPO 这些算法，本质都在解同一个方程。

现在方程教完了，我得更正一下：**这句话不够准确。**

准确的说法是：它们都绕着这笔账做文章，有的解它，有的只用一半，有的干脆绕开。

- **Q-learning**：是三者里真正在解贝尔曼最优方程的那个，一路迭代逼近最优动作价值。
- **PPO**：只用价值函数解「评估」这一半。critic 学 $V$，负责给每一步打分；但策略改进那一半走的是策略梯度，不是解贝尔曼方程。[GLM-5.2 把 critic 请回来](https://mp.weixin.qq.com/s/OEZtUhm8MT_En7enJo_8dw)，请的就是这一半。
- **GRPO**：连价值函数都省了。它让同一道题生成多份回答，用组内平均分当基线，是**绕开**方程。省了显存，代价是长程任务里信号变粗——这也是 GLM-5.2 长程任务换回 critic 的原因。

![三种走法：Q-learning 解它，PPO 用一半，GRPO 绕开它](04-three-routes.png)

绕开账本省了什么、又赔了什么，完整的数学留到第八篇 GRPO 再算。

我为什么要把这个更正写进正文？因为系列要兑现预告，也要兑现得准确。错了就改，比硬圆好看。

## 结尾

回到那个停在第 3 步的 agent。

带上价值函数之后，它不再问「这一步奖励是多少」。它问：**这一步会把未来账本推进多少。** 账本叫 $V$，记账法叫贝尔曼方程。

从「不敢只看眼前」到「只看一步就够了」，中间只隔着一个把未来折叠起来的方程。推导推到账做平的那一刻，我确实有了笔记里那句「守得云开见月明」的感觉。

但方程右边有一张转移表。修 bug、写代码、对话，这张表不存在。不能解方程，就只能走一步、看一眼。下一篇讲怎么用「实际奖励 + 下一步估值」当老师，一步步逼近——**TD 和 Q-learning**。

一个问题留给你：如果给 coding agent 配一个价值函数，你最想让它估哪一笔账？测试通过的概率、剩余步数，还是当前代码的健康度？评论区聊聊。
