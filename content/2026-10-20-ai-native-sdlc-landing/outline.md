# 大纲：AI Native SDLC 能落地吗：成本、独立性与验收

发布日期：2026-10-20 22:00 | 系列：软件工程 | 类型：落地篇

## 一句话
Anthropic playbook 给了"怎么做"，但落地要过三道坎：反馈延迟决定 agent 行为形态、成本核算决定混合架构有没有最优点、review 独立性决定"多开几个 agent 互相审"是不是纯浪费。

## 结构（目标 ~2400 字）

### 0. 开场（~200 字）[原声槽 1]
- 承接篇一：playbook 的"能"格已基本解决，值/撑/知三格才是真正的风险
- 原声槽：作者对"AI coding 工具突飞猛进仍不能解决软件工程核心挑战"的体会

### 1. 第一道坎：反馈延迟决定 agent 的行为形态（~350 字）
- Ian Johnson 四档：亚秒→TDD 实践者 / 几秒~1 分钟→小批次 / 5-10 分钟→"蒙一把" / 20 分钟+→"投机者"
- 人一天跑 5 次测试，agent 跑 200 次 → 延迟是乘数级的税
- 最高杠杆：依赖反转 + in-memory fake，把单测压到毫秒级
- 顺序警告：先有意义再变快——"一个验证不了任何东西的快检查，比慢而有意义的检查更危险，因为它伪造信任"；agent 会把测试改弱以便转绿
- 反模式：别把"加一层 evals"当成反馈回路（频率与目的不同）

### 2. 第二道坎：NFR 三层定义 + 类别特定反馈（~350 字）
- 三层：可单一数值化（预算+基线）/ 可结构规则化（fitness function 进 CI）/ 不可数值化（限制产量+人工读）
- Google 三阶段 prompt 干预：通用反馈无效，类别特定反馈才被 agent 当作约束消化
- "代码能不能跑由 build 裁决；但『这是不是正确的改动』没有传感器"（Simon Willison）
- review 努力度代理指标与低效代码存活无相关

### 3. 第三道坎：成本核算（~450 字）
- cost per accepted change：分母必须是"留存下来的变更"（30 天 post-merge），分子五项（licenses/metered/CI/审查/修复/事故）
- 整单跳档 cliffs：输入长度决定档位，输出单价也由输入长度决定；agentic coding input token 指数增长，实际单价比名义价高 2.5-5 倍
- 缓存回本点：显式缓存建 125%/命中 10%，一次命中就回本；但 5 分钟 TTL，价值取决于工作节奏
- 按层 ΔFCR：Pegatron 613 commit 重放，Low 层 fix rate 最高（63.4%）→ "简单任务→便宜模型"把 fix 最密集的层交给了更差的档
- 盈亏平衡式：基础设施节省 > ΔFCR × commits × t_fix × labor rate
- 结论：混合没有最优点，前沿单调；但这是大能力落差下的结论，小落差可能有拐点

### 4. 第四道坎：review 独立性（~400 字）
- n_eff = k/(1+(k-1)φ̄)：9 判官 = 2.2 票；全票一致时错误率 9.1% vs 独立假设 0.02%（差 455 倍）
- β 共失败天花板：任何聚合架构上限 = 1-β
- 越强越相关：更大更准的模型误差高度相关，即使架构与 provider 不同（Cornell 350+ 模型）
- 六轴多样性：模型/架构/provider/scope/上下文/方法——确定性检查是唯一不与模型共享 φ̄ 的层
- verifier cascade：自托管生成 → 确定性检查 → 通过接受/失败升 API 档；升级触发器用真值不用置信度
- 可复现实验方案摘要：缺陷注入 D1-D8 + 干净样本 + 6 个陷阱

### 5. 验收一致性：纪律只能画在权限和动作上（~300 字）
- agent 不会因为"公司规定"守规矩，只会因为这条路物理上走不通
- Anthropic Slack 事故教训
- 验收标准必须是 artifact 的一部分且可执行（script not prose）
- 归属不转移：同一产品负责人从 intent 审到 spec 审到验收
- 批次大小是理解一致性的最强杠杆（MinimumCD 链）
- "第二次犯错就写进 CLAUDE.md"——唯一让理解一致性单调改善的机制
- invariant 测试：把人达成的共识转成机器传感器

### 6. 残余风险与收尾（~250 字）
- cognitive debt 结构性成本：第 3 类（对不对）没有传感器，只能限制产量+保留人工读
- "判断力能否外化"：invariant 测试是成功样本，但审美/取舍/优先级目前无外化形式
- 原声槽 2：作者对"AI 时代工程师价值"的判断
- 系列导航：软件工程合集 + 篇一已发布 URL
- 话题标签

## 作者原声槽

- 槽 1（非功能约束）：已填 — "商业软件所期望的各种非功能约束，领域特定的需求范式，软件需求和测试如何拉通对齐，这些核心挑战其实都远远称不上被完美解决。"
- 槽 2（锯齿智能）：已填 — "确定性世界里人们积累的大量经验，想无缝照搬到 AI agent 上，期望用许愿式的方法直接得到期望的产品，基本上都是一厢情愿的过度简化。"
- 槽 3（一把梭哈）：已填 — "有的企业甚至提出很朴素的想法，尝试将各种文档、材料一股脑丢给 AI，使用各种 RAG、Graph 等技术，尝试让 coding agent 一把梭哈。然而这种方式很快就会碰上模型本身'锯齿智能'的弱点。"
- 槽 4（堆 token）：已填 — "各种软件千人千面，各种技术上的非技术上的约束混杂期间，是否所有的东西都可以用堆 token 来完成，这是很多做 agent 评测和玩具 coding 项目的人从来都不会关心的事情。"
- 槽 5（收尾）：已填 — "不过毕竟，它山之石可以攻玉，对于 Anthropic 这种工作方式，探讨和研究的价值还是很高的。"
