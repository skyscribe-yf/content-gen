## 交付句（本篇的双半句）

- **转 1（反常识 1：钱去了哪）**：2345 万人民币的强化学习账单里，评分器只拿到 **12.7%**。反直觉的点是——评分器不是不重要，是它只负责「及格线内排序」，判「对不对」这件最贵的事已经被便宜的单元测试做完了。
- **转 2（反常识 2：贵的不划算）**：花 260 万美元的 Pro 比花 90 万美元的 Flash 更不划算——每百万美元换到的分数，Flash 是 Pro 的 **3.5 倍**。所以「旗舰模型更值」是错的，钱花在 Pro 上不划算。

## 结构（7 节，悬念链）

### 1. 2345 万买了个什么东西
- 开头钩子（场景/反直觉提问，零导航）：9 月 15 日起，小米把一次 trillion 级模型的强化学习训练**全程直播**了，reward 曲线、rollout 步数、每分钟烧多少钱，五个字级别的实时面板。训练结束时账单定格：**约 2345 万元人民币**。
- 反问收口：训练结束不稀奇，稀奇的是**账单敢公开**——业界公开过预训练成本，公开 RL 阶段成本的极少。
- ⚠️ 只写「训练全程直播 + 开源训练动态」（报告原话 *open-source the training dynamics*），**不写具体天数**（5 天/6 天均为二手，报告未给）。

### 2. 87% 花在「生成」和「学习」，评分器只拿 12.7%
- 核心数据：成本三分（报告 Figure 3 右侧饼图，已读图核对）
  - MiMo-V2.6-Pro：Training 43.5% / Rollout 43.8% / **Grader 12.7%**
  - MiMo-V2.6-Flash：Training 40.9% / Rollout 44.9% / **Grader 14.2%**
- 关键观察：**两个模型结构几乎一样，评分器在两个模型里都是最小的一块**。
- 人话解释三件事：
  - **rollout（生成）** = 模型自己尝试解题，一个 prompt 展开 16 份答案
  - **training（学习）** = 把这些答案变成梯度更新参数
  - **grader（评分）** = 判断哪份答案更好
- 规模感：每步 1,568 个 prompt × 组大小 16 = 2.5 万条序列，**2.7B–3.7B tokens/步**，上下文最长 1M。

### 3. 同样跑 RL，DeepSeek 花 198 万，小米是它的 11.8 倍
- 对照表（⚠️ R1 / MiniMax 成本为二手转述，正文须标来源）：
  - 小米 MiMo-V2.6（Pro+Flash）$3,474,714 ≈ **2345 万元**
  - DeepSeek R1 RL 阶段 $294,000 ≈ **198 万元** → **11.8 倍**
  - MiniMax-M1 RL 阶段 $534,700 ≈ 361 万元
- ⚠️ 口径提醒必须写进正文：这些只是 **RL 阶段**成本，预训练成本小米未披露，不同厂商的 RL 任务难度也不完全可比——**别把它读成「谁更省」**。本文要回答的是「钱花在哪」，不是「谁家便宜」。
- 落点：11.8 倍的差额不是浪费，是**任务量级不同**——R1 主要在数学推理上做 RL，小米这轮铺了代码/通用/视觉/安全四个域。

### 4. 贵的那个反而更不划算
- DeepSWE v1.1 average@3 随累计成本变化（报告 Figure 3 左图，已读图）：
  - Pro：58.4 → **72.57**，花 $2.6M
  - Flash：48.7 → **65.68**，花 $0.9M
- ⚠️ **本节全部数字标注「按报告数据计算」**，非小米官方结论，也未见于任何媒体报道。
  - Pro：+14.17 分 / $2.6M = **5.45 分/百万美元**
  - Flash：+16.98 分 / $0.9M = **18.87 分/百万美元**
  - **Flash 性价比 = Pro 的 3.5 倍**
- 收口反问：读者看到 12.7% 会自然问「那是不是该多给评分器花钱？」——**数据说不是，钱花在 Pro 上才不划算**。
- 另一个可讲点（可选，看篇幅）：Pro 的曲线不是平滑上升，中间有明显回落（约 66 → 63 → 72.5 → 68 → 72.57），**最终分 partly 取决于你在哪一步停**。若篇幅紧则删。

### 5. 评分器为什么最穷
- 报告 §4.3 原文逻辑：二元测试奖励（跑单元测试）能判断「对不对」，但**区分不了「通过的解里哪个写得更好」**。
- 所以评分器只做一件事：在**已经通过测试**的解之间排序。
- 两种方法（人话）：
  - 离线造评分细则（先看多份答案，整理出一份「答题规范」，训练时照着打分）
  - 在线组内重分配（把确认是「钻空子」的奖励直接清零，剩下的正奖励往高质量解上挪）
- 🔗 **互链 09-14《机械臂蹭一下桶盖，成功率高10%：奖励函数才是AI钻空子的源头》**（`https://mp.weixin.qq.com/s/boIPBlmyX2ahoFYnEVLjxw`）——那篇讲评分器是脏活会被钻，这篇讲它为什么便宜，构成闭环。
- 补一条防钻空子的工程细节：小米这轮**冻结了 MoE 路由器**并建了多层防御（报告摘要）。术语首次出现必须带人话版。

### 6. 这 7k 个任务真有用吗
- 关键澄清（**必须写，否则像标题党**）：⚠️ 官方说 7,000 是**任务（tasks）**不是环境，环境是任务的载体；另加约 1k 音乐生成任务。
- 9B 模型三级跳（报告 Table 6，一手），从 Qwen3.5-9B 同一个 SFT 起点跑 GRPO：
  - Terminal Bench 2.1：27.0 → 37.1（SFT）→ **52.8**（RL），RL 增量 **+15.7**
  - MiMo Cyber：5.7 → 31.3 → **47.0**，RL 增量 **+15.7**
  - SWE-bench Verified：60.0 → 61.1 → **66.2**，RL 增量 +5.1
  - **RL 阶段 11/11 项全部提升**（报告原话）
- 落到「天花板效应」的洞察：SWE-bench Verified 只涨 5.1 分不是没用，是**这个公开榜已经接近饱和**；真正的新能力在没被刷过的内部集上（Cyber +15.7、Terminal Bench +15.7）。
- 反打 AI 质疑者：媒体曾报「9B 跑 RL 只涨 0.1 分」——**那是 SFT 的数字被当成了 RL 结果**，实际 11 项全涨。

### 7. 他们开源的其实不是模型
- 回扣开头：开头的问题是「敢公开账单」，答案是因为**真正值钱的东西不是权重**。
- 开源清单（报告摘要 + HF 仓库，一手）：约 7k 任务环境 + 带验证器的评分器 + 端到端 RL 训练框架（基于 verl / uni-agent / mini-swe-agent）+ 可组合的 mini-harness + MiMo-V2.6-Distill-Qwen-9B（MIT 许可）。
- 落点（硬收）：权重告诉你这次训练产出了什么；**环境告诉你下次怎么训**。半年后权重会过时，这套环境不会。
- 尾问候选（作者 30 秒可答）：你训练模型时，环境是自己搭还是直接抄开源的？
