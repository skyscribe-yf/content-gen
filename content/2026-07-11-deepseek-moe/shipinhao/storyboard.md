| # | 场景 | 动画要点 | 配音稿 |

| S1 | 开场钩子 | 代码助手两轮对话场景 → 两个问题（缓存 / MoE）→「30 倍不是通用结论」 | (breath) DeepSeek 便宜 30 倍，秘密到底藏在哪？用代码助手修报错，第一轮很重：系统提示词、仓库目录、团队规则、相关文件都要带进去。第二轮，你往往只补一句：还是失败，再查一下。这时两个问题同时出现：重复的仓库上下文，能不能不再重复收费？每个 token，能不能也不必让所有参数同时计算？前一个问题由缓存回答，后一个正是混合专家 MoE。但注意：便宜 30 倍不是通用结论，前提是输入、缓存命中和输出分开算。 |
| S2 | 价格账 | 4 模型价格表（卡片行）→ 真实 token 结构（99.5%/0.5% + 95%/5% 环形/条形）→ 成本公式 → 4 结果 grow_bar 对比（0.203/2.429/5.924/11.509）→ 29.2 倍 / 56.7 倍 counter | 先看账。2026 年 7 月核验的官方价格，每百万 token。DeepSeek-V4 Pro：普通输入 3 块，缓存命中只要 2 分 5，输出 6 块。GLM-5.2：8 块、2 块、28 块。GPT-5.6 Sol 和 Claude Fable 5 更贵，输出 204 和 340 块。但单价没用：每 1M 总 token 里，99.5% 是输入，0.5% 是输出；输入里 95% 命中缓存，只有 5% 是新写的。套进公式：DeepSeek 只要 2 毛钱，GLM 2 块 4，GPT 5 块 9，Claude 11 块 5。对 GPT 是 29.2 倍，约等于 30 倍；对最贵的 Claude 是 56.7 倍。价格账只是结果。接下来才问原因：为什么不必每次都为所有参数付计算费？ |
| S3 | 直觉：全科会诊 vs 分诊台 | 概念图（分诊台）→ 稠密 vs MoE 对比卡 → V3 数字（256 专家 / Top-8 / 1 共享）counter →「不是免费变大」爆点 | 传统的稠密模型，像一次全科会诊：一个 token 进入前馈网络，相关计算单元全都参与。混合专家 MoE 像分诊台：先看 token 的状态，再决定请哪些专家处理。不是每一份知识都要同时计算。注意，专家不是人工贴好的标签，是训练自然分工。DeepSeek-V3：256 个路由专家，每个 token 只选 8 个，另有 1 个共享专家。总容量可以很大，单次计算却不必跑完所有专家。所以 MoE 不是免费变大，而是只找最相关的人干活。 |
| S4 | 数学：打分→选人→合并 | 三步流程（打分/选人/合并）→ 组装公式 s=router(x)ᵢ、Top-k、y=Σwᵢ·Expertᵢ → 8/256=1/32 counter + 分数条 →「不是端到端快 32 倍」红叉边界 | 路由器怎么选人？三步：打分、选人、合并。设当前 token 的表示是 x，共有 N 个专家。路由器先为每个专家打分：s 等于 router 对 x 的输出。然后取分数最高的 k 个专家，叫 Top-k 路由。最后把选中专家的输出按权重合并，得到 y。如果 256 个专家只选 8 个，专家前馈要执行的计算，大致是全量的 8 除以 256，也就是 32 分之一。但注意边界：这不是端到端快 32 倍。所以只激活 8 个专家，能解释稀疏计算，却不能单独解释 API 价格。 |
| S5 | 负载均衡 | 分诊台排队比喻（概念图）→ 辅助损失（拥堵税）vs 偏置调节（导流）对比 →「解决的不是会不会回答」收尾 | 分诊还有第二个问题：如果所有病人都被送往同一科，那个科室排队，其他科室闲着。MoE 里这叫负载不均衡。早期做法是在训练目标里加辅助损失。但惩罚太强，干扰模型原本该学的任务；太弱，又压不住拥挤。DeepSeek-V3 用的是无辅助损失的负载均衡：系统给较忙或较闲的专家，调整选择时的偏置。可以把辅助损失想成收拥堵税，而偏置调节更像分诊台按排队长度导流。它解决的不是模型会不会回答，而是 token 能否稳定分散到不同 GPU 上。 |
| S6 | MoE 省的是哪一段 | Transformer 结构图（注意力 + FFN→专家集合）→ token 流经 router 到 8 个专家（脚本画图）→「不是 90% 参数没用」→ 通信瓶颈 | 那 MoE 省下来的，到底是哪一段？Transformer 里，注意力层负责让 token 看上下文；前馈网络 FFN，负责对每个 token 做更深的变换。MoE 通常把后者替换成专家集合。所以更准确的说法不是 90% 参数没有用，而是：在当前 token 的这一次前向计算中，大多数路由专家没有被调用。它们仍是模型容量的一部分，只是这次没被选中。专家越分散，通信越可能成为瓶颈。 |
| S7 | 回到价格：三层钥匙 | 三层卡片逐层展开（缓存复用 / 稀疏计算 / 系统工程）→ 完整公式组装 →「MoE 不负责全部故事」 | 现在把 30 倍拆开。第一层，缓存复用。95% 的缓存命中，让重复的仓库上下文变得很便宜。这是提示缓存的作用，不是 MoE 专属。第二层，稀疏计算。MoE 让专家前馈分支只运行必要专家。第三层，系统工程。把稀疏计算变成低账单，还要靠数值精度、通信、并行策略、批处理和服务调度。任何一环效率不足，省下的算力都会被等网络、等显存、等队列吃掉。所以更完整的公式是：低成本 API，等于缓存复用，加稀疏计算，加低精度计算，加高效通信与服务。MoE 负责谁干活，但不负责全部故事。 |
| S8 | 总结 + 尾卡 | 一句话总结（¥0.203 / 1/30 / 1/56.7）→ 下一篇预告（MLA）→ 互动问题 → 品牌尾卡（avatar + 关注 + 当期标题《DeepSeek便宜30倍的秘密：MoE混合专家入门》 + 查看公众号文章） | 一句话总结。按笔者真实写代码的 token 结构，DeepSeek-V4 Pro 每 1M 总 token 约 2 毛钱，约是 GPT-5.6 Sol 的 30 分之一，是本文最贵的 Claude Fable 5 的 56.7 分之一。下一篇，我们拆另一把钥匙：模型怎样用 MLA 减少 KV 缓存的显存压力？最后留个问题：你更愿意为更强的模型付高价，还是用足够强、但能反复调用的模型做日常开发？评论区聊聊。关注数解AI，我们下期见。 |
