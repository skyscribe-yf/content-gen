# 《多Token预测：一次猜两个词，快1.8倍》视频号分镜脚本

基于 content/2026-08-12-deepseek-mtp/weixin.md
规格：竖屏 1080×1920 · Manim 动画 · 精英男声 TTS 配音（speech-2.8-turbo，speed 1.0 pitch +2）+ 烧录字幕 · 目标 3-4 分钟

## 段落设计（6 段）

| # | 场景 | 动画要点（每页 1 个主视觉动效） | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子：一步一词的死结 | 概念图（接力赛）→ token 链逐个出现 → 问句爆点 | 大模型写一句话，是一个 token 一个 token 往外蹦的：猜出第 1 个，接在末尾，才能猜第 2 个。第 2 个永远在等第 1 个——GPU 算得再快，也被这个顺序锁死。能不能一次猜两个词？能。DeepSeek-V3 训练时顺手造了个小模块，叫 MTP。 |
| S2 | 训练时答案在手：teacher forcing + 侧头 | 侧头结构图（主干 + 拼接投影 + block）→ 两个交叉熵徽章 → 信号翻倍 | 训练的时候，情况完全不一样：语料里每个位置的真实词都是已知的。模型预测第 k+1 个词时，第 k 个词就明明白白写在训练数据里——这就是 teacher forcing，用真实词当条件。DeepSeek-V3 的 MTP 顺着这个思路：每个位置额外挂一个侧头，输入是主干表示加真实的下一个词的 embedding，输出预测下下一个词。一次前向，两个交叉熵，学习信号直接翻倍。 |
| S3 | 推理镜像：猜一串，验一串 | 草稿机流程（猜候选 → 主头验证）→ 接受率 85%-90% → 1.8 倍数字滚动 | 推理时没有真实词，第 2 个 token 还没生成，拿什么当条件？MTP 的答案：让侧头自己猜。这正好是投机解码的标准玩法：草稿阶段，侧头先猜出几个候选词；验证阶段，主模型一次前向，把这一串候选全部验证。哪个候选和主模型自己的想法一致，就收下；第一个不一致的地方，换成主模型自己的答案，重来。V3 报告实测：第二个 token 的接受率在 85% 到 90% 之间。算笔账：每步推进约 1.85 个词，侧头成本只占主头的 2% 到 3%，生成速度提升约 1.8 倍。 |
| S4 | 侧头从哪来：训练时白赚的信号 | 消融数字对比（BBH 39.0→41.4、HumanEval 20.7→26.8）→ 转折爆点 | 等等——这个侧头，本来就是为推理设计的吗？不是。MTP 的初衷是训练：一次前向两个交叉熵，等于每份数据给模型两次学习信号，训练信号更密，数据效率更高。消融实验也证明这不是白说：15.7B 的小模型，加上 MTP 后 BBH 从 39.0 涨到 41.4，HumanEval 从 20.7 涨到 26.8。而且推理时直接丢弃 MTP 模块，推理成本为零。训练时白赚信号，推理时白赚速度——这是 MTP 最妙的地方。 |
| S5 | 同题不同解：GLM-5.2 的激进版 | 保守 vs 激进对比卡 → 训练-推理不一致红叉 → IndexShare 流程 → 4.56→5.47 数字滚动 | 同样是 MTP，另一家国产模型走了完全不同的路线。DeepSeek 选保守方案：depth 等于 1，只多猜一个词。GLM-5.2 选激进方案：一次猜 5 个草稿 token。但多步草稿有个大坑——训练推理不一致：训练时第 2 步起的输入是真实词，推理时是侧头自己猜的词，模型从没见过这种输入分布。GLM-5.2 的解法是 IndexShare：多步草稿只在第一步跑索引，后续步骤复用第一步的 top-k 索引和 KV，训练和推理的条件分布终于一致。接受长度从 4.56 涨到 5.47，提升 20%。 |
| S6 | 接受率账 + 结尾预告 + 互动 | 三档接受率对比条（1.8×/1.4×/1.0×）→ 总结句 → 品牌尾卡 | 最后算一笔通用账：接受率 p 决定加速比。p 等于 0.85，每步推进 1.85 个词，加速约 1.8 倍；p 等于 0.5，加速约 1.4 倍；p 接近 0，草稿全被拒，加速比 1.0——白算，还倒贴草稿成本。所以投机解码的全部秘密就一句话：草稿猜得越准，加速越猛；猜不准，就是负优化。下一篇，单卡再快也有极限——V4 这种 1.6T 参数的模型，一块 GPU 连装都装不下，1000 块 GPU 怎么分活？一个问题留给你：如果让你设计，猜几个词最划算？评论区聊聊。关注数解AI。 |

## 爆点节奏（4 种轮换）

- S1 问句钩子：「能不能一次猜两个词？」+ 顺序锁死
- S2 数字对比（两个交叉熵、信号翻倍）
- S3 数字滚动（1.8 倍）+ 短句断句（猜一串，验一串）
- S4 转折爆点（不是为推理设计的——是训练白赚的）
- S5 转折爆点（激进 vs 保守）+ 数字（+20%）
- S6 总结 + 开放式问题（猜几个词最划算？）

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（精英男声 male-qn-jingying，speed 1.0 pitch +2）→ `tts_split.py` 切分 6 段
2. 概念图：`scripts/yairouter_img.py` 3 张 → `make_round_logo.py` 圆角
3. 动画：每段一个 Manim Scene（S1..S6），`at_clip` 挂 sentence-boundaries.json，`construct` 末尾 `pad_to_voice()`
4. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录 + 品牌尾卡
5. 封面：yairouter 1080×1920，标题文字强指令模板 + 读图验收
6. 归档：`content/2026-08-12-deepseek-mtp/shipinhao/`
