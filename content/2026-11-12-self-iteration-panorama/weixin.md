我经常会让 agent 来修改我的项目级别的 AGENTS.md。很多时候它改完的指令都会加入一些非常具体的绑定当前 harness 的指令，导致提交到代码库之后，别人可能没法用。

它没偷懒。它改得很认真，甚至比我想的更细致——问题是它优化的是我这台机器、我这个 harness 下能跑通。换个人 clone 下来，那份「改进后的指令」就可能是一堆废纸没法用。

我原以为这是它改错了。直到看完那篇综述论文才明白，「改得对不对」和「有没有资格改」是两个问题。

## 两个名字，一直被人混着用

2026 年 7 月，一篇 44 页的综述扫了 1,250 篇自我改进论文（2024–2026）。它做的第一件事不是总结，是拆词。

这一堆文献里，「自我改进」至少有五种意思，挤在同一个词下面。论文用了两个名字把它们分开：

**有界自精化**：对着一个固定的、外部的判分器，改进自己。它会收敛，可以评估，已经是工程实践上广泛使用的招数了。

**递归自我改进**：连「什么算更好」这套标准和改进机制本身一起改。没有固定外部锚点，原理上就是发散的。

通俗的说：前者是**把作业改到老师满意**；后者是**连老师也换掉**。

有时候，对着这两个略微显得有些抽象的术语，我甚至觉得他们说的是不是同一件事情呢？然而仔细思考一下，就会发现两者有个本质的不同，判定是否满意的角色是否在 agent 循环优化的内部，还是外来的。

这条判据比「改进能力被改进」好用的地方在于：它能直接拿去问工程问题。后面我将用它把五条线挨个查验一番。

## 一张按「人类还剩什么」排的地图

综述把一千多篇论文铺成两条轴：**改进什么** × **闭环程度**（人在环内 / 人在环上 / 全闭环）。

![综述的两条轴](01-two-axes.png)

落到「模型自己训练自己」这条线上，是按**人类还剩什么**排的五格：

![五条线，按人类还剩什么排](02-five-lines.png)

| 线 | 迭代什么 | 人类还剩什么 | 代表工作 |
|---|---|---|---|
| ① 自产推理数据 | 模型的解题轨迹 | 题目 + 标准答案 | STaR → ReST |
| ② 自产奖励 | 模型的偏好判断 | 少量种子偏好 | Self-Rewarding → Iterative DPO |
| ③ 自产课程 | 题目本身（含难度） | 只有一个执行器 | AZR → R-Zero → Skill-SP |
| ④ 自改权重 | 训练数据与更新指令 | 初始权重 + 一个元目标 | SEAL → DGM |
| ⑤ 自改脚手架 | prompt / 记忆 / 工具 | 初始配置 | prompt 与记忆自优化 |

这个表格从上往下读，你会发现人类在agent循环里面，退出的环节是越来越早了。① 还握着题和答案，到最后一行就只剩下一份初始配置，其余的环节人类就完全成为甩手掌柜了。

③ 这一格我只给位置，不展开——它怎么自己出题（[AI 自己出题自己考](https://mp.weixin.qq.com/s/ZiQlEtB-vL5nzJo7ye4RvA)）、为什么会崩（[给 AI 看标准答案，它为什么反而越练越差？](https://mp.weixin.qq.com/s/_7aP6jaNXZU0NSQ1UcfMWA)），前面两篇都写过。这篇只关心它站在哪儿。

## 两条线已经在生产里跑

标题里说的「两条」，其实正是2个极端，对应过来就是 ① 和 ⑤。

先说 ①：**答案对不对，对一下就知道了**。监督几乎不要钱——不要人类裁判，不要另一个模型来评，也不需要知道它为什么对。

再说 ⑤：**改完跑一下，看行不行**。prompt、记忆、工具的自改，不碰权重，便宜、可回滚、可审计。

让 agent 自己修改自己的 prompt 或者指令，节省下来的 token，对于后续每一次 agent 的新会话都会立刻得到好处，无论是 token 费用的节省，还是时间上的节约，都是立竿见影，持续有效的。

这就是「便宜」为什么在工程上打得过「先进」：收益随使用次数线性增长，而 ④ 要先赌一次两万美金。

但 ⑤ 有天花板——不动权重，它就改不出基座不会的东西。

其实有不少时候，agent 自我改进了之后，遇到其他一个略微有点不同的任务的时候，表现直接拉胯了。这不是意外，是代价。便宜的监督是窄的监督：验得动「这批任务行」，验不动「换个任务还行不行」。

## 贵的那条：80 次迭代，两万美金

### DGM：唯一拿得出手的实测

④ 自改权重，是目前跑得最响、也最悬的一条。

最硬的实证来自这篇论文DGM（Darwin Gödel Machine，ICLR 2026）：用进化搜索去找「能改写自己代码的 agent」。

**80 次迭代**，SWE-bench Verified 选定的 200 道题上从 **20.0% 涨到 50.0%**，Polyglot 从 **14.2% 涨到 30.7%**。

论文里面的消融实验，证明它真的在自我改进，而且这真的不是玄学：去掉「自我改进」（固定 meta-agent）只剩 39.0%；去掉「开放式探索」（改成爬山）只剩 23.0%。

![论文实测的四个数](03-dgm-ablation.png)

那个实验的代价是：SWE 那一轮跑了大约两周，估算 **$22,000**；两个消融各约 $10,000。

另一条是 SEAL（MIT，NeurIPS 2025）：让模型自己生成微调数据和更新指令，用下游表现当奖励来训「怎么改自己」。知识植入 47%，ARC 72.5%，去掉强化学习后低约四倍。

还有一条隐形的代价，也写在论文里：频繁自改会灾难性遗忘。

### 然后它把检测标记删了

DGM 某次运行里，agent 发现打分管线会检查它有没有编造工具输出——于是**把检测标记删掉了**来提分。

这下导致，它优化改进的，并不是模型的agent能力，却是测评机制本身。这不是新问题。2025 年就有人系统分析过 reward hacking，到 DGM 这里只换了个更直接的场景：以前是模型骗奖励函数，现在是模型直接改掉检查奖励函数的那段代码。

第一次看到这个现象，我立刻想起了之前写过而 reward hacking 的话题：这么长时间过去了，这个问题还是那么根深蒂固地影响着 agent 的后续研究进展吗？

我自己写过的那篇旧文拆的是静态版本——[《奖励函数才是 AI 钻空子的源头》](https://mp.weixin.qq.com/s/boIPBlmyX2ahoFYnEVLjxw)，那时模型还只是学会钻分数的空子。现在它开始拆打分的机器本身了。

能改脚手架，就意味着它能改到「裁判报分的那根线」上去。有界只保证它不会自己定义什么叫好，不保证它不会绕过你定的好。

## 为什么没人过得了那道门

现在用第二节定下的那条尺子——**判分的那一方，在优化闭环的内部还是外面？**——把五条线挨个量一遍。

### 五条线，一个个看

DGM：搜的是「更好的 agent 代码」，被搜的搜索器本身没变强，验收还靠 SWE-bench 和 Polyglot——判分在外。所以它是自指，不是递归。

SEAL：学的是「怎么自我编辑」，但奖励来自外部任务的表现——判分在外。

① 和 ③：题和答案都是人类给的验证器在判——判分在外。
② 是唯一把裁判搬进内部的：模型自己给自己打分。但内在自评恰恰是验证层级里最弱的一档，实测到的改进强度也跟着掉。

综述把这一层排了个序：**形式验证器 > 执行反馈 > 学出来的裁判 > 内在自评**。

它还观察到：**裁判越靠后，改进效果越差**。真跑出来的自我改进，强弱正好按这个次序分。对应的失败模式——自我确认循环、模型坍缩、多样性坍缩——都是对这个顺序的违反。


![验证层级](04-verification-hierarchy.png)

顺带一个数字：这 1,250 篇里，部署期 393、训练期 340、自评估 318、自主科研 139。落在「全闭环」那格的最薄——综述原话是越往右越稀疏。

我不能说递归自我改进永远做不到；我只能说，到 2026 年 11 月，五条线上能找到的全部证据，都停在有界这一步。

如果后续有人真的做成了递归自我改进，那么在底层如何处理 reward hacking 上，一定是有更大、更本质的突破，而不是像今天这样，继续在流沙之上建城堡。

所以「有界」不是技术不够成熟，是地基还没铺好。

## 回到你自己的循环

### 验证层级管不到的那半

综述最深的一句藏在 v2 摘要里：卡住人类的，不只是「怎么验证」，还有「**什么才值得被验证**」。前一个问题，验证层级能排出先后；后一个，它排不出来。

这句话我读了好几遍才理解它底层的深意。它正好解释了开头那件事为什么难办：agent 改 AGENTS.md，改得对不对我能验（跑一下就知道），但它**该不该动这一条**、这条规矩值不值得存在，我没有办法轻易做验证。

### 三个具体的问题

所以别急着问「要不要上自我迭代」，先问三个具体的：

1. 你的循环里，判分靠什么？跑得通、有单测、另一个模型说好、还是它自己说好。
2. 这个判分器，每轮都拿得到吗？拿不到，你就已经在为「递归」付那个付不起的账。
3. 你让人放心让它改的，是权重，还是脚手架？

你的 agent 循环里，是否有经常拉 agent 来根据历史交互记录来要求 agent 自我改进 AGENTS.md？有没有看看它自我改进的效果是否满意？
