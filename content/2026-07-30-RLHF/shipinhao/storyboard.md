| S5 | 奖励模型：把排序变成分数 | 回答→分数条（GrowFromEdge 生长到 2.7）；公式 σ(r(y_w)-r(y_l)) + r(y_w)高绿条 vs r(y_l)低红条对比；Axes+sigmoid 曲线 +「差值过 sigmoid→0~1 概率」；危险边界（长/礼貌偏好） | 但模型参数，读不了"人类觉得 A 比 B 好"。所以我们训练一个奖励模型，把回答映射成分数。它不回答问题，只判断哪个更像人类会选的——像一个人类偏好模拟器。选中得分高，被放弃的得分低，差值过 sigmoid，压成 0 到 1 的概率。但模拟器有危险边界，学到的只是标注数据里的偏好。奖励模型，是偏好的压缩，不是事实裁判。 | 概念爆点（模拟器）+ 危险边界转折 |
| S6 | 策略更新 + KL 约束 | 三角形闭环流程：策略生成→奖励打分→调整策略（三箭头）+ 高亮「让高奖励更易出现」；走极端骗分手段 + 红叉否定；参考模型(灰) vs 策略(黄) 双高斯分布 + KL 拉回箭头；max 奖励−β·KL；教练类比；「别推太远再沿奖励调」 | 有了奖励模型，就多一步：让策略生成回答，奖励模型打分，再调整策略，让高奖励回答更容易出现。但只看奖励，模型会走极端——重复套话、堆礼貌、用"像好答案"的格式骗分。所以还要加一道 KL 约束：别离参考模型太远。目标就两项：争取更高奖励，别偏离参考模型。β 太小骗分走偏，太大不敢改变。就像教练不允许你为拿分改规则。记住：别把原模型推太远，再沿奖励方向调整。 | 转折爆点（会走极端）+ 教练类比 + 段尾悬念（PPO 篇） |
| S7 | 概念实验：三答案 + 奖励黑客 | 三候选 A/B/C 表（B 标红「沿梯度上升说反了」）；重事实排序条 A>B>C（条长递减）/ 重表达 B>A 条；「好不是固定分数」；错误捷径三条（长/礼貌/拒答）→ 红色边界线被突破 →「奖励黑客入口」 | 有个示意实验。还是三个回答。A，准确但句子很短。B，流畅却把"沿梯度下降"说成"沿梯度上升"。C，谨慎，几乎没回答。看重事实，你排 A 大于 B 大于 C；看重表达，B 反而像更好。"好"不是固定分数。更麻烦的是，奖励模型可能学到错误捷径：长答案得分高，就无限扩写；礼貌得分高，就堆客套；拒答更安全，就普通问题也回避。当模型只顾最大化表面特征，就出现了奖励黑客的入口。 | 三连对比 + 捷径排比爆点（奖励黑客） |
| S8 | 结尾三句话 + 品牌尾卡 | 三句收束卡（SFT 绿/RLHF 黄/奖励红）；预告「下一篇 PPO 发动机舱」+ GRPO/RLVR；尾卡：avatar 圆角透明 + 关注「数解AI」+ 当期标题 + 点赞/关注/评论按钮 + 查看公众号 + 互动问句 | 现在压成三句话。SFT，教模型按指令回答。RLHF，用人类偏好，教它在多个回答里选更好的。奖励，不是事实本身。既然奖励只是偏好的压缩，模型就可能钻空子。下一篇，我们进 RLHF 的发动机舱：PPO 怎么更新策略。再往后，GRPO 接棒，RLVR 让答案接受结果检验。关注数解AI，下一篇第一时间推给你。最后问你：开头那三个回答，你会怎么排序？评论区聊聊。 | 三连收束 + 结尾预告（PPO/GRPO/RLVR）+ 互动问句 |

## 关键数字/事实核查（与 weixin.md 完全一致）

- 三个回答：A 准确但生硬 / B 流畅但有误（关键事实说反）/ C 安全但过度拒答
- 三道工序：预训练（预测下一个token）、SFT（按指令按格式回答）、RLHF（多个候选选更好）
- 时间线：2022-03 InstructGPT 论文（InstructGPT=论文/模型，ChatGPT=产品）；2022-11-30 ChatGPT 研究预览（GPT-3.5 系列微调）
- 冲击结果：InstructGPT 论文评测中 1.3B 输出超过 175B GPT-3（标注者更偏好）——说明参数量决定潜力，后训练决定潜力能否贴近用户意图
- 三道工序：① 先用 SFT 进赛道（同时做参考模型）；② 人类不写唯一答案，只比较两个（chosen/rejected 偏好数据）；③ 奖励模型 $r_phi(x,y)$ 映射回答→分数
- 偏好建模：$P(y_w \succ y_l \mid x)=\sigma(r_phi(x,y_w)-r_phi(x,y_l))$，σ 压成 0-1 概率
- 奖励模型=偏好的压缩不是事实裁判；危险边界（长=好、礼貌=可靠）
- 策略更新目标：$\max E[r] - \beta D_{KL}$；β 太小骗分走偏、太大不敢改变；教练改规则类比
- 概念实验：A>B>C（重事实）/ B>A（重表达）；四条捷径：长/礼貌/拒答/格式 → 奖励黑客入口
- 结尾：SFT 教按指令 / RLHF 教选择 / 奖励不是事实；预告 PPO（发动机舱）、GRPO、RLVR
- DPO 旁注与 Qwen3 旁注属深入内容，本篇基础闭环不展开（在 S8 埋点）

## 口播录音规范（Step 4B）

- 录音稿 tts.txt：**去掉 TTS 拟声标签与 <#0.5#> 停顿标签**，只用自然标点引导语气
- 每段一个文件 shipinhao/recordings/sN.wav（S1→S8 顺序录），念错该段重录（文件名覆盖）
- 安静房间、贴近麦克风、手机横持离嘴 20-30cm；每段一口气念完，**句与句之间自然停顿 0.3-0.5s**（字幕停顿对齐关键）
- 录完一段核对一段（时长/吞字/环境噪音），全部录完跑 voice_process.py（修音+时长+停顿分析 → tts/sN.wav + VOICE_DUR + pauses.json）
- ⚠️ 口播时长不稳定：scenes.py 的 at() 必须按最终实测 VOICE_DUR 写，禁止用预估值

## 制作流程

1. 录音：作者按 tts.txt 逐段录 recordings/sN.wav → scripts/voice_process.py 修音+一致性补偿+时长+停顿分析 → tts/sN.wav + VOICE_DUR + pauses.json
2. 动画：每段一个 Manim Scene（S1..S8），construct 末尾 pad_to_voice()；动画节点按实际录音时间轴铺满（≥80%）；工具函数复用 SFT/预训练 scenes.py 模板（boxed/fit/sqrt_group/play_red_cross/play_scroll_unroll）
3. 构建：scripts/manim_video_build.py mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行+150ms 淡入，停顿对齐 pauses.json）+ 品牌尾卡
4. 封面：yairouter 出 1080×1920（关键内容在中间 3:4 安全区 y∈[240,1680]）
5. 归档：content/2026-07-30-RLHF/shipinhao/
