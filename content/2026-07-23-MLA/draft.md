## 你的 GPU 显存，其实被一个你不知道的东西吃掉了

如果你用 RTX 4090（24GB 显存）跑过大模型，一定遇到过这个情况：模型权重刚加载完，显存已经吃了 18GB。你想跑个 8K 上下文，直接 OOM。

你以为是"模型太大"。

**但真正的显存黑洞不是模型权重，而是另一个东西——KV cache。**

> 模型权重是"煤矿"——一次性挖出来就不动了。
> KV cache 是"货车"——实时往返，越积越多，最后把整个矿区挤爆。

先看一组真实数字，你就会知道我在说什么：

| 组件 | LLaMA-3-70B（100K 上下文） | 占显存比例 |
|------|--------------------------|------------|
| 模型权重（bf16） | ~140GB | 81% |
| **KV cache** | **~31GB** | **18%** |
| 其他（临时张量等） | ~2GB | 1% |

LLaMA-3-70B 用了 GQA（8 KV 头），所以 KV cache 没权重多。但注意——**31GB 只是 GQA 压缩后的结果。** 如果换用 MHA 架构（如 LLaMA-3.1-405B 用 128 KV 头），KV cache 就会反超：516KB/token × 100K = ~49GB。

更关键的是：**KV cache 的增速是线性的——上下文翻倍，它翻倍。到 128K 时直接冲到 63GB。** 而模型权重不会随上下文增长。

## KV cache 是什么？为什么它这么大？

在[《注意力机制是什么？》](④链接)那篇我们讲过，每个 token 会生成 Q、K、V 三个向量，通过 Q·K 点积算注意力分数，再加权汇总 V。计算本身不复杂，问题在**规模**。

生成第 t 个 token 时，你需要和前面 t−1 个 token 全部算内积。这意味着**前面所有 token 的 K、V 必须全部存在显存里**，供当前 token 使用——这就是 **KV cache**。

每生成一个 token，KV cache 就多一条记录。上下文越长，KV cache 越厚，显存越紧张。

> 32K 上下文时，LLaMA-3-70B 的 KV cache 就有 10GB——相当于一块 RTX 4090 的一半显存。冲到 128K？40GB。模型权重没变，但 KV cache 线性增长，永不停止。

直观类比一下：

> 想象你在墙上贴便利贴记录会议内容。每说一句话贴一张。4 小时的会议，墙上贴了 3000 张。回顾第 1 句话？翻 3000 张。墙上再也贴不下了？墙塌了。
>
> 这就是 KV cache 的问题：**便利贴越来越多，墙就这么大。**

在[《为什么 AI 上下文越长越慢？》](https://mp.weixin.qq.com/s/PLVRS0TTHXHDve1Z3r6M7Q)那篇我们讲过，上下文长度是推理的硬墙。**KV cache 就是那堵墙的砖。**

## 能不能把便利贴写小一点？

自然你会想：让每张便利贴少占点地方不就行了？

还真有——**GQA（Grouped-Query Attention）**就是这个思路。Qwen3-8B 把 KV 头数从 32 减到 8，KV cache 体积降到 1/4。这在④里已经讲过了。

**但 GQA 的压缩率有天花板**——头数不可能减到 0。也就是说，即便只剩 1 个头，每个 token 的 KV 向量还是 d_h（128）维。128 维 × 128 层，每个 token 要存 2 × 128 × 128 = 32,768 个数字。

DeepSeek 换了一个全新思路：

> GQA 是"少请几个秘书"——减少 KV 头数。
> MLA 是"让秘书写摘要"——不记全文，只记要点。

---

## MLA 的数学魔术：三步压缩 32 倍

MLA（Multi-head Latent Attention）的思路出人意料地优雅：**不直接存 K，而是存一个"压缩摘要"c^KV，推理时再用数学等价变换变回来。**

它的核心只需要三步：

### 第一步：低秩投影——把 K 压成 c^KV

传统做法是：对每个 token 的隐状态 h，用 W^K 投影成完整的 K 向量（128 维）。

MLA 反过来：**先把 h 投影到一个很低的维度 d_c（V3 中是 512）**，得到压缩 latent c_t^KV：

> **c_t^KV = W^DK · h_t**

c_t^KV 就是一个"摘要"——512 维，相比完整 K 的 16,384 维（128 头 × 128 维），只有 1/32。

那推理时怎么用这个摘要？答案是——**不需要解压**。

### 第二步：矩阵吸收——把解压藏进 Q 里

完整 K 本来由 K = W^UK · c^KV 解压得到。那 attention score = Q · K^T 就可以改写为：

> **score = Q · (W^UK · c^KV)^T = (Q · W^UK) · (c^KV)^T**

妙处出现了：**不需要存完整的 K**，推理时只要存 c^KV，然后把 W^UK "吸收"进 Q 里，数学上完全等价。

```
# 矩阵吸收前：存完整 K 向量
K_full = W_K @ h                # 128头 × 128维 = 16,384维
score = Q @ K_full.T            # 注意力分数

# 矩阵吸收后：只存压缩 latent c^KV
c_kv = W_DK @ h                 # 512维（压缩32倍）
score = (Q @ W_UK) @ c_kv.T     # 数学上完全等价
```

**省 32 倍显存，不多算一次矩阵乘法。**

### 第三步：Decoupled RoPE——"位置"和"内容"走两步

还有一个坑：K 不只是内容，它还带**位置编码**（RoPE）——旋转位置编码告诉模型"这个词在第几个位置"。

问题来了：RoPE 是一个乘法操作。如果先压缩 c^KV 再算 RoPE，RoPE 会污染压缩维度，压缩就失效了。如果先算 RoPE 再压缩，位置信息就被压没了。

DeepSeek 的解法是：**把 Q 和 K 各拆成两路——**

- **内容路**：走低秩压缩 → 产出 c^KV（存进 cache）
- **位置路**：单独加 RoPE → 独立编码位置信息

两路并行，互不干扰。这就是"Decoupled RoPE"——解耦位置编码。

---

## 压缩 32 倍还不掉质量？为什么？

你肯定会问：**从 516 KB 压到 70 KB，信息不会丢吗？**

答案是——**注意力只关心点积，不关心向量本身。**

JL 引理告诉我们：保留 N 个向量之间的点积（注意力分数），所需的维度远低于原始维度。而 V3 的 W^DK 和 W^UK 是**学习出来的**，不是随机投影。数据显示学习的投影比随机投影好 4 倍——模型自己学会了哪些信息必须保留。

## 实测：MLA 和同类模型比，差多少？

DeepSeek-V3 论文给了直接的对比数据（每个 token 的 KV cache 占用）：

| 模型 | 注意力机制 | KV cache / token | 100K 上下文 |
|------|-----------|-----------------|------------|
| LLaMA-3.1-405B | GQA（128头） | 516 KB | ~49 GB |
| Qwen-2.5-72B | GQA（8头） | 328 KB | ~31 GB |
| **DeepSeek-V3** | **MLA** | **70 KB** | **~6.7 GB** |

> 数据来源：DeepSeek-V3 论文 Table 1（BF16 精度）

MLA 每 token 只占 70 KB——LLaMA-405B 的 1/7，Qwen-72B 的 1/5。

这差异从哪来？LLaMA-405B 用了 128 个 KV 头（每头 128 维），Qwen-72B 用了 8 个——这都是完整向量。MLA 把这些全部压进一个 512 维的 latent + 64 维 RoPE，直接跳过了"多头 × 全维度"的存储方式。

32K 上下文时：LLaMA-405B 吃掉 15.7 GB，MLA 只要 2.1 GB。**同样的 GPU，MLA 能跑更长的上下文——或者在同等上下文下，Batch Size 翻几倍。**

那精度呢？同等显存预算下，MLA 在 LongBench 长文本任务上的得分和 MHA 持平。**省显存不丢信息——因为注意力本来只需要点积，不需要完整向量。**

## 回到主线

MLA 省的不是参数，是推理时每一层都要存的历史记录。

> **从 516 KB 压到 70 KB——LLaMA-405B 七分之一的存储，同等精度。**

这是怎么做到的？矩阵吸收让"存摘要"和"存全文"在数学上等价，Decoupled RoPE 让位置信息和内容各走各的路。**不是暴力删信息，而是优雅地重新排列。**

但 MLA 有一个它自己解决不了的问题——它只能压缩，不能跳过。100 万 token 的上下文，即使压缩到 70 KB/token，KV cache 仍然需要存**全部** token 的记录。V4 的答案不是"压缩"，而是"选择"——只计算真正相关的 token。

> **存得下 ≠ 找得到。** 这就是 V4 抛弃 MLA 的原因，我们 D4 讲。
