# 《上下文并行：1M序列为什么切了会坏？》视频号分镜脚本

基于 content/2026-08-14-deepseek-cp/weixin.md
规格：竖屏 1080×1920 · Manim 动画 · MiMo 克隆音色配音 + 烧录字幕 · 目标 2-3 分钟

## 段落设计（8 段）

| # | 场景 | 动画要点 | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子 | 1M 长条序列切成 8 段给 8 张 GPU（切蛋糕隐喻）→「一切就坏」 | 上下文并行，把 1M token 的序列切成 8 段，分给 8 张 GPU。听起来像切蛋糕——切 8 块，每人一块，有什么难的？DeepSeek-V4 技术报告的回答是：一切就坏。 |
| S2 | 显存账 | 3.5TB 激活 vs 80GB H800，44 倍差距；Flash Attention 只压分数矩阵 | 先看为什么要切。1M 序列，单层注意力留住 Q、K、V 要大约 57GB；V4 有 61 层，激活总量约 3.5TB。一块 H800 只有 80GB，差了 44 倍。Flash Attention 只压分数矩阵，Q、K、V 一分没少。所以 CP 不是优化，是必须。 |
| S3 | 普通 CP 两个假设 | 序列切段 → 两个隐含假设逐条亮起 → Ring-Attention 击鼓传花 → 双双打破 | 普通 CP 的切法很朴素：每张卡持有一段连续 token，各算各的注意力。它成立，靠两个隐含假设：本地 token 和 KV 大致一一对应；跨段边界补一补就好。Ring-Attention 就是把 KV 块击鼓传花一样轮流传着算。但 V4 的压缩注意力，把这两个假设同时打破了。 |
| S4 | 坏因 1：长度不齐 | packed 两条序列（1000+7 token），m=4 独立压缩，尾部残块丢弃；8 rank 产出数量不等 | 坏因一：压缩后 KV 长度不齐。样本是多个序列打包的，每个序列按自己的边界独立压缩，尾部不足的 token 直接丢弃。每个 rank 分到的边界位置不一样，有的全是完整块，有的段尾正好是残块。每张卡产出的压缩 KV 数量彼此不等，all-gather 第一步就卡住。 |
| S5 | 坏因 2：窗口跨边界 | m=4 个 token 的压缩块横跨 rank 分界线 → 两边都只有半块；照片 4 张一组的相册比喻 | 坏因二：压缩窗口跨边界。压缩要 m 个连续的 KV entry，如果恰好有 m 个 token 横跨两张卡的分界线，左边只有前半块，右边只有后半块，任何一边都压不出来。就像照片 4 张一组，相册切给两个人，边界切在两张照片中间，谁都没拿到完整的一组。 |
| S6 | 阶段 1：边界原料交换 | rank r 末尾 m 个 KV 箭头传给 r+1，右邻居拼完整块再压；「传原料不传半成品」；KB 级通信量 | V4 的修法很直接：每个 rank 把自己末尾最后 m 个未压缩的 KV 发给右邻居，右邻居拼成完整块，在本地压出来。注意传的是原料，不是半成品——跨边界块在左边压不出合法输出。这一步通信量与序列长度无关，CSA 层只要约 2KB，几乎可以忽略。 |
| S7 | 阶段 2：all-gather + select-and-pad | pad 到统一上界 → gather blob 有洞 → select-and-pad 三步合一；C0/C1/C2/C3 例子 | 边界块补齐了，长度不齐还在。all-gather 要求形状整齐，V4 的办法：每张卡先把产出 pad 到统一上界，再 all-gather。但 gather 出来的数据里有洞，padding 会污染注意力。所以最后一步 select-and-pad：去 padding、尾对齐、稀疏重排，合并成一个 kernel，把 padding 全部滤掉。 |
| S8 | 账 + 实验 + 尾卡 | 9MB vs 72MB 条形对比；模拟器 277/276/277；总结句；品牌尾卡（avatar + 关注引导 + 当期文章标题《上下文并行：1M序列为什么切了会坏？》 + 查看公众号文章引导 + 下一篇预告） | 算笔账：压缩后每层平均约 9MB 通信，在 NVLink 上只要 0.02 毫秒；不压缩直接 gather，是 72MB，省约 8 倍。模拟器跑出来：朴素 CP 缺了跨边界的压缩块，两阶段 CP 与单卡基准完全一致。注意力公式变了，并行策略不能原封不动。关注数解AI，下一篇拆 DualPipe 和 DeepEP。 |

## 制作流程

1. 配音：`scripts/xiaomi_mimo_tts.py` 逐段生成 S1-S8（克隆音色 `branding/my-voice.wav`），ffprobe 记录各段真实时长
2. 动画：每段一个 Manim Scene（S1..S8），`construct` 末尾 `pad_to_voice()` 补齐
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录 + 品牌尾卡
4. 归档：`content/2026-08-14-deepseek-cp/shipinhao/`
