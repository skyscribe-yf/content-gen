# 《DeepEP：训练时GPU的空等怎么藏起来》视频号分镜脚本

## 段落设计（6 段）

| # | 场景 | 动画要点（每页 1 个主视觉动效） | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子：20 万 GPU 在等 | 概念图（食堂打饭排队）→ 利用率 60% 数字滚动 → 两处等待卡片（等上游/等网络） | 你花二十万买一块 H800，训练大模型的时候，它真正在算的时间有多少？盯训练日志，GPU 利用率只有六成多。模型没错——它是在等。等两样：等上游的数据传下来，等网络上 token 的 all-to-all 传完。两处空等，就是训练系统里最贵的浪费。 |
| S2 | 等待 1：气泡 + DualPipe | 流水线工件图（气泡红叉）→ 气泡公式 → 双向调度示意 → 气泡减半对比条 | 第一处空等，叫气泡。流水线并行里，micro-batch 像流水线上的工件，一个接一个灌进去。工件还没到，工位先空着。1F1B 调度下，PP 等于 16 时，气泡相当于 15 个前向加反向块的时间——一大块纯浪费。V3 的 DualPipe 怎么填？两个动作：从管道两端同时灌入，再把每个 chunk 拆成四段，计算和通信交错执行。气泡直接减半以上。代价是两份参数拷贝，但 EP 规模大时，每张卡只持有一小份参数，不贵。V4 还在用 DualPipe。 |
| S3 | 等待 2：all-to-all + DeepEP 三件真货 | 16GB 通信条 vs 带宽对比 → 三件真货卡片逐张拉幕 → 概念图（通信藏在计算阴影里） | 第二处空等，更狠：all-to-all。MoE 层里，每个 token 要发给持有对应专家的 GPU，算完再收回来。每层要传约 16GB，跨节点的 InfiniBand 带宽只有 NVLink 的约十八分之一。DeepSeek 开源的 DeepEP，就是干这个的。三件真货。第一，专用内核：dispatch 形状固定，专用内核把通用性省下的开销全换成带宽，FP8 dispatch 直接把带宽砍半。第二，异步重叠：通信放到独立流上，算完的 token 先算，不用等整批就绪。像食堂窗口，菜齐一碟端一碟。第三，极低 SM 占用：通信主要等网络，不抢算力，SM 占用从 24 个降到 4 到 6 个。三件真货合起来：all-to-all 从排队等待，变成藏在计算阴影里。 |
| S4 | 数学判据：6144 FLOPs/Byte | C/B 不等式组装 → 天平（NVLink 藏得满 ✓ / IB 藏不满 ✗）→ 2200 vs 39600 对比条 | 那通信藏在计算后面，什么时候藏得满？V4 报告给了一行漂亮的公式。记 C 为峰值算力，B 为互连带宽，通信能完全藏住，当且仅当 C 除以 B，小于等于 Vcomp 除以 Vcomm。V4 Pro 里，每个 token 专家对要算 6hd 个 FLOPs，通信只要 3h 个字节。一比，等于 2d，也就是 6144，单位是 FLOPs 每字节。代入 H800：节点内 NVLink，C 除以 B 约 2200，小于 6144，藏得满。跨节点 IB，约 39600，大于 6144，藏不满。差一个数量级。 |
| S5 | MegaMoE：wave 粒度摊平 | wave 流水示意（三波）→ 摊平箭头 → 加速倍数 1.92/1.73/1.96 数字滚动 → 转折（报告没提 DeepEP） | 藏不满，就摊平。V4 把 dispatch、专家计算、combine 融进一个 mega-kernel，专家切成 wave。第一波专家在算的时候，第二波的数据已经在路上，第三波待发。通信和计算在 wave 边界上无缝重叠——藏，一路藏到了 kernel 内部。把一整批 wave 的计算量摊给一次通信，有效比值就被抬过 6144 的门槛。wave 越深，摊得越平。理论加速 1.92 倍，实测 1.5 到 1.73 倍；RL 这种长尾小 batch 场景反而最吃这套，实测 1.96 倍。实现开源在 DeepGEMM 里，叫 MegaMoE2。V4 报告一次都没提 DeepEP？不是不用了——是进化了。 |
| S6 | 结尾：三粒度的藏 + 互动 + 尾卡 | 三粒度卡片（stage/层内/wave）→ 6144 不等式重现 → 互动问题 → 品牌尾卡（avatar + 关注 + 当期标题 + 查看公众号文章） | 回到开头：二十万的 GPU 为什么空等？两处等待：等上游，等网络。三个粒度的藏：DualPipe 在 stage 之间藏，DeepEP 在层内藏，MegaMoE 在 wave 内藏。藏到最后，判据是一行不等式——6144 FLOPs 每字节。一个问题留给你：NVLink 藏得满，IB 藏不满。如果让你设计训练系统，你会把通信往节点内搬，还是升级更宽的互连？评论区聊聊你的取舍。关注数解AI，训练系统系列收官。 |

## 制作流程

1. 配音：`minimax_tts.py --clone-audio branding/my-voice-denoised.wav` 整段生成 → `tts_split.py` 切 6 段 → `tts_sb_create.py` 生成 sentence-boundaries
2. 动画：每段一个 Manim Scene（S1..S6），`at_clip()` 挂字幕时间线，`pad_to_voice()` 兜底
3. 构建：`manim_video_build.py` mux 配音 + 拼接 + 黄色字幕烧录 + 品牌尾卡
4. 归档：`content/2026-08-15-deepseek-dualpipe-deepep/shipinhao/`
