## 段落设计（6 段）

| # | 场景 | 动画要点 | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子：K 是索引、V 是正文 | 概念图「图书索引卡 vs 正文页」；K 卡（靶子/匹配/要位置）vs V 卡（内容/取出/要干净）；K=V 反直觉问句 | K 是索引，V 是正文——两份职责，凭什么共用一份缓存？标准注意力里，K 负责匹配，必须知道位置；V 负责取出，内容必须干净。可 DeepSeek-V4 偏偏让同一个向量，又当 K 又当 V。这不串味吗？答案，藏在两个机制里。 |
| S2 | 双流重叠压缩：一份 entry 诞生 | 两条 KV 流（a 流当前块 / b 流前一块）→ 每 4 个 token 合并成一个压缩 entry（脚本画图：两流汇一）；「不再拆 K 和 V」爆点卡；128 头共享 + head_dim 512 数字卡；冲突 → 按维度分工 | 先看这份 entry 怎么诞生。CSA 用两组投影，生成两条 KV 流：a 流管当前块，b 流管前一个块。每 4 个 token，按权重合并成一个压缩 entry。关键一步来了：压缩后的 entry，不再拆成 K 和 V——同一个向量，直接同时充当二者。V4-Pro 的 128 个 query 头，共享同一份压缩 KV，维度是 512。可这里有个真冲突：同一个向量，既要被匹配，又要被取出。怎么破？按维度分工。 |
| S3 | Partial RoPE：只转最后 64 维 | 512 维向量条（脚本画图）：最后 64 维金色高亮「位置」，448 维青色「内容」；BF16/FP8 混合存储卡（64 维 BF16 / 448 维 FP8 → 体积近乎减半）；悬念问句 | V4 的解法，是把位置锁进最后 64 维。512 个维度里，64 维负责「我在哪个位置」，剩下 448 维，保留「我是什么内容」。位置和内容，在维度上物理分离。这个设计还有直接收益：既然只有 64 维需要精确位置，KV 就能混合存储——64 维用 BF16，448 维用 FP8。缓存体积，比纯 BF16 近乎减半。可问题来了：这个向量还当 value 用，带着旋转被加权求和，位置信息不就渗进输出了吗？ |
| S4 | de-RoPE：输出端解旋 | 旋转箭头（Rj 带绝对位置）→ 加权求和 → 输出混入绝对位置（脚本画图：箭头旋转）；R₋ᵢRⱼ=Rⱼ₋ᵢ 公式；「解旋不是去位置」爆点；概念图「齿轮回旋」 | 所以输出端，还要再解一次旋。entry 在位置 j，带着自己的旋转；查询在位置 i。加权求和之后，输出里混进了「第 3 块的旋转」和「第 300 块的旋转」——同一段内容，换个位置，输出坐标就漂了。V4 的解法很漂亮：对输出，再按查询位置，反向旋转一次。旋转角度可以相加：负 i 的旋转，乘 j 的旋转，等于 j 减 i 的旋转。绝对位置消掉了，只剩相对距离。注意，de-RoPE 不是去掉位置，是解旋——de 是 undo，不是 delete。这套设计，真的经得起验证吗？ |
| S5 | 机制验证 + Kimi K3 对照 | 实验三行卡：K=V 路径成立 / 内积只依赖相对距离（2.0361=2.0361，counter_value）/ 无 de-RoPE 漂移 0.28 vs 有 de-RoPE 1e-16（数字对比动效）；K3 卡「rotary_emb = None」完全不旋转（转折爆点） | 光看公式不够。我用 NumPy 写了个自包含实验，验证三条路径。同一个 entry 同时当 K 和 V，路径成立；QK 内积只依赖相对距离——绝对位置从 5 和 8，换成 105 和 108，内积结果一模一样，2.0361 对 2.0361。不解旋，同一内容换个绝对位置，输出漂移 0.28；解旋之后，漂移降到 1e-16，机器精度。另一家国产旗舰走得更远：Kimi K3 的注意力，干脆完全不旋转——代码里 rotary_emb 直接是 None。V4 是部分旋转加输出解旋，K3 是彻底不转。RoPE 是不是必须的，已经成了开放问题。那这笔账，到底省了多少？ |
| S6 | 效率收口 + 回扣 + 尾卡 | 三根对比条（grow_bar）：27% FLOPs / 10% KV cache / 2% 基线；四件事卡（压缩、K=V、混合存储、FP8）；回扣「各归其位」；尾卡：avatar 圆角图 + 黄色「关注「数解AI」」+ 当期标题 + 绿色引导 + 下一篇 mHC 预告 | 最后算笔账。1M 上下文，官方口径：推理 FLOPs，是 V3.2 的 27%；KV 缓存，是 V3.2 的 10%；以 BF16 基线算，只有 2%。省在哪？压缩、K=V 单份缓存、混合存储、索引器 FP8——四件事。回到开头的问题：K=V 为什么没让「找」和「取」串味？因为职责拆到了不同维度上：Partial RoPE 把位置锁进最后 64 维，de-RoPE 在输出端把绝对位置翻译成相对距离。两份工作共用一份缓存，各用各的维度——这不是偷工减料，是更精细的分工。关注数解AI，下一篇拆 mHC：为什么普通残差连接，在 60 层以上会「传话传没」。如果你是架构师，会把位置放在少数维度，还是干脆不旋转？评论区聊聊。 |

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（full.txt，默认精英男声）+ `--subtitle` 句子级时间戳 → `scripts/tts_split.py` 按时间戳切分 6 段
2. 动画：每段一个 Manim Scene（S1..S6），`construct` 末尾 `pad_to_voice()`；动画节点按台词时间轴铺满（≥80% 配音时长）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：yairouter 1080×1920（3:4 安全区）
5. 归档：`content/2026-08-05-deepseek-kv/shipinhao/`
