| S1 | 开场钩子 | 大标题「PPO」登场 + 所有人扔 critic / 智谱请回来 对比 → 问号放大 | 所有人都在扔掉 Critic 的时候，智谱却把它请了回来。2026 年 6 月，GLM-5.2 悄悄切回了一种更经典的算法——PPO。一个被 NIPS 2017 拒稿的算法，凭什么成了 RLHF 的发动机？这条视频，用三道机关给你讲透。 |
| S2 | 前世今生 | 策略更新太猛/太慢 天平 → TRPO 信任域圆圈 → 二阶导数打叉 → clip 替代 → NIPS 2017 拒稿红戳 | PPO 要解决强化学习的核心矛盾：策略更新太猛会崩溃，太慢又学不动。TRPO 说，划一个信任域，新策略不能离旧策略太远。但它要算二阶导数，工程上几乎不可行。2017 年，OpenAI 的 Schulman 用 clip 替代了复杂优化——效果接近，实现只要几行代码。然后，它被 NIPS 2017 拒稿了。审稿意见：创新性有限。时间，才是最公正的评审。 |
| S3 | GRPO 变体 | GRPO 流程：同题 32 个回答 → 组内平均分 → 矮子里拔将军 → GLM-5.1 标签 → 问号悬念 | RLHF 时代，开源社区开始简化 PPO。2024 年，DeepSeek 提出 GRPO：不训练价值网络，让模型对同一道题生成一组回答，拿组内平均分当基线。就像几十个学生同时交卷，互相比较打分——矮子里也能拔将军。省显存、又稳定，GLM-5.1 用的就是这套。那 GLM-5.2，为什么又放弃了它？ |
| S4 | 机关 1：Clip | 骑自行车摆动 → 概率比截断 1±ε 区间（超出截断）→ ε 标注 | 第一道机关：Clip，管微观稳定——策略不能更新太快。就像学骑自行车：左倾就往右摆，但摆猛了，反而摔向另一边。PPO 把新旧策略的概率比，限制在一加一减 Epsilon 的区间里，超出就截断，不给它贡献梯度。一次截断，替代了 TRPO 的整套二阶优化。 |
| S5 | 机关 2：Critic | 优势函数「比平均好多少」→ 5 步 vs 50 步两条轨迹对比 → 组内平均失效打叉 → critic 独立打分 → 悬念问号 | 第二道机关：Critic。优势函数回答一个问题：这个动作比平均水平好多少？GRPO 拿同组均值当基线，可两条轨迹，一条 5 步、一条 50 步，怎么放在一起算平均？Critic 呢，给每条轨迹独立打分，长度不影响估值。长程任务里，这就是胜负手。可光有它，模型会不会走偏？ |
| S6 | 机关 3：KL + 协同 | 模型改语言能力 红色警告 → KL 约束拦截 → 三层卡片（微观/中观/宏观） | 会。为了骗奖励，模型什么都干得出来——突然改掉原本的语言能力。所以第三道机关：KL 约束，防止它走偏。三道机关各管一层：Clip 限制单步幅度，Critic 提供 token 级信号，KL 锚定整体方向。微观、中观、宏观，各司其职。 |
| S7 | GLM-5.2 实战 | 长轨迹 200 步 → 压缩成 3 条子轨迹（50/30/120）→ GRPO 组内比较打叉 → critic 通吃 → 作弊拦截返回假信息 | GLM-5.2 瞄准长程任务：coding agent 执行几十步工具调用，轨迹远超上下文窗口。压缩后，一条 200 步的轨迹，变成 3 条长短不一的子轨迹——GRPO 的组内比较，直接失效。Critic 却无所谓：独立估值，长短通吃。模型作弊呢？GLM-5.2 拦截后返回假信息，让轨迹继续——让模型亲眼看到，作弊没用。 |
| S8 | 总结 | 短任务/长任务 分栏 → 三句话压缩 → 下一篇预告 GRPO 数学 | PPO 不是万能，但目前最稳。短任务，GRPO 便宜够用；长任务，PPO 更鲁棒。算法选择，正在变得任务相关。下一条，我们拆 GRPO 的数学：组大小 32，为什么是甜点？最后留道题：一个 agent 花 50 步修 bug，压缩成 3 条长短不一的子轨迹，GRPO 和 PPO 会怎么处理？评论区聊聊。 |
