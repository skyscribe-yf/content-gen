## 结构（7 节悬念链弧线，单篇深潜 NSA 本体）

### 一、注意力为什么非要全算？（先建立瓶颈共识）
- 自注意力 = 每个 query 和所有历史 K 打分（复用已发《注意力机制》篇概念，不重推）
- 数学硬墙：O(N²)。64k 解码时注意力占总延迟 70-80%（论文 §1）
- 人话账：1M 上下文，第 100 万个 token 进来要和前 999,999 个逐一比对，每层都这么做
- 埋钩：能不能少算点？别人试过，都失败了——NSA 说可以，而且算得少还更准

### 二、前人为什么都失败？（先失败后解法）
- 三类失败（论文 §2 的「Illusion」和「Myth」，人话化）：
  - **阶段受限**：H2O 只加速解码、MInference 只加速 prefill——总有一段是满负荷
  - **和 GQA 打架**：Quest 每个头独立选，KV 访问变成所有头的并集，省了计算没省搬运
  - **不可训练**：聚类/哈希（ClusterKV/MagicPIG）不可微，梯度断流——模型学不会「该看哪」
- 悬念：NSA 怎么同时躲过这三个坑？

### 三、主菜：读书法三层（核心认知交付）
- 人话比喻：读 100 万字长文档的三招——扫目录（压缩）→ 精读重点页（选择）→ 余光保底（滑动窗口）
- **层 1 扫目录**：把 32 个连续 token 压成 1 个「摘要」token（MLP + 块内位置编码，步长 16 有重叠防碎片化）——全局粗看
- **层 2 精读**：怎么知道哪页重要？**零成本妙招**：目录层已经算好了 attention score，直接复用当重要性打分，选 Top-16 个 64-token 块——细看重点
- **层 3 余光**：最近 512 个 token 单独保底，独立 KV 防止「只看眼前」偷懒（论文说这是防 shortcut learning）
- 三路输出用门控（MLP+sigmoid）按 query 加权融合
- 关键设计呼应：块状选择 = 论文 Figure 8 的 blockwise clustering（相邻 token 重要度相近，这也是开头 attention map 白的部分）
- 术语门槛：≤2 新术语——压缩块（扫目录）、选择块（精读）。滑动窗口/门控用阅读类比带过，不立术语

### 四、数字验证：8.6% 凭什么反而更强？（论文数字逐条核）
- **8.6% 账本**：64k 解码每步只需加载 5632 个 token（压缩 ~4096 + 选择 1024 + 滑动窗 512）÷ 65536 = 8.6%（论文 Table 4；⚠️ 只到 64k，1M 未测，标题不写 1M）
- **速度**：解码 11.6× / 前向 9.0× / 反向 6.0×（64k，vs FlashAttention-2 同后端）
- **质量反超**：LongBench 0.469 vs 全注意力 0.437；NIAH 64k 满分；GSM8K 0.520 vs 0.486；AIME 8k 0.121 vs 0.046（+0.075）
- **为什么反而强**（诚实边界）：27B 规模验证；论文解释 = 稀疏过滤噪声 + 多尺度归纳偏置；个别基准（MMLU 0.565 vs 0.567）略降——不当「全面碾压」写

### 五、过渡一句：后来 DeepSeek 自己怎么用？（一句话，不重讲）
- V3.2 = MLA + DSA（索引器扫全文，已发 08-04 篇，正文链接引用不重讲）
- V4 = CSA + HCA（先压缩后选择），NSA 原版三分支未直接进产品线
- 转折点：亲爹为什么不用亲儿子？

### 六、收尾反差：谁在用，为什么？（路线分叉，非拉踩）
- **反差事实**：NSA 论文（DeepSeek 2025.02）→ V3.2 落地 DSA（简化版）→ V4 换 CSA+HCA；GLM-5.3-Flash（08-27 已发文）：45 层 3:1（34 层 KDA + 11 层 MLA/DSA）——还在 DSA 路线上；Kimi K2.6 用 KDA（写稿前验证数字）
- **为什么分叉**（不拉踩，讲取舍逻辑）：三方案各打各的——NSA 算得少（8.6%）、DSA 选得准但索引器仍扫全文（O(L²) 残留）、CSA 先压后选（候选池小后再选）。V4 不要 8.6% 这个数字，要的是「1M 上下文计算量可控」的结果
- 回扣标题：8.6% 是 NSA 论文的答案；「谁在用、为什么用、不用换成了什么」才是 2026 年的问题
- 诚实边界：GLM 是 3:1 混合不是落后；KDA 是 Kimi 自家路数（链接已发 07-28）

### 七、回扣 + 互动问题 + 尾部惯例
- 回扣开头 attention map：白的不是噪声，是模型的「读书法」；稀疏不是偷懒，是把力气花在刀刃上
- 开放式问题（30 秒测试）：「你平时跑长上下文，是让模型从头全算，还是试过 FlashAttention / 稀疏注意力这类加速方案？踩过最深的坑在哪一步？报出模型名和序列长度。」
