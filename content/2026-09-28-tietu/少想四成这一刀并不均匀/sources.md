## 71% 是哪一格：同一篇的 A/B 节

正文：两个客户的生产 coding 流量，每种情况都是每任务大约少 35% token，质量差不多。其中一个客户已经在线上用，并计划换掉基座。35% 是两个客户的大约值。

明细表没有客户名字。列是 Score、Steps、Output Tokens、Reasoning Token reduction、Total token reduction。斜体行是对照，下一行是 Ember-1：

| | 分数 | 步数 | 输出 token | 推理 token | 总 token |
| --- | --- | --- | --- | --- | --- |
| 对照（斜体） | 0.751 | 23.8 | 49.3K | — | — |
| Ember-1 | 0.753 | 21.4 | 29.9K | −71.3% | −39% |

- 71.3% 只属于推理 token 这一列。39% 是总 token。不要并成「砍了 71%」。
- 0.753 对 0.751 不是博客写的「同一成功率」。Cline 帖子写成同一成功率，图上不采用。
- 输出 token 从 49.3K 到 29.9K。不另算一个百分比，避免和总 token 的 39% 搅在一起。

## 机制，进文不进「效果」

同一篇：

- 推理模型生成的 token 里，多数、有时超过 90%，是内部思考而不是答案。90% 是「有时超过」，不是测量均值。
- 多轮里，每一轮都会把此前的思考再送回去，上下文大约按轮数平方增长，早先的长思考会被反复计费。这是机制说明。
- 把 K3 的推理努力档拧低，丢的质量太多。所以他们重新训练，而不是只拧档。
- 训练用自己的数据，没有用客户数据。50 多次训练实验，200 多次评测。这是规模，不是效果，不进图。
- 训练集合覆盖数学、代码、指令遵循、对话、搜索、工具使用、软件工程。Cline 帖写成「在真实 agent 编码循环上做 RL」。博客的范围比这一句宽。图上不写 Cline 的训练范围。
