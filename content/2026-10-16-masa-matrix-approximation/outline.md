## 交付句（全文唯一想证明的事）

> **稀疏注意力挑格子，该问的不是「谁的分数大」，而是「挑进来的这部分，对输出的矩阵乘积保留了多少」——「分数大 = 重要」只在 value 之间几乎两两正交时才成立，而长上下文里它永远不成立。**

## 反直觉答案（三连）

1. **逐元素挑最大不是笨办法，它是「逐元素误差」这个目标下的精确最优解。** 论文 Eq.4 有证明：在 $\|A-M_{\mathcal S}\odot A\|_F^2$ 上，Top-$|A_{ij}|$ 就是最优。**错的是目标本身**，不是解法。
2. **反例里质量高 66 倍的那一列，value 的范数是另一列的 1/2158。** 自测复刻的参数（质量比 66 / 范数比 2158 / 两方向夹角 49°）——质量排序把预算交给了一个几乎不产出的列。
3. **自测把旋钮拧一遍：质量排序的误差从 37% 冲到 93%。** 让质量最大的块内部方向互相抵消，质量排序跌到 92.8%，矩阵逼近打分只跌到 50.6%；而且质量排序选对块的比例从 100% 掉到 **42.5%**。

## 拿得走的结论

- **给做设计的人 · 一个判据**：任何按注意力质量/集中度排序的挑选或路由（含各家选择器、路由器、KV 淘汰），都值得追问一句——**挑进来的这部分，对输出的矩阵乘积保留了多少？**
- **给做评测的人 · 一个自测**：把候选单元的 value 方向翻转比例当旋钮，看质量排序和矩阵逼近排序会不会分开；**分开的地方，就是你的选择目标和工作目标脱钩的地方**。预算越紧，脱钩的代价越大。
- **一条边界（别过度使用）**：这个错位**只在「质量排行」和「贡献排行」脱钩的地方咬人**。所有单元同等程度抵消时，两种排序几乎分不开；预算放宽（自测里 1/16 → 4/16 块）差距也被压掉。

### 一、先说清注意力是怎么被「消费」掉的（~250 字）

- 注意力不是被「读」的，是被**矩阵乘法**消费的：$\mathrm{softmax}(QK^\top)V$。分数矩阵 $A$ 自己不是终点，$AV$ 才是。
- **分数本身是怎么来的**：每个 token 的 query 向量和 key 向量做内积，过一遍 softmax，得到一行注意力分数。所以「分数大」= 这个 token 的向量表示和当前这个 query 最说得上话。**后面第一节末那句作者判断，就挂在这一层上**
- 现有三家的共同动作：给每个候选单元（竖线 / 斜线 / 块）算一个标量分
  $$s_{\text{entry}}(u)=\sum_{(i,j)\in u}\phi(A_{ij})$$
  $\phi$ 多数时候就是注意力质量，也可以是最大质量、阈值质量，或一个学出来的门分数（论文 §3.1 Eq.3）。
- **术语 1 · 注意力质量**：一个候选单元里所有注意力分数加起来是多少。分数大 = 模型在这儿看得重，这是行业的默认直觉。
- 🔗 内链：《DeepSeek 注意力只算 8.6%，为什么 V4 反而不用？》（09-02 NSA 篇）
- 落点：它们回答的是「**哪些格子分数大**」，不是论文要问的那句「**哪些格子保住了输出**」

### 二、这个目标错在哪：一个精确最优解，配一个错的目标（~320 字）

- 把误差写开（论文 Eq.5）：
  $$\big\|(A-M_{\mathcal S}\odot A)V\big\|_F^2=\mathrm{tr}\big((A-M_{\mathcal S}\odot A)\,VV^\top(A-M_{\mathcal S}\odot A)^\top\big)$$
- 于是第一件反直觉的事：**逐元素挑最大，恰好是 $\min\|A-M_{\mathcal S}\odot A\|_F^2$ 的精确最优解**（Eq.4）。它不笨，它只是答错了题。
- **只有 $VV^\top$ 像单位阵时**，这个逐元素目标才等于真目标。而 $V\in\mathbb R^{N\times d}$、$N\gg d$，所以 $\mathrm{rank}(VV^\top)\le d\ll N$——**这个条件在长上下文里永远不成立**。
- **术语 2 · 矩阵逼近**：把「挑格子」重新定义成「用一小部分格子把矩阵乘积 $AV$ 逼近到多好」。由此得到的单元打分（论文 §3.2 Eq.7）：
  $$s(u)=\|O_X\|_F^2-\|O_X-C_u\|_F^2=2\langle O_X,C_u\rangle_F-\|C_u\|_F^2$$
  逐对形式（Eq.8）：$s(i,j)=2A_{ij}\langle O_{X,i},X_j\rangle-A_{ij}^2\|X_j\|_2^2$。
- **退化检查**：若 $XX^\top=I$，它退化成 $A_{ij}^2$——**逐元素排序只是它在单位 Gram 下的特例**。
- *（[本槽为作者原声：槽 3，沿用](#作者原声槽)）*
- 落点句：**公式里多出来的那个 $\|X_j\|^2$ 和内积项，就是质量排序整个丢掉的东西**

### 三、66 倍 vs 98%：一个两列的反例（~280 字）

- **论文 Fig.1（一手）**：同一列预算，mass 排序选中质量大 $66\times$ 的那列，带来 **98%** 相对矩阵乘积误差；MASA 选另一列，误差降到 **3%**。
- **我们复刻了一遍（自测）**：构造质量比 66、value 范数比 2158、两方向夹角 49° 的两列，得到 **98.0% / 3.0%**，与论文一致。打分核验：mass 选中的列 $s=19.18$，矩阵逼近选中的列 $s=484.44$。
- **翻译成人话**：那一列分数高，是因为它把每一行 softmax 必须分配出去的质量都接住了（**sink**），但它的 value 几乎不往输出里加东西。分数高这件事本身是真的，只是**它高的原因和「重要」无关**。

### 四、把旋钮拧一遍：质量排序什么时候才真的崩（~330 字，**本文主图**）

- **自测设计**：16 个块 × 每块 16 列；**所有列的 value 范数都设为 1**（先把范数因子剥掉，只留方向，避免跟第三节的 sink 混在一起）；预算 1/16 块；400 次重复。
- **旋钮**：块内 value 方向的翻转比例 $f$（$0$ = 方向一致；$0.5$ = 完全互相抵消）。
- **结果**：
  - $f=0$：两种排序**完全一样**（37.1% vs 37.1%，质量与真贡献相关系数 **1.000**，选对率 100%）；
  - $f=0.5$：质量排序 **92.8%**，矩阵逼近打分 **50.6%**；相关系数掉到 **0.774**；**质量排序选对块的比例从 100% 掉到 42.5%**。
- 图：`02-direction-scan.png`（**已生成**，93% vs 51%，放正文）
- ⚠️ **图下必写的一句**：两条线都不到 0，是因为预算只给了一块（1/16）；这里要比的是**两条线分开的那一段**，不是绝对值。
- **三条边界（自曝，防杠）**：
  1. 错位要看得见，必须**不对称**——所有块同等程度抵消时两种排序几乎分不开（mass 37.1%→51.0%，MASA 37.1%→30.4%）；
  2. 预算放宽到 4/16 块，差距被压到约 0（mass 24.4% vs MASA 25.1%）——**代价随预算收紧而放大**；
  3. ⚠️ 第一版我们拿**单列**当单元，结果跑反了（方向越随机，质量排序误差反而**下降** 60.1%→56.2%）——单列内部不存在抵消。**「单元内的相互作用」这句话，只有在块/多 entry 单元上才成立。**

### 五、为什么长上下文把这件事放大（~250 字）

- 单元的净贡献量级 ≈ **质量 × ‖value‖²（+ 相干修正）**；质量排序丢掉的正是整个范数因子和那项内积修正。
- 长上下文里两个因子**同时**走向极端：
  - $A$ 侧：sink 的注意力质量占比暴涨——大量分数挤在少数位置上；
  - $X$ 侧：高范数的 value **outlier** 开始支配输出（论文消融里 norm control 有效，修的就是这一侧）。
- *（[本槽为作者原声：槽 6，沿用](#作者原声槽)）*
- 论文实验对得上：增益随长度变大——32K–128K 四个配置里 **11/12** 个长度级提升，且每个配置在长段的平均增益都超过 4K–16K 段。
- 落点：所以不是「长上下文更容易出错」，是**两个极端同时变尖锐**

### 六、论文自己怎么证明这不是玩具（~300 字，含防守段）

- **协议（刻意干净）**：挂到 MInference / SeerAttention / FlexPrefill 三家的**官方配置**上，kernel、候选单元、预算全不动，**唯一变量是排序分数**。
- **8/8**：3 方法 × 3 基准（RULER / InfiniteBench / LongBench）× 2 个 backbone（Llama / Qwen），**8 个匹配平均分全部提升**。
- **两个「翻盘」时刻**：SeerAttention 在 RULER 上 **87.60 → 88.09**（全注意力 88.01，**从低于翻到高于**）；FlexPrefill-Llama 在 InfiniteBench 上 **47.14 → 47.99**（全注意力 48.06，回收约 **92%** 的差距）。
- **128K 的增益**：MInference **+1.28**、SeerAttention **+0.48**、FlexPrefill-Llama **+1.45**、FlexPrefill-Qwen **+2.16**；64K 最高 **+3.65**。
- **直接量目标本身（附录 E）**：四个 framework–backbone 对的归一化平方输出误差全降 **+0.41% / +2.10% / +2.34% / +7.17%**，四个配对 98.75% 置信区间**全部大于 0**。这是对「矩阵乘积保留」这个目标最直接的验证。
- **防守段（必须紧跟上面这一条，两步自曝挨着放）**：
  - 主动摆最低值：**+0.48** 就是全部提升里最小的那个，不藏；
  - 主动摆前提：MASA **只在基线已有的候选单元上重排序**，候选集本身设计得差（块粒度太粗、模式选错）它救不回来——论文自己把它写成 **practical boundary**，它是**矫正器，不是新搜索空间**。所以「零成本」的准确说法是「**不新增一层计算**」。
- **论文自划的边界原样带进正文**：全注意力是**参考不是严格上界**，部分基线配置已接近甚至超过 dense；真正的问法是「**同预算下一次排序修正能回收多少**」。
- 落点：它没把稀疏注意力变成另一个东西，只是把「挑哪个」这件事的**目标函数改对了**

### 七、DeepSeek 的选择器线：值得再问一句（~280 字，回应开头）

- **NSA（arXiv:2502.11089 §3.3.2）**：块重要性分数**直接来自压缩分支的注意力分数** $p^{\text{cmp}}_t=\mathrm{Softmax}(q_t^\top\tilde K^{\text{cmp}}_t)$；同块划分时选块分数就等于它，GQA 组内跨头求和，再取 Top-$n$。
- **V3.2 的 DSA 索引器（arXiv:2512.02556 §2.1）**：监督目标是 **KL 散度对齐主注意力分布**——把主注意力多头分数求和、沿序列 L1 归一化当目标分布；预热 1000 步 × 16 条 × 128K；稀疏阶段每 query 选 2048 个 KV。
- **V4 的 CSA**：先压后选——索引键也先压缩，再按 DSA 那套分数选 top-$k$ 压缩块。
- 🔗 内链：《稀疏注意力怎么挑重点？DeepSeek-V4 只算 1/64》（08-11 索引器篇）
