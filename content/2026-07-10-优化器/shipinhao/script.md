
## 4. TTS 口播全文（可直接粘贴）

> 纯口播见同目录 `tts.txt`（无时间码、无舞台指示）。  
> 字数约 **300 字**，知识科普语速约 **240 字/分** → 约 **75 秒**。

### 分镜对齐版

**【镜1 · 0:00–0:04】**  
学习率调了一整天，loss 还是抖？问题可能不在你，而在 SGD 那把尺子。

**【镜2 · 0:04–0:16】**  
梯度已经告诉模型该往哪走，但 SGD 只给所有参数同一个学习率。有的梯度大一百倍，走一步就冲过；有的几乎不动。同一把尺子，量不了百万个参数。

**【镜3 · 0:16–0:28】**  
损失面像压扁的椭球：陡处像深谷，平处像浅盘。SGD 在陡壁上之字横跳，该走的长轴却几乎没动。

**【镜4 · 0:28–0:36】**  
（可叠 `05-sgd-vs-adam.png`，本段可无独立口播，接镜5；或轻声垫：左边 SGD 横跳，右边 Adam 直切。）

**【镜5–6 · 0:28–0:52】**  
Adam 就一句话：方向，除以尺度。分子稳住方向，来回抖的会抵消；分母看梯度大小——大的减速，小的加速。每个参数，自己的步长。

**【镜7 · 0:52–1:02】**  
所以 DeepSeek、Qwen 训练里常见 Adam W，不是跟风，是自动调速。

**【镜8 · 1:02–1:12】**  
记住：Adam 等于方向除以尺度。完整拆解，公众号数解 AI，搜 Adam。你还在手动试学习率吗？

### 念法提示（给 TTS / 后期）

| 片段 | 处理 |
|------|------|
| 「loss 还是抖」 | 稍顿，加重「抖」 |
| 「同一把尺子」 | 放慢 |

| 「数解 AI」 | 品牌名稍清晰，勿吞音 |

## 6. TTS 方案（Linux · 已接通）

**默认：Xiaomi MiMo-V2.5-TTS**（环境变量 `XIAOMI_MIMO_API_KEY`）。

剪映无 Linux 客户端，本项目 **不依赖剪映**。

### 生成口播（已跑通）

```bash
python3 scripts/xiaomi_mimo_tts.py \
  --text-file content/2026-07-10-优化器/shipinhao/tts.txt \
  --out content/2026-07-10-优化器/shipinhao/voice.wav \
  --voice Chloe
```

| 项 | 值 |
|----|-----|
| 模型 | `mimo-v2.5-tts` |
| 音色 | `Chloe`（可换内置精品音色） |
| 产物 | `voice.wav` / `voice.mp3` |
| 实测时长 | **≈53s**（294 字，偏紧凑，利于完播） |

风格指令写在脚本默认参数里：沉稳知识科普、略快、不播音腔。可用 `--style` 覆盖。

### 备选

| 方案 | 何时用 |
|------|--------|
| `mimo-v2.5-tts-voicedesign` | 要用自然语言定制「沉稳男声」等 |
| Grok TTS | 有 `XAI_API_KEY` 时 A/B |
| edge-tts | 无 Key 时本地兜底 |

### TTS 避坑

1. 公式不要读 LaTeX；口播已写成「方向除以尺度」  
2. `AdamW` 在 `tts.txt` 写成 **Adam W**  
3. 生成后听一遍专有名词；怪腔就改 `tts.txt` 重跑脚本  
4. 句末疑问保留（「还抖？」「吗？」）

## 7. 成片（Linux · ffmpeg，无剪映）

口播就绪后，用竖屏信息图分镜 + `voice.wav` 合成 9:16 mp4。

推荐流程：

1. 按分镜表把插图居中铺在 `#1a1a2e` 画布（1080×1920）  
2. 按时长切开（总长对齐 `voice.wav` ≈53s，可按字数比例分镜）  
3. `ffmpeg` 拼接视频轨 + 音轨 + 硬字幕（可选）  
4. 导出 `shipinhao/final.mp4`
