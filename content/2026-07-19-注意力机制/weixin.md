## 🎯 驱动问题：向量之间，关系从哪里来

**注意力机制（Attention）** 不是数据库查询。每个 token 用 Q 去和允许的位置上的 K 打分，再经 softmax 对 V 做软加权汇总——名字叫「注意力」，干的是「加权汇总」。

前面三篇已经把一句话变成一组向量：

- BPE 分词把"猫追老鼠"切成 token——猫、追、老鼠（即将发布）
- 词嵌入把每个 token 变成一串坐标——"猫"和"狗"的坐标近，和"追"的坐标远（即将发布）
- 位置编码给每串坐标加上位置信息——"猫追老鼠"和"老鼠追猫"的向量不再相同（即将发布）

现在每个 token 都带着「我是谁」和「我在第几位」的信息。但它们怎么互相影响？

"追"和"猫"是什么关系？"追"和"老鼠"又是什么关系？光靠每个 token 自己的向量，看不出来。需要一种机制，让它们能"对话"。

这个机制就是注意力。

*“猫追老鼠”经过分词、词嵌入和位置编码后，得到等待彼此计算关系的向量序列。*

## 先把计算过程摆出来

注意力的计算过程并不长：

> **每个 token 生成三个向量 Q、K、V。Q 和 K 做内积 ⟨Q, K⟩ 得到分数，分数除以 √d 再过 softmax 得到权重，最后用权重对 V 做加权求和。**

内积、缩放、归一化、加权求和，四步而已；难的是别把它们想成另一件事。

文中说的内积，具体就是点积（dot product）：对应分量相乘再求和，记作 **⟨a, b⟩ = a₁b₁ + a₂b₂ + ⋯ + aₙbₙ**。GPU 很擅长这种计算。容易混淆的，是 Q、K、V 这三个名字和它实际在算什么。

---

## 数据库类比，在哪一步走偏了

人们常把它讲成这样：

> Q 是查询（Query），K 是键（Key），V 是值（Value）——就像数据库：你输入搜索词（Q），系统用索引（K）匹配，返回记录（V）。

这个类比能帮你记住 Q、K、V 的名字，却容易把计算过程想错。注意力确实会用 Q 和 K 打分、再用 V 汇总，但它既不是一次精确查找，也没有固定的"查询方"和"被查方"。

### 每个 token 都在提问，也都能被问到

数据库查询里，查询方和被查方是固定的——你敲搜索词，数据库返回结果。

自注意力呢？**每个 token 同时生成 Q、K、V 三个向量。** token 1 的 Q 和 token 2 的 K 做内积，token 2 的 Q 也和 token 1 的 K 做内积。每个 token 既是提问者，也是被提问者。

> **小注**：上面说的是双向注意力（如 BERT），所有 token 两两互算。但像 Qwen3、GPT 这类自回归语言模型，用的是**因果注意力（causal attention）**——每个 token 只能和**它之前的** token 算内积，不能"偷看"后面的内容。否则模型在生成第 5 个 token 时就提前知道第 10 个 token 是什么，推理就没意义了。下文的圆桌比喻仍然成立，只是每位参与者只能听到**先发言的人**的话。

更贴切的直觉是**圆桌讨论**：每个 token 都带着一张"可被匹配的名片"（K）、一个"我想找什么"的提问（Q），以及真正要传递的信息（V）。它用自己的 Q 给允许参与的 K 打分，再按分数加权汇总对应的 V。因果注意力下，允许参与的是当前位置及其之前的 token。

![](02-roundtable-vs-database.png)

*左：数据库类比——一方查、一方被查。右：圆桌讨论——每个人同时发言和倾听*

### 它不会只取一条记录

把注意力想成传统的键值查找时，常会误以为它只命中一个键、返回一条记录。实际计算不是这样：对每个**未被 mask 的位置**，softmax 会给出一个权重，再对对应的 V 做加权求和。token 1 对 token 2 的权重可能是 0.7，对 token 3 是 0.2，对 token 4 是 0.1；它不是只取其中一个。

因此，Q/K/V 的命名可以借用"查询、键、值"来记忆，但不能把注意力当成 `WHERE key = query`。前者是在一组允许的位置上做连续的加权汇总，后者是按条件选择记录。

---

## “关注”不是“只看一个”

“token A 关注了 token B”“模型知道该看哪里”都很常见。“看”听起来像一次二选一：看了，或者没看。可注意力真正做的是分配权重。

对**未被 mask 且分数有限的位置**，softmax 之后没有零权重。权重可能很小，比如 0.001，但不是 0。

为什么？因为 softmax 的数学性质：**指数函数永远为正，归一化后不可能恰好为零。** 因果注意力中未来位置会先被 mask 成 −∞，它们的权重才是 0；训练时若启用 attention dropout，也可能额外置零。

[Softmax 那篇](https://mp.weixin.qq.com/s/5wMquh_v3oon2-NEDeQLEw)解释过，它不是直接取最大值，而是把分数变成一组总和为 1 的权重。放到注意力里，这意味着模型通常不是排除某个 token，而是在允许的位置之间分配多少。

![](03-look-vs-distribute.png)

*上："看"暗示二元选择——只看一个。下：注意力是权重分配——0.7/0.2/0.1，每个 token 都参与*

所以"token A 关注了 token B"更准确的说法是：**在允许的位置中，token A 对 B 的权重是 0.7，对 C 是 0.2，对 D 是 0.1。** 这是分配，不是选择。

## 矩阵写法，没有改变谁在计算

公式通常写成：

> Attention(Q, K, V) = softmax(QKᵀ / √d) V

看到 QKᵀ，很容易以为注意力是"矩阵层面的操作"——两个矩阵相乘，得到注意力矩阵，再乘 V。

### 展开一行就够了

QKᵀ 的**第 i 行**，是 qᵢ（第 i 个 token 的查询向量）和**它之前所有** K 向量做内积的结果（因果注意力下，后面的 K 被 mask 掉了）。本质是：

> **token i 拿自己的 Q，和之前每个 token 的 K 算匹配分数，过 softmax 变成权重，再用权重对 V 加权求和。**

每个 token 独立完成这套流程。矩阵写法只是把 N 个向量运算**打包成并行形式**——方便 GPU 一次算完，但逻辑上每个 token 只和之前的 token 算注意力，各算各的。

注意力矩阵的下三角不是一张“检索结果表”，而是 N 个 token 各自的权重分布拼在一起。矩阵让 GPU 能并行计算，但没有把每个位置各自做出的决定变成一个全局查询。

## Q 和 K，为什么能打出匹配分数

接下来要回答的是：**为什么 Q 和 K 做内积，就能给出“匹配分数”？**

### 先看方向

两个向量的点积可以写成：

> **⟨Q, K⟩ = Q · K = ‖Q‖ ‖K‖ cos θ**

θ 是两个向量之间的夹角。若长度相近，方向越对齐（θ 越小），cos θ 越大，点积通常越大；正交时点积为零，反向时点积为负。

但要留一个关键限定：Q 和 K 不是原始词向量，而是模型从同一输入通过两套不同投影学出来的向量。它们的长度也会影响点积。因此，**⟨Q, K⟩ 不是通用语义相似度，而是这个注意力头学到的"匹配分数"。** "我在找的"和"你有的"越匹配，分数通常越高，softmax 分到的权重也越大。

![](04-dot-product-geometry.png)

*二维示意：q 和 k₁ 方向接近 → 内积大 → 权重高；q 和 k₂ 近乎正交 → 内积小 → 权重低*

### 为什么除以 √d

高维空间里有个反直觉的现象：随机两个向量的内积，**方差随维度增长**。维度 d = 64 时内积可能还在 ±10 以内，d = 4096 时内积可能跑到 ±100。

不缩放的话，softmax 收到的分数太大，输出会趋近 one-hot——最大值接近 1，其余接近 0，"软"选择退化成"硬"选择。除以 **√d** 就是把内积的方差压回可控范围，让 softmax 保持"分配"而非"独占"的能力。

这里先停在点积的直觉。投影、子空间和正交分解会在后续文章里接上。

## 多头注意力：不是一副眼镜

前面讲的都是"一个头"的注意力。实际模型用的是**多头注意力（Multi-Head Attention, MHA）**：同一个输入会经过多组可学习投影，每个头在自己的低维表示里独立计算 Q、K、V，最后再拼接并投影回隐藏维度。

以 Qwen3-8B 为例：[官方 `config.json`](https://huggingface.co/Qwen/Qwen3-8B/blob/main/config.json) 给出隐藏维度 **d = 4096**、注意力头数 **h = 32**、每头维度 **dₖ = 128**。因此 32 个 Q 头合起来正好是 4096 维。

可以把它理解成 32 套不同的匹配方式：

- 输入 x ∈ ℝ⁴⁰⁹⁶ 先通过可学习投影，得到每个头自己的 qᵢ、kᵢ、vᵢ（每个都是 128 维）
- 每个头在自己的表示空间里独立计算注意力
- 32 个头的输出拼接回 4096 维，再过一次输出投影

多头的重点不是把一次大运算机械地拆小来省计算量。头数增多时，总维度通常保持不变，Q/K/V 投影和注意力的主计算量并不会凭空消失。它给模型的是多套独立的投影参数，让不同头能学到不同的匹配模式；GPU 并行计算则让这种设计在工程上可行。

## 4K 上下文，到底要算多少次

以 Qwen3-8B 为例。假设输入 4096 个 token（约 3000 字中文），并采用因果注意力：

**一层里有多少对 token 要比较？**

- 第 1 个 token 可以看 1 个位置，第 2 个可以看 2 个，依此类推
- 每个头要计算 **1 + 2 + ⋯ + 4096 = 8,390,656** 个 Q·K 分数
- 32 个头一共是约 **2.68 亿次** 128 维点积
- 仅计算 QKᵀ 分数，就要约 **343.7 亿次乘加**

得到权重后，还要用权重对 V 加权求和。这一步的量级和 QKᵀ 相同。因此，只算这两次序列间矩阵乘，一层约 **687.4 亿次乘加**；Qwen3-8B 的 36 层合计约 **2.47 万亿次乘加**。

> **36 × 687.4 亿 ≈ 2.47 万亿次乘加**

这里没有计入生成 Q/K/V 和输出的线性投影，也没有计入前馈网络；它只是在量化注意力随序列长度增长的那部分成本。把上下文从 4K 拉到 32K，因果注意力的配对数量约增至 **64 倍**，这两次矩阵乘在 36 层里就约为 **158 万亿次乘加**。还记得[AI 上下文那篇](https://mp.weixin.qq.com/s/PLVRS0TTHXHDve1Z3r6M7Q)聊过的 KV Cache 占显存吗？注意力计算量涨得更狠——它不是线性增长，是平方增长。

## 用四个 token 看看权重怎么分

下面用随机初始化的向量模拟“猫追老鼠”四个 token 的注意力权重。它不是训练好的语言模型，但能把因果 mask 和 softmax 的作用拆开看：

```python
import torch, torch.nn.functional as F

torch.manual_seed(42)
tokens = ["猫", "追", "老", "鼠"]
d = 128  # head_dim

# 模拟 4 个 token 的 Q 和 K（随机初始化）
Q = torch.randn(4, d)
K = torch.randn(4, d)

# 内积 → 缩放 → 因果 mask → softmax
scores = Q @ K.T / (d ** 0.5)
causal_mask = torch.triu(torch.ones(4, 4, dtype=torch.bool), diagonal=1)
scores = scores.masked_fill(causal_mask, float("-inf"))
weights = F.softmax(scores, dim=-1)

# 打印每个 token 对其他 token 的注意力权重
for i, t in enumerate(tokens):
    row = "  ".join(f"{tokens[j]}:{weights[i,j]:.3f}" for j in range(4))
    print(f"{t} → {row}")
```

输出：

```
猫 → 猫:1.000  追:0.000  老:0.000  鼠:0.000
追 → 猫:0.604  追:0.396  老:0.000  鼠:0.000
老 → 猫:0.572  追:0.201  老:0.227  鼠:0.000
鼠 → 猫:0.209  追:0.249  老:0.166  鼠:0.376
```

![](06-attention-heatmap.png)

*4×4 因果注意力权重热力图。每行加起来 = 1；右上角的 0 来自因果 mask，其余允许位置由 softmax 分配权重*

从这组输出能看出三点：

1. **0 的来源不同**：未来位置被因果 mask 后是 0；每一行已允许的位置里，softmax 仍会给每个有限分数非零权重。
2. **自身权重不一定最大**：最后一个 token "鼠" 对"鼠"的权重是 0.376，但对前文的权重也并不相同。随机初始化没有语言规律；训练完成后，权重模式取决于具体层、头和任务，不能仅凭热力图断定语法关系。
3. **每行独立分配**："追"和"鼠"的权重分布不同——每个 token 独立地决定怎么分配自己的注意力，不是全局统一检索。

## Qwen3-8B 怎样减少 KV Cache

前面讲的都是朴素的多头注意力（MHA）：每个头各有自己的 Q、K、V。Qwen3-8B 的 config.json 里有两个参数：

- **num_attention_heads = 32**（Q 的头数）
- **num_key_value_heads = 8**（K、V 的头数）
- **head_dim = 128**

Q 有 32 个头，K 和 V 各只有 8 个头：每 4 个 Q 头共享一组 KV。这叫 **Grouped-Query Attention（GQA）**。也就是说，Q 总宽度仍是 32 × 128 = 4096，而 K、V 的总宽度各是 8 × 128 = 1024，不再和 Q 一样宽。

为什么？推理时 KV 要缓存（还记得[AI 上下文那篇](https://mp.weixin.qq.com/s/PLVRS0TTHXHDve1Z3r6M7Q)讲的 KV Cache 越长越占显存吗？），KV 头数从 32 减到 8，缓存体积也随之降到约 1/4。代价是不同 Q 头不能拥有完全独立的 KV 表示；GQA 的意义正是在效果和推理成本之间做这个折中。

![](05-gqa.png)

*左：MHA——每个 Q 头独占一组 KV。右：GQA——多个 Q 头共享一组 KV*

GQA 在效果和效率之间找平衡。MLA 从压缩 KV 表示入手，MQA 则让所有 Q 头共享一组 KV；不同方案省下的内存和付出的代价并不一样。

## 回到开头的问题

注意力不是检索，也不是某种神秘的矩阵操作。

**每个 token 会对允许参与的位置做软加权汇总；权重来自 Q 与 K 学到的匹配分数。**

- ⟨Q, K⟩ 结合方向和长度，给出某个头学到的匹配分数
- 对未被 mask 的有限分数，softmax 给每个位置非零权重——这是分配，不是选择
- 矩阵写法是并行打包，逻辑上是逐 token 的向量运算
- 多头注意力提供多套独立投影，让不同头学习不同的匹配模式

把它看成“每个位置按自己的需要，从上下文里汇总信息”，就足够开始读懂 QKV 了。

真正难的地方在规模：因果注意力里，每个 token 只和之前的 token 算内积，但序列一长，配对数量仍是 **O(N²)**。Qwen3-8B 在 4K 上下文时，仅两次序列间矩阵乘就约 2.47 万亿次乘加；到 32K 约为 158 万亿次。稀疏注意力、压缩注意力和线性注意力，都在试着解决这笔越来越大的账。
