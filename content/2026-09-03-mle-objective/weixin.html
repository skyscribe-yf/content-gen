看起来只能一次预测下一个token的模型，在经过了海量文本的预训练之后，却突然具备了写代码、调工具、写文章的能力，这是让很多第一次接触的人感到极度惊讶的一个现象。不过很快你就能发现，这个模型有时候会在一些非常基本的问题上，一本正经地胡说八道，犯下一些小学生都不会犯的错误，更麻烦的是，很多时候你根本无法事先预测这次它是表现得像一名博士生，还是一个小学生。

它到底学到了什么？

如果把大语言模型最底层的动作拆开，它似乎一直在做一件非常单调的事情：给定一个前缀，预测下一个 token。

但就是这样一个看起来并不复杂的动作，在海量文本上重复了足够多次之后，居然能表现出写文章、写代码，甚至调用工具的能力。要理解这个反差，得先把一个问题说清楚：MLE 到底在优化什么？

MLE 的优化目标，是在给定训练文本输入的情况下，寻找到一组参数，让模型在给定的神经网络架构设定下，产生预定义的输出的可能性最大。

这句话还可以说得更精确一点。

把训练文本记作 D，把神经网络的参数记作 θ。对于文本中的每一个位置，模型看到前缀 x<t​，然后给出下一个 token 的概率分布。训练数据则告诉模型：这一次真实出现的 token 是 xt​。

MLE 要做的，就是调整 θ，让这些真实出现过的 token 在各自前缀下的条件概率尽可能大。

θ^MLE​=argθmax​P(D∣θ)

这里的“预定义输出”，并不是一个老师提前写好的、唯一正确的整段答案。它更像是训练文本在每一个位置上已经发生过的下一个 token。

给定海量的输入，模型每次对一个前缀产生下一个token的输出，这个输出并不是要完全严丝合缝。训练的过程其实是需要让输出概率分布有最少的意外，让给定输入情况下真实出现的下一个 token 尽可能处在高概率区域。

所以，模型不是在每一步都被要求“必须严丝合缝地回答”。它面对的是一个概率分布：真实 token 的概率越低，这次预测就越意外；真实 token 的概率越高，这次预测就越不意外。

这也意味着，模型没有必要把其他所有可能性都压到零。只要训练文本本身允许多种表达，模型就可以保留多个候选 token 的概率。

二、Logit：概率出现以前，模型先打一个分

模型到底是怎么得到这些概率的？通常不是神经网络最后一层直接吐出一排 0 到 1 之间的数字，而是先给词表中的每个候选 token 算出一个原始分数。

这个分数可以从负无穷大到正无穷大。它可以是正数，也可以是负数，不要求所有分数加起来等于 1，因此它还不是概率。在机器学习里，这些原始分数通常被称为 logits。

假设通过计算得到一个从负无穷大到正无穷大的实数，希望用这个实数来表述一个概率，那么这个实数必须能够转换为一个 0 到 1 之间的数字，并且所有这些转换后的概率之和必须为 1。常见的转换函数是 Softmax，也可以使用其他具备类似归一化特征的函数。

以 Softmax 为例，四个候选 token 的原始分数如下：

候选 tokenlogit归一化后的概率（约）
猫588.0%
狗311.9%
兔-20.08%
企鹅-100接近 0

这里的数字不是概率论里的最终答案，而是模型先给出的倾向性打分。Softmax 会把它们重新映射到 0 到 1 之间，同时保证总和为 1。

需要注意，“企鹅”最后的概率接近 0，并不代表它在数学上严格不可能。它只是相对于“猫”和“狗”太不符合当前前缀了。

于是，训练回路可以先记成一条很短的链：

参数 → 原始分数（logit） → 概率 → NLL

三、NLL：衡量真实 token 有多意外

有了概率之后，就需要一把尺子去衡量：模型给真实 token 的概率到底够不够高？

这个负对数概率，就是 NLL，Negative Log-Likelihood，负对数似然的缩写，是一把绝佳的尺子，可以对每一个 token 的可能性进行度量。

对于某一个位置，真实出现的 token 是 xt​，模型给它的概率是 P(xt​∣x<t​,θ)，那么这个位置的 NLL 可以写成：

Lt​=−logP(xt​∣x<t​,θ)

为什么要加一个负号？因为概率通常在 0 和 1 之间，直接取对数会得到负数。加上负号之后，概率越高，NLL 越小；概率越低，NLL 越大。

模型如果给真实 token 很高的概率，说明这次延续并不意外，损失就小。模型如果把真实 token 放到了一个非常低的概率位置，说明这次延续让它很意外，损失就大。

最小化 NLL，就是让模型给训练文本中真实出现的 token 更高的概率。这里所说的规律，不是模型直接看见了一个完整的现实世界分布，而是训练预料所代表的语言内在的统计规律。这个内在的统计规律事先是不知道的，但是可以假设它固定存在，并通过大量观测到的文本逐渐呈现出来。

前面的文章里已经说过交叉熵和 KL 散度。把所有位置的 NLL 做平均，本质上就是在经验数据分布上计算交叉熵；而交叉熵又可以拆成熵和 KL 散度：

H(p,q)=H(p)+DKL​(p∥q)

其中，p 可以理解为训练数据代表的分布，q 是模型给出的分布。对模型参数来说，H(p) 是一个与参数无关的常数，所以最小化交叉熵，也就等价于让模型分布在 KL 意义上尽量靠近训练语料呈现出来的分布。

四、一段文本的概率：条件概率的乘积

单个 token 的概率还不够。一段文本的概率，其实是一系列条件概率的乘积。每一个步骤，都需要计算在给定前缀的情况下，下一个 token 的概率。

对于整段文本，只需要把每一个 token 位置处的下一个 token 概率算出来，依次相乘，就得到了整体的概率：

P(x1:T​∣θ)=t=1∏T​P(xt​∣x<t​,θ)

一旦对这个概率取对数，这些相乘的项就变成了加法。再加上负号，就得到了可以逐项累加的 NLL：

L=−t=1∑T​logP(xt​∣x<t​,θ)

这里有两个非常奇妙的地方值得说。

一个是概率都是小数，乘法越乘，数字越小。对于精度有限的计算机而言，这是一个非常大的挑战，容易出现浮点数下溢，最后小到无法表达。

另外一个是，乘法的计算开销通常也大于加法。NLL 累加的方式，让原本难以计算的连乘问题变得相对容易解决。

所以，取对数并不是为了把一个数学表达式写得更漂亮。它同时解决了两个实际问题：把乘法变成加法，也避免了长序列概率不断相乘后发生数值下溢。

五、概率和似然，究竟差在哪里？

概率和似然使用的是同一个表达式，却在回答两个方向相反的问题。

如果参数 θ 已经固定，我们问“这段数据在这个模型下出现的概率是多少”，这是概率。

如果数据 D 已经固定，我们反过来比较“哪一组参数更能解释这批数据”，这个函数就叫似然：

L(θ;D)=P(D∣θ)

似然的变量是参数，数据已经被观察到并固定下来。它不要求似然函数对所有参数的值加起来等于 1，因为参数并不是这里被描述的随机结果。

MLE 做的正是第二件事：固定训练文本，在参数空间里寻找一组让这批文本最可能出现的参数。

这就是为什么说，MLE 的优化目标不是“找到唯一正确答案”，而是“找到一组最能解释训练数据的参数”。

六、梯度在推动哪个方向？

前面的文章已经解释过梯度下降了，这里不再重复。只需要把视线放到 logit 这一层，就能看到 NLL 如何告诉参数该往哪里走。

设模型输出的 logit 是 zj​，Softmax 后的概率是 pj​，真实 token 的位置是 y。交叉熵对 logit 的梯度是：

∂zj​∂L​=pj​−1(j=y)

当 j=y 时，梯度是 py​−1，通常为负。梯度下降会把这个 logit 往上推。

当 j=y 时，梯度是 pj​，通常为正。梯度下降会把这些 logit 往下推。

所以在每一个 token 位置，训练都在做一件非常具体的事情：提高真实 token 的倾向，降低其他候选的相对倾向。

这依然是在调整概率分布，而不是把一条“标准答案”直接写进模型参数。

想回顾梯度下降，可以看《梯度下降：蒙着眼下山》；想回顾 Softmax，可以看《Softmax为什么不直接取最大值？》。

七、训练时一次看全句，生成时一次走一个 token

这里还藏着一个很容易被忽略的区别。

训练时，模型可以同时计算一整段序列中多个位置的预测。比如：

输入：我   喜欢   吃
目标：喜欢 吃     苹果

每一个位置的目标都是训练文本里真实出现的下一个 token。模型并不需要等自己生成出“喜欢”之后，才能计算第二个位置的损失；它可以直接使用训练文本里的真实前缀，这就是 teacher forcing。

在因果注意力的约束下，每个位置只能看见自己之前的内容，但多个位置的矩阵计算仍然可以并行完成。

生成时就完全不同了。模型先根据当前前缀预测一个 token，这个新 token 再成为下一步的前缀，模型继续预测下一个 token。它不能提前知道未来的真实答案，只能沿着自己刚刚生成出来的路径往前走。

所以，训练目标是海量局部条件概率的集合，而生成能力是这些局部预测在长序列上不断滚动之后的表现。

八、从 MLE 到能力：为什么会写代码，也为什么会胡说

当训练文本足够多、模型容量足够大时，模型会在参数中压缩大量的语言模式、代码模式和知识表达方式。

给定一个代码前缀，训练语料中常见的后续 token 会获得更高概率；给定一篇文章的开头，符合语言习惯的后续表达也会获得更高概率。许多连续的高概率局部选择串在一起，就表现成了完整的代码、文章，甚至一段看起来像推理的回答。

但“高概率”不等于“真实”。训练文本里有错误，世界本身有歧义，问题还可能落在训练分布之外。MLE 没有直接优化“这句话是否符合现实”，它优化的是这句话在训练数据规律下是否像一个合理的延续。

工具调用还要再多走一步。调工具的能力通常不是 MLE 预训练阶段单独教出来的，而是在之后的指令微调、工具轨迹训练、强化学习等后训练阶段，被进一步塑造成更稳定的行为模式。

这里有一个需要谨慎表述的部分业界认知：预训练建立了知识、表示和潜在能力空间，后训练可以改变模型在这个空间里的行为概率，并把某些行为稳定下来。因此，预训练基座很可能会对后训练能够达到的上限构成重要约束。但这不是一个已经被证明的“预训练结束就把能力上限锁死”的数学定理。

以 DeepSeek-V4-Pro 为例，DeepSeek 官方在 2026 年 8 月 13 日的 GA 公告中把 Agent 能力升级作为发布重点，并说明 API 模型名仍为 deepseek-v4-pro。官方 Hugging Face 模型卡则将 DeepSeek-V4-Pro-0813 标为 V4-Pro 的正式版本。这个例子说明的是后训练和模型形态的现实边界，并不意味着工具调用能力由 MLE 单独直接优化出来。

九、延伸：MLE 选一个点，贝叶斯保留一团分布

MLE 的视角是：找到一组最优参数，然后把这组参数交给模型。

如果有很多组参数都能把训练数据解释得差不多，MLE 最终仍然倾向于给出一个参数点。它告诉你“哪一组最可能”，但不太告诉你“这个答案有多确定”。

贝叶斯估计的想法不一样。它不只求解一组固定的参数，而是把参数本身当成随机变量，用后验分布来描述在观察数据之后，我们对参数的全部认识：

P(θ∣D)∝P(D∣θ)P(θ)

这个后验分布可以描述宽度、形状和方差，而不仅仅是一个离散的点。这里的“随机”主要是对参数不确定性的数学表达，不是说模型参数在物理上每次运行都会随机漂移。

这只是 MLE 的一个延伸视角：MLE 选一个最优点，贝叶斯估计保留一整团可能性。至于如何求解这团分布，就不在本文继续展开了。

十、这不是一个 bug，而是一个 feature？

Andrej Karpathy 用 jagged intelligence 描述过一种很有意思的能力形状：模型在某些任务上表现得非常聪明，在相邻的另一些任务上却突然掉下去。中文里把它叫作“锯齿智能”，其实非常形象。原始表述见这里。

现在再回头看开头那个问题，模型为什么会一会儿像博士生，一会儿像小学生？因为它优化的是大量局部条件概率，而不是一张能够覆盖所有现实问题的“智能刻度表”。某些任务落在高概率、熟悉、结构稳定的区域里，它就像博士生；另一些任务落在稀疏、含糊或分布外的区域里，它就可能突然失去方向。

这不是一个bug,而是一个feature！

你有没有被它的锯齿智能坑过？有没有哪个让你无语的时刻，模型刚刚还像一名博士生，下一句却突然变成了一个小学生？
