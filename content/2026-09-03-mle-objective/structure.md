## 2. 核心问题与文章承诺

开篇提出一个读者已经见过、但不容易解释的矛盾：一个看起来只会逐个预测下一个 token 的模型，为什么能写代码、写文章、调工具；与此同时，它又可能在基础问题上犯非常低级的错误，而且事先难以预测它这次会表现在哪个水平？

文章的回答不是“模型突然获得了某种神秘智能”，而是逐层拆开 MLE 的实际目标：模型在固定架构和训练文本下，调整参数，让真实出现的下一个 token 获得更高的条件概率。logit、概率、整段文本似然、NLL 和梯度，都是这条训练回路上的不同位置。

## 3. 建议正文结构

### 3.1 开头：它到底像博士生，还是像小学生？

- 直接使用作者关于“写代码、调工具、写文章”和“基础问题胡说”的原声段落。
- 把读者带入“能力落差无法事先预测”的困惑。
- 提出悬念：如果模型的基本动作只是预测下一个 token，训练时究竟在优化什么？

### 3.2 MLE 优化的不是一个标准答案

- 先固定神经网络架构、训练文本和参数符号 $θ$。
- 将作者的“预定义输出可能性最大”精确落到“训练文本中真实下一个 token 的条件概率尽可能大”。
- 强调模型输出的是一个概率分布，不是对错二元开关；真实 token 概率越低，意外越大，损失越高。
- 明确边界：MLE 最大化的是训练数据的似然，不直接最大化事实正确率、用户满意度、工具调用成功率或某种唯一答案。

可用公式：

$$
\hat{\theta}_{\mathrm{MLE}}=\arg\max_{\theta}P(D\mid\theta)
$$

对自回归文本展开为：

$$
P(x_{1:T}\mid\theta)=\prod_{t=1}^{T}P(x_t\mid x_{<t},\theta)
$$

### 3.3 Logit：概率出现之前，模型先给 token 打分

- 用通俗语言定义 logit：模型给每个候选 token 的原始分数或倾向值。
- 说明 logit 可以是负数或正数，不在 0 到 1 之间，也不要求加起来等于 1；它还不是概率。
- 说明 Softmax 是常见的归一化方式，但正文不把它说成唯一形式。
- 使用“猫、狗、兔、企鹅”的四个分数做可视化：猫 5、狗 3、兔 -2、企鹅 -100。
- 只展示归一化后的近似结果：猫约 88.0%、狗约 11.9%、兔约 0.08%、企鹅接近 0；补一句“接近 0 不等于严格不可能”。
- 形成一条易记的链：参数 → 原始分数（logit）→ 概率 → NLL。

### 3.4 NLL：衡量真实 token 有多“意外”的尺子

- 使用作者关于“负对数概率”和 NLL 的原声。
- 技术上写成单个位置的损失：

$$
L_t=-\log P(x_t\mid x_{<t},\theta)
$$

- 概率越高，负对数越小；真实 token 概率越低，NLL 越大。
- 连接到训练预料所代表的语言内在统计规律：这个规律事先未知，但通过大量样本以统计形式呈现。
- 简短引用前文的交叉熵与 KL 散度：平均 NLL 可以看作经验分布上的交叉熵，和真实/经验分布之间的 KL 关系留给前文，不在本篇重新推导。

### 3.5 一段文本的概率：条件概率的连乘，NLL 的累加

- 使用作者“一段文本的概率”原声，修正“成绩”为“乘积”。
- 先写链式法则：

$$
P(x_{1:T})=\prod_{t=1}^{T}P(x_t\mid x_{<t})
$$

- 取对数后，乘法变成加法，负号后得到累加的 NLL：

$$
L=-\sum_{t=1}^{T}\log P(x_t\mid x_{<t})
$$

- 重点解释概率连乘会越来越小，计算机容易遇到浮点数下溢；“溢出”在正文中校正为“下溢”。
- 计算开销的差异只作为补充，主因仍是链式分解和数值稳定性。

### 3.6 梯度究竟在推动什么？

- 引用此前梯度下降文章，不重复解释梯度下降本身。
- 在 logit 层给出交叉熵梯度：

$$
\frac{\partial L}{\partial z_j}=p_j-\mathbf{1}(j=y)
$$

- 用一句话说明：真实 token 的 logit 被推高，其他 token 的概率相对被压低；这仍然是在调整分布，而不是直接把“答案”写进参数。
- 这一节作为从直觉回到训练更新的桥，不展开完整反向传播。

### 3.7 训练时一次看全句，生成时一次走一个 token

- 训练时采用 teacher forcing 和错位标签，例如输入“我 喜欢 吃”，目标是“喜欢 吃 苹果”。
- 同一个序列的多个位置可以并行计算每个真实下一个 token 的损失。
- 生成时前一个输出会成为新的前缀，必须逐 token 继续预测。
- 由此解释：训练目标是大量局部条件概率的集合，生成能力是这些局部预测在长序列上不断滚动后的表现；局部概率目标并不保证每一步都符合事实或常识。

### 3.8 从 MLE 到能力：为什么会写代码，也为什么会胡说

- 先区分预训练与后训练：工具调用通常是 MLE 预训练之后的指令调优、强化学习或其他后训练行为。
- 用谨慎表述呈现部分业界认知：预训练建立知识、表示和潜在能力空间，后训练改变行为概率并稳定某些行为；预训练基座可能对能力上限形成重要约束，但不要写成已证明的绝对定律。
- 以 DeepSeek-V4 做现实模型落点，只讲与本文概率化主线直接相关的抽象现象，不展开架构和参数细节；起草时实时核验一手资料。
- 回到开头：MLE 让模型越来越擅长生成训练分布中高概率的延续，但“高概率”不等同于“真实、可靠、适合当前任务”。

### 3.9 延伸：MLE 选一个点，贝叶斯保留一团分布

- 用一小节区分两种视角：MLE 找到一组最优参数；贝叶斯估计在观察数据后得到参数的后验分布。
- 公式只保留核心关系：

$$
P(\theta\mid D)\propto P(D\mid\theta)P(\theta)
$$

- 说明后验可以表达分布的宽度、形状和方差，从而描述参数不确定性；不展开求解方法。
- 作为“MLE 只给一个点”的补充，不改变全文主线。

### 3.10 收束：这不是一个 bug，而是一个 feature？

- 引入 Andrej Karpathy 所说的 “jagged intelligence”，把“锯齿智能”作为对能力不均匀的描述。
- 保留作者反讽句：“这不是一个bug,而是一个feature！”
- 反问读者：有没有被这种锯齿智能坑过？有没有一个让你无语的时刻，模型从“像博士生”突然变成“像小学生”？

“看起来只能一次预测下一个token的模型，在经过了海量文本的预训练之后，却突然具备了写代码、调工具、写文章的能力，这是让很多第一次接触的人感到极度惊讶的一个现象。不过很快你就能发现，这个模型有时候会在一些非常基本的问题上，一本正经地胡说八道，犯下一些小学生都不会犯的错误，更麻烦的是，很多时候你更本无法事先预测这次它是表现得像一名博士生，还是一个小学生。”

### R02｜MLE 定义

“MLE的优化目标，是在给定训练文本输入的情况下，寻找到一组参数，让模型在给定的神经网络架构设定下，产生预定义的输出的可能性最大。”

“对，同意。这个负对数概率，就是NLL负对数似然的缩写，是一把绝佳的尺子，可以对每一个token的可能性进行度量，最小化它，就是最小化这个概率和实际世界上，语言规律中的组合概率的差距。”

### R06｜概率、似然与贝叶斯

“可以，似然和概率的区别是非常重要的。如果有空间，我也想来探讨下贝叶斯估计的想法，它求解的就不是一组固定的参数，而是把参数本身看作是随机变量来求解。它能刚好地描述分布的宽度/形状/方差等，而不仅仅是一个个离散的点。”

### R07｜Logit 解释

“假设通过计算得到一个从负无穷大到正无穷大的一个实数，希望用这个实数来表述一个概率，那么根据概率论基本公设，这个实数必须要能够转换为一个0到1之间的数字，并且需要满足所有这些原始描述概率的数，转换后的数字概率之和必须为1. 统计学里面，将这些原始数字成为logits，转换后得到概率的函数一般常见的是softmax，或者其他具备类似归一化特征的函数。有了这些概率，就可以很容易地用求和的方式计算NLL了。”

### R08｜Logit toy example

“打分可以用猫，狗，兔，企鹅，分别打分5, 3, -2, -100”

### R09｜整段文本概率与 NLL

“一段文本的概率，其实是一系列的概率的成绩，每一个步骤，都需要计算在给定了前缀的情况下，下一个token的概率（即条件概率），对于这整段文本，只需要将每一个token的位置处，下一个token的概率计算出来，依次相乘，就得到了整体的概率。然后对这个概率，做对数似然，这些相乘的项都变成了加法，从而将很难计算的乘法操作变成了加法。这里有2个非常奇妙的地方值得说，一个是概率都是小数，乘法越乘，数字越小，其实对于精度有限的计算机而言，是一个非常巨大的挑战，容易引起浮点数操作溢出而无法表达的情况。另外一个是乘法的计算开销也大于加法。NLL累加的方式，让难以计算的问题变得相对容易解决。”
