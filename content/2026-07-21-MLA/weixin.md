## 你的显存，可能不是被模型权重吃掉的

你不必自己装过服务器，也可能听过 RTX 4090：它是很热门的消费级高性能显卡，配有 **24GB 显存**。24GB 听起来不少；可一旦让 AI 读很长的文档、持续对话，显存仍可能很快见底。

很多人第一反应是：“模型太大了。”这只说对了一半。

模型权重像一本已经印好的百科全书：加载进显存后，大小基本不再变化。真正会在对话过程中不断变胖的，是 **KV cache**——模型为记住前文留下的一摞“阅读笔记”。

> 模型权重像煤矿：挖出来、放在那里，体积基本固定。
>
> KV cache 像进出矿区的货车：每说一句话又来一辆，越积越多，最后把路堵住。

以 LLaMA-3-70B 为量级参照，在 BF16 精度、100K 上下文下，模型权重大约是 140GB，KV cache 约 31GB。它还没有超过权重，却已经相当于一张 24GB 显卡的全部显存；上下文继续变长，权重不动，KV cache 还会继续长。

> 注：这里的计算基于 BF16（16 位，每参数 2 字节）。今天的模型几乎不会这样存储权重——今天的模型早已推进到 INT8/INT4 甚至更稀疏的量化，以 INT4 为例，70B 权重大约只有 35GB，但 KV cache 该 31GB 还是 31GB，此消彼长之下 KV cache 反而成了更大的那个。后面的比例图如果按量化权重重画，KV cache 的占比还会更高。

![](01-kv-ratio.png)

所以，判断一个模型能否处理长文本，不能只问“它有多少 B 参数”，还得问：**每多一个 token，它要留下多少 KV cache？**

## KV cache 到底在记什么？

关于 Q、K、V 的详细讲解，请参阅前文《注意力机制是什么？》。这里先抓住最关键的一点：模型生成下一个 token 时，需要拿当前的 Query 去查询前面所有 token 的 Key，并按结果汇总对应的 Value。

前文的 K 和 V 如果每次都重新计算，速度会慢得不可接受；于是模型把它们缓存进显存。这份缓存，就是 KV cache。

每生成一个 token，KV cache 就多一条记录；每一层注意力都要留记录。因此它的大小近似满足：

> **KV cache ∝ 层数 × 上下文长度 × KV 头数 × 每头维度**

它最容易被忽略的性质是：**线性增长，而且不会自己停。** 上下文从 32K 翻到 128K，KV cache 也翻四倍。模型权重一字未增，显存预算却可能已经不够。

在[《为什么 AI 上下文越长越慢？》](https://mp.weixin.qq.com/s/PLVRS0TTHXHDve1Z3r6M7Q)里，我们讲过长上下文的两道墙。KV cache，就是其中那道“存储墙”的砖。

> 想象你在墙上贴便利贴记录会议。每说一句就贴一张。会议越久，墙上的纸越多；想回答一个问题时，你得从全部便签里找线索。墙的面积有限，贴满了，会议就开不下去。

## 先少留几份笔记：GQA 还不够

一个直接的办法是 GQA（Grouped-Query Attention）：让多个 Query 头共用同一组 K、V。好比原来每个人各有一名秘书记笔记，现在几个人共用一名秘书；KV cache 会小很多。

但 GQA 仍然在保存完整的 K、V 向量，只是副本变少了。它像“少请几位秘书”，不是“把笔记写得更短”。

DeepSeek 的 MLA（Multi-head Latent Attention，多头潜在注意力）换了一个问题：**能不能不存全文，只存一份足够用的摘要？**

> GQA：少存几份完整笔记。
>
> MLA：存一份压缩摘要，需要时在计算里使用它。

这正是标题里“省下约九成”的含义：它说的是 **KV cache 这笔开销**，不是说一台机器的全部显存都会自动少九成。

## MLA 的三步：摘要、改写问题、另存位置

MLA 的设计看似复杂，直觉其实只有三步。

![](02-mla-flow.png)

### 第一步：先写摘要，不存完整笔记

传统注意力会把每个 token 的完整 K、V 都存下来。MLA 先把当前 token 的隐藏状态压到一个更小的潜在向量 cᴷⱽ。在 DeepSeek-V3 的公开配置中，这个 KV latent 的维度是 **512**。

它不是随便删掉信息，而是由训练过程学出一份对注意力最有用的“摘要”。缓存里留下的是 cᴷⱽ，而不是每个注意力头各自的一整套 K、V。

### 第二步：不解压，改写提问方式

“只存摘要”最自然的疑问是：要算注意力分数时，不还是得把完整 K 解压出来吗？

关键在矩阵乘法的结合律。若完整 Key 可以写成 K = Wᵁᴷ · cᴷⱽ，那么：

> **Q · (Wᵁᴷ · cᴷⱽ)ᵀ = (Q · Wᵁᴷ) · (cᴷⱽ)ᵀ**

左边是“先还原完整 K，再提问”；右边是“先把 Q 的提问方式改写，再直接问摘要”。结果相同。于是推理时不必把每一条历史记录真的解压成完整 K，这就是 **矩阵吸收**。

### 第三步：位置单独记，别把它搅进摘要

还有一个麻烦：K 不只携带内容，还携带位置。RoPE 位置编码会告诉模型“这个词在第几个位置”。如果把位置旋转和内容压缩硬混在一起，前面的矩阵吸收就不再好用。

DeepSeek 的做法是 Decoupled RoPE（解耦 RoPE）：

- 内容走压缩通道，留下 cᴷⱽ；
- 位置走独立通道，留下很小的 RoPE key；
- 两路在计算注意力时再共同发挥作用。

可以把它理解为：会议纪要写摘要，日期和座位号放在单独的索引卡上。摘要可以很短，索引也不会丢。

## “省下90%”到底是怎么比较的？

这里需要把口径说清楚。

DeepSeek-V2 的技术报告做过成对实验：在其他架构尽量对齐的条件下，把注意力机制分别设为传统 MHA 和 MLA。结果是，MLA 的 KV cache 在小型 MoE 对照中是 MHA 的 **14%**，在大型 MoE 对照中是 **4%**。

换句话说，KV cache 分别减少了 **86%** 和 **96%**。标题里的“90%”是这个区间的通俗说法，不是承诺所有模型、所有显存都固定减少 90%。

| 对照实验 | MHA 的每 token 缓存 | MLA 的每 token 缓存 | MLA 保留比例 |
|-----------|-------------------:|-------------------:|-------------:|
| 小型 MoE | 110.6K 个元素 | 15.6K 个元素 | 14% |
| 大型 MoE | 860.2K 个元素 | 34.6K 个元素 | 4% |

> 上表来自 DeepSeek-V2 技术报告 Table 9。元素数量与实际占用的字节数还会受精度影响，但比例关系不变。

表中的"元素"数指的是每 token 的 KV 缓存中需要存储的标量个数：MHA 要为每一层存完整的 Key 和 Value 向量，MLA 只存压缩后的低维潜向量，因此元素个数大幅减少。元素个数乘上存储精度才是实际占用的字节数。

这也解释了为什么不要把不同模型的一串“KB/token”直接当成 MLA 的唯一成绩单：模型层数、KV 头数、头维度和缓存精度都会改变绝对值。比如 DeepSeek-V3 的公开配置是 61 层、512 维 KV latent、64 维 RoPE key；按 BF16 存储计算，KV cache 约为 **70KB/token**。这个数字适合估算 V3，却不是所有模型共用的常数。

## 压缩这么多，为什么不等于“把记忆忘掉”？

MLA 当然不是魔法，也不意味着把任意信息压小后都毫无损失。它的目标很具体：让后续 token 仍能得到足够好的注意力关系，而不是逐字节复原过去所有 K、V。

DeepSeek-V2 的成对实验里，MLA 不仅缓存更小，在报告列出的 BBH、MMLU、C-Eval、CMMLU 等测试上还不弱于对应的 MHA 对照。原因不在于“压缩必然无损”，而在于这个投影矩阵会和模型一起训练：模型会学着把对注意力最重要的关系留下来。

这就像把一本书做成给考试用的提纲。提纲不等于原书；但如果提纲是围绕题目反复训练出来的，它可以比逐页翻书更高效。

## 回到显存这笔账

MLA 省的不是模型参数，而是推理时每一层都在累积的历史记录。

它用低秩摘要减少要存的内容，用矩阵吸收避免把摘要重新展开，再用解耦 RoPE 单独保留位置信息。DeepSeek-V2 的同架构实验给出的结果，是 KV cache 节省 **86%–96%**。

所以，下一次看到“支持 128K 上下文”的模型，别只看参数量。再多问一句：**它每个 token 要留下多少 KV cache？它用的是 MHA、GQA，还是 MLA？** 这往往比“多少 B”更能决定长对话到底跑不跑得动。

MLA 解决的是“存得下”；但上下文极长时，模型仍要面对全部历史记录。怎样从海量记录里更快找到真正相关的部分，是另一道题。

值得补充的是，**KV cache 本身还可以继续量化压缩**，而且已经是推理栈的标准操作：
- **INT8** 几乎零精度损失，被 OpenVINO 设为默认；
- **INT4** 在 LMDeploy、vLLM 等框架普遍可用，2026 年的新技术（如块对角 Hadamard 旋转）把精度损失压到了 1–3 分；
- 更激进的做法是 **Key 4-bit + Value 2-bit 的混合精度**（如 TurboQuant），平均 3-bit 就能近无损运行。

MLA 先通过低秩蒸馏把每 token 的缓存从 110K 元素压到 15K，**量化再在 15K 的基础上把存储位宽砍到 1/4 甚至 1/8**。这套“蒸馏 + 量化”的双重压缩，让 DeepSeek-V3 的 KV cache 在 70KB/token 的基础上还能再降几倍。

回到主线，下一篇我们讲⑥**归一化：61 层网络为什么不崩？**

> 📎 预告：MLA 并不是终点。注意力机制的演进路线比很多人想象的要丰富：**MLA（低秩压缩）→ NSA（原生稀疏注意力）→ DSA（DeepSeek Sparse Attention）**，每一步都在解决上一步遗留的问题——NSA 让注意力只聚焦真正重要的序列位置，DSA 用 Indexer 从全部历史中硬性选出最相关的 top-k 个 token。至于 DeepSeek-V4，又在这条线上走出了非常不同的路。后面的文章会逐一拆解这段演进，这里先留一个楔子。

## 附录：为什么压缩后，关系还能大致保留？

高维概率论里有一个很有用的结论，叫 **Johnson–Lindenstrauss（JL）引理**。它说：如果把有限个高维点随机投影到一个足够低、但并非过低的新空间，这些点之间的距离通常能在小误差内保住。直觉上，随机投影不是只看一个方向，而是在许多方向上“平均取样”；单个坐标会丢，点与点之间的相对关系却常能留下。

注意力关心的恰好是向量之间的点积和相对相似度，而不是必须逐坐标还原完整向量。因此，JL 引理给了一个直觉：**保存“关系”所需的空间，可能远小于保存“原样副本”所需的空间。**

MLA 不是直接套一个随机矩阵。它的下投影、上投影会随训练数据一起学习，目标也不是保证任意向量都完美保真，而是让语言模型在任务中保留足以计算注意力的信息。所以更准确的说法是：JL 引理帮助我们理解“低维仍可能保住关系”；MLA 则把这个想法变成一个由数据学习、并由实验检验的工程设计。

![JL引理直观图解：高维空间的点经过随机投影到低维空间后，单个坐标丢失，但点间距离关系近似保留](05-jl-lemma.png)
