## 正文结构

### 📐 第一层：信息缺口（~400字）—— "你的 GPU 显存其实被一个你不知道的东西吃掉了"

**生活类比：便利贴墙**
- 想象你在墙上贴便利贴记录会议内容。每说一句话就贴一张。4 小时的会议，墙上贴了 3000 张便利贴。你想回顾第 1 句话时，需要从 3000 张里找到相关的几张。
- AI 推理也一样：每个 token 都会生成 K、V 两个向量，全部存在显存里，叫做 **KV cache**。
- 真实数字：LLaMA-3-70B 在 100K 上下文下，KV cache 占 **160GB** 显存——而模型权重才 140GB。
- 信息缺口：多数人以为推理慢是因为"模型太大"，其实 80% 的显存被 KV cache 吃掉。

**回链 07-04**：上一篇[为什么 AI 上下文越长越慢？](https://mp.weixin.qq.com/s/PLVRS0TTHXHDve1Z3r6M7Q)我们讲过，上下文长度是推理的硬墙。KV cache 就是那堵墙的砖。

### 📐 第二层：概念引入（~300字）—— "KV cache 是什么？为什么它这么大？"

**一句话回链 ④**：
> 在[注意力机制](链接④)那篇我们讲过，每个 token 会生成 Q、K、V 三个向量。推理时，前面所有 token 的 K、V 必须缓存下来供后续 token 使用——这就是 KV cache。

**量化 KV cache 大小**：
- 公式：KV = 2 × L × T × n_h × d_h bytes
- 每个 token 的 K 和 V 都要存，每层都存，每个头都存
- 为什么减 KV 头数能省显存？GQA 把头数从 32 减到 8，缓存降到 1/4（④已讲过）

### 📐 第三层：解决方案揭秘（~600字）—— "DeepSeek 的数学魔术：三步压缩 32 倍"

**MLA 的三步数学魔术**：

① **低秩投影**：K = W^{UK} · (h · W^{DK})，把 d_h 压缩到 d_c（~128）
- 不直接存 K，而是存一个压缩后的"摘要" c_t^{KV}

② **矩阵吸收**：W^{UK} 预乘进 Q^T 和 V
- 推理时只需存压缩后的 latent c_t^{KV}，不再需要展开成完整 K

③ **Decoupled RoPE**：Q/K 各拆两路
- 一路走低秩压缩，一路单独加 RoPE（位置编码）
- 为什么？RoPE 会污染压缩维度，必须解耦

**压缩比**：
- V3 中 d_c = 512 vs n_h · d_h = 128 × 128 = 16384
- 压缩比：**32 倍**

**为什么压缩 32 倍不损失质量？**
- JL 引理：保留点积（注意力分数）需要的维度远小于保留向量本身
- 薄壳现象：高维向量的能量集中在低维子空间
- 学习的投影 ≈ 4× 优于随机 JL 投影

### 🔧 第四层：算法层（~300字）—— "矩阵吸收前后对比"

**伪代码对比**：
```
# 吸收前：存 K_full，推理时算 Q @ K^T
K_full = W_K @ h          # 完整 K 向量
score = Q @ K_full.T      # 注意力分数

# 吸收后：存 c^{KV}，推理时算 (Q @ W^{UK}) @ (c^{KV})^T  
c_kv = W_DK @ h           # 压缩后的 latent
score = (Q @ W_UK) @ c_kv.T  # 数学上等价，但只需存 c_kv
```

**RoPE 为什么让矩阵吸收失效**：
- 位置编码混进压缩维度，破坏低秩结构
- Decoupled RoPE 的解决方案——分开两条"血管"

### 🧪 第五层：实测层（~300字）—— "三个场景的显存对比"

| 场景 | 上下文长度 | GQA (LLaMA-3) | MLA (V3) | 压缩比 |
|------|-----------|---------------|----------|--------|
| 短文本 | 4K | ~2GB | ~0.06GB | 33× |
| 长文档 | 32K | ~16GB | ~0.5GB | 32× |
| 极端 | 128K | ~64GB | ~2GB | 32× |

**精度维持验证**：同等显存下 MLA vs GQA 在 LongBench 得分持平

### 🔄 回扣 + 预告（~200字）

**回扣**：
MLA 省的不是参数，是推理时每一层都要存的历史记录。省 90% 显存 = 同样的 GPU 能跑 10× 长的上下文。

**预告 D4**：
但 MLA 有一个它自己解决不了的问题——它只能压缩，不能跳过。100 万 token 的上下文，即使压缩 32 倍，KV cache 仍然需要存全部 token 的记录。V4 的答案不是"压缩"，而是"选择"——只计算真正相关的 token。这就是 CSA 的故事，我们 D4 讲。
