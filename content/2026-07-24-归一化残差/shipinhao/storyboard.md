## 段落设计（8 段）

| # | 场景 | 动画要点 | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子 | 61 层 Block 堆叠（3 层示意 + 「×61」）；每层开头黄色高亮 Norm 块；残差箭头直通示意；大标题「归一化为什么总在前面？」 | 61 层的模型，训练为什么不崩？答案藏在每一层开头的那一步：归一化。等等——残差连接不是已经开了直通车吗？信号有路走，为什么还要稳压器？这条视频讲清楚：归一化，为什么总放在前面。 |
| S2 | 捷径保真 ≠ 尺度不变 | 残差块图：x 直通捷径 + F(x) 分支汇合；向量长度对比（同向≈2 倍 / 反向≈抵消）；「原件没丢，稿子失控」文档比喻（原件档案不动 + 修改意见越并越多） | 先看残差：捷径这一路，原样通过，长度不变。但真正送进下一层的，是 x 加上子层的输出。同向，长度最多翻倍；反向，可能几乎抵消。几十层滚下来，文档没丢，稿子却失控了。捷径保住了原件，可整体尺度，谁说了算？ |
| S3 | LayerNorm 每 token 自己算 | 单 token 向量条（7168 个数字）→ 算均值 μ → 方差 σ → 减均值除标准差；两张卡片：银行 ±50 / 贷款 ±2；「一起算」小数字被吞（红叉）vs「分开算」各自保留 | 答案：归一化。它不擦信息，只管尺度。以 LayerNorm 为例：一个 token 有 7168 个数字，先算均值，再算方差，减去均值，除以标准差。注意。每个 token，自己算。"银行"在正负 50 的区间，"贷款"只有正负 2。一起算，小数字会被吞掉；分开算，谁都不被洗掉。可减均值这一步，真的非做不可吗？ |
| S4 | RMSNorm 省掉减均值 | LayerNorm 两步 vs RMSNorm 一步对比卡；「减均值」盖红叉；均方根缩放保留（黄色）；梯度爆炸警告小图标 | 大模型说：不是。RMSNorm 直接跳过减均值，只按均方根缩放。子层真正怕的，是数值过大导致梯度爆炸，不是输入偏正偏负。省一步，计算更轻，关键的尺度控制还在。可别以为归一化只是训练技巧——低精度下，它决定计算会不会崩。怎么个崩法？ |
| S5 | BF16 数值刚性需求 | 尾数位数对比条（FP32 23 位 vs BF16 8 位）；logits 误差「>80% 元素误差 >0.01」大数字；eps 安全网示意（分母逼近 0 被 1e-6 兜住） | 今天训练推理普遍用 BF16，八位尾数，能表示的最小精度在十的负八次方量级。开发者社区实测过：同一份代码，BF16 跑出的 logits，超过 80% 的元素误差超过 0.01。根源就在归一化附近的一次低精度乘加。DeepSeek-V4-Pro 把 eps 设为十的负六次方——FP32 下几乎可忽略，BF16 下，是刚性安全网。可归一化放哪个位置，差别巨大。放后面，会怎样？ |
| S6 | Pre-Norm vs Post-Norm（核心） | 并排两个 block：Post-Norm（Norm 在后）梯度回传箭头逐层穿过 Norm 衰减闪烁 vs Pre-Norm（Norm 在前）残差主路黄色直达箭头；warm-up 躲爆炸小标签 | 原始 Transformer 用 Post-Norm：先做子层，加残差，再归一化。但梯度回传，必须逐层穿过 Norm，缩放因子随输入尺度变，多层连乘，梯度指数级放大或衰减——早期训练尤其危险。Pre-Norm 把 Norm 挪到子层前面：先稳住输入，再做增量，加回主路。梯度在残差主路上，几乎不衰减。放在前面，不是装饰，是立规矩。那代码，长什么样？ |
| S7 | 四行代码 + DeepSeek-V4-Pro | 4 行伪代码块，两次 rms_norm 黄色高亮、两次加法绿色；节奏循环「先稳住→做增量→加回」；DeepSeek-V4-Pro 参数卡（61 层 / 7168 / eps 1e-6 / hc_mult 4）；Hyper-Connections 4 车道示意（4 份隐藏状态汇合） | 四行。先稳住 Attention 的输入，加回原始状态；再稳住 FFN 的输入，再加回。没有一行是"把残差归一化"。节奏就八个字：先稳住，做增量，再加回。61 层的 DeepSeek-V4-Pro 就是这么写的：隐藏宽度 7168，Attn 和 FFN 前各一个 RMSNorm。它的残差还升级了——Hyper-Connections，四份隐藏状态一起混合，但归一化依然守在每条车道入口。四份状态怎么混？ |
| S8 | 总结 + 品牌尾卡 | 三职责卡：捷径保通路 / 归一化管尺度 / Pre-Norm 排顺序；尾卡：avatar-sjai-round.png 圆角图 + 黄色「关注「数解AI」」+ 当期文章标题 + 「查看公众号文章」绿色引导 + 下一篇预告 | 回头看：捷径保住信号的通路，归一化管住每次加工的尺度。61 层不崩，靠的不是一个神招，而是分工，加上正确的顺序。残差主路，你想让它保持纯粹的直通，还是也学会混合多份状态？评论区聊聊。下一篇，跟一句话走完 Transformer 全景，把注意力、FFN、残差、归一化串成一条闭环。 |

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（tts.txt = 8 段合并）+ `--subtitle` 句子级时间戳 → `scripts/tts_split.py` 按时间戳切分 8 段（克隆音色 `branding/my-voice-denoised.wav`，speed 1.15 pitch +2，speech-2.8-turbo）
2. 动画：每段一个 Manim Scene（S1..S8），`construct` 末尾 `pad_to_voice()`；动画节点按台词时间轴铺满（≥80% 配音时长）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：Cover 场景单帧渲染（复用 Pre-Norm block 视觉）→ `<标题>-封面.png`（1080×1920）
5. 归档：`content/2026-07-24-归一化残差/shipinhao/`
