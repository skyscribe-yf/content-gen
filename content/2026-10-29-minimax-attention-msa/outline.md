## 定位

MiniMax 在 22 个月里对注意力做了三次方向性选择：7:1 混合线性注意力（Text-01）→ 全注意力回调（M2）→ MSA 块稀疏（M3），M3.1 Flash 又把最后三层全注意力也换成了稀疏。

**这不是一篇 MSA 机制说明书，而是一篇「为什么同一家公司两次推翻自己」的决策拆解。** 面向被「1M 上下文」成本折磨的工程读者，给出一条可复用的判据：稀疏能不能上生产，不看 FLOPs 省多少，看选择器有没有被当成一个「要训练的部件」——而不是训练完再硬换上去。

## 交付句

- **转 1**：1M 上下文里，每个 query 每层只看 16 个 128 token 的块 = **2048 个 token**；主分支仍是精确 softmax，省掉的是「看谁」，不是「怎么算」。
- **转 2**：SWA-CPT 失败、MSA-CPT 成功，差别不在 CPT 本身，在索引器有没有先热身 40B token、学会对齐主分支的注意力分布，再接管路由。
- **转 3**：28.4× 是 FLOPs，H800 墙钟只有 prefill 14.2× / decode 7.6×；稀疏不是免费午餐，是把账单从「全量点积」挪到了「索引、top-k、gather、combine」。

### 一、三次转向：先押线性，再退回全量，最后只算 2048 个（约 350 字）

- Text-01（2025-01）：每 7 层 lightning attention + 1 层 softmax，80 层，456B / 45.9B，1M 训练、4M 外推。线性注意力省 KV、省算力，但论文自己承认**检索能力有限**，才插 softmax 补。
- M2（2025-10）：全注意力 GQA，62 层，229.9B / 9.8B，192K。官方复盘三条理由：小规模榜单打平、大规模多跳推理掉；SWA 各种混合做遍全负；CPT 改不动预训练早期成形的 retrieval / induction head。
- M3（2026-06）：MSA 块稀疏，428B / 23B，1M。不是回到线性，也不是固定滑窗，而是**保留 softmax、只挑块**。
- 三行表（Text-01 / M2 / M3：注意力设计、总参/激活、上下文）。
- **【槽 2】** 45.9B → 9.8B → 23B 这条激活曲线之后的判断 / 吐槽。
- 内链：Kimi K3 KDA（线性注意力那条路）、智谱阿里拆注意力（混合路线）、四家 KV 账本（1M 上下文的 KV 开销）。

### 二、MSA 怎么选：128 个 token 一盒，每个 group 自己列调阅单（约 350 字）

- 两阶段：Index Branch 先选块，Main Branch 只对选中的块做精确 softmax。
- Index Branch 极轻：每个 GQA group 一个 index query 头，全局共用一个 index key 头；先给 token 打分，再按 128 token 一块做 max-pool，取 top-16；**local block 无条件常驻**。
- 选择结果按 GQA group 共享：一个 group 里 16 个 query 头共用一张调阅单。
- Main Branch：只算 16 × 128 = 2048 个 token；「候选可以少，精度形式不缩水」。
- 档案盒比喻（只在这里用一次，三句话内）：1M token 是一屋子卷宗，128 页一盒，每层只调 16 盒；每个 group 自己列单，不是全公司共用一张。
- FLOPs 对比式：`F_GQA = 2 Hq dh N²`；`F_MSA = Hkv didx N² + 4 Hq dh N kBk`；1M 处 28.4×。
- **【槽 3】** 档案盒比喻之后的类比 / 亲历（怎么跟人解释「按块选」和「按 token 选」）。
- 内链：NSA 篇（三分支 vs 两分支、token 级 vs 块级、全头共享 vs per-group）、V4.1 四十层（lightning indexer / 跨层复用）。

### 三、索引器怎么学会选：先当 40B token 的学徒，再接管路由（约 400 字）

- 难点：top-k 不可微，语言建模损失传不到 index 投影。
- 解法：KL 对齐——让 index 分支的分布去对齐主分支在该 group 上、选中 token 上的平均注意力分布。
- 两个 stop-gradient：teacher 分布 detach；index 分支输入 `X` 也 detach，辅助损失只更新两个 index 投影，不污染主干。
- 40B token warmup：先两分支都跑全注意力、只训索引器；热完再切稀疏，让它接管路由。
- local block 常驻：防止退化选择把 query 自己的邻域丢掉。
- 档案管理员回收一次：管理员先跟着老馆员学归类，再自己列调阅单。
- 对照 SWA-CPT：SWA 是固定规则，MSA 的选择器是学出来的；MSA-CPT 从 2.6T 全注意力 checkpoint 接 400B（前 40B warmup）能成，SWA-CPT 败在「全局模式早期定型、事后改不动」。

### 四、为什么这次能上生产：三个条件同时成立（约 350 字）

- 条件一：选择器可训练（KL + warmup + stop-grad），不是事后硬换。
- 条件二：主分支保留精确 softmax，只缩小支撑集，不改变注意力形式。
- 条件三：kernel 协同设计，把 FLOPs 变成墙钟：
  - exp-free top-k：softmax 保序，直接排原始分，跳过 max/exp/sum；每线程寄存器维护 k 元小顶堆。
  - KV-outer：以 KV 块为外循环，聚合命中它的 query，每块只读一次；两阶段 LSE combine 处理 split-K。
  - 预调度分块：热门块（sink 行）拆给多个 CTA，避免单块拖垮。
- 账本：H800 上 prefill 14.2× / decode 7.6×；M3 对比 M2 在 1M 处 prefill 9× / decode 15×，单 token 算力 1/20。
- **【槽 5】** 三个条件之后的判断：哪个最容易被团队低估？
- 内链：V4.1 四十层（索引成本与上下文长度脱钩）可放这里或第二节，二选一，不重复。

### 五、账单的另一面：三条不能忽略的边界（约 300 字）

- 检索残差：HELMET-128K 总体 −0.60（Rerank/RAG −2.10）；RULER-128K 总体 +0.12，但 CWE/FWE −1.35。不是全面打平，是「多数打平、检索略亏」。
- FLOPs ≠ 墙钟：28.4× 是理论算力；索引构建、top-k、反向索引、query gather 都要花钱，实际只兑现到 14.2× / 7.6×。
- 规模缺口：消融在 109B / 3T，生产 M3 是 428B；MSA 与全注意力在 428B 上的差距没有公开消融。
- **【槽 6】** 看到 28.4× 与 7.6× 的落差之后的吐槽 / 判断。
- 内链：MASA 篇（稀疏注意力是矩阵逼近，不是挑 mass；扔掉的列里可能藏着高分数）。

### 六、M3.1 把保险也撤了：稀疏从「可选优化」变成「模型语义」（约 250 字）

- QAT 一句带过：路由专家压到 W4A4、注意力 KV 压到 4 位；链 FP4/QAT 篇，不展开。
- 账本：线上推理快近 3×、agent 综合成本 −70%、200+ TPS（P50 170+）、$0.15 / $0.60 / $0.015 每 1M token。
- 关键判断：稀疏不是推理时的一个开关，模型就是按稀疏训练的；把它当 dense 跑，是分布外近似。
