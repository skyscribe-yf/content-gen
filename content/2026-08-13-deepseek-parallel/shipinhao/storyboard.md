# 《1.6T参数怎么塞进GPU？V4五维并行策略》视频号分镜脚本

基于 content/2026-08-13-deepseek-parallel/weixin.md
规格：竖屏 1080×1920 · Manim 动画 · 精英男声 TTS 配音（speech-2.8-turbo，speed 1.0 pitch +2）+ 烧录字幕 · 目标 3-4 分钟

## 段落设计（6 段）

| # | 场景 | 动画要点（每页 1 个主视觉动效） | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子：1.6T 塞不进 80GB | 概念图（塞行李箱）→ 20 倍数字滚动 → 问句爆点 | 一块 H800 只有 80G 显存，DeepSeek-V4-Pro 却有 1.6T 参数——差了 20 倍。怎么塞进去，还让它跑得动？答案是切：按层切、按矩阵切、按数据切、按专家切、按序列切。五把刀，各切一刀。 |
| S2 | 先算账：显存不是瓶颈 | 推理 20 卡/11 卡对比 → 训练 16GB/卡 → 转折爆点 | 先算账。FP8 精度下每个参数 1 字节，1.6T 参数就是 1600GB，推理至少 20 块卡；专家权重压成 FP4 后，部署口径降到约 826GB，11 块卡就够。但训练要存权重、梯度和优化器状态，账完全不一样。V4 把模型按 16 路流水线乘 64 路专家并行拆开，每张卡只管 15.6 亿参数，权重加梯度加优化器状态，加起来才 16GB 左右。注意，这里藏着第一个反直觉的转折：显存不是瓶颈。 |
| S3 | 五维地图 + PP/TP | 五维地图卡片 → PP 流水线 → TP 矩阵切 → 转折爆点（TP 关了） | 那为什么要 2048 张卡？因为算力。最大 batch 94.4M tokens 一步，矩阵乘法量巨大。协同干活，就躲不开通信。先看两个基本切法：按层切，叫流水线并行，61 层切成 16 个 stage，micro-batch 像工厂流水线一样流过，代价是流水线气泡；按矩阵切，叫张量并行，hidden 7168 切成 8 片，每层两次 all-reduce，必须走节点内 NVLink。直觉告诉你，1.6T 这么大，TP 肯定拉满了吧？V4 反手把 TP 关了。注意力被 CSA 压得极扁，通信税不值了。 |
| S4 | DP + ZeRO-1 免费午餐 | 优化器状态 4 倍账 → ZeRO-1 只切优化器 → 通信免费 | 模型装下了，怎么算得快？最朴素的想法：数据并行，每张卡一份完整模型，各算各的 batch，反向结束后同步一次梯度。但每张卡要存一份完整的优化器状态——10B 模型 160GB 里优化器占 80GB，是参数的 4 倍。1.6T 的模型，优化器状态就是 12TB 级。ZeRO-1 的答案：只切优化器状态，梯度照常全量同步。神奇的是通信量和普通 DP 一模一样——all-reduce 本来就能拆成 reduce-scatter 加 all-gather，ZeRO-1 只是把更新参数插在中间。省掉一整份优化器状态，通信一分钱没多花，近乎免费。 |
| S5 | EP 通信账：1800 倍 | token 找专家示意 → 16GB vs 9MB 对比条 → 1800 倍爆点 | 但真正的主角是专家并行。V4 是 MoE 模型：384 个路由专家，每个 token 只激活 6 个。把专家摊到 64 路，token 通过 all-to-all 通信上门找专家算，算完再把结果带回来。这笔账有多大？每 token 每层要发 6 个专家对乘 7168 维，约 129KB。1M 上下文的训练场景，单层 EP 通信 16GB——同一场景下，上下文并行每层只要 9MB。差了近 1800 倍。61 层加起来，一次前向的 EP 通信接近 1TB，按跨节点 IB 的 50GB/s 算，光传数据就要 20 秒。所以 IB 带宽是训练系统的命脉。 |
| S6 | CP + 四重身份 + 结尾 | CP 两阶段示意 → 四重身份卡片 → 五把刀总结 → 尾卡 | 最后一个维度：序列。1M token 的序列，单卡放不下也算不完，切成 8 段，每张卡管一段，这就是上下文并行。它传的是压缩后的 KV，每层只要 9MB，走节点内 NVLink。现在把五维叠起来看：2048 张卡里随便抽一张，它同时是 DP 副本、PP stage、CP rank、EP 专家组——四个身份，四个正交的切割轴。装下只是第一步，让几千张卡协同干活、通信不打架，才是并行策略真正的战场。下一篇，拆五维里最年轻的 CP：1M 序列为什么切了会坏？一个问题留给你：如果让你给 1T 参数的 MoE 模型设计并行方案，你会抄 DeepSeek 的作业，还是给 TP 留个位置？评论区聊聊。关注数解AI。 |

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（精英男声 male-qn-jingying，speed 1.0 pitch +2）→ `tts_split.py` 切分 6 段
2. 概念图：`scripts/yairouter_img.py` 3 张 → `make_round_logo.py` 圆角
3. 动画：每段一个 Manim Scene（S1..S6），`at_clip` 挂 sentence-boundaries.json，`construct` 末尾 `pad_to_voice()`
4. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录 + 品牌尾卡
5. 封面：yairouter 1080×1920，标题文字强指令模板 + 读图验收
6. 归档：`content/2026-08-13-deepseek-parallel/shipinhao/`
