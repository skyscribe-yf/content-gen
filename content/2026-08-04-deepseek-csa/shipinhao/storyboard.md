## 段落设计（6 段）

| # | 场景 | 动画要点（每页 1 个主视觉动效） | 配音稿 |
|---|------|---------|--------|
| S1 | 开场钩子 | 「存不下」→「找不动」两卡片对比；MLA 压缩 vs 位置数量不变；V4 换 CSA+HCA | 百万 token 上下文，瓶颈从「存不下」变成「找不动」。上篇讲 MLA，把每个位置留下的缓存压短了——可它只解决了每个位置存多少，没解决要看多少位置。V4 没沿用 MLA，改用 CSA 加 HCA。MLA 已经很省，为什么非要换？ |
| S2 | 注意力成本 + DSA | L² 平方增长动效；DSA 索引器打分 + TopK；「目录整本扫」比喻 | 先回到注意力的基本动作：当前 token 的查询，和历史 token 的键比相关性，再按相关性加权。历史长度是 L，预填充要处理的查询键配对，近似是 L 的平方——长上下文，就是被这个平方项卡住。V3.2 给出过渡答案，在 MLA 上叠加 DSA。DSA 用一个轻量索引器给候选位置打分，只保留最高的 k 个，核心注意力从此只读这 k 个位置。可索引器面对的，仍是整段原始历史——目录，还得从整本书逐页扫出来。这瓶颈，堵住了吗？ |
| S3 | CSA 双流压缩 | 整本书→目录→选章节三层；m 块覆盖 counter；压缩条目 L→L/m；TopK 选中条目 | V4 的关键动作，是先把整本书压成目录，再选重点章节。每个压缩块覆盖 m 个 token，CSA 用两组投影生成两条键值流、两条权重流，相邻摘要共享一部分范围，避免块边界切断依赖。压缩条目数量，从 L 降到大约 L 除以 m。索引器面对的，不再是一整段原始 token，而是一组更短的压缩条目。候选池变小，扫描成本跟着缩小。核心注意力，只读被选中的压缩条目。 |
| S4 | HCA 更狠压缩 | CSA(挑 TopK) vs HCA(不挑) 对比；m 直接汇摘要→稠密注意力；精读 vs 覆盖双卡 | 比 CSA 更狠的是 HCA。CSA 压缩后还要挑 TopK，HCA 压得更狠，却不做稀疏选择：每 m 个 token 直接汇成一个摘要，序列足够短，直接做稠密注意力。可以这么记：CSA 从目录里挑出最相关的几章精读；HCA 快速浏览一份极短的全书摘要，避免模型失去全局。两种机制交替堆叠，一个精读，一个覆盖。这就是 V4 的混合注意力。到底省了多少？ |
| S5 | 论文数字 | 27% / 10%（Pro）counter 滚动；10% / 7%（Flash）；1.6T/49B/1M + 284B/13B 模型卡 | 按技术报告口径，1M 上下文下，V4-Pro 单 token 推理 FLOPs 约是 V3.2 的百分之二十七，KV 缓存约百分之十。V4-Flash 更激进：推理 FLOPs 约百分之十，KV 缓存约百分之七。看模型卡：Pro 总参数一万六千亿，激活 490 亿；Flash 总参数 2840 亿，激活 130 亿。当然，这是 1M 场景的估算比较，不是所有任务都固定快这么多。 |
| S6 | 总结 + 品牌尾卡 | 四机制总结链（MLA→DSA→CSA→HCA）；尾卡：avatar 圆角图 + 黄色「关注「数解AI」」+ 当期文章标题 + 查看公众号引导 + 下一篇预告 + 互动 | 注意力每一次改变，都在处理上一步的瓶颈：MLA 压缩存储，DSA 减少精读，CSA 缩短候选池，HCA 保留全局。这不是一句「MLA 不行了」——而是百万上下文，要求位置本身也变少。下一篇拆 V4 最激进的部分：为什么一个压缩条目能同时当键和值？Partial RoPE 为什么只旋转最后 64 维？关注数解AI。评论区聊聊：你是选完整保留但检索贵，还是选先压缩更快、但可能漏掉细节？ |

## 制作流程

1. 配音：`scripts/minimax_tts.py` 默认精英男声（male-qn-jingying，不传克隆参数）整段生成（full.txt = 6 段合并）+ `--subtitle` 句子级时间戳 → `scripts/tts_split.py` 按时间戳切分 6 段（speed 1.0 pitch +2，speech-2.8-turbo）
2. 动画：每段一个 Manim Scene（S1..S6），`construct` 末尾 `pad_to_voice()`；动画节点按台词时间轴铺满（≥80% 配音时长）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：`scripts/yairouter_img.py` 出 1080×1920，关键内容在 3:4 安全区（y∈[240,1680]）
5. 归档：`content/2026-08-04-deepseek-csa/shipinhao/`
