> "这篇文章用一句话走完 Transformer 全过程。"

就这 7 个 token，我要让它走完一条流水线。
7 个 token → 2048 维向量 → 28 层循环 → 在 15 万个候选 token 里选 1 个。

等等，7 个 token？这句话明明不止 7 个汉字。
它也不能按“词”来数。这里的 7，数的是 Qwen3-1.7B 的 tokenizer 输出。

BPE 那篇讲过：模型不按人类的词切。它会把高频片段合并成一个 token。
走到第 1 站，你会看到“这篇文章”“一句话”和“Transformer”都可能各占 1 个 token。

2048 维、28 层——哪个模型？

Qwen3-1.7B。选它不是因为它最强，而是因为它刚好小到能在我的笔记本上完整跑完一次前向传播，拿到每一层的真实内部状态。
这篇文章里你看到的注意力数据都不是示意图。我真的把这句话喂进去，再把第 1 层、第 14 层、第 28 层的输出导出来给你看。

为什么不是更大的模型？后面会解释。现在，先跟着数据走。

前六篇其实就是这条流水线的六个零件。
先在 [BPE 分词](https://mp.weixin.qq.com/s/5nR_KI47v_U8KwpQA4Uv5Q) 里把文字切成 token，再在 [词嵌入](https://mp.weixin.qq.com/s/rDryn1z_hLt7mwi3X8fsxQ) 里查成向量。
[位置编码](https://mp.weixin.qq.com/s/4nO2VqQLaYxGdDmtQeypCQ) 补上顺序，[注意力机制](https://mp.weixin.qq.com/s/KrilwX6VRjI9KfjvD7C6kw) 负责跨 token 找关系。
[前馈网络 FFN](https://mp.weixin.qq.com/s/vBCzukDlQyB9O6ASgAmlvQ) 独立加工，[归一化残差](https://mp.weixin.qq.com/s/v-SBuMTbMANSTxHj7gYDkg) 把每一层接稳。

现在把这些零件拼在一起，一个奇怪的问题才冒出来：

**注意力决定"跟谁说话"，FFN 决定"说了什么"。凭什么就这两个操作，重复 28 次，就能理解语言？**

下面我们跟着这 7 个 token，走完其中一层。然后挑出第 1 层、第 14 层、第 28 层，看看"跟谁说话"从浅到深发生了什么变化。

## 第 1 站：分词——一句话被切成 7 个 token

在 [BPE 分词](https://mp.weixin.qq.com/s/5nR_KI47v_U8KwpQA4Uv5Q) 那篇我们讲过，模型不能直接处理汉字。
它先把文本切成 tokenizer 能识别的片段，再把片段映射成编号。
BPE 不是按汉字或“词”切分：高频片段可以整体保留，罕见片段则可能拆开。

把这句话送进 Qwen3-1.7B 的分词器：

| 分词片段 | 这篇文章 | 用 | 一句话 | 走 | 完 | Transformer | 全过程 |
|----------|----------|-----|--------|-----|-----|-------------|--------|
| Token ID | 113273 | 11622 | 105321 | 99314 | 46306 | 46358 | 109092 |

这句话 → 7 个 token → 7 个 token ID。

这里的“7”不是汉字数，也不是词数。它是 tokenizer 输出的 7 个片段。
“这篇文章”“一句话”“Transformer”和“全过程”各自都是一个 token。
“用”“走”“完”也各自是一个 token。
这正是 BPE 的反直觉之处：一个 token 可以是一个汉字、多个汉字、完整英文词，也可以只是一个子词片段。

> **维度变化**：一句话 → 7 个 token ID。

## 第 2 站：词嵌入——7 个 token 变成 7 行 2048 列的矩阵

[词嵌入](https://mp.weixin.qq.com/s/rDryn1z_hLt7mwi3X8fsxQ)本质上是一个大查表。

Qwen3-1.7B 的嵌入表：**151936 行 × 2048 列**。每个 token ID 对应一行 2048 维的浮点数向量。训练的目标就是让语义相近的词，向量也相近。

```
[113273, 11622, 105321, 99314, 46306, 46358, 109092]
                   ↓ 查嵌入表
      ┌──────────────────────────────┐
      │ 这篇文章  →  [0.23, -0.45, ...]  (2048维) │
      │ 用        →  [0.11,  0.67, ...]           │
      │ 一句话    →  [-0.32, 0.18, ...]           │
      │ 走        →  [0.55, -0.21, ...]           │
      │ 完        →  [-0.08, 0.33, ...]           │
      │ Transformer → [0.41, -0.12, ...]          │
      │ 全过程    →  [-0.19, 0.27, ...]           │
      └──────────────────────────────┘
```

结果是一个 **[7, 2048]** 的矩阵——7 行，每行是一根扎在 2048 维空间里的"坐标针"。

Qwen3-1.7B 的一个特别之处是 **`tie_word_embeddings: true`**。
输入和输出共享同一个嵌入表。第 6 站会看到，输出层用的就是这个嵌入表的转置。

> **嵌入表大小**：151936 × 2048 × 2 字节（bf16）= **~622 MB**——光这一张表就占了模型参数的不小比例。

> **维度变化**：[7] → **[7, 2048]**

## 第 3 站：位置编码——"顺序"信息怎么加进去？

[位置编码](https://mp.weixin.qq.com/s/4nO2VqQLaYxGdDmtQeypCQ)解决一个问题：注意力机制本身不知道词的顺序。

"Transformer 全过程 走完 一句话"——如果把这 7 个 token 打乱，再输入没有位置编码的模型。
它看到的就是一模一样的向量集合。必须有某种方式告诉模型："第 1 个位置、第 2 个位置……"。

Qwen3 用的是 **RoPE**（旋转位置编码）。思路很优雅：不额外加数字，而是把向量在 2048 维空间里"转一个角度"——每个位置转的角度不同。

- 位置 0（"这篇文章"）：旋转 θ₀ 角度
- 位置 1（"用"）：旋转 θ₁ 角度
- 位置 2（"一句话"）：旋转 θ₂ 角度
- ……
- 位置 6（"全过程"）：旋转 θ₆ 角度

关键是：**旋转不改变向量长度，只改变方向**。所以维度还是 [7, 2048]，没变。

那 θ 是怎么算的？Qwen3 的 `rope_theta: 1000000` 是"基频"——决定旋转的速度：

> **θᵢ = 1000000^(-2i/d)**。
>
> 其中 i = 0, 2, 4, ..., 126。每个 128 维 head 有 64 个维度对。

- 低维度（i 小）：θ 接近 1，转得快——能区分相邻位置
- 高维度（i 大）：θ 接近 0，转得慢——感知远距离位置

这就是 RoPE 的精髓：**用不同频率的旋转，同时捕捉"隔壁那个词"和"远处那个词"的位置关系**。

> **维度变化**：[7, 2048] → **[7, 2048]**（维度不变，方向变了）

## 第 4 站：注意力——"谁跟谁说话"

这是今天最重的一站。我们要掰扯三件事：注意力怎么算、为什么分头、从第 1 层到第 28 层发生了什么。

在 Qwen3 的一个 Transformer Block 里，顺序大致是：
RMSNorm → 注意力 → 残差相加 → RMSNorm → FFN → 残差相加。
前一篇 [归一化残差](https://mp.weixin.qq.com/s/v-SBuMTbMANSTxHj7gYDkg) 已经解释过这条“先稳住、再加回”的支路。

### 注意力怎么算

[注意力机制](https://mp.weixin.qq.com/s/KrilwX6VRjI9KfjvD7C6kw)那篇我们讲过：每个 token 拿着自己的问题（Q），去问所有 token"你跟我有关系吗"。每个 token 用键（K）回答，答案加权汇总到值（V）里。这里我们直接用这 7 个 token 跑一遍真实计算：

```
输入：[7, 2048] 矩阵（已经加了位置编码）
```

**Step 1：生成 Q, K, V**

```
[7, 2048] × W_Q [2048, 2048] = Q [7, 2048]
[7, 2048] × W_K [2048, 1024] = K [7, 1024]
[7, 2048] × W_V [2048, 1024] = V [7, 1024]
```

W_Q 是 2048×2048，约 420 万参数。
W_K 和 W_V 各是 2048×1024，约 210 万参数。

**Step 2：算注意力分数**

![Q × Kᵀ 注意力分数矩阵](imgs/matrix-qk.png)

这 7×7 的矩阵，每一格 = 一个 token 的 Q 向量和另一个 token 的 K 向量做**点积**。点积的几何意义：两个向量的夹角越小（方向越接近），点积越大——"这两个 token 关系越紧密"。

先除以 √128（**head_dim=128**），缩放因子用来防止点积过大。
再对每行做 softmax，把每行的 7 个数归一化到和为 1。

### 16 个 Q 头，8 个 KV 头——分组查询

Qwen3-1.7B 没有用标准的"每头独立 K、V"方案。它用了 **GQA（分组查询注意力）**。
16 个 Q 头，但只有 **8 个 KV 头**，每 2 个 Q 头共享 1 组 K 和 V。

为什么分组？因为 KV 缓存在推理时太占显存了。
如果 16 个头各自独立存 K 和 V，每层每 token 就要额外存 16 × 2 × 128 = 4096 个数。
28 层、长文本、再叠加批处理，很快就会显存爆炸。
压缩到 8 组 KV 后，缓存直接减半，同时保留足够的注意力多样性。

为什么分组能工作？回到多头注意力的本质：把 2048 维切分成 **16 个头**，每个头 **128 维**（16 × 128 = 2048）：

```
原来：[7, 2048] → 1 个注意力视角
切分：[7, 16, 128] → 16 个独立的注意力视角
```

16 个头各自独立计算 Q×Kᵀ，在各自的 128 维子空间里产生一个 [7, 7] 的注意力矩阵。
最后，再把 16 个头拼回 [7, 2048]。不同头学到的模式完全不同。有的头成了"语法头"（动词找主语），有的成了"语义头"（近义词互相关注），有的成了"位置头"（只看相邻词）。

GQA 的直觉是：相邻的 Q 头关注的模式往往相近。让头 1 和头 2 共享同一组 K、V，就像两个不同角度的问题在查同一本书——答案不损失多少多样性，但省了一半书。

更大的模型会用更极端的压缩比。
比如放大版可以用 4:1，让 32 个 Q 头共享 8 组 KV。
这就是 MLA 能省 90% KV 缓存的思路雏形，详见 [MLA 篇](https://mp.weixin.qq.com/s/HHMNEdCYThOjCLRozQorhg)。

![多头注意力 + GQA 分组查询](imgs/02-attention-gqa.png)

### 层间对比：从"到处看"到"盯住关键词"

前面讲的都是一层的注意力。现在来看真正的魔法：**同样这几个词，在第 1 层、第 14 层、第 28 层的注意力分布完全不同。**

下面是我实际跑 Qwen3-1.7B 的真实数据。我把 16 个头的注意力平均后，画成 7×7 的热力表。每一行的 7 个数加起来 = 1，代表这个位置的 token 把注意力分给了哪些 token。

**第 1 层**：对角线主导——每个 token 主要看自己和前一个 token。

![第 1 层注意力分布](imgs/matrix-layer_1.png)

清晰的下三角结构——每个 token 只看到自己及之前的 token（因果注意力，看不到后面的）。注意力集中在**对角线附近**，每个 token 最关心自己，其次是紧挨的前一个 token。

**第 14 层**：首 token 开始吸走注意力。

![第 14 层注意力分布](imgs/matrix-layer_14.png)

第一列的数值爆炸了——"用"把 86% 的注意力给了"这篇文章"。
"走"是 68%，连最后的"全过程"也把 57% 给了首 token。模型学会了：**"这篇文章"是整个句子的主题锚点。**

**第 28 层**：首 token 的"吸力"达到极限。

![第 28 层注意力分布](imgs/matrix-layer_28.png)

所有位置都在"盯着"首 token——79% 到 87% 的注意力集中在"这篇文章"上。自己的自注意力只剩 5%-13%。

### 望远镜调焦——从"到处看"到"盯住关键"

![注意力就像望远镜：浅层→深层](imgs/04-telescope-layers.png)

这个从浅到深的注意力变化，就像调望远镜：

> **第 1 层是短焦**——每个 token 只管自己跟紧挨的前一个 token。像在逐字阅读，"这篇文章...用...一句话..."。
>
> **第 14 层是中等焦距**——模型发现"这篇文章"是这句话的主题词，开始有意识地在它身上聚焦。像读完全句后，意识到"哦，这句话的核心是'文章讲 Transformer'"。
>
> **第 28 层是长焦**——首 token 几乎吸走了所有注意力。每个 token 都在问同一个问题："整句话在做什么？"——然后把自己的含义对齐到首 token 传递过来的全局语义上。

**反常识，但只针对这组数据**：深层不是简单“看更广”，而是把注意力更集中到关键 token。
它没有在每个 token 上平均分配。

为什么会这样？第 1 层开始时，每个 token 主要拿到自己的 2048 维嵌入。
它还没有经过多轮上下文加工。
经过 27 次注意力和 FFN 反复揉捏后，对靠后的 token 来说，向量已经包含了大量可用的历史上下文。
它不必再平均看所有位置，看几个锚点就够了。

从**函数变换**的角度看，每一层都在对上一个表示做一次非线性变换。
浅层变换更局部，深层变换则完成了更充分的上下文加工。
**层越深，注意力分配可能越集中，但这不等于每个 token 都能看到未来信息。**

> **维度变化**：[7, 2048] → **[7, 2048]**

注意力不改变维度。它只做一件事：**重新分配信息**——决定谁跟谁说话。但"说了什么"，要看下一站。

## 第 5 站：FFN——"说了什么"

[FFN](https://mp.weixin.qq.com/s/vBCzukDlQyB9O6ASgAmlvQ)那篇我们讲过：注意力是"路由器"，FFN 是"存储器"。

如果只有注意力，7 个 token 可以互相聊天，但谁也学不到新知识——就像 7 个人开了一天的会，没有一个人去查资料。FFN 就是每次开完会后，每个人去书架上翻一下相关的书。

### 一层 FFN 的完整计算

Qwen3-1.7B 用的是 **SwiGLU 门控**。不是简单的 ReLU（负数直接扔掉），而是"学习什么时候激活"——用另一个神经网络来控门。

```
注意力输出：[7, 2048]
```

**Step 1：双路投影**

```
gate_proj: [7, 2048] × [2048, 6144] = [7, 6144]   → 门控信号
up_proj:   [7, 2048] × [2048, 6144] = [7, 6144]   → 信息通道
```

注意 6144 = 2048 × 3。
FFN 先把每个 token 从 2048 维"膨胀"到 6144 维（3 倍），再在这个大空间里做"知识检索"。

**Step 2：门控激活**

```
SiLU(gate_proj 输出) → 平滑缩放，不是 0/1 概率
```

SiLU（也叫 Swish）是 sigmoid 加权版——不像 ReLU 在 0 处一刀切，SiLU 在负值区缓慢衰减。Qwen3 的 `hidden_act: "silu"` 就是这个：**x × sigmoid(x)**。当 x 很大时 ≈ x，当 x 很负时接近 0；过渡区平滑，梯度不会突然断掉。注意，SiLU 的输出不限制在 0~1 之间，它不是概率，而是用来连续缩放信息通道的门控信号。

**Step 3：逐元素相乘**

```
门控信号 [7, 6144] ⊙ 信息通道 [7, 6144] = [7, 6144]
```

门控信号 × 信息信号。门控接近 0 = "这部分知识几乎不传"。门控绝对值较大 = "这个方向被强烈缩放"。它不是只有开和关两档。

**Step 4：压缩回原维度**

```
down_proj: [7, 6144] × [6144, 2048] = [7, 2048]
```

![SwiGLU 门控 FFN 机制](imgs/03-swiglu-gate.png)

### 为什么 FFN 是"知识库"？

"知识库"是直觉比喻，不是说每个参数对应一条事实。
注意力先把上下文线索汇入每个 token。
FFN 再用参数中的知识，对这份上下文做非线性加工。
"用"后面应该接一个动作，这是搭配知识。
"Transformer"是一个 NLP 模型名，这是事实知识。
"全过程"的三个字应该组合成一个词，这是构词知识。
这些关联被编码在 gate_proj、up_proj、down_proj 三个矩阵里。
三者共有 3 × 1258 万 ≈ 3774 万个参数。

这就是为什么 FFN 的参数比注意力多（Qwen3-1.7B 一层 FFN 参数占一层总参数的约 75%）。知识是重的，路由是轻的。

> **注意力是"路由器"——决定信息怎么流动。**
> **FFN 是"存储器"——决定每个位置之后"知道"了什么。**

这个"存储器"里有 10 亿个参数。如果你想教模型写公众号文章——只用 FFN 里存的互联网通用知识显然不够——直观想法是把这 10 亿个参数全部更新一遍。但显卡撑不住。LoRA 给了一个取巧的答案。

### LoRA 微调——为什么我们只动小矩阵？

抓住 FFN 后面的数字：gate_proj、up_proj、down_proj。
每个矩阵约有 2048×6144 ≈ **1258 万参数**。
三个加起来约 3774 万，只算一层 FFN。28 层全加起来 ≈ 10.6 亿，占总参数（17 亿）的 62%。

全量微调这些参数太贵了。**LoRA 的直觉**：不碰原矩阵，在它旁边插两个小矩阵（低秩分解）。
原来 2048×6144 的变换，被拆成 2048×r + r×6144，r 通常取 8 或 16。
只训练那两个小矩阵，参数就从 1258 万降到约 10 万。

后面预训练那篇会展开讲微调的全过程。

> **维度变化**：[7, 2048] → [7, 6144]（膨胀） → **[7, 2048]**（压缩回原维度）

## 第 6 站：输出——从向量回到下一个 token

注意力让每个 token 知道了"该跟谁说话"。
经过 28 层后，靠后位置的向量已经浓缩了大量上下文语义。
FFN 再让每个 token 提取存储在参数里的知识。

现在输入 [7, 2048] 经过了全部 28 层 → **[7, 2048]**。
Qwen3 在 lm_head 前还会做最后一次 RMSNorm，维度不变。
怎么预测下一个 token？

**Step 1：取最后一个位置**

做文本生成时，我们只关心"下一个 token 是什么"，不是前面的。所以取最后一个 token（"全过程"）对应的向量：

```
[7, 2048] → 取最后一行 → [1, 2048]
```

**Step 2：映射到词表**

```
[1, 2048] × 嵌入表ᵀ [2048, 151936] = [1, 151936]
```

还记得第 2 站说的 `tie_word_embeddings: true` 吗？
输出层用的就是输入那个嵌入表的转置。
同一个 2048×151936 的矩阵，输入时查行（token→向量），输出时乘列（向量→token 分数）。

**Step 3：softmax 选词**

在 [Softmax 那篇](https://mp.weixin.qq.com/s/5wMquh_v3oon2-NEDeQLEw)我们详细讲过：为什么不用 argmax 直接取最大值，为什么需要把分数变成概率分布。这里不重复——只说它在输出层的作用：

[1, 151936] → softmax → 151936 个概率。每个候选 token 一个概率，最高那个就是模型猜的"下一个 token"。如果训练得好，这 7 个 token 后面可能接"过程"、或"的"、或"——"。
具体取决于训练数据里，类似上下文之后最常见的续写。

> **维度变化**：[7, 2048] → [1, 2048] → [1, 151936] → **1 个 token ID**

## 收官：为什么先看懂"标准版"？

你跟那一句话走完了 Transformer 的 28 层。
回头看：文本→数字→向量→位置→注意力→FFN→输出，共六个环节。
每一环的信息形态都在变，但每一环只做一件事。

**注意力决定"跟谁说话"，FFN 决定"说了什么"**。
两个操作重复 28 次，把一个句子的语义一层层压进向量里。

这就是标准 Transformer。
更大的模型——比如 DeepSeek V4——不是另起炉灶，而是在这个骨架上改装引擎。
[MLA](https://mp.weixin.qq.com/s/HHMNEdCYThOjCLRozQorhg) 把 KV 缓存压缩到极致，CSA 让路由不再一刀切。
但改装之前，你得先知道活塞和曲轴长什么样。
**今天这篇文章，就是你看那些升级之前先刻进脑子里的"标准版"。**
