## 段落设计（8 段）

| # | 场景 | 动画要点 | 配音稿 | 爆点 |
|---|------|---------|--------|------|
| S1 | 开场钩子 | 句子「这篇文章用一句话走完Transformer全过程」拆成 7 个 token 卡片；数字链 7 token → 2048 维 → 28 层 → 15 万选 1 逐个点亮；两块操作牌「注意力」「FFN」居中 | 这条视频，跟一句话走完 Transformer 的 28 层。那句话只有 7 个 token——变成 2048 维向量，穿过 28 层循环，最后在 15 万个候选里，选出一个字。全程只有两个操作：注意力，和 FFN。凭什么，重复 28 次，就能理解语言？ | 开场价值承诺 + 段尾悬念钩 |

| S4 | 第 4 站a 注意力+GQA | Q 卡片向 7 个 token 发问连线；16 个 Q 头 2 个一组，连线归并到 8 个 KV 头；KV 缓存对比条 16 组 → 8 组「直接减半」 | 注意力。每个 token 拿着自己的问题 Q，去问所有 token：你跟我有关系吗？Qwen3 一层里有 16 个 Q 头，但只有 8 个 KV 头。每 2 个 Q 头，共享同一组答案。为什么？KV 缓存太吃显存。16 组独立缓存，压缩成 8 组——直接减半。但同一句话，在第 1 层和第 28 层看到的，是同一个世界吗？ | 问句钩子 + 数字对比（减半）+ 段尾悬念 |
| S5 | 第 4 站b 层间对比 | 三个 7×7 热力矩阵并排（第 1/14/28 层）：第 1 层对角线亮、第 14 层首列爆亮「86%」、第 28 层首列 79-87% 高亮；望远镜三档（短焦→中焦→长焦）示意 | 我把这句话真的喂进 Qwen3，把第 1 层、第 14 层、第 28 层的注意力导出来。第 1 层：每个 token 只盯着自己和前一个，像逐字阅读。第 14 层：变了。"用"把 86% 的注意力，给了"这篇文章"。第 28 层：所有位置都在盯首 token——79% 到 87%。反常识。深层不是"看更广"，而是"盯得更准"。注意力决定跟谁说话。那"说了什么"呢？ | 转折爆点（反常识）+ 段尾悬念 |
| S6 | 第 5 站 FFN | SwiGLU 流程图：2048 膨胀→6144，门控信号 × 信息通道（两路相乘符号）→ 压回 2048；参数对比：一层 FFN 3774 万 = 75%；LoRA 大矩阵旁插两个小矩阵（1258 万 → 10 万） | FFN——知识库。注意力开完会，FFN 负责查资料。Qwen3 用 SwiGLU 门控：先把每个 token 从 2048 维，膨胀到 6144 维——3 倍。一道门控信号，一道信息通道，相乘，再压回 2048 维。一层 FFN，3774 万个参数，占一层的 75%。知识是重的，路由是轻的。全量微调太贵了。LoRA 的办法：不碰原矩阵，在旁边插两个小矩阵。1258 万个参数，降到 10 万。向量里已经装满答案。最后一步：怎么变回一个字？ | 数字对比（1258 万 → 10 万）+ 段尾悬念 |
| S7 | 第 6 站 输出 | [7, 2048] 矩阵取最后一行高亮；乘嵌入表转置（同一张表倒过来用）；151936 个概率条 → 最高一根点亮「选 1 个」 | 取最后一个位置的向量——我们只关心下一个 token。还记得吗？输入和输出，共享同一张嵌入表。现在倒过来用：向量乘上它的转置，映射到 151936 个候选。再 softmax：15 万个概率，最高的那个，就是模型猜的下一个字。如果训练得好，这 7 个 token 后面，可能接"过程"，也可能接"的"。 | 问句钩子（还记得吗？）+ 数字对比 |
| S8 | 收官 + 品牌尾卡 | 六站纵向流水线链（分词→嵌入→位置→注意力→FFN→输出，垂直排列铺满屏幕）；路由器/存储器两张牌 + 28 格节奏带；「活塞和曲轴」隐喻（标准版骨架 → DeepSeek V4 改装）；尾卡：avatar 圆角图 + 黄色「关注「数解AI」」+ 当期文章标题 +「查看公众号文章」绿引导 + 下一篇预告（预训练） | 回头看。文本变数字，数字变向量，加位置，注意力找关系，FFN 存知识，最后变回一个字。注意力是路由器——决定信息怎么流；FFN 是存储器——决定每个位置知道了什么。两个操作，重复 28 次，语义一层层压进向量里。这就是标准 Transformer。DeepSeek V4 不是另起炉灶，是在这个骨架上改装引擎。但改装之前，你得先认识活塞和曲轴。关注数解AI。下一篇：17 亿参数，是怎么从零学出来的。你觉得更深的层，会"看"得更广，还是"看"得更准？评论区聊聊。 | 短句断句 + 结尾预告&互动 |

## 关键数字核查（与 weixin.md 一致）

- 7 个 token：这篇文章/用/一句话/走/完/Transformer/全过程；ID 113273/11622/105321/99314/46306/46358/109092
- 嵌入表 151936×2048 ≈ 622 MB；[7, 2048]；tie_word_embeddings（输入输出同一张表）
- RoPE：基频 rope_theta = 1000000；旋转不改变长度只改变方向
- 注意力：16 Q 头 / 8 KV 头（每 2 Q 头共享 1 组 KV）；KV 缓存减半
- 层间：第 1 层对角线主导；第 14 层「用」86% 给首 token；第 28 层 79%-87% 盯首 token
- FFN：2048→6144（3 倍）→2048；一层 3×1258 万 ≈ 3774 万，占一层 75%；28 层 FFN ≈10.6 亿（62%）；LoRA 1258 万 → ~10 万
- 输出：取最后一行 → ×嵌入表ᵀ → softmax → 151936 个概率选 1

## 制作流程

1. 配音：`scripts/minimax_tts.py` 整段生成（full.txt）+ `--subtitle` 句子级时间戳 → `scripts/tts_split.py` 按时间戳切分 8 段（克隆音色 `branding/my-voice-denoised.wav`，speed 1.15 pitch +2，speech-2.8-turbo）
2. 动画：每段一个 Manim Scene（S1..S8），`construct` 末尾 `pad_to_voice()`；动画节点按台词时间轴铺满（≥80% 配音时长）；工具函数复用注意力机制 scenes.py 模板（boxed/fit/sqrt_group/play_red_cross）
3. 构建：`scripts/manim_video_build.py` mux 配音 + 无缝拼接 + 黄色字幕烧录（MarginV=210, 75 号，整行 + 150ms 淡入）+ 品牌尾卡
4. 封面：Cover 场景单帧渲染（复用六站流水线 + 7 token 卡片视觉）→ `<标题>-封面.png`（1080×1920，关键内容在中间 3:4 安全区 y∈[240,1680]）
5. 归档：`content/2026-07-26-Transformer全景/shipinhao/`
