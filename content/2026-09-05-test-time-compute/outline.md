# 推理篇大纲：「同一个模型，多想 3 秒，数学分从 71 涨到 86.7」

- 发布日期：2026-09-06 20:00（恢复期，合格才发）
- 目标篇幅：**≤2000 字**（硬约束）
- 系列：R1 两篇拆解 · 下篇（推理）——上篇（训练）为 09-05「没人教它思考，数学分从 15.6 涨到 71」
- 关键词前置：推理时计算 / test-time compute（标题用中文+数字），正文首次出现标注英文术语
- 数据源：DeepSeek-R1 论文（arXiv 2501.12948）：同权重同模型，majority voting（cons@64）AIME 2024 **71.0% → 86.7%**
- 补充锚点（按字数取舍）：Snell et al.（ICLR 2025）——compute-optimal 策略比 best-of-N 省约 4× 算力；小模型+推理时算力可超过 14× 大模型（FLOPs 匹配）

## 结构（悬念链小标题，A 类叙事弧线）

### 1. 钩子（承接上篇一句话 + 新场景）
- 承接：昨天那个没人教的模型，学会了自己检查自己（一句带过，不展开，不构成导航）。
- 新驱动问题：它已经 71 分了。**不改模型、不加知识，只让它多想一会儿，还能涨分吗？** —— 答案：能，涨到 86.7。

### 2. 多想 = 答 64 次，取多数票（自一致性的直觉）
- DeepSeek 干的「笨办法」：同一道题，让模型答 64 遍，统计哪个答案出现最多，交卷。
- 为什么「多数票」比「单次」可靠：单次 = 一次豪赌；多数 = 地图上同一条高准确率路径被反复踩中——**投票天然把答案拉向流形上那个高准确率子流形**（回应用户核心理论，训练篇的「修路」在下篇变成「开车走大路」）。
- 反直觉点：一分钱训练没花，16 个点。

### 3. 数字兑现：71.0 → 86.7
- 同权重、同 prompt、只改解码策略（采样+投票）。顺带：甚至超过了 o1-0912 的 83.3%（cons@64）——开源模型用「多想」追平了闭源。
- 一句话：**推理时计算 = 在已经学到的轨迹分布里搜索**（点题训练篇流形理论的推理半场）。

### 4. 搜索怎么花钱有讲究（可选节，按 2000 字预算取舍）
- 投票是「并行多试」；更聪明的是「串行验证」：每个中间步骤请验证器打分（best-of-N / PRM），算力花在刀刃上。
- Snell 的实验（一句）：同样算力，按题目难度分配「多想」量，比无脑多答省 4× 算力；小模型 + 多想能打赢 14 倍大的模型。→ 若超字数整节压缩为一段。

### 5. 边界：不是多想就一定好
- 反例（诚实加分项）：2025 年底 30 亿 token 级实验发现，GRPO 训出来的短视距模型（R1 属此类）长链过头会掉分——「过度思考」（overthinking）。简单题想太多，反而把对的改错。
- 修正句：多想不是无脑加时，是**在正确的轨道上多走**；这也是「子流形」理论的另一半——搜索要在高准确率的子流形内进行才有意义。

### 6. 回扣两篇闭环
- 训练篇：RL 让模型学会搜索（15.6 → 71）；推理篇：考试时执行搜索（71 → 86.7）。
- 一句话总收束（作者原声落点）：**长思维链 = 在预先学习到的轨迹分布里，用训练学出的搜索能力 + 推理时花的算力，稳定落到准确度更高的子流形上**。
