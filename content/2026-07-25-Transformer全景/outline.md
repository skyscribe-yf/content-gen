# 大纲：注意力找人，FFN存知识：跟一句话走完Transformer

> 系列：大模型原理 ⑥ | 参考模型：Qwen3-1.7B（28层/2048维）| 状态：outline

---

## 一、开头（~300字）

**A+B 融合钩子**：

> "这篇文章用一句话走完Transformer全过程。" 就这 7 个词，接下来我要让它走完一条流水线：7 个 token → 2048 维向量 → 28 层循环 → 15 万选 1 的预测。

然后立刻抛出反常识问题：

> 你读完了前五篇——BPE、词嵌入、位置编码、注意力、FFN——但这些零件拼在一起的那一刻，一个奇怪的问题才会冒出来：**注意力决定"跟谁说话"，FFN 决定"说了什么"。凭什么就这两个操作，重复 28 次，就能理解语言？**

紧接着复杂度预告：
> 先看一眼全景图——Qwen3-1.7B 有 28 层，每层都做一遍注意力+FFN。下面我们跟着这句话，走完其中一层。然后挑出第 1 层、第 14 层、第 28 层，看看"跟谁说话"从浅到深发生了什么变化。

## 二、第1站：分词——7 个汉字变成 7 个编号

**最小回顾**（1-2 句）：BPE 把文本切成子词，高频词组整存，低频拆碎。

**自指句追踪**：
```
"这篇文章用一句话走完Transformer全过程"
→ ['这篇文章'] ['用'] ['一句话'] ['走'] ['完'] ['Transformer'] ['全过程']
→ [113273, 11622, 105321, 99314, 46306, 46358, 109092]
```

**关键细节**：
- "这篇文章"和"一句话"各自是一个 token——Qwen3 的 tokenizer 对中文词组有优化
- "Transformer"是单独 token（id=46358）——高频英文术语也被整存
- 回链 BPE 篇："还记得 BPE 那篇吗？'这篇文章'碰巧就是一个 token"

**维度变化**：文本 → [7]，7 个整数。

---

## 三、第2站：词嵌入——7 个编号变成 7 行 2048 列的矩阵

**最小回顾**（2-3 句）：词嵌入是一个大查表——151936×2048 的矩阵，每个 token ID 对应一行 2048 维的浮点数向量。训练的目标就是让语义相近的词，向量也相近。

**自指句追踪**：
- Token ID [113273, 11622, ...] → 查嵌入表 → 每个 ID 取一行 2048 维向量
- 结果：[7, 2048] 的矩阵
- 7 个 token，每个是一根 2048 维空间里的"坐标针"

**关键细节**：
- Qwen3-1.7B 的 `tie_word_embeddings: true`——输入和输出共享同一个嵌入表（预告输出站）
- 嵌入表大小：151936 × 2048 × 2 字节（bf16）= ~622 MB

**维度变化**：[7] → [7, 2048]

---

## 四、第3站：位置编码——"顺序"信息怎么加进去？

**最小回顾**（2-3 句）：注意力机制本身不知道词的顺序——"Transformer 全过程 走完 一句话"和原句对它来说是一样的。RoPE（旋转位置编码）通过把向量在 2048 维空间里"转一个角度"，把位置信息编码进去。

**自指句追踪**：
- 位置 0 的"这篇文章"向量：旋转 θ₀ 角度
- 位置 1 的"用"向量：旋转 θ₁ 角度
- ...
- 位置 6 的"全过程"向量：旋转 θ₆ 角度

旋转不改变向量长度——只改变方向。这意味着**加位置编码后，维度依然是 [7, 2048]**。

**关键细节**：
- `rope_theta: 1000000`——这个参数决定了旋转的"波长"（基频）
- θ₀ = 1000000^(-0/128), θ₁ = 1000000^(-2/128), 逐对递减
- 高频维度转得快（区分相邻位置），低频维度转得慢（感知远距离）

**维度变化**：[7, 2048] → [7, 2048]（维度不变，方向变了）

---

## 五、第4站：注意力——"谁跟谁说话"（核心站）

这是全文重点，分三个层次讲。

### 5.1 一层注意力的完整计算

**最小回顾**（3-4 句，重点给回顾）：
> 注意力不是"查数据库"，而是"每个词拿着自己的问题（Q），去问所有词'你跟我有关系吗'——每个词用它的键（K）回答，答案加权汇总到值（V）里。

**自指句追踪**：
```
输入：[7, 2048] 矩阵
    ↓ × W_Q（2048×2048）→ Q [7, 2048]
    ↓ × W_K（2048×2048）→ K [7, 2048]
    ↓ × W_V（2048×2048）→ V [7, 2048]

Q × Kᵀ → [7, 7] 的注意力分数矩阵
  ↓ ÷ √128（缩放，head_dim=128）
  ↓ softmax（每行归一化到和为1）
  ↓ × V → [7, 2048] 的输出
```

**掰扯重点：分头（Multi-Head Attention）**
- Qwen3-1.7B 有 16 个注意力头，每个头 128 维（2048 ÷ 16）
- 8 个 KV 头（GQA, 2:1 压缩）——每 2 个 Q 头共享 1 个 KV 头
- 16 个头各自独立计算注意力，最后拼回 2048 维
- **为什么分头？** 不同头学会关注不同类型的关系——有的看语法，有的看语义，有的看位置

**点积几何意义**（简单提，不留过多数学）：
> Q 和 K 的点积 = 两个 128 维向量的夹角余弦 × 长度乘积。夹角越小（方向越一致），分数越高——说明"这个词跟我关系大"。

### 5.2 层间对比：从"到处看"到"盯住关键词"

**实测数据展示**（Qwen3-1.7B 真实推理）：

| 层 | 注意力特征 | 典型行为 |
|-----|-----------|----------|
| **第 1 层** | 对角线主导 | "用"主要看"这篇文章"和"用"自己（0.406 + 0.594）|
| **第 14 层** | 首 token 锚定出现 | "走"把 68% 注意力给了"这篇文章" |
| **第 28 层** | 首 token 极端锚定 | 几乎所有 token 把 80-90% 注意力放在了"这篇文章"上 |

**望远镜调焦比喻**：
> 第 1 层是短焦——每个词只看自己和紧挨的前一个词。
> 第 14 层是中等焦距——模型发现"这篇文章"是这句话的主题词，开始在它身上聚焦。
> 第 28 层是长焦——"这篇文章"几乎吸走了所有注意力。每个词都在问："整句话在讲什么？哦，讲的是这篇文章——那我调整一下自己的含义。"

**反常识点**：深层不是"看得更广"，而是"看得更准"——它学会了把注意力浓缩到几个关键 token 上。

### 5.3 附录：感受野 / 函数变换视角

> 为什么从第 1 层到第 28 层，注意力的"视野"变化这么大？
>
> 从感受野的角度：第 1 层每个 token 的直接感受野是 128 维的"原始嵌入"；到第 28 层，每个 token 已经被 27 次注意力和 FFN 反复揉捏过，它的向量里**已经包含了整句话的上下文信息**。所以它不需要再看所有 token——看几个锚点就够了。
>
> 从函数变换的角度：每一层都在对上一个表示做一次非线性变换。浅层变换是局部的（平滑函数），深层变换是全局的（高度弯曲的函数）——就像多项式，低次项画直线，高次项画复杂曲线。

**维度变化**：[7, 2048] → [7, 2048]

## 六、第5站：FFN——"说了什么"（知识存储站）

### 6.1 一层 FFN 的完整计算

**最小回顾**（2-3 句）：
> 注意力决定了"跟谁说话"，但说话的内容——"这个人是个名词""这个词和前面那个词组成短语"——是靠 FFN 存储的。FFN 是 Transformer 的"知识库"。

**自指句追踪**：
```
输入：[7, 2048]
    ↓ gate_proj: [7, 2048] × [2048, 6144] = [7, 6144] → SiLU 激活 → 门控信号
    ↓ up_proj:   [7, 2048] × [2048, 6144] = [7, 6144] → 信息通道
    ↓ 逐元素乘: [7, 6144] ⊙ [7, 6144] = [7, 6144]
    ↓ down_proj: [7, 6144] × [6144, 2048] = [7, 2048]
```

**掰扯重点：SwiGLU 门控**
- 不是简单的 ReLU（负数直接扔掉），而是"学习什么时候激活"
- gate_proj 输出 → SiLU 平滑激活 → 一个 0~1 之间的门控信号
- up_proj 输出 = 信息本身
- 两者逐元素相乘：门控信号 × 信息 = 选择性通过的输出
- `hidden_act: "silu"` = Sigmoid Linear Unit（SiLU 或 Swish）

### 6.2 为什么注意力不够，还要 FFN？

**核心洞察**（全文金句）：
> 注意力是"路由器"——决定信息怎么流动。
> FFN 是"存储器"——决定每个位置之后"知道"了什么。
>
> 如果只有注意力，7 个 token 可以互相聊天，但谁也学不到新知识——就像 7 个人开了一天的会，没有一个人去查资料。FFN 就是每次开完会后，每个人去书架上翻一下相关的书。

### 6.3 LoRA 微调钩子

> 注意这几个大矩阵：gate_proj、up_proj、down_proj——每个 2048×6144 ≈ 1258 万参数。三个加起来 ≈ 3774 万参数——只算一层 FFN。
>
> 完整微调这些矩阵太贵了。LoRA 的思路：不碰原矩阵，在它旁边插两个小矩阵（低秩分解），只训练小的。后面预训练篇会展开。

**维度变化**：[7, 2048] → [7, 6144]（膨胀）→ [7, 2048]（压缩回原维度）

## 七、第6站：输出——从向量回到下一个字

**最小回顾**（1-2 句）：最后一层输出 [7, 2048] → 只取最后一个位置 [1, 2048] → 乘嵌入矩阵的转置 [2048, 151936] → [1, 151936] → softmax → 151936 个候选词的概率分布。

**自指句追踪**：
- 最后一层 FFN 输出后，"全过程"这个位置的向量已经浓缩了整句话的语义
- 用这个向量去预测下一个 token
- Qwen3-1.7B 的 `tie_word_embeddings: true`——输出层用的就是第 2 站那个嵌入表
- 151936 选 1：最高概率的那个词，就是模型猜的"下一个字"

**维度变化**：[7, 2048] → [1, 2048] → [1, 151936] → 1 个 token ID

## 八、结尾（~400字）

### 8.1 为什么用 Qwen3-1.7B？

> 8B 和 1.7B 的架构完全一样——只是层数从 28 变到 36，维度从 2048 变到 4096。1.7B 小到刚好能在我的笔记本上跑完一次完整前向传播，拿到真实的注意力数据。
>
> 这篇的目的不是比数字大小，而是看清楚数据的流动路径。1.7B 的路径和 8B 的路径，是同一条路。

### 8.2 DeepSeek V4 伏笔

> 至于 DeepSeek V4——它在注意力和 FFN 上都做了升级：MLA 把 KV 缓存压到原来的 1/10，CSA 让路由更聪明。这些我们后面单独讲。
