> "这篇文章用一句话走完 Transformer 全过程。"

就这 7 个词，接下来我要让它走完一条流水线：7 个 token → 2048 维向量 → 28 层循环 → 15 万选 1 的预测。

等等，2048 维、28 层——哪个模型？

Qwen3-1.7B。选它不是因为它最强，而是因为它刚好小到能在我的笔记本上完整跑完一次前向传播，拿到每一层的真实内部状态。这篇文章里你看到的所有注意力数据，都不是示意图——是我真的把这句话喂进去，然后把第 1 层、第 14 层、第 28 层的输出导出来给你看。

为什么不是更大的模型？后面会解释。现在，先跟着数据走。

你读完了本系列前五篇——[BPE → 词嵌入 → 位置编码 → 注意力 → FFN](https://mp.weixin.qq.com/mp/appmsgalbum?__biz=MzkyMzQyODExNQ==&action=getalbum&album_id=4597831652025925632#wechat_redirect)——但这些零件拼在一起的那一刻，一个奇怪的问题才会冒出来：

**注意力决定"跟谁说话"，FFN 决定"说了什么"。凭什么就这两个操作，重复 28 次，就能理解语言？**

下面我们跟着那句话，走完其中一层。然后挑出第 1 层、第 14 层、第 28 层，看看"跟谁说话"从浅到深发生了什么变化。

> ![六站流水线全景](01-pipeline.png)

## 第 1 站：分词——7 个汉字变成 7 个编号

在 [BPE 分词](https://mp.weixin.qq.com/s/5nR_KI47v_U8KwpQA4Uv5Q)那篇我们讲过，模型看不懂汉字，只看得懂编号。BPE 把文本切成子词——高频词组整存，低频拆碎。

把我们的自指句送进 Qwen3-1.7B 的分词器：

| 汉字 | 这篇文章 | 用 | 一句话 | 走 | 完 | Transformer | 全过程 |
|------|----------|-----|--------|-----|-----|-------------|--------|
| Token ID | 113273 | 11622 | 105321 | 99314 | 46306 | 46358 | 109092 |

7 个汉字 → 7 个 token。

有意思的是"这篇文章"和"一句话"各自是一个完整 token——Qwen3 的 BPE 分词器对中文词组做了大量优化，高频搭配直接整存。"Transformer"也是一个独立 token（id=46358），作为高频英文术语被整存到词表里。

"还记得 BPE 那篇吗？'这篇文章'碰巧就是一个 token。"

> **维度变化**：一句话 → 7 个整数。

## 第 2 站：词嵌入——7 个编号变成 7 行 2048 列的矩阵

[词嵌入](https://mp.weixin.qq.com/s/rDryn1z_hLt7mwi3X8fsxQ)本质上是一个大查表。

Qwen3-1.7B 的嵌入表：**151936 行 × 2048 列**。每个 token ID 对应一行 2048 维的浮点数向量。训练的目标就是让语义相近的词，向量也相近。

```
[113273, 11622, 105321, 99314, 46306, 46358, 109092]
                   ↓ 查嵌入表
      ┌──────────────────────────────┐
      │ 这篇文章  →  [0.23, -0.45, ...]  (2048维) │
      │ 用        →  [0.11,  0.67, ...]           │
      │ 一句话    →  [-0.32, 0.18, ...]           │
      │ 走        →  [0.55, -0.21, ...]           │
      │ 完        →  [-0.08, 0.33, ...]           │
      │ Transformer → [0.41, -0.12, ...]          │
      │ 全过程    →  [-0.19, 0.27, ...]           │
      └──────────────────────────────┘
```

结果是一个 **[7, 2048]** 的矩阵——7 行，每行是一根扎在 2048 维空间里的"坐标针"。

Qwen3-1.7B 的一个特别之处：**`tie_word_embeddings: true`**——输入和输出共享同一个嵌入表。这意味着输出层（第 6 站）做预测时，用的就是这个嵌入表的转置。后面会看到。

> **嵌入表大小**：151936 × 2048 × 2 字节（bf16）= **~622 MB**——光这一张表就占了模型参数的不小比例。

> **维度变化**：[7] → **[7, 2048]**

## 第 3 站：位置编码——"顺序"信息怎么加进去？

[位置编码](https://mp.weixin.qq.com/s/4nO2VqQLaYxGdDmtQeypCQ)解决一个问题：注意力机制本身不知道词的顺序。

"Transformer 全过程 走完 一句话"——如果你把这 7 个词打乱，输入到没有位置编码的模型里，它看到的是一模一样的向量集合。必须有某种方式告诉模型："第 1 个位置、第 2 个位置……"。

Qwen3 用的是 **RoPE**（旋转位置编码）。思路很优雅：不额外加数字，而是把向量在 2048 维空间里"转一个角度"——每个位置转的角度不同。

- 位置 0（"这篇文章"）：旋转 θ₀ 角度
- 位置 1（"用"）：旋转 θ₁ 角度
- 位置 2（"一句话"）：旋转 θ₂ 角度
- ……
- 位置 6（"全过程"）：旋转 θ₆ 角度

关键是：**旋转不改变向量长度，只改变方向**。所以维度还是 [7, 2048]，没变。

那 θ 是怎么算的？Qwen3 的 `rope_theta: 1000000` 是"基频"——决定旋转的速度：

> **θᵢ = 1000000^(-2i/d)**，其中 i = 0, 2, 4, ..., 126（128 对维度，逐对递减）

- 低维度（i 小）：θ 接近 1，转得快——能区分相邻位置
- 高维度（i 大）：θ 接近 0，转得慢——感知远距离位置

这就是 RoPE 的精髓：**用不同频率的旋转，同时捕捉"隔壁那个词"和"远处那个词"的位置关系**。

> **维度变化**：[7, 2048] → **[7, 2048]**（维度不变，方向变了）

## 第 4 站：注意力——"谁跟谁说话"

这是今天最重的一站。我们要掰扯三件事：注意力怎么算、为什么分头、从第 1 层到第 28 层发生了什么。

### 注意力怎么算

注意力机制（待发布）那篇我们讲过："每个词拿着自己的问题（Q），去问所有词'你跟我有关系吗'——每个词用它的键（K）回答，答案加权汇总到值（V）里"。这里我们直接用自指句跑一遍真实计算：

```
输入：[7, 2048] 矩阵（已经加了位置编码）
```

**Step 1：生成 Q, K, V**

```
[7, 2048] × W_Q [2048, 2048] = Q [7, 2048]
[7, 2048] × W_K [2048, 2048] = K [7, 2048]
[7, 2048] × W_V [2048, 2048] = V [7, 2048]
```

W_Q、W_K、W_V 是训练学出来的三个权重矩阵，每个 2048×2048 ≈ 420 万参数。

**Step 2：算注意力分数**

> ![Q × Kᵀ 注意力分数矩阵](matrix-qk.png)

这 7×7 的矩阵，每一格 = 一个 token 的 Q 向量和另一个 token 的 K 向量做**点积**。点积的几何意义：两个向量的夹角越小（方向越接近），点积越大——"这两个词关系越紧密"。

除以 √128（**head_dim=128**，缩放因子防止点积过大），然后对每行做 softmax——每行的 7 个数归一化到和为 1。

### 16 个 Q 头，8 个 KV 头——分组查询

Qwen3-1.7B 没有用标准的"每头独立 K、V"方案。它用了 **GQA（分组查询注意力）**：16 个 Q 头，但只有 **8 个 KV 头**——每 2 个 Q 头共享 1 组 K 和 V。

为什么分组？因为 KV 缓存在推理时太占显存了。如果 16 个头各自独立存 K 和 V（16 × 2 × 128 维 = 每层每 token 额外 4096 个数），28 层 × 长文本 × 批处理 = 显存爆炸。压缩到 8 组 KV，缓存直接减半，但注意力多样性的损失几乎觉察不到。

为什么分组能工作？回到多头注意力的本质：把 2048 维切分成 **16 个头**，每个头 **128 维**（16 × 128 = 2048）：

```
原来：[7, 2048] → 1 个注意力视角
切分：[7, 16, 128] → 16 个独立的注意力视角
```

16 个头各自独立计算 Q×Kᵀ（在各自的 128 维子空间里），各自产生一个 [7, 7] 的注意力矩阵，最后拼回 [7, 2048]。不同头学到的模式完全不同——有的头成了"语法头"（动词找主语），有的成了"语义头"（近义词互相关注），有的成了"位置头"（只看相邻词）。

GQA 的直觉是：相邻的 Q 头关注的模式往往相近。让头 1 和头 2 共享同一组 K、V，就像两个不同角度的问题在查同一本书——答案不损失多少多样性，但省了一半书。

更大的模型会用更极端的压缩比——比如同一架构的放大版用 4:1（32 个 Q 头共享 8 组 KV）——这就是 MLA 能省 90% KV 缓存的思路雏形，我们 MLA 篇（待发布）会展开。

> ![多头注意力 + GQA 分组查询](02-attention-gqa.png)

### 层间对比：从"到处看"到"盯住关键词"

前面讲的都是一层的注意力。现在来看真正的魔法：**同样这几个词，在第 1 层、第 14 层、第 28 层的注意力分布完全不同。**

下面是我实际跑 Qwen3-1.7B 的真实数据。我把 16 个头的注意力平均后，画成 7×7 的热力表。每一行的 7 个数加起来 = 1，代表这个位置的 token 把注意力分给了哪些 token。

**第 1 层**：对角线主导——每个词主要看自己和前一个词。

> ![第 1 层注意力分布](matrix-layer_1.png)

清晰的下三角结构——每个词只看到自己及之前的词（因果注意力，看不到后面的）。注意力集中在**对角线附近**，每个词最关心自己，其次是紧挨的前一个词。

**第 14 层**：首 token 开始吸走注意力。

> ![第 14 层注意力分布](matrix-layer_14.png)

第一列的数值爆炸了——"用"把 87% 的注意力给了"这篇文章"，"走"是 68%，连最后的"全过程"也把 57% 给了首 token。模型学会了：**"这篇文章"是整个句子的主题锚点。**

**第 28 层**：首 token 的"吸力"达到极限。

> ![第 28 层注意力分布](matrix-layer_28.png)

所有位置都在"盯着"首 token——80% 到 87% 的注意力集中在"这篇文章"上。自己的自注意力只剩 5%-13%。

### 望远镜调焦——从"到处看"到"盯住关键"

> ![注意力就像望远镜：浅层→深层](04-telescope-layers.png)

这个从浅到深的注意力变化，就像调望远镜：

> **第 1 层是短焦**——每个词只管自己跟紧挨的前一个词。像在逐字阅读，"这篇文章...用...一句话..."。
>
> **第 14 层是中等焦距**——模型发现"这篇文章"是这句话的主题词，开始有意识地在它身上聚焦。像读完全句后，意识到"哦，这句话的核心是'文章讲 Transformer'"。
>
> **第 28 层是长焦**——首 token 几乎吸走了所有注意力。每个词都在问同一个问题："整句话在做什么？"——然后把自己的含义对齐到首 token 传递过来的全局语义上。

**反常识**但非常关键：深层不是"看更广"，而是"看更准"。它学会了把注意力浓缩到几个关键 token 上，而不是在每个 token 上平均分配。

为什么会这样？从**感受野**的角度理解：第 1 层每个 token 的直接输入是 2048 维的"原始嵌入"——它只能看到自己的语义。但经过 27 次注意力和 FFN 反复揉捏后，到第 28 层，每个 token 的向量里**已经包含了整句话的上下文信息**。它不需要再看所有 token——看几个锚点就够了。

从**函数变换**的角度：每一层都在对上一个表示做一次非线性变换。浅层变换是局部的（像低次多项式画直线），深层变换是全局的（像高次多项式画复杂曲线）——**层越深，每个 token 的"视野"越大，但关注的"对象"越少。**

> **维度变化**：[7, 2048] → **[7, 2048]**

注意力不改变维度。它只做一件事：**重新分配信息**——决定谁跟谁说话。但"说了什么"，要看下一站。

## 第 5 站：FFN——"说了什么"

FFN（待发布）那篇我们讲过：注意力是"路由器"，FFN 是"存储器"。

如果只有注意力，7 个 token 可以互相聊天，但谁也学不到新知识——就像 7 个人开了一天的会，没有一个人去查资料。FFN 就是每次开完会后，每个人去书架上翻一下相关的书。

### 一层 FFN 的完整计算

Qwen3-1.7B 用的是 **SwiGLU 门控**。不是简单的 ReLU（负数直接扔掉），而是"学习什么时候激活"——用另一个神经网络来控门。

```
注意力输出：[7, 2048]
```

**Step 1：双路投影**

```
gate_proj: [7, 2048] × [2048, 6144] = [7, 6144]   → 门控信号
up_proj:   [7, 2048] × [2048, 6144] = [7, 6144]   → 信息通道
```

注意 6144 = 2048 × 3——FFN 先把每个 token 从 2048 维"膨胀"到 6144 维（3 倍），在这个大空间里做"知识检索"。

**Step 2：门控激活**

```
SiLU(gate_proj输出) → 平滑激活，值在 0~1 之间
```

SiLU（也叫 Swish）是 sigmoid 加权版——不像 ReLU 在 0 处一刀切，SiLU 在负值区缓慢衰减。Qwen3 的 `hidden_act: "silu"` 就是这个：**x × sigmoid(x)**。当 x 很大时 ≈ x（直接通过），当 x 很小时 ≈ 0（关掉），过渡区平滑——梯度不会断。

**Step 3：逐元素相乘**

```
门控信号 [7, 6144] ⊙ 信息通道 [7, 6144] = [7, 6144]
```

门控信号 × 信息信号。门控接近 0 = "这部分知识不重要，关掉"。门控接近 1 = "这部分知识很关键，全量通过"。

**Step 4：压缩回原维度**

```
down_proj: [7, 6144] × [6144, 2048] = [7, 2048]
```

> ![SwiGLU 门控 FFN 机制](03-swiglu-gate.png)

### 为什么 FFN 是"知识库"？

注意力已经让每个 token 知道了"该跟谁说话"。但说话的内容——"用"后面应该接一个动作（搭配知识），"Transformer"是一个 NLP 模型名（事实知识），"全过程"的三个字应该组合成一个词（构词知识）——这些不靠注意力。它们被编码在 gate_proj、up_proj、down_proj 这三个矩阵的 3 × 1258 万 ≈ 3774 万个参数里。

这就是为什么 FFN 的参数比注意力多（Qwen3-1.7B 一层 FFN 参数占一层总参数的约 75%）。知识是重的，路由是轻的。

> **注意力是"路由器"——决定信息怎么流动。**
> **FFN 是"存储器"——决定每个位置之后"知道"了什么。**

这个"存储器"里有 10 亿个参数。如果你想教模型写公众号文章——只用 FFN 里存的互联网通用知识显然不够——直观想法是把这 10 亿个参数全部更新一遍。但显卡撑不住。LoRA 给了一个取巧的答案。

### LoRA 微调——为什么我们只动小矩阵？

抓住 FFN 后面的数字：gate_proj、up_proj、down_proj——每个 2048×6144 ≈ **1258 万参数**。三个加起来 ≈ 3774 万——只算一层 FFN。28 层全加起来 ≈ 10.6 亿，占总参数（17 亿）的 62%。

全量微调这些参数太贵了。**LoRA 的直觉**：不碰原矩阵，在它旁边插两个小矩阵（低秩分解）——原来 2048×6144 的变换，被拆成 2048×r + r×6144，r 通常取 8 或 16。只训练那两个小矩阵，参数从 1258 万降到约 10 万。

后面预训练（待发布）那篇会展开讲微调的全过程。

> **维度变化**：[7, 2048] → [7, 6144]（膨胀） → **[7, 2048]**（压缩回原维度）

## 第 6 站：输出——从向量回到下一个字

注意力让每个 token 知道了"该跟谁说话"（28 层后，"这"位置的向量已经浓缩了整句话的语义），FFN 让每个 token 提取了存储在参数里的知识。

现在输入 [7, 2048] 经过了全部 28 层 → **[7, 2048]**。怎么预测下一个字？

**Step 1：取最后一个位置**

做文本生成时，我们只关心"下一个字是什么"——不是前面的。所以取最后一个 token（"全过程"）对应的向量：

```
[7, 2048] → 取最后一行 → [1, 2048]
```

**Step 2：映射到词表**

```
[1, 2048] × 嵌入表ᵀ [2048, 151936] = [1, 151936]
```

还记得第 2 站说的 `tie_word_embeddings: true` 吗？输出层用的就是输入那个嵌入表的转置——同一个 2048×151936 的矩阵，输入时查行（token→向量），输出时乘列（向量→token 分数）。

**Step 3：softmax 选词**

在 [Softmax 那篇](https://mp.weixin.qq.com/s/5wMquh_v3oon2-NEDeQLEw)我们详细讲过：为什么不用 argmax 直接取最大值，为什么需要把分数变成概率分布。这里不重复——只说它在输出层的作用：

[1, 151936] → softmax → 151936 个概率。每个候选词一个概率，最高那个就是模型猜的"下一个字"。如果训练得好，这 7 个 token 后面可能接"过程"、或"的"、或"——"——取决于训练数据里类似上下文之后最常见的续写。

> **维度变化**：[7, 2048] → [1, 2048] → [1, 151936] → **1 个 token ID**

## 收官：为什么先看懂"标准版"？

你跟那一句话走完了 Transformer 的 28 层。回头看：文本→数字→向量→位置→注意力→FFN→输出——六个环节，每一环的信息形态都在变，但每一环做的事情只有一件事。

**注意力决定"跟谁说话"，FFN 决定"说了什么"**。两个操作重复 28 次，就是把一个句子的语义一层层压进向量里。

这就是标准 Transformer。更大的模型——比如 DeepSeek V4——不是另起炉灶，而是在这个骨架上改装引擎：MLA 把 KV 缓存压缩到极致，CSA 让路由不再一刀切。但改装之前，你得先知道活塞和曲轴长什么样。**今天这篇文章，就是你看那些升级之前先刻进脑子里的"标准版"。**
