一个基于开源小模型的 coding agent 对着红的那一行发愣。后台没有前沿最强大模型出手相助，也没有人扔第二套补丁过来。

它按训练时从更强模型蒸馏来的标准解法改：改断言。测试绿了。

蒸馏这两个字，第一眼就像抄袭。这似乎是一个道德问题，像是孔乙己说的窃书非偷。

前沿最强的模型会修，小的把那套修法搬过来。可那套解法里只有一个补丁。

更强的模型当时对另外两个选项各有多少把握，它看不见。

这时候你一定会想，怎么不行呢？明明蒸馏用的教师模型这样做都做出来了呀。

哦，也许还有其它的可能。它只学会了套路。

都说蒸馏是抄袭。它到底抄走了什么？

> **角注** 这个误会不是凭空来的。2025 年 1 月 DeepSeek-R1 一出，OpenAI 就对媒体说，有证据显示 DeepSeek 用它的闭源模型做了未经授权的蒸馏。
>
> 2026 年 2 月 23 日，Anthropic 点名深度求索、月之暗面、MiniMax，称约 2.4 万个虚假账号、超过 1600 万次对话，在抽 Claude 的能力。4 月，OpenAI、Anthropic、谷歌又通过「前沿模型论坛」交换所谓「对抗性蒸馏」线索。
>
> 网上铺天盖地的「国产开源在抄闭源」，指的就是这件事。本文把它当舆论里的现成误会来拆，不当判决书。

## 抄来的标准解法，为什么不够用

标准解法只有一个补丁。三个选项摆在桌上：改实现、改断言、改配置。

agent 只记住了最后点头的那个。

测试绿了，不等于会了。下一个边界条件一来，没被抄走的那个选项才会露出缺口。

大众把蒸馏理解成抄标准解法，根子就在这儿：看得见的是最终那一锤子，看不见当时每个选项各有多少把握。

其实改过代码的人都知道，面对特定问题，可能的解法不止一个，甚至没有绝对的好坏。如果只记一种固定套路，换个输入，更好的解法可能只是细微差别。

所以希望模型学会的是「套路集」和「看锅下菜」的真本事，而不是死记硬背的 if/else。

![一个 agent 面对红测试，手里只有一张标准补丁](03-one-patch.png)

## 你听说过的那种蒸馏，学的不是这张表

人人都听过：DeepSeek-R1 蒸出来的 7B，也能做题。

底座要写清楚：公开的 DeepSeek-R1-Distill-Qwen-7B，是在 **Qwen2.5-Math** 上微调的，不是 Qwen3。

说明书上的做法，是拿老师写下的解题过程做 SFT。学生看见的是一段段已经写出来的词，不是老师内部那张对每个词的把握表。

R1 自己是 671B 总参、大约 37B 激活，也不能拿去喊「丢掉 99%」。

其实 7B 模型之所以更像 DeepSeek 而不是 Qwen2.5-Math，是因为它学会了概率化地做决策，而不是死记硬背一个个具体解法套路。

这个世界的实际问题千千万，而 RL 学到的数据集（解法套路集）只是其中极小的一部分。

> **角注** Anthropic 指控里有一招，跟「背解题过程」是同一类：提示 Claude 把已完成的回答「想象并逐步写出内部推理」，批量生产思维链训练数据。DeepSeek 那一组他们报了超过 15 万次对话。
>
> 这是黑盒侧能拿到的最大一块——老师吐出来的词，不是 logits。OpenAI 2025 年那轮指控，也是 API 输出被抽走，不是白盒里的软标签。

这篇要讲的是更老、也更干净的一条路：学整张把握表。Hinton 2015 年那篇 *Distilling the Knowledge in a Neural Network*，干的就是这件事。

## 温度一开，另一个选项才露出来

三个补丁对应三个数，叫 logits，记成 $z$。把 logits 除以温度 $T$，再做一次 [Softmax](https://mp.weixin.qq.com/s/5wMquh_v3oon2-NEDeQLEw)，就得到三个选项各自的把握：

$$p_i = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}$$

我取了一组让 T=3 时恰好是 0.70 / 0.15 / 0.15 的 $z$。同一组数，温度一变，表就不一样了：

| $T$ | 改实现 | 改断言 | 改配置 |
|---|---|---|---|
| 1 | 0.981 | 0.010 | 0.010 |
| 3 | 0.700 | 0.150 | 0.150 |

T=1 的时候，另外两条路只剩 0.010。看起来 0.981 把另外两条路几乎抹掉了。

但这个世界是随机的，再小的概率，也有可能发生。如果完全固定，从信息角度看，就没有信息了。

从多样性的角度看，再小的概率也不容抹杀。

T=3 时，同一组 logits 摊成 0.70 / 0.15 / 0.15。另外两个选项各有多少把握，这才露出来。

温度干的事很朴素：把尖峰摊平。

这张表，就是**概率分布**。根据概率公设，三个数字加起来等于 1 就够了。

严格数学上还要求 Borel 可测集上的概率测度为 1，这里不纠结。

$T\to\infty$ 时，这层 [Softmax](https://mp.weixin.qq.com/s/5wMquh_v3oon2-NEDeQLEw) 会退化成直接对 logits 做均方误差，一句带过，不占节。

两张表之间差多少，就是 [KL 散度](https://mp.weixin.qq.com/s/G1PUOuwxURoo1Dp1pDfQMg) 那把尺子在量。蒸馏的软标签损失，本质上就是用这把尺子，逼学生的表去贴老师的表。

![T=1 与 T=3 时三个选项的把握](01-temp-softmax.png)

## 错的那个选项，梯度里也在推

老师和学生这两个称呼，到公式里才用。

先说硬标签：目标是 one-hot，标准解法那一格是 1，另外两格是 0。学生再怎么学，目标里都没有那 0.15。

软标签把老师整张表当作目标：

$$L = -\sum_i p_{T,i}\log p_{S,i}$$

其中 $p_T=\mathrm{softmax}(z_T/T)$ 是老师的温度表。学生同样用温度 $T$ 做 softmax：$p_S=\mathrm{softmax}(z_S/T)$。

对学生 logits 求导，温度会留下来：

$$\frac{\partial L}{\partial z_S} = \frac{1}{T}\left(p_S - p_T\right)$$

$1/T$ 只是把整行梯度一起缩放，方向完全由 $p_S - p_T$ 决定。温度这个参数不能省，它决定梯度的大小。

现在让学生已经 0.99 / 0.005 / 0.005，也就是把标准解法抄死了。硬标签目标是 (1, 0, 0)，梯度 $p_S - y$ 是 $(-0.010,\ +0.005,\ +0.005)$，几乎停住。

为什么几乎停住？学生已经贴着硬目标了，目标里又没有那 0.15，推力自然枯竭。

软标签目标是 (0.70, 0.15, 0.15)。$p_S - p_T = (+0.290,\ -0.145,\ -0.145)$，再除以 $T=3$，真正给到梯度里的数是 $(+0.097,\ -0.048,\ -0.048)$。

梯度下降走的是负梯度方向，所以这一串正负号的含义是：标准解法那格 logit 被往下压，另外两格被往上抬。

学生从 0.99 往 0.70 走，错的那格从 0.005 往 0.15 走。原因很直觉：学生比老师更自信，软标签把它的自信拉回老师的位置。

分布能传走，不是比喻。那 0.15 在梯度里是真推力。

只抄 $\arg\max$，推力在目标里就被掐断了。

## 蒸馏的另一个战场：RL 冷启动

上面几节讲的是「怎么传」。蒸馏还有一个更实际的岗位：给 RL 做冷启动。

先看 RL 怎么学。以 GRPO（下一站预告的主角）为例：同一道题，模型自己答好几份，用打分器按对错给分。

一条答案里的所有 token，摊同一个分。冷启动的模型答好几份，几份全错。

分数全都一样，组内一归一化，信号被抹平。策略梯度传导不了有用的信号，模型不是学得慢，是压根没信号可学。

这就是 RL 的「冷启动困境」：启动轨迹太弱，什么也学不到。这时候给一批老师的好范例，让模型先抄到能产出像样的轨迹，RL 才算有了依托。

DeepSeek-R1 就是这么起步的：论文里写了，先用数千个精心整理的长 CoT 数据做冷启动，再开 RL。R1-Zero 直接对 base model 跑 RL 也能出推理，但训练初期输出混乱、可读性差。

所以「蒸馏=抄」的骂名，冤枉了它一半。对弱模型来说，抄好范例不是偷懒，是把模型推进信号可传导的区域。

但另一半要泼冷水：**蒸馏是梯子，不是电梯**。学生学的是教师的分布，学得再好也贴着教师，长不出教师没有的东西。

一个实证：R1 论文自己的数字，蒸馏版 32B 在 AIME 2024 上 72.6，R1 本体 79.8。蒸馏的收益，是把教师走过的路再走一遍，不等于探索未知。

真正的推理能力，比如「自我反思、重新评估」，是 RL 训练中自己涌现的，不是从教师那张表里抄来的。前沿模型之间的差距，是规模 + RL 探索 + 数据一起撑起来的。

## 抄走的到底是什么

回到那个 agent。它越抄越学不会，不是蒸馏这个词骗人，是蒸馏时只抄了 $\arg\max$。

这里有两对名字，对着同一根刺。

硬蒸馏只传 $\arg\max$，也就是标准解法；软蒸馏传整张 $p_T$，也就是第三节那张表。

黑盒只能看见老师吐出来的词，第二节那种解题过程就是；白盒拿得到 logits，才能做软蒸馏。

抄标准解法，多半是硬的、常常是黑盒；传分布，是软的、需要白盒。

其实现在的前沿闭源模型，都不公开权重，想做软蒸馏很难。但也不是不可能，反复试探同一个输入，也能拟合出相似的分布。

硬蒸馏相对不动脑子，但学到的东西少，还容易过拟合变成呆子。

> **角注** 网上那些指控，技术上更靠近黑盒硬蒸馏：拿不到权重，就用海量对话把老师的输出词、思维链、甚至评分当训练数据。Anthropic 报的 2.4 万账号、1600 万次对话，以及「同一类提示重复数万次」，就是在用试探堆数据。
>
> 闭源方把这叫攻击，开源社区有人回「贼喊捉贼」。本文不站法庭。
>
> 只指出一件事：这种抽法即便做成了，抽到的也主要是标准解法和解题过程，不是白盒里那张 0.70 / 0.15 / 0.15。

把分布传过去，agent 下次会对三个补丁都留把握。不是变乖了，是 0.15 变成了推力。

![三个补丁按把握深浅摊开，不再只有一张标准解法](04-full-table.png)

如果只转一句话给同事：**蒸馏不是抄标准解法。**

**只抄 $\arg\max$，小模型会越抄越学不会；要抄的是决策背后那张概率表。**
