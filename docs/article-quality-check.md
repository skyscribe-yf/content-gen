# 文章质量核查规则

草稿写完后，**必须执行以下核查**（共 15 项），全部通过才能进入发布流程。第 15 项「说人话 / 去 AI 味」不豁免。

## 1. 数据准确性核查

**规则**：文章中的所有数值、实验结果、模型参数必须可验证。

执行：
1. **示例代码必须跑一遍** — 复制代码到运行环境执行，对比输出与文中描述是否一致
2. **实验数据必须复现** — 文中声称"N 步到 90%"等结果，用相同代码和种子跑一遍确认
3. **模型参数必须查源** — 引用 DeepSeek/Qwen 等模型参数时，对照 HuggingFace config.json 核实

常见错误：
- 指数计算溢出导致数值对不上
- 手算结果与代码输出不一致
- 模型版本过时（如引用已更新的 vocab_size）

## 2. 逻辑一致性核查

**规则**：文章不能存在未解释的矛盾或悖论。

执行：
1. **反直觉值必须解释** — 负数票数、概率为零等现象，不能硬说合理，必须给出直觉解释（如"反对票被算成负数"）
2. **矛盾必须化解** — 如果文章前后存在张力（如"T=1 在深层网络学不了"但"默认值是 T=1"），必须用完整段落解释转折，不能只加一句说明
3. **参数双视角** — 讨论参数时（如温度），必须同时覆盖训练和推理两个阶段的作用，不能只讲一个

自检：标出文中所有"但是""然而""看似矛盾"的地方——每个是否都有充分解释？

## 3. 本土化核查

**规则**：产品举例必须是中国用户可访问的。

```
❌ ChatGPT、Claude、GPT-4（中国用户无法直接访问）
✅ DeepSeek、豆包、Kimi、通义千问
```

涉及 API 调用时同理——用国内可访问的 API 举例。

## 4. 配图核查

**规则**：每篇文章配图不少于 4 张，穿插在各主要段落，不能集中在某一段。

配图要求：
- 每个核心概念（直觉、公式、实验）至少 1 张图
- 图片必须有信息量，不是纯装饰
- 图片中的文字/数据必须与正文一致

## 5. 结尾钩子核查

**规则**：结尾的互动问题必须满足：
1. **结合文章内容** — 不写泛泛的问题，要和文中具体知识点挂钩
2. **真正开放** — 没有标准答案，读者凭经验/直觉就能接
3. **引发讨论** — 问题本身有争议性或个人偏好空间

```
❌ 欢迎留言讨论（太泛）
❌ Softmax 的公式是什么？（有标准答案，不是开放问题）
✅ 你平时 temperature 设多少？更喜欢稳定答案还是惊喜答案？（结合内容+个人偏好）
```

## 6. 系列回引核查

**规则**：每篇文章必须主动勾引读者回读系列前文。

执行：
- 驱动问题/开头部分：提一下前文的关键结论，嵌入微信链接
- 正文涉及前文概念时：用内联链接引导回去（如"我们在[损失函数那篇]看到的 ŷ−y 魔法"）
- 不只是列链接，要让读者觉得"我需要先看那篇才能懂这篇"

## 7. 原创声明

**规则**：发布到微信公众号时，必须勾选**声明原创**。

## 8. 图片路径检查

**规则**：图片必须与 `weixin.md` 同级，markdown 引用不带 `images/` 前缀。

**原因**：图片路径错误是 `45166: invalid content hint` 发布失败的根因（详见 `docs/wechat-image-path.md`）。

## 9. 尾部链接

**规则**：尾部只用合集链接收纳逐篇链接，不用单篇链接堆叠。

## 10. 长句拆分核查

**规则**：正文中单句（两个句号/问号/感叹号之间）不超过 **60 个汉字**（含标点、不含 LaTeX/代码/链接）。

**原因**：手机屏幕每行约 15-20 字，超过 60 字的句子在手机上会折成 3-4 行无断点，读者容易读丢、读累。

执行：
1. 用脚本扫描 `weixin.md`，按句号/问号/感叹号切分，标记超长句
2. 逐条拆分：优先在破折号（——）、冒号（：）、逗号（，）处断句，断开后补句号
3. 拆分后重读，确保逻辑连贯、语气自然

常见拆分手法：
- `A——B` → `A。B`（破折号改句号）
- `A：B` → `A。B`（冒号改句号）
- `A，B，C` → `A，B。C`（长逗号链中间断开）

**豁免**：frontmatter digest、参考资料链接、合集导航链接不检查。`raw.md` / 原声槽里的作者原声句也不机械拆到 60 字——原声节奏优先，见第 15 项。只拆 AI 补的过渡句。

## 11. 正文禁词核查

**规则**：正文（含引用、图片文案）禁止出现内部工作流术语，包括「钩子」「伏笔」等写作侧词汇。

**原因**：这些是创作流程里的元词汇，读者看到会出戏，影响阅读流畅度（历史教训：引用前文时带「💡 钩子：」前缀，被读者指出）。

执行：
1. `grep -n "钩子\|伏笔" weixin.md` 必须为零
2. 引用前文原文时，只保留原文内容，去掉「💡 钩子：」这类标注前缀
3. 「伏笔/预告弧线」等说法只允许出现在 `outline.md` 的定位/自检部分，不得进入正文

**豁免**：`outline.md`、`.grill/` 日志、`draft-status.yaml`（工作文件）。

## 12. 用词规范核查

**规则**：正文中表示「剖析/讲解」含义的动词统一用「拆解」，不用单字「拆」。

**原因**：单字「拆」在正文里语义含糊（可指「拆开/分开」也可指「拆解讲解」），统一为「拆解」更清晰、更书面。

执行：
1. 表示「拆解讲解」处一律写「拆解」：如「上篇拆解五维并行」「下一篇拆解 DualPipe」「把「为什么坏」和「怎么修」拆解」
2. 表示「分开/分离」的字面动作保留「拆开」：如「把 A 和 B 拆开处理」——此处「拆开」是「分开」的意思，不改
3. 自检：`grep -n "拆" weixin.md`，逐处判断是「拆解讲解」还是「分开」语义，前者改「拆解」

## 13. 爆款检查器（不满足必须改写）

**规则**：对照 [`docs/viral-article-playbook.md`](viral-article-playbook.md) 的爆款规律逐项核查，任一不满足**必须改写对应部分**后重查，禁止带病进入发布流程。

核查清单：

1. **标题**：命中「反常陈述 + 为什么/怎么」疑问句？有数字反差或否定常识？专业关键词前置？（对照：「慢50倍的硬盘，为什么反而更快」✅ vs「打分标准决定学习方向」❌）
2. **开头前两段**：场景对比 / 个人故事 / 行业冲突（抛问题）三选一？**禁止**以系列导航、「上一篇我们……」链接列表开头（推荐流量 86% 是陌生人，导航开头劝退）
3. **小标题悬念链**：把所有小节标题单独拎出来连读，能否构成一条完整故事线？「数学原理」「算法实现」这类纯功能标签超过 1/3 即不通过，改成推进叙事的问句/结论句
4. **首尾闭环**：开头抛的问题，结尾是否明确回答？
5. **选题**：是否含痛点（慢/贵/反直觉）或绑当期国产热点模型？纯概念又无反直觉点的选题，回退选题人重议

**原因**：56 篇实证——标题强弱直接区分 300 阅读上下（对照组 185/135，爆款组 362~2328）；开头放导航的两篇（566/362）显著低于钩子开头（1100+）。

## 14. 自动成稿原声槽

**规则**：自动成稿（grill-me → `outline.md` → `weixin.md`）必须对照大纲 `## 作者原声槽`，确认 `weixin.md` 里至少 5 处「已填」或「沿用」原句逐字在场。缺一条就按槽补插，禁止改写成书面语后再过关。

执行：
1. 确认本文走自动成稿。目录里有作为素材入口的 `raw.md`、且按素材直出 skill 成稿的，**本项豁免**（仍核它自己的原声句清单）。
2. 打开 `outline.md` 的 `## 作者原声槽`，数状态为「已填」或「沿用」的条目，必须 ≥ 5。
3. 对每一条「原句」在 `weixin.md` 里逐字检索，必须在场。
4. 缺句则按槽的「位置」原句插入后再查；不得把口语改成书面语充数。

细节（什么算一处、对话怎么问、不满 5 不准写正文）见 [`docs/writing-flow.md`](writing-flow.md)。

## 15. 说人话 / 去 AI 味（不满足必须改写）

**规则**：成稿必须像作者在说话，不像 AI 在讲课，也不像 AI 在「注入人味」。声音对照 [`branding/style-corpus/style-features.md`](../branding/style-corpus/style-features.md)，**不要**对照 `style-guide.md` 的禁用词表或「人味儿八法」配额——那两处会误杀作者口头禅、并诱使编造第一人称。

本项不豁免。素材直出核过渡段；自动成稿核 AI 写的钩子、过渡、小结。原声句本身不拿来「去 AI 味」。

### 先认语料

1. 读 `style-features.md` 全文。
2. 按当篇体裁抽金标准对照：
   - **长文 / 数学篇**：至少读一篇金标准 `raw.md`（矩阵秩 / 期望与导数换序 / 多维高斯注解 / KL 散度，任选与本文接近的）
   - **贴图**：读 `branding/style-corpus/tietu-raw/` 里 2 篇手敲 digest
3. **禁止当对照**：2026-08-23 及之后的贴图轨道（`price-war-sequel`、`dsh-harness`、`pi-dsh-pruner` 等，作者标明不是完全手敲）；`style-guide.md` 里学徒/实习生那类示例。

### 执行（六步，漏一步不算过）

1. **真 AI 腔扫描**（命中必改）：

   ```
   grep -nE '值得注意的是|让我们来|总而言之|综上所述|不难发现|不难看出|需要指出的是|深入探讨|全面分析|由上可知|今天我们来聊聊|随着AI的发展|随着 AI 的发展' weixin.md
   ```

   教材/公文套话一并改：表现优异、具有显著优势、综合来看、首先…其次…最后…（作为段骨架时）。

2. **口头禅误杀检查**：`然而` / `其实` / `本质上` / `事实上` / `实际上` / `某种程度上` / `不过` / `当然` / `嘛` / `呗` **不是** AI 腔。出现在原声或作者同款推演里一律保留。只有写成「本质上来说，我们可以发现」这种套话才改。

3. **假人味扫描**：AI 过渡里若出现「我第一次 / 我盯着 / 看了十分钟 / 差点把键盘摔了 / 学徒 / 实习生」等发现戏，到 `raw.md` 或 `outline.md`「作者原声槽」里检索。**原文没有 → 删掉或改回中性陈述**，禁止用假第一人称充「人味」。人味儿八法的次数配额不作验收。

4. **术语人话**：每个新术语首次出现，后面要有一句作者口气的解释。合格：「用一句通俗的话说，这个变换其实是有很大水分的。」不合格：打标签「说人话就是：……」。`grep -n '说人话就是' weixin.md` 必须为零（恢复期 B.4 要的是人话解释，不是这四个字）。

5. **节奏对体裁**：
   - 长文：原声长句不要拆成「这是真的，不是段子。」式短打；AI 过渡应能接上「先怎么学 → 换视角推 → 落到 AI → 划边界」
   - 贴图：保持手敲短段 + 亲测 + 结尾互动，不要写成数学长文

6. **抽读**：抽 3 处原声、3 处 AI 过渡，连起来读。过渡接不上原声（突然变讲师腔、突然变新闻短打、突然开始排比小结）→ 只改过渡，不改原声。

### 自检

- [ ] 第 1 步 grep 为零（或命中处已改）
- [ ] 没有为去 AI 味删掉作者的「然而 / 其实 / 本质上」
- [ ] 没有原文没有的第一人称发现戏
- [ ] 没有「说人话就是」标签
- [ ] 没有把原声长句拆成昨今贴图那种短打
- [ ] 删掉所有第一人称之后，长文仍能看出「有人把一条思路推完」，贴图仍能看出「有人用过」——如果只剩知识搬运，缺的是原声，去找作者补，禁止 AI 代拟

**原因**：旧流程只扫 `style-guide.md` 禁词、再按人味八法「注入」。结果是误杀作者口头禅，并编出一堆作者没说过的「我」。2026-08 长文 raw.md 表明作者真声是带从句的推演 + 典故类比；去 AI 味是去掉讲师腔，不是把稿子改成另一个人。
