# 文章质量核查规则

草稿写完后，**必须执行以下核查**（共 19 项），全部通过才能进入发布流程。第 15 项「说人话 / 去 AI 味」、第 16 项「转发 / 点赞欲」、第 17 项「段落长度与标题分层」、第 18 项「段落衔接与章节过渡」与第 19 项「结尾引用文献核查」不豁免。

## 1. 数据准确性核查

**规则**：文章中的所有数值、实验结果、模型参数必须可验证。

执行：
1. **示例代码必须跑一遍** — 复制代码到运行环境执行，对比输出与文中描述是否一致
2. **实验数据必须复现** — 文中声称"N 步到 90%"等结果，用相同代码和种子跑一遍确认
3. **模型参数必须查源** — 引用 DeepSeek/Qwen 等模型参数时，对照 HuggingFace config.json 核实

常见错误：
- 指数计算溢出导致数值对不上
- 手算结果与代码输出不一致
- 模型版本过时（如引用已更新的 vocab_size）

## 2. 逻辑一致性核查

**规则**：文章不能存在未解释的矛盾或悖论。

执行：
1. **反直觉值必须解释** — 负数票数、概率为零等现象，不能硬说合理，必须给出直觉解释（如"反对票被算成负数"）
2. **矛盾必须化解** — 如果文章前后存在张力（如"T=1 在深层网络学不了"但"默认值是 T=1"），必须用完整段落解释转折，不能只加一句说明
3. **参数双视角** — 讨论参数时（如温度），必须同时覆盖训练和推理两个阶段的作用，不能只讲一个

自检：标出文中所有"但是""然而""看似矛盾"的地方——每个是否都有充分解释？

## 3. 本土化核查

**规则**：产品举例必须是中国用户可访问的。

```
❌ ChatGPT、Claude、GPT-4（中国用户无法直接访问）
✅ DeepSeek、豆包、Kimi、通义千问
```

涉及 API 调用时同理——用国内可访问的 API 举例。

## 4. 配图核查

**规则**：每篇文章配图不少于 4 张，穿插在各主要段落，不能集中在某一段。

配图要求：
- 每个核心概念（直觉、公式、实验）至少 1 张图
- 图片必须有信息量，不是纯装饰
- 图片中的文字/数据必须与正文一致

## 5. 结尾钩子核查

**规则**：结尾的互动问题必须满足：
1. **结合文章内容** — 不写泛泛的问题，要和文中具体知识点挂钩
2. **真正开放** — 没有标准答案，读者凭经验/直觉就能接
3. **引发讨论** — 问题本身有争议性或个人偏好空间

```
❌ 欢迎留言讨论（太泛）
❌ Softmax 的公式是什么？（有标准答案，不是开放问题）
✅ 你平时 temperature 设多少？更喜欢稳定答案还是惊喜答案？（结合内容+个人偏好）
```

## 6. 系列回引核查

**规则**：每篇文章必须主动勾引读者回读系列前文。

执行：
- 驱动问题/开头部分：提一下前文的关键结论，嵌入微信链接
- 正文涉及前文概念时：用内联链接引导回去（如"我们在[损失函数那篇]看到的 ŷ−y 魔法"）
- 不只是列链接，要让读者觉得"我需要先看那篇才能懂这篇"

## 7. 原创声明

**规则**：发布到微信公众号时，必须勾选**声明原创**。

## 8. 图片路径检查

**规则**：图片必须与 `weixin.md` 同级，markdown 引用不带 `images/` 前缀。

**原因**：图片路径错误是 `45166: invalid content hint` 发布失败的根因（详见 `docs/wechat-image-path.md`）。

## 9. 尾部链接

**规则**：尾部只用合集链接收纳逐篇链接，不用单篇链接堆叠。

## 10. 长句拆分核查

**规则**：正文中单句（两个句号/问号/感叹号之间）不超过 **60 个汉字**（含标点、不含 LaTeX/代码/链接）。

**原因**：手机屏幕每行约 15-20 字，超过 60 字的句子在手机上会折成 3-4 行无断点，读者容易读丢、读累。

执行：
1. 用脚本扫描 `weixin.md`，按句号/问号/感叹号切分，标记超长句
2. 逐条拆分：优先在破折号（——）、冒号（：）、逗号（，）处断句，断开后补句号
3. 拆分后重读，确保逻辑连贯、语气自然

常见拆分手法：
- `A——B` → `A。B`（破折号改句号）
- `A：B` → `A。B`（冒号改句号）
- `A，B，C` → `A，B。C`（长逗号链中间断开）

**豁免**：frontmatter digest、参考资料链接、合集导航链接不检查。`raw.md` / 原声槽里的作者原声句也不机械拆到 60 字——原声节奏优先，见第 15 项。只拆 AI 补的过渡句。

**脚本口径（2026-10-24 起）**：`quality_check.py` 判定阈值是 **60 字 + 10% 容差 = 66 字**（作者在后台编辑时常把句子顺手拉长几个字，逐字卡 60 会把「作者改稿」误报为「AI 长句」）；原声段按第 14 项的相似度判定豁免；尾部块（热门文章 / 合集导航 / 参考资料 / 话题标签）整块不扫。已发布文章回拉后用 `--published` 跳过本项（见第 20 项）。

## 11. 正文禁词核查

**规则**：正文（含引用、图片文案）禁止出现内部工作流术语，包括「钩子」「伏笔」等写作侧词汇。

**原因**：这些是创作流程里的元词汇，读者看到会出戏，影响阅读流畅度（历史教训：引用前文时带「💡 钩子：」前缀，被读者指出）。

执行：
1. `grep -n "钩子\|伏笔" weixin.md` 必须为零
2. 引用前文原文时，只保留原文内容，去掉「💡 钩子：」这类标注前缀
3. 「伏笔/预告弧线」等说法只允许出现在 `outline.md` 的定位/自检部分，不得进入正文

**豁免**：`outline.md`、`.grill/` 日志、`draft-status.yaml`（工作文件）。

## 12. 用词规范核查

**规则**：正文中表示「剖析/讲解」含义的动词统一用「拆解」，不用单字「拆」。

**原因**：单字「拆」在正文里语义含糊（可指「拆开/分开」也可指「拆解讲解」），统一为「拆解」更清晰、更书面。

执行：
1. 表示「拆解讲解」处一律写「拆解」：如「上篇拆解五维并行」「下一篇拆解 DualPipe」「把「为什么坏」和「怎么修」拆解」
2. 表示「分开/分离」的字面动作保留「拆开」：如「把 A 和 B 拆开处理」——此处「拆开」是「分开」的意思，不改
3. 自检：`grep -n "拆" weixin.md`，逐处判断是「拆解讲解」还是「分开」语义，前者改「拆解」

## 13. 爆款检查器（不满足必须改写）

**规则**：对照 [`docs/viral-article-playbook.md`](viral-article-playbook.md) 的爆款规律逐项核查，任一不满足**必须改写对应部分**后重查，禁止带病进入发布流程。

核查清单：

1. **标题**：命中「反常陈述 + 为什么/怎么」疑问句？有数字反差或否定常识？专业关键词前置？（对照：「慢50倍的硬盘，为什么反而更快」✅ vs「打分标准决定学习方向」❌）
2. **开头前两段**：场景对比 / 个人故事 / 行业冲突（抛问题）三选一？**禁止**以系列导航、「上一篇我们……」链接列表开头（推荐流量 86% 是陌生人，导航开头劝退）
3. **小标题悬念链**：把所有小节标题单独拎出来连读，能否构成一条完整故事线？「数学原理」「算法实现」这类纯功能标签超过 1/3 即不通过，改成推进叙事的问句/结论句
4. **首尾闭环**：开头抛的问题，结尾是否明确回答？
5. **选题**：是否含痛点（慢/贵/反直觉）或绑当期国产热点模型？纯概念又无反直觉点的选题，回退选题人重议

**原因**：56 篇实证——标题强弱直接区分 300 阅读上下（对照组 185/135，爆款组 362~2328）；开头放导航的两篇（566/362）显著低于钩子开头（1100+）。

## 14. 自动成稿原声槽

**规则**：自动成稿（grill-me → `outline.md` → `weixin.md`）必须对照大纲 `## 作者原声槽`，确认 `weixin.md` 里至少 5 处「已填」原句逐字在场，且无 `【作者填入】` 占位符残留。缺一条就按槽补插，禁止改写成书面语后再过关。

**两轮质检口径（2026-11-07 作者定）**：第一轮质检（`--skip-voice`）**跳过本项**——作者此时正在 VS Code 填原声；本项只在**发布前终检**把关。终检前 AI 先把 `outline.md` 中「已填」原句同步进本篇 `quality_check.json` 的 `slots`（逐字）。

执行：
1. 确认本文走自动成稿。目录里有作为素材入口的 `raw.md`、且按素材直出 skill 成稿的，**本项豁免**（仍核它自己的原声句清单）。
2. 打开 `outline.md` 的 `## 作者原声槽`，数状态为「已填」的条目（「待填」「跳过」不计），必须 ≥ 5。
3. 对每一条「原句」在 `weixin.md` 里比对（归一化后覆盖率 ≥ 90%，见下方脚本口径），必须在场。
4. 缺句则按槽的「位置」原句插入后再查；不得把口语改成书面语充数。
5. 扫 `weixin.md` 无 `【作者填入】` 残留（脚本门禁，见 `quality_check.py` 第 14 项）。

细节（什么算一处、占位符怎么列、不满 5 不准存草稿箱）见 [`docs/writing-flow.md`](writing-flow.md)。

**脚本口径（2026-10-24 起）**：原声核对从「逐字包含」改为**归一化覆盖率 ≥ 90%**（去空白后比对；容忍后台编辑的少量增删与标点替换，例如「一年以前→其实一年多以前」「原因很简单，→原因很简单：」）。作者在后台**大幅改写**（覆盖率 < 90%）时，视为新的原声版本：把 `SLOTS` 里该槽**按线上文字重录**并在注释写明日期，不得为了过门禁把线上文字改回去。已发布文章回拉后用 `--published` 跳过本项。

## 15. 说人话 / 去 AI 味（不满足必须改写）

**规则**：成稿必须像作者在说话，不像 AI 在讲课，也不像 AI 在「注入人味」。声音对照 [`branding/style-corpus/style-features.md`](../branding/style-corpus/style-features.md)，**不要**对照 `style-guide.md` 的禁用词表或「人味儿八法」配额——那两处会误杀作者口头禅、并诱使编造第一人称。

本项不豁免。素材直出核过渡段；自动成稿核 AI 写的钩子、过渡、小结。原声句本身不拿来「去 AI 味」。

### 先认语料

1. 读 `style-features.md` 全文。
2. 按当篇体裁抽金标准对照：
   - **长文 / 数学篇**：至少读一篇金标准 `raw.md`（矩阵秩 / 期望与导数换序 / 多维高斯注解 / KL 散度，任选与本文接近的）
   - **贴图**：读 `branding/style-corpus/tietu-raw/` 里 2 篇手敲 digest
3. **禁止当对照**：2026-08-23 及之后的贴图轨道（`price-war-sequel`、`dsh-harness`、`pi-dsh-pruner` 等，作者标明不是完全手敲）；`style-guide.md` 里学徒/实习生那类示例。

### 执行（六步，漏一步不算过）

1. **真 AI 腔扫描**（命中必改）：

   ```
   grep -nE '值得注意的是|让我们来|总而言之|综上所述|不难发现|不难看出|需要指出的是|深入探讨|全面分析|由上可知|今天我们来聊聊|随着AI的发展|随着 AI 的发展' weixin.md
   ```

   教材/公文套话一并改：表现优异、具有显著优势、综合来看、首先…其次…最后…（作为段骨架时）。

2. **口头禅误杀检查**：`然而` / `其实` / `本质上` / `事实上` / `实际上` / `某种程度上` / `不过` / `当然` / `嘛` / `呗` **不是** AI 腔。出现在原声或作者同款推演里一律保留。只有写成「本质上来说，我们可以发现」这种套话才改。

3. **假人味扫描**：AI 过渡里若出现「我第一次 / 我盯着 / 看了十分钟 / 差点把键盘摔了 / 学徒 / 实习生」等发现戏，到 `raw.md` 或 `outline.md`「作者原声槽」里检索。**原文没有 → 删掉或改回中性陈述**，禁止用假第一人称充「人味」。人味儿八法的次数配额不作验收。

4. **术语人话**：每个新术语首次出现，后面要有一句作者口气的解释。合格：「用一句通俗的话说，这个变换其实是有很大水分的。」不合格：打标签「说人话就是：……」。`grep -n '说人话就是' weixin.md` 必须为零（恢复期 B.4 要的是人话解释，不是这四个字）。

5. **节奏对体裁**：
   - 长文：原声长句不要拆成「这是真的，不是段子。」式短打；AI 过渡应能接上「先怎么学 → 换视角推 → 落到 AI → 划边界」
   - 贴图：保持手敲短段 + 亲测 + 结尾互动，不要写成数学长文

6. **抽读**：抽 3 处原声、3 处 AI 过渡，连起来读。过渡接不上原声（突然变讲师腔、突然变新闻短打、突然开始排比小结）→ 只改过渡，不改原声。

7. **表达自然度扫描**（2026-09-06 新增，因 R1 下篇打磨教训）：
   - **标题朗读测试**：标题完整读一遍，语序是否顺口？「正确率为什么从 71% 涨到 86.7%」这类把疑问词夹中间的句式直接毙，改为「为什么正确率能从 71% 涨到 86.7%」；
   - **系列文开头**：若是上/下篇、续集，第一段必须对没读过前文的读者友好——快速交代前篇背景（谁、干了什么、结论是什么），不能「昨天那个模型」直接开场；
   - **专名首现介绍**：AIME、MATH、o1、DeepSeek 等评测名/模型名首次出现必须带一句身份介绍（是什么/哪家的/何时），不能裸奔；
   - **突兀短句**：段落/小节开头不能是突然甩出的断言句（「边界必须说清楚」「数字说话：」），要有过渡（「有一点必须要和大家说明白」「让数字自己来说话」）；
   - **引文句式**：「XX 等人的实验：」生硬，用「XX 等人的实验表明：」；「论文里的对照」不完整，用「论文原文里面的对照表明」；
   - **错别字**：常见「类似与/以至于/在再」类错字，`grep` 一遍全文。

8. **禁止自造半术语**（2026-09-19 新增，因扩散步数篇「团宽」教训）：把一个标准量写成自创的合成词，读者从没见过、也查不到，同时还丢了精度——「团宽」即为一例（它其实就是高斯团的标准差 σ=0.35，写成「宽」还含混了 1σ / 2σ / 全宽）。规则：**要么用标准名（标准差 σ、方差、FID、能量距离），要么用大白话（这个团有多宽），禁止把两者焊成一个半术语**。自检：把正文里所有带「宽 / 度 / 率 / 值 / 量 / 系数 / 尺度」后缀的名词逐个问一遍「这个词在教材或论文里出现过吗？」没把握的就换成标准名 + 一句人话解释。改名时注意连带核对：术语一旦从「比喻」变成「精确量」，原文里靠比喻蒙过去的断言会立刻变成错句（本篇「误差超过团宽 → 点被推出自己那个团」在 σ 口径下就不成立，实测 1.04σ 到不了邻团，须一并改写）。脚本图注、`outline.md` 里的旧措辞同批改掉，图片要重渲。

### 自检

- [ ] 第 1 步 grep 为零（或命中处已改）
- [ ] 无自造半术语（第 8 步）：带「宽/度/率/值/量/系数/尺度」后缀的名词逐个核过是标准名还是大白话
- [ ] 没有为去 AI 味删掉作者的「然而 / 其实 / 本质上」
- [ ] 标题朗读顺口、无拗口语序（第 7 步）
- [ ] 系列文第一段对没读过前文的读者友好，交代前篇背景
- [ ] 评测名/模型名首现均有身份介绍（AIME 2024 = 美国数学邀请赛等）
- [ ] 无突兀断言句开场、无「XX 等人的实验：」式生硬引文
- [ ] 无「类似与」类错别字
- [ ] 没有原文没有的第一人称发现戏
- [ ] 没有「说人话就是」标签
- [ ] 没有把原声长句拆成昨今贴图那种短打
- [ ] 删掉所有第一人称之后，长文仍能看出「有人把一条思路推完」，贴图仍能看出「有人用过」——如果只剩知识搬运，缺的是原声，去找作者补，禁止 AI 代拟

**原因**：旧流程只扫 `style-guide.md` 禁词、再按人味八法「注入」。结果是误杀作者口头禅，并编出一堆作者没说过的「我」。2026-08 长文 raw.md 表明作者真声是带从句的推演 + 典故类比；去 AI 味是去掉讲师腔，不是把稿子改成另一个人。

## 16. 转发 / 点赞欲检查器（2026-08-31 新增，不满足必须改写）

**规则**：第 13 项管「点进来」，本项管「转出去」和「赞起来」。推荐系统的冷启动测试看的是信息流点击（第 13 项）+ **首日互动样本**（转发/点赞/留言），转发和点赞是算法判断「这篇值得给量」的硬信号；同时分享率 ≥10% 是恢复期文章级 KPI 之一（见 `wechat-ops.md` 监控判据），转发欲要做成设计而非碰运气。逐项核查，任一不满足**必须改写对应部分**后重查。

### A. 转发欲（把「想想吧」变成「顺手吧」）

1. **有可转发的一句话吗？** 全文里至少有一处能原样转发的「金句」——一句自成一体、脱离上下文也成立的话（一句话总结结论 / 一句反直觉判断 / 一句能当枪使的吐槽）。替代读法：如果只转一句话给同事，你转哪句？转不出来 = 没设计。
2. **有身份标签吗？** 读者转发时，标题/内容让 TA 显得什么？（上进的专业人 / 懂行的内行 / 有态度的意见领袖）。没有身份标签的转发=普通分享，读者没有动力替你扩散。
3. **有分享借口吗？** 文末是否给了「一句话总结卡」或类似结构（见 `wechat-ops.md` 恢复期互动增量第 3 条）？——把转发决策从「想想吧」变成「顺手吧」。
4. **转发后好看吗？** 截取标题+封面缩图模拟朋友圈卡片：陌生人在信息流里看到这一帧，会不会因为「标题有画面/有反差」而愿意点开？顺手检查标题和封面感官冲击力（`article-title-seo.md` 第 9 条 / `image-generation.md` 封面冲击力节）。
5. **封面文字是脚本叠的吗？** 封面文字必须 `make_cover.py` 脚本叠加（AI 禁止直写中文），总字数 ≤12，缩到 ~120px 仍可辨；`quality_check.py` 每次运行自动核验（`check_cover.py` + `cover_meta.json` + `00-cover-base.png` 证据）。

### B. 点赞欲（把「看过」变成「认同」）

1. **有情绪高点吗？** 全文至少一处让读者「哇」或「认同」的瞬间（反直觉结论揭晓 / 打脸常识 / 数字反差落地）。技术文也要有：读者读完有「原来如此」的顿悟点 → 点赞动机是「这文帮我搞懂了」。
2. **有立场/态度吗？** 作者有没有明确站边（「这个做法是错的」「我没想到这里这么重要」）？中性科普文没有态度，读者看完只会「哦」，不会「赞」。
3. **3 秒决策检查**：信息流刷到时，标题/首屏是否 3 秒内给出「这篇值得点/值得赞」的理由？首屏信息密度过低、纯背景铺垫开场 = 点赞欲望被掐灭。
4. **结尾有互动杠杆吗？** 文末是否有可回答的具体问题（30 秒能答）+ 点赞/关注引导（见第 13 项 + `wechat-ops.md`）？互动引导缺失或太泛「欢迎点赞」= 白送的机会。

### 自检（发布前必过）

- [ ] 能指认全文至少 1 句「金句」（原样可转发，脱离上下文成立）
- [ ] 转发场景下身份标签明确（读者转出去像个懂行的人）
- [ ] 文末有一句话总结卡 / 分享借口
- [ ] 有 1 个明确情绪高点或「原来如此」顿悟点
- [ ] 作者立场明确（有态度，不是中性搬运）
- [ ] 文末问题 30 秒可答（参考恢复期 B.4 合格模板）

**数据依据**（2026-08-31 审计）：分享率 ≥10% 达标 2/5（每步 20.3%、智谱 19.2%；信息熵 8.3%、GAE 6.6% 不达标）；留言 ≥5 达标 0/5。转发/点赞做的好的（智谱 14 分享/73 读、每步 12/59）与差的（GAE 4/61）在阅读量相当的情况下分享差 3 倍——差异就在转发欲设计，不在内容质量。

## 17. 段落长度与标题分层（2026-10-10 作者新规，不满足必须改写）

**作者口径（2026-10-10 原话）**：控制好每一个段落的字数，**不超过 80 个字一段，长段落必须拆分**，拆分**按意思来**；有些**醒目的句子要单独放一段**；标题要**多级**，不能让很长的段落没有分二级标题。

### A. 段落 ≤80 字

1. **硬上限 80 个可视字（CJK）**。扫描 `weixin.md` 正文时排除：标题行、列表项、图片行、尾部热门/标签块、参考资料。任一普通段落超 80 字即不合格。
   **脚本口径（2026-10-24 起）**：判定条件是「**超 88 字（80 + 10% 容差）且超过 3 句**」——作者在后台合并相邻短段时，两三个 ≤80 字的段落会并成 100 字上下的一段，只要句子数 ≤3 就视为排版选择而非长段；原声段按第 14 项豁免。尾部边界不再依赖「📖 合集导航」单一行（作者可能删掉它），改为在 `🔥 热门文章` / `📖` / `**参考资料` / 话题标签行任一出现处截断。
2. **按意思拆，不按字数切**：在语义边界断开（一个论点一段 / 一个转折一段 / 一组数字一段）。禁止为了凑字数把一句话拦腰截断。
3. **原声优先级最高**：作者原声句**不受改写**，但可在**原句自带的句读处加句号、分段**——只加标点与分段，**不增删任何字**。授权口径沿用 Pi Durable 篇（2026-09-20）与 Context Rot 篇（2026-10-10）；改完必须在 `outline.md` 该槽下写明「分段 / 标点说明」。

### B. 醒目句独立成段

- 全文**驱动句、反转句、金句**必须独立成段（前后各留空行），不得埋在长段里。
- 判据：这句话**脱离上下文仍然成立**（同第 16 项 A.1「金句」）→ 就该独立成段。

### C. 标题分层

- **至少 5 个 `##` 节**；任一 `##` 节正文超过约 400 字，**必须补 `###` 小标题**。禁止出现「很长一段没有任何小标题」。
- `###` 小标题同样要走**悬念链 / 信息链**（见 `viral-article-playbook.md` 第四节），禁用「概述 / 小结 / 其他」这类功能标签。

### 自检（发布前必过）

- [ ] 脚本扫描：无「超 88 字且 >3 句」的普通段落（≤80 字或 ≤3 句即过，见 A.1 脚本口径）
- [ ] 原声如需分段，只有「加句号 + 分段」，无增删字，且 `outline.md` 已注明
- [ ] 全文驱动句 / 金句独立成段
- [ ] `##` 节 ≥5 个；超 400 字的节都有 `###` 小标题
- [ ] `###` 小标题不是「概述 / 小结 / 其他」式功能标签

**参考实现**：`content/2026-10-10-context-rot-isolation/quality_check.py` 的 `[新] 段落 ≤80 字` 与 `[新] 标题层级` 两项，可直接复制到新文章目录的 `quality_check.py`。

**数据依据**（2026-10-10）：Context Rot 篇重构前单段最长 121+ 字、超 80 字段落多；重构后段落 126 个 / 超标 0、H2=6 + H3=14。同批长句也一并清零（超 60 字 AI 句 0）。

## 18. 段落衔接与章节过渡（2026-10-22 作者新规，不满足必须改写）

**作者口径（2026-10-22 原话）**：需要确保段落之间的衔接是清晰自然的。

### A. 段间衔接

- 每段结尾与下一段开头之间必须有**显式的逻辑连接**（问答链 / 因果链 / 转折链），禁止段落间硬跳。
- 判据（删标题通读法）：把所有 `##` / `###` 标题遮住通读全文——读者不靠标题也能顺着读下来。每个普通段落的最后一句，要么是下一段的铺垫，要么是下一段要回应的对象；标注不出「这段给下段留了什么」的段就是断点。
- 常见不合格形态：
  - 段落间无连接直接换话题（数字摆完 → 突然另起炉灶讲别的）
  - 过渡写成功能标签（「接下来看……」「下面介绍……」）而非悬念 / 问答 / 因果
  - 原声槽前后的 AI 过渡接不上原声语气（突然变讲师腔或新闻短打）

### B. 章节过渡

- 每个 `##` 节的**最后一段**必须留下「钩子」：一个下一节要回答的问题、一个未算完的账、一个被推翻一半的结论。
- 下一节的**第一段**必须「接住」：直接回应上一节留下的钩子（问句原样接、或先答再转进）。
- **首段接钩禁短促断言**（2026-10-22 作者补充）：新节首段直接回应上节钩子时，**禁止**用短断言句硬接——读者像被「弹」进新节，太突兀。合格形态：完整句 + 上下文（先交代这笔账是什么、范围多大，再回应钩子），长度与正文段持平，让读者「滑」进新节。
  - ❌ 上节末「Rust 输在哪？」→ 新节首「输在账本上。」（四字 punch 直接接问句）
  - ✅ 上节末「Rust 输在哪？」→ 新节首「难任务上，Rust 输的不是写得对不对，是等不等得起。」（完整句 + 重构问题，下一段顺势展开）
- 自检：把六节的小标题+每节首末段连起来读，能否构成一条完整的问答链？断在哪一节，就补哪一节的过渡。

### 执行

1. 通读 `weixin.md`，逐段在段尾标注「给下一段留了什么」；标不出的补过渡句（优先用「问题变成：……」「所以……的另一面是……」「那 X 到底什么时候成立？」这类承接句式）。
2. 章节交界处单独检查：上节末段 → 下节首段是否同一话题的延续。
3. 原声槽位置重点检查：AI 过渡句要同时接住前文论点和原声的口气（见第 15 项第 6 步抽读法）。

### 自检（发布前必过）

- [ ] 遮住标题通读，无「读到这里不知道下一段要干嘛」的断点
- [ ] 每节末段留下钩子、下节首段接住钩子
- [ ] 新节首段接住钩子时为完整句（非短促断言），带上下文铺垫
- [ ] 过渡句不是「接下来 / 下面介绍」式功能标签
- [ ] 原声槽前后过渡不跳语气

## 19. 结尾引用文献核查（2026-10-22 作者新规，不满足必须改写）

**作者口径（2026-10-22 原话）**：结尾引用文献需要符合事实准确性要求。

### 规则

文末「参考资料与数字溯源」每一条必须**可回溯**，逐条核对四项：

1. **来源真实**：人名 / 机构名 / 文章名与素材源（vault 笔记、一手链接）一致，不凭记忆写。
2. **日期准确**：用素材内标注的**原始日期**（发布日 / 访谈日 / 推文日），不是笔记归档日；同一件事有多个日期时（如发布 vs 访谈），取文中论断实际出处那个。
3. **归属正确**：文中每个关键数字 / 论断能对上是哪条参考文献出的；每条参考至少支撑文中一个具体数字或论断，不列「充数文献」。
4. **二手标注**：转述、未核对原文的来源必须标明（「转述」「第三方清点」等）；素材源自带折扣清单的（如 vault 笔记「使用这些材料时的折扣」节），按折扣执行——降权数字不引用或标注二手，禁止把二手数字写成一手。

### 执行

1. 对照素材源（笔记 / 一手页面）逐条打勾：人名 ✓ 日期 ✓ 归属 ✓。
2. 文中数字倒查：挑 3-5 个关键数字，逐个确认「这条文献出不出这个数」。
3. 任何一条对不上：改文献、改日期、或改文中表述——禁止「差不多就这样」进发布流程。

### 自检（发布前必过）

- [ ] 每条参考文献的人名 / 日期 / 出处与素材源逐条核对过
- [ ] 文中关键数字均能归属到具体文献条目
- [ ] 二手来源均已标注，折扣清单内的降权数字未当一手引用

## 20. 发布后回拉与 `--published` 模式（2026-10-24 新增）

**背景**：作者常在公众号后台直接改正文（措辞、分段、合并段落、增删句子、改标题）。本地 `weixin.md` 定期从线上回拉后与「发布版」逐字一致，此时成稿期门禁（原声逐字、段落 ≤80、长句 ≤60、篇幅）会大面积报红——**这不是质量回归，是门禁与「作者改稿」口径冲突**。2026-10-24 的三篇文章（pi-codemode / Rust / 三家收敛）就是第一批。

**规则**：`quality_check.py` 支持 `--published`，两种模式各管一段：

| 模式 | 用途 | 检查内容 |
|---|---|---|
| 默认（成稿期） | 发布前 | 原声相似度 ≥90%、段落、长句、篇幅 + 全部发布不变量 |
| `--published` | 发布后回拉 / 对账 | **只查发布不变量**：禁词、`（待发布）` 残留、话题标签、图片路径与数量、微信内链、承重数字、标题/首尾闭环 |

**发布不变量在任何模式都不豁免**；成稿期门禁在 `--published` 下打印「跳过」而不是静默通过。

**三条口径（与第 10/14/17 项配套）**：

1. **尾部边界**：`🔥 热门文章` / `📖` / `**参考资料` / 话题标签行，任一出现即视为正文结束——不再只认「📖 合集导航」（作者会删这一行）。⚠️ **2026-11-07 起新文尾部不再有 `📖 合集导航` 与「下一篇预告」**，边界以 `🔥` / `**参考资料` / 标签行为准；从旧文复制 `quality_check.py` 时**删掉「下一篇预告在位」断言与 `📖` 硬依赖**，否则新文会误报红。
2. **篇幅口径**：字数只统计**尾部之前**的正文（不含热门文章、参考资料、话题标签），否则「加一条热门链接」会误判超篇幅。
3. **原声重录**：后台大幅改写（相似度 < 90%）时，把 `SLOTS` 该槽按线上文字重录并注明日期；小幅改写（标点、增删几字）由 ≥90% 覆盖率自动容忍。

**参考实现**：`content/2026-10-21-pi-codemode-mcp/quality_check.py`、`content/2026-10-22-rust-agent-language/quality_check.py`、`content/2026-10-23-mcp-tool-exposure-convergence/quality_check.py`（三份脚本的尾部截断 / 相似度 / `--published` 逻辑一致，可直接复制到新文章目录）。
