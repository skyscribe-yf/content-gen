# 公众号运营规则

## 发布节奏

**规则**：每天最多发布 **1 篇**文章，两篇之间至少间隔 2 天。

**原因**：同日发多篇 = 自己抢自己的推荐位。推荐算法给每篇的曝光池有限，同日发表会互相分流，导致每篇都拿不到足够曝光。

**数据验证**（2026-07-08 统计）：07/03 同日发了《梯度下降》和《损失函数》两篇，结果梯度下降仅 18 读（7.69%），而同期的损失函数经推广后 133 读（56.84%）。虽然两篇内容质量相当，但同日发表互相分流 + 仅一篇获推广，导致另一篇几乎被埋没。**验证结论**：同日发多篇的警告是真实的，即使推广也只够带一篇。

**二次验证**（2026-07-09 统计）：两次推广日（07/06、07/08）间隔 2 天，中间间隔日（07/07）仍有 8 个新关注。说明 ≥2 天间隔规则既避免了同日分流，又让推广余温有接盘文章。损失函数文章从 133 读自然增长至 144 读（+11），证明间隔日不推广时文章也会持续积累阅读。

**三次验证**（2026-07-10 统计，修正）：07/09 新增关注 21 人，但渠道拆解显示：名片分享 +7、其他 +9（合计 16 人来自互助群转发），文章页关注仅 +4（残差连接文章自然吸粉）。修正结论：**纯新文章衰减日 ≈ 10% 推广日水平（+5 vs +48）**，之前说 40%+ 是把互助群效应和新文章效应混在一起了。真实规律：新文章自身只能拉回 ~10% 的衰减，互助群转发才是衰减日的高效补量手段（一次 ≈ 16 粉）。

**执行**：
1. 规划好发布日历，标记每篇的预计发布日期
2. 即使文章已写好，也不要囤积后同日发出
3. 固定节奏：每 2 天 1 篇，于 08:00 发布；具体日期以 `draft-status.yaml` 为准

**数据验证**（2026-07-11 复采，数据截至 07-10）：07/03 同日发布的《损失函数》和《梯度下降》现为 150 读与 35 读。推广和标题同时不同，不能把差距完全归因于同日发布；但同日多篇仍会分散编辑、推广和读者注意力，维持每天最多 1 篇、间隔至少 2 天的规则。

**最新排期提醒**（2026-07-11 后台同步）：07/09、07/10、07/11 连续三天均有新文章发表，其中 07/11 的 MoE 文章尚未进入日结报表。连续发布既偏离当前节奏，也会干扰标题和渠道对比；自 **07/13** 起恢复每 2 天 1 篇的固定节奏。

**数据验证**（2026-07-12 复盘）：MoE 已进入内容分析（14 阅读人数，占比 2.14%）。07/11 全站 25 读 / 0 分享 / 8 留言——连发第三天 + 周六 + 无推广脉冲，首日阅读显著弱于 Adam（109）与残差（93）。**验证结论**：间隔 ≥2 天不可再破；每篇发布当日至少做一次聊天会话或互助群轻推。MoE 分享/留言率并不差，值得二次分发后再评估，不要按首日绝对阅读判死刑。

## 文章末尾关注引导

**规则**：每篇文章末尾必须包含**关注引导**，放在系列导航之后。

**引导内容**：
1. **价值承诺**（不是「求关注」）：告诉读者关注后能得到什么
2. **系列结构**：列出系列全部篇目，标明当前是第几篇，让读者知道后续还有什么

**模板**：

```
---
📖 **当前系列名**
① 第一篇 → ② 第二篇 → ③ 第三篇（本篇）→ ...

每 2 天更新一篇，把大模型的底层原理讲到不用回头查。关注「数解AI」，下一篇第一时间推给你。

---
📖 **其他系列名**（已完结）
① [篇名](微信URL) → ② [篇名](微信URL) → ...

🔥 **DeepSeek 技术解密系列**（对应原理讲完后发布）
① 篇名（发布日期 / 微信URL）

---
*如果这篇帮到了你，点个「在看」让更多朋友看到。*[开放式问题]？评论区聊聊。
```

**要点**：
- 当前系列放在最上面，用 `📖` 图标 + roadmap（①→②→...）
- 已完结系列放在中间，只列有微信 URL 的
- DeepSeek 系列用 `🔥` 图标，标注其对应的原理篇与发布状态
- 结尾三段式：在看引导 → 开放问题 → 系列导航
- 系列用箭头 `→` 连接，不要用换行列表

**数据验证**（2026-07-08 统计）：公众号主页回读占比 **21.8%**。

**更新**（2026-07-09 统计）：主页回读占比升至 **31.0%**，上涨 9.2 个百分点。文章矩阵从 4 篇扩展到 6 篇（已发布）后，回读比例不降反升。存量旧文（2022 年敏捷开发）也被回读激活（19 读）。

**再更新**（2026-07-10 统计）：主页回读占比 **29.6%**（微降 1.4pp），但绝对阅读数从 364→476（+31%）。占比下降因为推荐流量大幅上升（+5.7pp）稀释了份额。旧文持续被激活（敏捷开发 19→24 读）。

**验证结论**：系列化策略非常有效，每新增一篇都在带动旧文回读。推荐流量上升说明内容质量被算法认可。必须补上明确的交叉链接（微信 URL），把自发回读变成引导式阅读路径。

**数据验证**（2026-07-11 复采，数据截至 07-10）：公众号主页占 26.1%，按近 30 天 628 名阅读用户估算约 164 人，较上次约 141 人增加。占比虽下降 3.5pp，绝对回读仍在增加；文末系列导航和微信 URL 交叉链接继续保留。

**数据验证**（2026-07-12 复盘）：主页回读 **26.5%**（+0.4pp），推荐仍第一（31.5%），推广（聊天+朋友圈）35.1%。近 30 天 653 阅读人中约 173 人来自主页。即将开启「大模型原理」系列时，BPE 首篇必须用微信 URL 回链旧系列与 MoE，把主页回读变成跨系列路径。

**数据验证**（2026-07-14 复盘）：主页回读 **23.3%**（-3.2pp），推荐 **35.8%**（+4.3pp，成为主驱动），近 30 天阅读总数 906（+38.7%）。绝对回读 = 906×23.3% ≈ 211 人，较 07-12 的 173 人增加。占比下降因推荐流量上升稀释，主页回读绝对量仍健康。BPE（07/13）已发布，下一篇词嵌入须用微信 URL 回链 BPE/MoE 与「训练回路」旧系列，构建跨系列路径。

## 互动引导

**规则**：每篇文章结尾（关注引导之前）必须包含 **1 个开放式问题**，引导读者留言。

**原因**：0 留言 = 算法认为内容无互动价值。1 条种子评论就能显著提升互动率。

**写法**：问题要具体、有争议性、读者能凭直觉回答：
```
✅ 你觉得 ReLU 和 Sigmoid 哪个更适合图像分类？评论区聊聊
✅ 学习率 0.1 和 0.001，你会先试哪个？
❌ 欢迎留言讨论（太泛，没人接得住）
```

**数据验证**（2026-07-08 统计）：5 篇文章共 234 阅读，**0 条留言**。

**更新**（2026-07-09 统计）：**26 条留言**（07/08 单日爆发）。从 0 → 26 的突变说明：(1) 读者基数跨过临界点（56 → 105）；(2) 具体争议性问题比泛泛提问有效得多；(3) 推广带来的新读者中可能有更多活跃互动者。**验证结论**：互动引导的方向正确，关键是问题要具体、有争议性、读者能凭直觉回答。基数达到 100+ 后留言概率自然提升。

**再更新**（2026-07-10 统计）：**24 条留言**（07/09 单日），连续两天 20+。留言率约 19%（24/126），远高于公众号平均 1-3%。验证结论：互动已形成习惯而非偶发。基数 126 人后互动已达稳态。**关键因素**：问题要有可争论性（「为什么不直接取最大值」「为什么56层比20层还差」比「欢迎留言」有效 100x）。

**数据验证**（2026-07-11 复采，数据截至 07-10）：后台显示 07/10 单日 15 条留言，低于 07/08 的 26 条但保持非零。具体、可回答的开放式问题仍应保留；不要把单日波动写成“留言稳定在 20+/日”。

**数据验证**（2026-07-12 复盘）：近 30 天留言合计 83；07/11 单日 8 条（对 25 读）。首页卡片上残差与 Softmax 留言各约 21，梯度下降为 0——**可争论的反常识问题**仍是互动主因。废除「留言稳定 20+/日」表述；发布检查只要求：文末有 1 个具体开放问题 + 发布后非零互动即可。

**数据验证**（2026-07-14 复盘）：昨日留言仅 **4 条**（vs 07/09 的 24、07/12 的 07/11 单日 8）。BPE（07/13）文末开放问题未触达预期互动，需检查问题是否紧扣核心冲突。结论：互动引导不能只看“有无开放问题”，问题必须**可争论 + 紧扣文章核心反常识点**（如「为什么不直接取最大值」「56层为什么比20层还差」）；词嵌入发布前复核文末问题的争议性。

## 摘要关键词

**规则**：文章摘要（digest）必须包含 **2-3 个搜索关键词**，不能纯文学化。

**原因**：搜一搜不只看标题，也索引摘要。摘要里没有关键词 = 丢失搜索流量。

**示例**：
```
❌ 3分钟搞懂梯度下降——从生活直觉到数学公式，一个闭环讲透AI最核心的优化算法。
✅ 梯度下降是什么？用生活直觉讲清学习率、步长和梯度方向，3分钟看懂AI最核心的优化算法。
```

**自检**：写完 digest 后 grep 一下，确认至少包含 2 个专业术语关键词。
