# 图片生成

项目图片生成默认后端：**yairouter**（gpt-image-2）。

> ⚠️ **已知问题（2026-08-07 实测）**：上游官方 API 忽略 `size` 参数——请求任意尺寸（21:9 / 4K / 1:1）实际输出均为 1254x1254 / 1536x1024 / 1024x1536 等固定或轮转尺寸。属官方 API 行为，暂不裁剪、不规避，工具按实际输出保存。详见 [`yairouter-gpt-image-2-experiment.md`](yairouter-gpt-image-2-experiment.md)。

## 封面图规则

**公众号封面图必须使用电影宽幅 21:9**（`size: "21:9"`），禁止使用 1:1 正方形或 16:9。

原因：电影宽幅（2.35:1）在微信消息列表和朋友圈分享中不会被裁切，视觉冲击力更强，且能容纳更多画面内容。16:9 仍有轻微裁切风险。

**grok 模型下的封面生成（2026-08-15 实测）**：grok 不支持 size 参数，输出固定 1024x1024（偶尔 1280x720）。封面需生成后用 PIL center-crop 到 21:9：

```python
from PIL import Image
im = Image.open("00-cover.png")
tw, th = 1280, 548  # 21:9 at 1280 wide（或 1024x438）
src_ratio, dst_ratio = im.width/im.height, tw/th
if src_ratio > dst_ratio:
    new_w = int(im.height*dst_ratio); x=(im.width-new_w)//2; im = im.crop((x,0,x+new_w,im.height))
else:
    new_h = int(im.width/dst_ratio); y=(im.height-new_h)//2; im = im.crop((0,y,im.width,y+new_h))
im = im.resize((tw,th), Image.LANCZOS)
im.save("00-cover.png")
```

⚠️ 裁剪风险：center-crop 可能切掉边缘内容（如底部小字、角落元素）。封面 prompt 须写「主标题居中/居右中部、四周留白、重要元素避开上下边缘」。

## 封面标题文字（硬性，2026-08-26 复盘新增）

**封面必须包含标题文字，且由图像模型直接渲染**（无脚本叠加；k3 系列封面均为 prompt 渲染文字）。

⚠️ **事故复盘（2026-08-04 deepseek-csa 视频号封面）**：prompt 里写了标题但被模型忽略，生成出无文字封面且被直接归档。根因两条：
1. **prompt 写法太弱**——标题只作为 LABELS 里一句普通描述（「只排版这一行完整标题」），没有位置/字符/标点的硬性约束；gpt-image-2 对中文渲染是尽力而为，弱指令会被丢弃
2. **无验收门禁**——生成后没读图确认文字存在就归档

**必须使用的强指令模板**（k3 验证有效，逐字照抄）：

```
必须在<位置>以清晰、准确、无错别字的简体中文排版<N>行标题：
第一行「<标题第一行>」
第二行「<标题第二行>」，第二行末尾必须使用中文全角问号「？」，绝不能使用半角问号「?」
只出现以上中文文字、数字和字母；不要出现英文说明、公式、额外标签或乱码。
标题的文字、数字和标点必须与本文完全一致。
```

**验收门禁（生成后必做）**：读图确认 ① 标题文字存在且无错别字 ② 标点全角（半角 `?` 宽度约为全角 `？` 的一半，可用像素宽度比对验证）。任一不满足 → 强化 prompt 重生成；gpt-image-2 连续两次失败可换 `--model grok-imagine-image-quality`（grok 中文渲染更可靠，已 5 张验证）。

## 封面感官冲击力（2026-08-31 新增，推荐测试池导向）

**背景**：推荐系统决定给不给首日测试量的信号，是信息流里用户 3 秒内的点击决策——封面是那一帧里除了标题外唯一的主角。赢家封面（opencode 杀疯了 5,435 读/推荐 98.5%、高维 1,613/85.2%）共性是「一眼有冲击」；纯信息图/无主体/平铺文字封面在信息流里是隐形帧。

**硬性要求（prompt 写进生成指令）**：

1. **单一主视觉主体**：封面有且只有一个视觉焦点（物体/场景/冲突），禁止平铺多个小图标、信息图碎片——信息流缩图后多个元素糊成一片，无焦点的封面 = 无点击。
2. **强对比配色**：背景与主视觉/标题文字高对比（深底亮字或亮底深字）；禁止同色系灰蒙（同色相深浅搭配在信息流缩图中失去轮廓）。标题文字颜色与背景对比度要求 ≥ 4.5:1（近似 WCAG AA），大字大色块优先。
3. **视觉动势**：主视觉有方向感/冲突感（攻向、上扬、倾斜、对撞），禁止静止对称平铺（对撞/动势是最强抓眼结构）。
4. **字大且少**：封面标题 ≤ 12 字（超出部分由正文承担），字号占封面宽度 ≥ 30%；信息流缩到 1/4 大小后仍必须可读。
5. **情绪可感**：贴合标题情绪（震惊/反转/急切），热点文可直接用情绪场景（价格战/屠刀/魔幻）；技术文至少让画面「有事件感」而不是教科书示意图。

**禁止（2026-08-31 起列入封面验收）**：
- 信息流缩图后主体小于 1/5 画面、无焦点的多元素平铺
- 低对比同色系（灰底灰字、蓝底蓝字）
- 静态对称平铺且无动势
- 封面标题 > 12 字或字号过小（缩图后不可读）
- 一行文本全宽排满、无视觉留白（信息流里读不下去）

**验收门禁（生成后必做，与标题文字门禁同批）**：读图确认 ① 单一主视觉 ② 高对比 ③ 缩图（缩成信息流卡片大小）后标题仍清晰可读。任一不满足 → 重构 prompt 重生成；封面不合格同样禁止发布。

## 封面标题显眼度规格（2026-09-05 定稿，R1 两篇验证）

**版式：无左右分栏。标题作为前景元素横贯整个横幅，完全占满宽度，是画面唯一主角**；背景图形（轨迹网络/主干道等）压暗、低对比、退居标题之后。

硬性规格（prompt 逐条写入）：

1. **金色发光字体**：高饱和金色（金黄到琥珀金，如 #FFD700/#FFB800 金属质感）+ 柔和 glow，深色背景下霓虹感，对比 ≥ 4.5:1；无花纹无复杂描边
2. **字号**：每行字高约画面高度 1/8，两行合计约画面 1/3（2026-09-05 实测：1/4 过大、1/8 平衡；1/5 中间值亦可）；ultra-bold 黑体，缩略图尺寸可读
3. **横向占满**：每行从画面左边缘延伸到右边缘（左右不留边距），两行各自用满全宽，居中排列
4. **一行一律不拆词组**：长标题（>12 字）分两行整句换行（如「……，DeepSeek 正确率」/「凭什么从 15.6% 涨到 71%？」），不得拆散词组；与「封面感官冲击力」第 4 条的关系：≤12 字为短标题优选建议，超长标题按本规格两行全量渲染、禁止截断
5. **数字标点一字不差**：与文章标题完全一致（含 %、小数点、全角问号），AI 常把全角「，」画成半角「,」——验收时检查，严重时重生成
6. **除标题外无任何文字数字**（含背景里的路牌、草稿、小字）

模板已固化于各文章 `prompts/00-cover.md`（含 ZONES 分区说明）。

## 语言规则

**所有图片中的文字必须使用中文**，包括标题、标签、坐标轴、图例、注释等。Prompt 中需明确写明中文文字内容，避免生成英文图片后返工。

## ⭐ yairouter API — 默认后端（gpt-image-2，自动 fallback grok）

客户端脚本：`scripts/yairouter_img.py`

**模型选择（2026-08-15 起）**：默认 `gpt-image-2`；若它不可用（API 返回 404 无权限 / 400 `Argument not supported: size` 等），脚本**自动改用 `grok-imagine-image-quality`**，无需人工干预。也可用 `--model grok-imagine-image-quality` 或 cards.json 的 `model` 字段显式指定。

**grok 模型的差异（实测 2026-08-15）**：
- 不支持 `size` 参数（请求必 400）——输出固定 **1024x1024 JPEG**
- 必须带 `response_format="b64_json"`（Zero Data Retention team 无 URL 格式）
- 中文渲染可靠（标题/标签逐字正确，已用 5 张公众号配图验证）
- 封面 21:9 需生成后裁剪：见下方「封面图规则」的 grok 补充
- 脚本保存时自动把 JPEG 字节转成真 PNG（避免微信上传格式不匹配）

**默认参数（成本控制）**：
- **size: `1:1`**（1024×1024，正方形）
- **quality: `high`**

**默认分辨率规则**：所有图片默认 1K，包括封面图。`1:1` = 1024×1024，`21:9` = 1248×528。需要 2K/4K 时**必须先告知费用差异并要求用户确认**，不得擅自升级。

**ENV**：需要 `YAI_API_KEY` 环境变量（shell 环境变量优先，`.env` 兜底）。**若 shell / `.env` 都找不到 key，先 `source ~/.bash_env` 再重试**——`~/.bash_env` 是作者维护的全局密钥文件（含 `YAI_API_KEY` 等），不要直接报「缺 key」或擅自换后端。

### Size 快捷映射

| 快捷名 | 实际尺寸 | 推荐场景 |
|--------|----------|----------|
| `1:1` | 1024×1024 | 正方形配图（默认） |
| `3:4` | 1024×1536 | 小红书卡片 |
| `16:9` | 1792x1024 | 横版配图 |
| `2.35:1` | 1792x768 | 电影宽幅（封面图） |

> ⚠️ 上述 size 目前不生效（见文件头已知问题），仅为工具接口保留。

**场景速查**：

| 用途 | size | 像素 |
|------|------|------|
| 公众号封面（默认 1K） | `21:9` | 1248×528 |
| 小红书卡片 | `3:4` | 1024×1536 |
| 正方形配图 | `1:1` | 1024×1024 |
| 竖版海报 | `9:16` | 1024×1792 |

**费用递增**：像素量决定成本。1K 最便宜，4K 最高。

### 批量生成

通过 JSON 配置文件 + `--config` 参数，每张卡片可覆盖全局 size：

```json
{
  "output_dir": "content/my-article/images",
  "size": "1024x1536",
  "quality": "high",
  "cards": [
    {
      "title": "封面",
      "prompt": "A cinematic illustration of...",
      "size": "1248x528",
      "filename": "cover.png"
    },
    {
      "title": "卡片2",
      "prompt": "An infographic showing...",
      "size": "1024x1536",
      "filename": "card-01.png"
    }
  ]
}
```
