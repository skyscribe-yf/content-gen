# DeepSeek MLA 显存文章润色设计

## 目标

将 `content/2026-07-23-MLA/weixin.md` 打磨成面向纯科普读者的技术文章。读者应理解：长上下文部署不能只看模型参数量和权重显存；KV cache 会随上下文增长，MLA、GQA 等注意力架构也会影响显存预算。

## 读者与边界

- 读者是对 AI 感兴趣的普通读者，不假定其具备本地部署经验。
- RTX 4090 作为常见消费级高性能显卡的 24GB 显存参照，不作为读者必须拥有的设备。
- 不新增训练教程、部署教程或长代码示例。
- 保留 MLA 的三步直觉和一条矩阵等价式；删除伪代码。
- 在文末增加可跳过的高维概率论附录，解释 JL 引理与随机投影。

## 叙事与结构

1. 标题改为“显存被谁吃掉了？DeepSeek如何省下90%”。开头从 24GB 显存的直观限制切入，指出权重以外的 KV cache 会随对话增长。
2. 解释 KV cache：每个 token 的 K、V 都要保留，因而上下文翻倍，缓存也翻倍。链接前文作为补充，而非理解前提。
3. 简述 GQA 是减少“记录副本”，随后引出 MLA 的“记录摘要”。
4. 用“低秩摘要 → 矩阵吸收 → 解耦 RoPE”解释 MLA。正文仅保留 `Q · (W^UK · c^KV)ᵀ = (Q · W^UK) · (c^KV)ᵀ`，说明存摘要也能算出等价的注意力分数。
5. 数据比较分开两层：传统 MHA 与 MLA 的架构量级对照用来说明“约九成级”的节省；LLaMA/Qwen/DeepSeek 的跨模型表格明确标示模型配置不同，仅作每 token KV cache 量级参照。不得把该表写成同模型前后对照。
6. 结尾回扣资源判断：选长上下文模型或评估资源时，显式查看每 token KV cache/注意力结构，不只看参数量。
7. 附录以约 300–450 字介绍 JL 引理、随机投影如何近似保留向量关系，以及 MLA 的投影由训练学习；明确这是一种直觉解释，不是 MLA 完全无损的数学证明。

## 数据与措辞规则

- 全部模型版本、配置、论文表格值和显存换算在写作前以原始论文、官方模型配置或官方技术报告核验。
- “90%”只修饰相对传统 MHA 的 KV cache 架构级节省，不能修饰总推理显存、所有模型或固定部署成本。
- 跨模型数字在表格标题或脚注披露不同模型规模、层数、KV 头数和精度会影响结果。
- 不把低维表示说成严格无损；使用“在任务目标下保留足够的注意力关系”等限定表达。

## 验收标准

- 标题、摘要和正文对“90%”的对象及比较基线一致。
- 纯科普读者能在不阅读附录的情况下理解 KV cache 与 MLA 的作用。
- 删除伪代码，保留的唯一关键等式使用 Unicode 表示。
- 附录不打断正文，并明确其解释边界。
- 所有模型数据和技术主张附有可追溯的原始来源或明确的来源说明。
