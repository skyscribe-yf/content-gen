# 预训练文章：一小时 RTX 4090 受控实验

## 目标

用一小时以内的单卡 RTX 4090 实验，替换现有“重复 590 字文本”的 toy demo。新证据必须区分训练集背诵、独立验证集上的预测泛化，以及自由生成的质量；它不试图复现前沿大模型的涌现、推理或意识。

## 已确认约束

- 执行环境为 AutoDL 单卡 RTX 4090（24GB 显存），可访问 Hugging Face，数据盘空间充足。
- 单次运行的总时长控制在 60 分钟：含环境核验、数据准备、吞吐校准、训练、验证和结果导出。
- 正文仍以中文呈现；训练数据选择公开的中文短故事，以便读者直接阅读固定样例。
- 实验只在作者明确批准实施计划后运行；本规格不授权下载数据、配置远程实例、编写训练代码或修改正文。

## 数据

使用 `adam89/TinyStoriesChinese` 的固定 revision `98547ad8ca1205e2e5ce564343cb78f972f72ffa`，许可证为 CDLA-Sharing-1.0。它是 TinyStories 的中文翻译版，适合观察小模型从零学习受限叙事分布，但不是互联网的代表性语料，也不能用于世界知识、推理或意识结论。

数据处理规则：

1. 以“故事”为切分单位，用确定性哈希将故事分为 train（98%）和 validation（2%）；任何一篇故事不得跨集合。
2. 不重复文本；不将未知字符映射为高频字符。分词器须有明确的 unknown／byte fallback 行为。
3. 下载后的原始压缩包、抽样文本、tokenized 数据、检查点和日志均放在 `/root/autodl-tmp/pretraining-demo/`。
4. 记录数据集 revision、故事数、训练 token 数、验证 token 数、分词器训练样本与最终词表大小。

## 两个实验条件

### 条件 A：背诵对照

保留现有 590 字材料重复 40 次的设置，但将它明确标为背诵对照。它只运行约 1 分钟，用于显示训练 loss 可趋近于零而不构成泛化证据。验证集必须换成未重复的独立文本；不能复用原先的尾段切分。

### 条件 B：多故事预训练

从零训练一个约 3,000 万参数的 causal Transformer：8 层、512 隐层、8 个注意力头、8K BPE 词表、256 token 上下文。使用 bfloat16、AdamW、cosine 学习率调度和 PyTorch SDPA；训练循环按墙钟时间停止，主训练预算 30–35 分钟。

配置不是固定承诺：先用 3 分钟吞吐和显存探测确定可用 micro-batch 与梯度累积，目标是稳定而非榨干显存。若验证 loss 发散或显存不足，先缩小 batch 或学习率，不能为完成一小时预算牺牲结果可信度。

## 记录与评估

两个条件都必须导出：

- train NLL/PPL 与 validation NLL/PPL 的完整时间序列；不以单一 batch loss 代表训练状态。
- 随机种子、软件版本、GPU 名称、CUDA 运行时、峰值显存、tokens/s、总步数与总训练 token。
- 三个固定验证故事前缀的贪心解码，以及固定种子、temperature=0.7 的采样解码。
- 对所有生成文本的最长连续 n-gram 训练集匹配审计，避免把大段复述写成泛化。
- 最终检查点及可复跑的配置文件。

文章只可据此做以下结论：独立验证损失与未见故事续写共同提供比训练 loss 更强的泛化证据；更低的 loss、连贯生成或低复制率都不是理解、推理或意识的证据。

## AutoDL 环境设计

1. 选择官方 PyTorch 镜像，优先 Python 3.10/3.11、PyTorch 2.4+、CUDA 12.x 的稳定组合；不要选纯 Miniconda、WebUI、LLaMA 工厂或需要自行编译 CUDA 的社区镜像。
2. 先用镜像自带 PyTorch 运行 `torch.cuda.is_available()` 与 bfloat16/SDPA 烟雾测试。`nvidia-smi` 显示的是驱动支持上限，不能用它替代 `torch.version.cuda` 的兼容判断。
3. 不单独安装 CUDA/cuDNN，不安装 `flash-attn`。后者会增加编译时间和版本风险，PyTorch SDPA 足够本实验使用。
4. 仅额外安装数据、分词、记录与测试依赖：`huggingface_hub`、`tokenizers`、`sentencepiece`、`tqdm`、`matplotlib`、`tensorboard`、`pyyaml`、`pytest`。精确版本在验证通过后写入锁定文件。
5. 使用 `tmux` 或 `screen` 启动训练，避免 SSH 断开中止；将环境核验与每阶段输出保存到日志。
6. 环境验证成功后，保存 AutoDL 自定义镜像以备重跑；数据仍留在数据盘并另行备份关键产物。

## 一小时时间盒

| 时间 | 动作 | 退出条件 |
|---|---|---|
| 0–5 分钟 | GPU、PyTorch、bfloat16、SDPA、磁盘与网络核验 | 任何一项失败即停止并诊断 |
| 5–15 分钟 | 下载／抽样、按故事切分、训练分词器、写入元数据 | 数据泄漏审计通过 |
| 15–18 分钟 | 3 分钟吞吐与显存探测 | 固定安全 batch 与学习率 |
| 18–53 分钟 | 条件 B 训练；条件 A 用约 1 分钟完成 | 持续记录 train/validation 曲线 |
| 53–60 分钟 | 固定生成、n-gram 审计、导出图表和检查点 | 产物可复跑、结论边界已写明 |

## 文章改动边界

- 以一张“背诵组 vs 泛化组”的 train/validation 曲线取代现有 05 图的阶段性 PPL 叙事。
- 输出例子必须标明是验证集前缀、贪心还是采样；不把单次顺眼的输出当指标。
- 与《西部世界》反思段相呼应：预测结构可以更丰富，仍不能推出理解或意识。
- 不使用固定 PPL→语法／事实／推理的能力阶梯，也不声称观察到规模涌现。

## 验收

- 两个条件均无 train/validation 文本重叠；split、seed、数据 revision 和环境版本可核验。
- 主实验在单卡 4090 上总耗时不超过 60 分钟，并完整保留中断前的可用证据。
- 任何图表或正文结论均能回链到导出的 JSON/CSV、生成日志与训练配置。
- 实验失败、未收敛或结果平淡时如实报告；不挑选单次生成来掩盖验证指标。
