# 发布前最终检查

调用 `baoyu-post-to-wechat` 发布前的**最后一道门禁**，在 `docs/article-quality-check.md`（内容质量）和 `AGENTS.md` 发布前检查（流程）之后执行。逐项确认，全部通过才能点发布。

## 1. 标题与关键词 SEO

- 标题符合 `docs/article-title-seo.md` 最新标准：关键词前置 + 痛点驱动 + ≤22 字 + 含 1 个专业关键词 + **过 9 条自检清单（含感官冲击力第 9 条）**
- 摘要含 2-3 个搜索关键词
- 正文核心关键词在标题、摘要、首段中自然出现（不堆砌）
- **感官冲击力（2026-08-31 新增）**：① 标题一眼可读、有画面、有反差/情绪词（详见 article-title-seo.md 第 9 条）；② 封面缩成信息流卡片大小后仍单一主视觉、高对比、标题 ≤12 字且清晰可读（详见 image-generation.md「封面感官冲击力」节）——两项任一不满足，测试池期首日推荐可能为 0

## 2. 正文开头无重复封面图 / 无重复标题

- 封面图 `00-cover.png` 由发布工具单独上传为封面，**正文开头不得再插入同一张图**
- 检查 `weixin.md` 第一张配图：如出现与封面相同的图片，删除正文中的引用
- **正文开头不得重复文章标题**：文章标题由发布工具单独作为标题，正文第一行不得再出现与 frontmatter `title` 相同的 H1 标题（`# 标题`），否则发布后正文开头会多出一个重复标题

## 3. 硬件数字事实核查

文中所有 **GPU 型号、显存容量、模型规模、上下文长度** 的组合必须能实际跑通。自检规则：

- 模型参数 × 量化位宽 + KV cache 估算值 **≤** 显卡总显存
- 消费级场景一律用消费级硬件（4090 / 5090 / Mac 统一内存），服务器级场景用 A100 / H100 / H200
- 同一个段落内，硬件上下文必须一致：不能前半句在讲 4090，后半句的数据却是 70B 模型才能产生的
- 数字给到具体的 GB 或 MB，不写"很大""很多""几百兆"等模糊量

**本次 MLA 篇的教训**：70B 模型即使 4-bit（~35GB）也装不进 24GB 的 4090；KV cache 31GB 应和 A100 80GB 比，不是和 4090 比。

## 4. 无「待发布」残留

- 全文搜索 `（待发布）`、`待发布` 字样，必须为零
- 系列中已发布的文章，全部替换为真实微信链接（`https://mp.weixin.qq.com/s/...`），链接来自各篇 frontmatter 的 `wechatUrl` 字段
- 确实未发布的后续篇目：不列链接，按第 5 条的尾部格式处理

## 5. 文末话题标签

- 末尾含 3-5 个 `#标签`，格式与选取规则见 `docs/wechat-topic-tags.md`
- 放在全文最末尾，独占一行

## 6. 尾部系列导航（统一风格）

- 尾部**只用合集链接**收纳逐篇链接，不用单篇链接堆叠（见 AGENTS.md 微信文章链接规则）
- 系列介绍放在尾部，箭头链列出全系列篇目（含未发布篇目），当前篇加粗标注
- 导航篇目必须与 `content/` 实际系列目录**一致，不漏篇**；下一篇预告必须与导航顺序一致

```markdown
📖 **[大模型原理合集](https://mp.weixin.qq.com/mp/appmsgalbum?__biz=XXX&action=getalbum&album_id=YYY)**：BPE → 词嵌入 → 位置编码 → 注意力 → **KDA 长上下文** → MLA → FFN → …
```

## 6b. 尾部「热门文章」（如有）

- 用 `scripts/hot_articles.py --md --cited <本文weixin.md>` 生成：读 `docs/wechat-data-audit-log.json` 聚合历史最高阅读量 Top 6，自动过滤贴图（publish-data `item_show_type!=0` ∪ tietu-corpus-summary ∪ tietu-extra），再追加本文引用的相关公众号文章；禁止手写、禁止挑最近发布的文章
- 链接行之间**不留空行**（空行 = 独立 `<p margin:1.5em>` = 视觉空行）；榜单变更后跑 `--self-check`

## 7. 下一篇预告

- 结尾必须有系列下一篇的预告，一句话勾住读者（预告内容 = 下一篇的核心痛点/问题）

```markdown
下一篇我们聊残差连接：为什么网络越深反而越训不动？
```

## 8. 互动引导

- 尾部必须引导读者**点赞、关注、收藏**，结合价值承诺，不要只写干巴巴的"欢迎关注"

```markdown
觉得有用就点个赞 👍、收藏 ⭐ 备用；关注「数解AI」，下一篇第一时间推给你。
```

## 9. 叙事闭环：开头 ↔ 结尾预告

- 开头驱动问题、正文论证、结尾预告必须形成**完整的逻辑链条**，不能各自独立
- 自检：读者看完结尾预告后，回头想起开头的驱动问题——两者是否在同一叙事弧线上？

### 闭环标准

| 环节 | 要求 |
|------|------|
| 开头 | 提一个具体的痛点/问题，让读者知道"这篇文章要解决什么" |
| 正文 | 逐层拆解、给出答案，结束时形成阶段性结论 |
| 结尾预告 | 从**当前文章结论的边界**自然引出下一篇——当前篇没答完的、回答引发的新问题、同链条上的下一步 |

### 常见断裂（必须修正）

```markdown
❌ 开头：1M 上下文到底难在哪？
   正文：KDA 用线性注意力解决
   结尾预告：下一篇我们聊 MoE 如何挑专家
   → 断裂：MoE 和"长上下文"是两个独立话题，读者会困惑"为什么突然跳到这？"

✅ 开头：1M 上下文到底难在哪？
   正文：KDA 用线性注意力省掉"每次回看全部历史"
   结尾预告：KDA 省了"回看"这头的计算——但如果历史本身的 KV Cache 太大呢？
             下一篇 MLA：怎么把 KV Cache 这份记忆先压缩 90%？
   → 闭环：KDA 解决"怎么回看"，MLA 解决"回看的东西太大"——同一条线、差一步
```

### 系列内预告串联检查

全文通读一遍，确认预告句中的"下一篇"确实解决的是**当前篇留下的缺口**，而不是列表上的下一项。
