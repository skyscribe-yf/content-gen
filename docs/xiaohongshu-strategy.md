# 小红书内容策略

## 核心原则：入口必须是痛点，不是概念

小红书用户搜的是**问题**，不是**概念**。同一个知识点，换一个入口。

| 教科书式（❌） | 痛点式（✅） |
|---------------|------------|
| 梯度下降：蒙着眼下山 | 训练 3 天 loss 不降？一个参数救回来 |
| 损失函数详解 | loss 爆炸/NaN 一张图排查 |
| Softmax 原理 | 分类模型总猜错？最后一步你可能搞错了 |
| 反向传播推导 | 为什么 GPU 比 CPU 快 100 倍训练模型 |

## 目标受众

不是学生（学生去 B 站），是**刚入行的从业者**：

- 会跑代码，但不懂原理
- 遇到问题只会搜
- 搜索词是报错信息、调参困惑、性能疑问

## 封面图规则

小红书用户 0.3 秒决定划走。信息密度太高的封面 = 看不懂 = 划走。

| 禁止 | 必须 |
|------|------|
| 第一张就是知识点 | 封面图只放**一句话钩子** + 大字 + 强视觉 |
| 排满文字 | 大面积留白，核心文字 ≤8 个字 |
| 学术感设计 | 情绪感设计（对比色、箭头、问号） |

## 选题改写公式

```
原选题 → 痛点改写

[概念] 是什么 → [症状] 怎么办
[算法] 原理 → [报错/异常] 一张图排查
[技术] 详解 → 为什么 [现象]？[一个参数] 救回来
```

## 标签策略

用**长尾标签**，不打大词（竞争太大被淹没）：

```
❌ #深度学习 #AI科普
✅ #loss爆炸怎么办 #学习率调参 #PyTorch训练技巧
```

## 评论区种子

0 评论 = 算法判死。发完立刻留一条**有争议的评论**：

```
❌ "学到了"（没人会回复）
✅ "学习率 0.01 就够了，设太大肯定崩"（有人会反驳）
```

| 时间段 | 效果 |
|--------|------|
| 7:00-9:00 | 通勤，好 |
| 12:00-13:00 | 午休，好 |
| 20:00-22:00 | 晚间高峰，最好 |

## 冷启动流程

小红书推荐：**初始小池 → 互动率达标 → 放大推荐池 → 再测 → 再放大**

卡在第一步 = 封面和选题没通过 0.3 秒测试。先改封面和选题，再考虑其他优化。

## 与公众号的分工

| 平台 | 入口 | 深度 | 作用 |
|------|------|------|------|
| 小红书 | 痛点关键词 | 浅（一图一解） | 引流入口 |
| 公众号 | 系统化长文 | 深（原理+实践） | 沉淀留存 |

小红书负责"看得到"，公众号负责"留得住"。

## 卡片序列模板

卡片数量控制在 **6 张以内**，精简掉代码实操和独立关注引导页。

| 序号 | 类型 | 说明 |
|------|------|------|
| 1 | 封面钩子 | ≤8 字痛点 + 大面积留白 + 强视觉 |
| 2 | 核心问题 | 反直觉/痛点揭示，引发"为什么" |
| 3 | 直觉解释 | 比喻/生活化，让小白秒懂 |
| 4 | 关键洞察 | 全篇最值得收藏的一个点 |
| 5 | 实验数据 | 具体数字佐证，增强可信度 |
| 6 | 总结+关注 | 5 条要点 + 系列导航 + CTA |

旧文章用了 9 张（含代码实操、公式翻译、独立关注页），信息密度太高，用户滑不完。6 张是上限。

## 卡片生成流程

1. **确认 weixin.md** — 必须以 weixin.md 为准（AGENTS.md 规则）
2. **清理旧文件** — 删除旧的 .jpg/.png 占位图和过时的 cards.json，避免新旧混放
3. **设计卡片** — 按上方序列模板，每张卡片只讲一个点
4. **封面必须 ≤8 字** — 在 cards.json 的 prompt 中强制写明字数限制
5. **生成图片** — 用 apimart 客户端，size=3:4, resolution=1k
6. **重命名文件** — 按序列编号（01-cover.png, 02-xxx.png ...）
7. **写 copy.txt** — 痛点开头 + 长尾标签 + 互动钩子
8. **策略自检** — 对照本文档检查清单逐条过

## 回修规则

已有文章的小红书内容如果不符合当前策略（如标签是大词、封面不是痛点钩子、用 copy.md 而非 copy.txt），需要回修。

优先回修：封面图 > 标签 > 文案开头 > 卡片数量
