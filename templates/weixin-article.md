# 公众号文章模板

> 核心原则：一个问题驱动，三层递进，闭环回扣。
> 数学回答"为什么"→ 算法回答"怎么做"→ 实测回答"真的吗"→ 结果回扣原理。

## 写作流程：你指挥，AI 逐段填充

**内容按你的要求逐步生成，不是一口气全文输出。** 每写完一段你审核、调整，再推进下一段。你决定方向和深度，AI 负责执行。

### 流程

1. 你告诉 AI："写驱动问题" → AI 填充这段 → 你审核/修改
2. 你告诉 AI："写直觉解释" → AI 填充这段 → 你审核/修改
3. 逐段推进直到完成
4. 你最终确认 → AI 处理格式、发布

### 你可以给的指令

- "写这段，重点放在 [具体要求]"
- "这段太学术了，改口语一点"
- "类比换成 [你想要的类比]"
- "公式不需要推导，直接给结论"
- "实测用 [具体实验设计]"
- "这段删掉" / "这段加个转折"
- "重写这段，语气参考我之前的敏捷那篇"

### AI 的角色

- 按你的指令填充内容
- 保持风格约定和逻辑链结构
- 数据必须真实可复现，不编造
- 每段只填充当前指令要求的段落，不越界
- **配图自动处理**：直觉解释、数学原理、算法实现等需要可视化的段落，AI 自动生成高质量配图并插入，封面图同步生成。配图风格与文章主题一致（可用 baoyu-article-illustrator 或 yairouter API 生成）。

## 风格约定

**语气**：像跟聪明的朋友聊天。可以猜测、可以怀疑、可以吐槽，但推理链必须清晰。不用"笔者""本文""综上"，端着写不如不写。

**句式**：长句串推理，逗号连因果链，短句给结论。反问是好工具——"真的是这样吗？""凭什么？"分号并列多视角。破折号给结论——"——纯粹是因为……"

**强调**：引号框概念（"稀疏激活"），不用加粗。偶尔加粗，但只加在真正需要读者停下来的那句话上，一篇不超过 3 处。

**不用**：emoji 做标题、大段表格做对比、列表堆砌要点、感叹号。这些是 PPT 的活，不是文章的活。

**小标题**：小标题本身就是观点或判断，不是中性分类。写"话语权是怎么丢的"，不写"背景分析"。

**过渡**：段落之间逻辑自然衔接，不用"接下来我们看""下面进入"这种硬切。上一段的结论就是下一段的起点，或者先承认反面再转折——"当然辩证地来看……""事实却并没有这么完美"。

**公式**：先说人话，再给公式。公式出现时必须紧跟一句翻译。读者应该能跳过公式仍然读懂文章。

**代码**：注释用中文，只写核心逻辑。代码是公式的翻译，不是独立的存在——先有公式，代码才有意义。

**比喻**：自然不刻意。"上了贼船"可以，"就像一朵花在风雨中绽放"不行。

**论证**：递进式挖深——现象→原因→更深原因→反思。先承认反面再转折，比一上来就下结论更有说服力。

## 逻辑链模型（每篇必须遵循）

```
驱动问题
  │
  ├→ 数学层：为什么会这样？（直觉+公式）
  ├→ 算法层：怎么实现这个"为什么"？（核心代码）
  ├→ 实测层：跑一下看看，真的如数学预测的那样吗？
  └→ 回扣层：实测结果验证/推翻了前面的原理
```

**关键约束**：实测必须测试算法层面的行为，算法必须体现数学层面的原理，回扣必须把实测结果翻译回数学语言。三层是同一根绳子的三段，不是三根绳子绑在一起。

## 标题模板（3选1）

- 「直觉版」：3分钟搞懂[概念]——[生活类比]
- 「悬念版」：[概念]为什么能[令人惊讶的效果]？
- 「融合版」：[模型]做[任务]翻车了？[概念]的数学原理告诉你为什么

## 文章结构

### 驱动问题（100字）

用一个反直觉问题或热点事件开头，这个问题将贯穿全文，最终在回扣层得到回答。

> 示例：为什么DeepSeek R1比GPT-4o便宜10倍，能力却差不多？答案藏在一个数学事实里——大部分参数在大部分时候是沉睡的。

**约束**：这个问题必须同时涉及数学原理和模型表现，不能只涉及一方。

---

### 直觉解释（400字）

**这一段不许出现公式。** 只用生活类比和图。

写法：先描述一个日常场景，让读者"哦，原来是这样"，然后点出关键 insight。不要急着说"这对应数学里的XX"，留到下一段。用叙述而非列表。

> 示例：MoE就像一个公司不需要每次开会都请所有顾问——只有相关问题才请相关专家。这就是"稀疏激活"。

---

### 数学原理（400字）

现在可以写公式了，但每条公式必须紧跟一句话解释。

写法：先给变量起名字和含义，然后给核心公式，然后翻译成人话。推导最多 2 步，每步都要说"这一步在干什么"。最后标出算法实现的关键点——公式里哪一项决定了代码怎么写。

> 排版注意：
> - 公式用 LaTeX，独立公式居中
> - 每个公式独立一行
> - 公式后面必须跟一句"翻译成人话"

**关键**：数学层必须自然引出算法层——"这个公式告诉我们需要计算X，那算法上怎么高效地算X？"

---

### 算法实现（400字）

用 Python 给一个最小实现。

要求：
- 代码不超过 40 行
- 只包含核心逻辑，不写花架子
- 代码注释用中文
- **代码结构必须对应数学公式的结构**——公式里的每一步，代码里有对应的一行

```python
# 示例：MoE路由算法（对应数学公式）
# 公式：g(x) = softmax(top_k(x · W_g))  ← 路由权重
#        y = Σ g_i(x) · f_i(x)            ← 加权输出

def moe_route(x, W_g, experts, k=2):
    # 步骤1：计算门控分数（对应 x · W_g）
    scores = x @ W_g
    # 步骤2：取top-k + softmax（对应 softmax(top_k(...))）
    topk_idx = scores.topk(k).indices
    gates = softmax(scores[topk_idx])
    # 步骤3：加权求和（对应 Σ g_i · f_i）
    return sum(g * experts[i](x) for g, i in zip(gates, topk_idx))
```

**关键**：算法层必须自然引出实测层——"这个算法有X个关键决策点，跑一下看看会怎样？"

---

### 实测（300字，融合篇/评测篇重点，原理篇可简述）

用真实代码跑出真实数据，让结果说话。不要编造模型对比数据。

写法：设计一个简单实验，只改一个变量，看结果怎么变。用叙述呈现——"lr=0.001 时，500 步了 loss 还在 0.072；lr=0.01 时，大约 200 步就收敛了；lr=0.1 呢？参数直接飞到天文数字。"不要用表格，用递进式叙述。

**约束**：实测必须测试算法层面的行为，差异必须能用数学原理解释。数据必须真实可复现。

---

### 回扣原理（150字）

**这是闭环的关键段落。** 把实测结果翻译回数学语言。

写法：先说实测印证了什么，再说哪个差异对应数学里的哪个性质，最后回答开头的驱动问题。

> 示例：DeepSeek虽然用了O(n²)的实现，但结果仍然正确——因为MoE的数学保证只要求top-k选对，不要求计算全量分数。这就是为什么它能便宜10倍：省掉90%的计算，数学上等价。

**如果实测结果与原理矛盾**，更要写这段——"理论上应该X，但实测发现Y，原因是……"，这比印证原理更有价值。

---

### 一句话总结（50字）

用一句话闭环：驱动问题 + 直觉 + 数学 + 实测结论。

> 格式：「[概念]的本质是[直觉]，数学上是[公式核心]，实测告诉我们[关键发现]。」

## 三种文章类型的侧重

| 部分 | 原理篇 | 融合篇 | 评测篇 |
|------|--------|--------|--------|
| 驱动问题 | ✅ | ✅ | ✅ |
| 直觉解释 | ✅ 详细 | ✅ | ✅ 简述 |
| 数学原理 | ✅ 详细 | ✅ | 简述/跳过 |
| 算法实现 | ✅ | ✅ 详细 | ✅ |
| 实测 | 简述/跳过 | ✅ 详细 | ✅ 详细 |
| 回扣原理 | ✅ | ✅ 详细 | ✅ 详细 |

**即使跳过某层，逻辑链不能断**——原理篇如果跳过实测，回扣段改为"如果让模型实现这个算法，最容易出错的地方是X，留待实测验证"。

- [ ] 开头的问题在结尾是否有回答

- [ ] 有没有引导关注/转发
