#### D2 详细结构：MLA — 注意力为什么能省 90% 显存？

```
📐 数学层（~600字）
  - 直觉类比：KV cache 是推理的"记忆笔记"，token 越多笔记越厚
  - 显存黑洞：KV = 2 × L × T × n_h × d_h bytes，真实数字——LLaMA-3-70B 在 100K context 下 160GB
  - MLA 的数学魔术——三步：
    ① 低秩投影：K = W^{UK} · (h · W^{DK})，把 d_h 压缩到 d_c（~128）
    ② 矩阵吸收：W^{UK} 预乘进 Q^T 和 V，推理时只需存压缩后的 latent c_t^{KV}
    ③ Decoupled RoPE：Q/K 各拆两路——一路走低秩压缩，一路单独加 RoPE（解耦！）
  - 压缩比：MLA 显存 ≈ 2 × L × T × d_c，d_c << n_h · d_h（V3 中 512 vs 128×128 = 16384 → 32×）
  - 几何解释：为什么压缩 32× 不损失质量？
    · JL 引理：保留点积（注意力分数）需要的维度远小于保留向量本身
    · 薄壳现象：高维向量的能量集中在低维子空间
    · 学习的投影 ≈ 4× 优于随机 JL 投影

🔧 算法层（~500字）
  - 矩阵吸收前后对比伪代码：
    吸收前 → 存 K_full，推理时算 Q @ K^T
    吸收后 → 存 c^{KV}，推理时算 (Q @ W^{UK}) @ (c^{KV})^T
  - RoPE 为什么让矩阵吸收失效（位置编码混进压缩维度）
  - Decoupled RoPE 的解决方案——分开两条"血管"

🧪 实测层（~400字）
  - 三个场景显存实测：短文本（4K）、长文档（32K）、极端（128K）
  - DeepSeek-V3（MLA） vs LLaMA-3（GQA） KV cache 增长曲线对比
  - 精度维持验证：同等显存下 MLA vs GQA 在 LongBench 得分

🔄 回扣（~200字）
  MLA 省的不是参数，是推理时每一层都要存的历史记录。
  省 90% 显存 = 同样的 GPU 能跑 10× 长的上下文。
  预告：MLA 这么强，为什么 V4 还抛弃了它？D4 见。

🎣 标题候选
  1. DeepSeek 的注意力为什么能省 90% 显存？（搜索力 ⭐⭐⭐⭐，痛点 ✅，18字）← 推荐
  2. KV Cache 压缩 32 倍：MLA 的数学原理（搜索力 ⭐⭐⭐，痛点一般，19字）
```

#### D3 详细结构：GRPO — R1 怎么学会"想清楚再说"？

```
📐 数学层（~600字）
  - 直觉类比：考试时先做一遍，再检查一遍，擦掉错的只留对的
  - 传统 RLHF 的痛点：需要额外训练一个"评委模型"（Value Model）→ 训练不稳定
  - GRPO 的核心：不请评委，让回答之间互相比
    ① 给同一个问题，生成 G 个回答 {o₁, ..., o_G}
    ② 打分 {r₁, ..., r_G}
    ③ 组内标准化：Â_i = (r_i - μ_r) / σ_r
    ④ 用 Â_i 更新策略——比平均分高的加强，低的削弱
  - 为什么组内均值能替代 Value Model？
    · μ_r 作为 baseline → Var[r_i - μ_r] < Var[r_i]，方差更小
    · σ_r 做归一化 → 学习率不受 reward 绝对值影响
  - KL 散度约束：新策略不能离参考模型太远 → 防止"为了高分走火入魔"
  - 可验证 Reward：数学题有标准答案 → 不需要人类标注

#### D4 详细结构：V4 注意力进化 — 为什么抛弃 MLA？

```
📐 数学层（~600字）
  - 全文主线：V3 的 MLA 省显存 → 但 MLA 有一个致命问题
  - MLA 的瓶颈：
    · KV cache 虽然小但**仍需存所有 token**——1M context 时 d_c=512 仍有 ~2.5GB
    · 关键问题：MLA 没有"选择"能力，它只能压缩，不能跳过不重要的 token
  - V4 的答案：CSA（压缩稀疏注意力）+ HCA（超压缩全局注意力）
    · CSA = 压缩 + 稀疏选择 + 滑窗（三叉戟）
    · Lightning Indexer：独立的小模型打分，只选 top-k 相关 token
    · I_{t,s} = Σ w_{t,h} · ReLU(q_{t,h} · K_s^{IComp})——用 ReLU 替代 softmax！
    · HCA：极度压缩的全局概览，粗粒度建模全文
  - mHC（流形约束 Hyper-Connections）：Birkhoff 双随机矩阵约束训练稳定

#### D5 详细结构：FP8 训练 — "残缺数字"练出顶级模型

```
📐 数学层（~600字）
  - 直觉类比：记账时零头用"约等于"，不影响大局但省一半纸
  - 数字格式对比：FP32（32bit）→ BF16（16bit）→ FP8（8bit）
  - 两种 FP8 格式：
    · E4M3：4 bit 指数 + 3 bit 尾数，范围 ±240，Forward 用（精度优先）
    · E5M2：5 bit 指数 + 2 bit 尾数，范围 ±57344，Backward 用（范围优先）
  - 三个坑和三个解法：
    ① Outlier：Block-wise 量化——每 128 个值一组，各自算缩放因子
    ② 下溢：Loss Scaling——计算前把值乘大，算完后除回来
    ③ 偏差累积：随机舍入——x 以概率 (x-x_low)/(x_high-x_low) 舍入到高位
  - 为什么 FP8 不崩？H100 Tensor Core 原生 FP8 → 硬件级保障

🔧 算法层（~400字）
  - FP8 矩阵乘法伪代码：量化 → 乘加 → 反量化
  - V4 精度分配策略（哪些用 FP8、哪些保留 BF16）

🧪 实测层（~400字）
  - DeepSeek-V3（FP8） vs 同规模 BF16 模型的训练 loss 曲线对比
  - 显存节省对比：FP8 vs BF16 在 1.6T 模型上的数字

🔄 回扣（~200字）
  FP8 训练的哲学：不是靠更精密的计算，而是靠"知道在哪可以粗糙"。
  随机舍入的数学保证了长期期望无偏，block-wise 量化护住了局部异常值。
  精度降一半，质量不降——这就是数学在工程里最漂亮的时刻。

🎣 标题候选

  2. 训练精度降一半，模型质量为什么没崩？（搜索力 ⭐⭐⭐，痛点 ✅，18字）
```
